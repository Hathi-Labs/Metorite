## Description

## Phase 3 · item 3.6

The pattern-review screen let you approve/reject only **pending** patterns. Gaps:
- An **In force** (approved) pattern offered only **Forget** — which *deletes* the row, so the auto-learner re-infers the same pattern within the hour. The sticky verdict (**Reject**, which `_upsert_rule_pattern`'s re-learn guard respects) had no UI. → "endpoint exists, no UI".
- A **rejected** pattern couldn't be restored at all.

### Change
Pure UI. `PatternRow` now renders actions by which handlers it's given:
- **In force** rows gain **Reject** (alongside Forget). Reject is titled "won't be re-learned", distinguishing it from Forget's plain delete.
- **Rejected** rows gain **Restore** (approve).

The `/rules/patterns/review` endpoint already supported reject/approve of any pattern by id — only "approve all" (no ids) is scoped to the pending set.

### Deferred (documented in-commit)
Manual pattern-add UI / dropping the unused `USER` source badge, and re-exposing exclude-teaching from the "None" Fix — lower-value/speculative vs the concrete gap here.
