## Description

## Phase 2 — 2.4: drafts carry Cc/Bcc (kill the native-vs-full-send composer branch)

The draft write-path carried only **To**. A Cc/Bcc reply couldn't be saved as a draft, so every composer special-cased it into a **full send** — which starts a fresh, *unthreaded* message and discards the auto-saved draft. Three composers each carried that three-way branch (review §3.2).

### Change
- **Provider** — `create_draft`/`update_draft` gain `cc`/`bcc`. Outlook sets `ccRecipients`/`bccRecipients` on the draft (createReply PATCHes them on); Gmail/IMAP add MIME `Cc`/`Bcc`. `update_draft` only touches recipients when given, so a body-only autosave can't wipe a Cc the draft already has.
- **Transport** — `DraftUpsertRequest` + `PUT /drafts` carry cc/bcc; `_upsert_local_draft` mirrors them into `cc_addresses`/`bcc_addresses` so a reopened draft shows them at once.
- **Composers** — EmailDetail / ConversationView / ComposePanel now send a Cc'd reply via the **native draft path** (Drafts → Sent, threaded). The full-send detour is reserved for attachments/artifacts only.

Native send preserves Cc/Bcc: recipients live on the provider draft and Graph's send uses the stored message; the sign-in-place `update_draft` passes `cc=None` so it never clears them.

### Deferred (by design)
Attachment **content** on drafts needs an upload flow — still routes via full send. `create_draft` already accepts `attachments` for when that lands.

### Verification
- `test_outlook_draft_cc`: `ccRecipients`/`bccRecipients` on create (standalone + reply PATCH) and update; a body-only update leaves them untouched. 101 draft-related tests pass; blocking lint clean; frontend `tsc` clean (dead `sendEmail` import removed).
