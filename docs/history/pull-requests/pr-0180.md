## Description

A comprehensive review-and-refactor of the calendar app, done as an external reviewer would: the single biggest maintainability problem was that `CalendarView.tsx` had grown to **3300 lines** across nine subcomponents from the incremental Focus-OS PRs. This is a **pure structural refactor — no behavior change.**

## What changed
- **`components/calendar/shared.ts`** — the constants, date/grid geometry, formatters (`fmtClock`/`fmtLeft`), `layoutBlocks`/`deadlinesForDay`/`useNow`, and `energyWindowsPayload` (the plan-request builder) now have one home.
- **`components/calendar/{TimeGrid,MonthGrid,UnscheduledRail,NowNextBar,PlanDayPanel,EndOfDayReview,ScheduleSheet,CalendarSettings}.tsx`** — one component per file, none over ~750 lines.
- **`CalendarView.tsx` (~810 lines)** is now just the orchestrator: state + the schedule mutations (all routed through the store's undoable `applySchedule`).

## Deduplication folded in
- The **identical energy-window→ISO mapping** that was copy-pasted into `rollOver()` and the Plan-day panel is now `energyWindowsPayload()`.
- The **clock formatter** existed as *five* copies (local `const fmtClock` in ScheduleSheet/NowNextBar/EndOfDayReview/FocusSession + two inline `toLocaleTimeString` calls in TimeGrid) — all now the shared `fmtClock`.
- Refreshed CalendarView's stale "scaffold / P0-P1" module header; dropped dead/over-provisioned imports.

## Preserved on rebase
Regenerated on top of the latest `main`, so it keeps the minimizable-Focus-session wiring (#174) and the day-state sync (#166) intact in the orchestrator.
