## Description

## Problem

Moving a task to **Done** on the My Next Actions board made it disappear. Dropping a card on the Done column marks it `DONE`, which flipped its disposition — and the `next` view filters `disposition = 'NEXT'`, so the card was instantly evicted from the board (it silently jumped to the separate Done list). The user expected it to **rest in the Done column until they archive it**.

## Fix

A `DONE`-but-not-archived task now stays visible in the board's last (Done) stage:

- **`itemsForView("next")`** includes `DONE & isMine` — but only the board and grouped list consume this, and both slice by stage so completed tasks land in the Done column / Done section. The sidebar "My Next Actions" count (`viewCounts`) and the Priority/Engage views still exclude `DONE`, so open-work counts are unaffected.
- **`statusColumnForItem`** routes any `DONE` task to the last stage regardless of a stale `workflowStage` / `providerStatus`.
- **Reopen:** dragging a `DONE` card back to an earlier stage flips disposition → `NEXT` and clears `completed_at` (invariant: `completed_at` non-null iff `DONE`). Upstream reopens naturally via the stage→status map (the target stage resolves to an open ClickUp status).

## Tests

3 new backend tests (110 pass total): DONE stamps `completed_at`, reopen clears it, and the stage-boundary disposition flip works both ways. Frontend `tsc --noEmit` + eslint clean.
