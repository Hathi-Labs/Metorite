## Description

## Problem

The orchestrator chat (and memory reads/writes) intermittently 401 with a misleading *"model API key missing/invalid — re-enter in Settings → Models"* error, while the GitHub Copilot SDK agent works fine.

**Root cause (diagnosed live on the VPS):** a two-env-file split.
- The **gateway / orchestrator / all Python agents** read `GATEWAY_INTERNAL_TOKEN` from the shared `/opt/acb/app/.env` via pydantic Settings.
- The **workbench** (`acb-workbench`, Next.js) is a *separate* systemd service that reads its **own** `control_plane/.env.local` via `process.env`. Its server routes forward that token to the gateway's `require_internal_auth`.

`deploy.yml` injects the token into `.env` only and rebuilds the workbench **without touching `.env.local`**. So `.env.local` was hand-managed and had drifted to the dev default `sk-local-dev-change-me`, while the gateway expected the real 64-char token. Result: every workbench→gateway internal call (`/memory` every ~30s, `/v1/chat/completions` for orchestrator chat) 401'd. Backend agents were unaffected because they share `.env` with the gateway — hence the confusing partial outage.

The live VPS was already hot-fixed (token aligned + `acb-workbench` restarted; `/memory` and `/v1` now return 200). **This PR prevents recurrence on future deploys.**

## Fix

Make `.env` the single source of truth. After `.env` is provisioned, reconcile `GATEWAY_INTERNAL_TOKEN` in `.env.local` to exactly match — in-place, idempotent, preserving every other workbench key.

Handles: drift (update), in-sync (no-op), missing file (create), tokens with shell-special chars (`grep -v` + `printf`, **not** `sed s///` which breaks on `/`), and unset token (skip, never wipe). Backs up before rewriting.

- Only backend agents that share `.env` were confirmed safe; the workbench was the sole drift point, now closed.
