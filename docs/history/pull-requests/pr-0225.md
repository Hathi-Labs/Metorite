## Summary

The site is currently fully down (both `commandcenter.fracktal.in` and `api.commandcenter.fracktal.in`) while deploy runs stayed green. Two compounding blind spots in `deploy.yml` caused this:

1. **`systemctl reload caddy || true` swallowed a chronically failing reload** — visible in the logs of the last two deploys (`Job for caddy.service failed.`). The on-disk Caddyfile is broken, so the running Caddy served its stale in-memory config until it next restarted, at which point it could not come back up and every public hostname went dark.
2. **`verify()` gated only on the gateway `/health`**, with a direct-IP fallback that passes even when Caddy — which fronts everything users see — is dead.

## Changes

The remote deploy script now, at the Caddy step:
- prints Caddy's systemd state and last 25 journal lines into the CI log (remote diagnosis)
- validates the live `/etc/caddy/Caddyfile`; if invalid, backs it up (timestamped) and reinstalls the repo's known-good `deploy/hostinger/caddy/Caddyfile`
- reloads Caddy if running, restarts it if dead
- fails loudly (`CADDY FAILED TO START` + journal dump) instead of `|| true`

`verify()` now requires the **public workbench URL** to answer 2xx/3xx in addition to gateway health, so a dead proxy can never ship as a green deploy again.

Merging this triggers a deploy that should bring the site back up, and its logs will show exactly why Caddy was failing.
