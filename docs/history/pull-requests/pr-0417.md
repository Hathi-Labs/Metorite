## The adversarial review's two catches (fixed here, both invisible to every hermetic suite)

1. **Auto-lead would have died today**: the background mail path (`process_new_mail` → `_create_lead`) calls the now-converted `create_record` with no ambient tenant → `TenantUnbound` on every message → `_consider` counts it failed → the watermark never advances. Fixed the H4 way, early: the mailbox owner's organization is resolved from their `app_user` row and bound explicitly around the call. A new AST ratchet (`test_exempt_files_do_not_reach_converted_sessions_unreviewed`) now catches this whole class mechanically — the exemption markers are file-scoped but the call graph is not, so any exempt file calling a `tenant_session`-opening function needs a reviewed edge in `H2_EXEMPT_CALL_EDGES`.
2. **A mid-block commit inside three email handlers**: `_store_ai_draft(db, …)` defaulted `commit=True` under the tenant wrapper — ending the transaction and dropping the GUC for everything after it (partial commits today; zero-row tails under RLS phase 4). Now `commit=False` at the one call site whose callers all hold wrapper sessions.
