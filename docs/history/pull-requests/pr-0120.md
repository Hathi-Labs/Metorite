## Description

## Phase 2 — 2.7: digest is a projection (shared aggregates, self-exclusion, HTML, empty-suppression)

The digest re-derived inbox aggregates with its own SQL — the standing risk of drifting from what Analytics computes (the class behind the 1.6 needs-reply lie). Make it a projection and stop it counting itself (review §2.5).

### Change
- **Composed from named helpers** — `_generate_digest` now composes `_digest_totals` / `_digest_categories` / `_digest_top_senders` / `_digest_needs_reply`, each testable and each reading one shared windowed inbound-inbox definition. needs-reply stays on `email_thread_status`.
- **Self-exclusion everywhere** — the account's own address is dropped from totals and the category breakdown too (not just top-senders). The digest email lands in the inbox *from the account*; counting it (plus self-notes / BCC-to-self) inflated the next digest. One shared `_DIGEST_INBOUND` predicate.
- **HTML body** — `_render_digest_html` renders a self-contained, escaped HTML version alongside the Markdown; both send paths pass `body_html`.
- **Empty-digest suppression** — the scheduler skips a digest with no new mail AND nothing awaiting a reply, *without* stamping `last_digest_at`, so a later arrival the same day still delivers. Manual "send now" is never suppressed.

### Deferred (by design)
Unifying with `analytics.py`'s own aggregate helpers (the audited module — not worth destabilising mid-refactor) and merging the two frontend digest config dialogs.

### Verification
- `test_email_digest`: every windowed aggregate excludes self + binds `:self`; totals + both bodies returned; empty detection; HTML escapes sender/category text. Blocking lint clean.
