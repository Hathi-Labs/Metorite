## Description

Two follow-ups to the ClickUp status work.

## 1. A synced task's Stage picker showed every workspace status (regression)

My previous change aggregated **all** list-level statuses into `account.statuses` so the settings mapping could see them (e.g. a list-level "Done"). But the detail Stage picker also reads `account.statuses`, so opening a ClickUp task started listing the whole-workspace union instead of just that task's project pipeline.

**Fix:** a lightweight `GET /items/{id}/stage-options` returns **this task's own list statuses** (`list_statuses_for_task`, already ordered by ClickUp pipeline order). The detail picker uses those, falling back to the account-wide set until they load / if unresolved. The settings mapping still gets the full union — unchanged, as it should.

## 2. ClickUp statuses displayed in lowercase

ClickUp's API returns status names lower-cased (`"to do"`, `"done"`) while its UI shows them title-cased. Added a **display-only** `formatStatus()` (raw values are kept for matching and back-sync) and applied it where ClickUp statuses render:
- the detail Stage picker (current value + options),
- the ClickUp subtask status chips,
- the status-mapping settings table,
- the dedup notice,
- the per-project board columns.

The global Next-Actions board keeps the user's own workflow-stage names exactly as typed, and the status-grouped list headers keep their existing uppercase section styling.
