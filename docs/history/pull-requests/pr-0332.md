## Description

Recording worked but **Talk** did nothing in either direction. The socket was dying before the handler ran.

## Root cause

The audio WebSocket was mounted on the feature-gated router. `require_feature_router`'s check declares `request: Request`, and **FastAPI only populates that for HTTP routes** — on a WebSocket the dependency is invoked without it:

```
TypeError: require_feature_router.<locals>._check() missing 1 required positional argument: 'request'
```

Raised during the handshake, so there was no handler, no close code the client could interpret, and nothing in the log to suggest audio had even been attempted. Confirmed by reproducing it directly rather than inferring it.

Exempting the path could never have helped: the dependency still has to run in order to read the path and decide.

## Fix

WebSockets now live on their own ungated router (`core.ws_router`), included separately in `main.py`. That's the only correct shape — a gate that requires an HTTP request cannot guard a socket. Anything mounted there must authenticate itself, as this one does with a call-scoped HMAC token.

## Why no test caught it

Every unit test passed throughout, because none of them opened a socket. Three now do:

- a **bad token** must produce a clean `1008` — which only happens if the handler runs at all
- a **missing token** likewise
- a third pins the underlying FastAPI behaviour, so if gated routers ever become websocket-safe the test fails and this workaround can be removed

Plus a guard asserting the audio path is not on the gated router.
