# Part 1 — Default-deny authentication (BO‑2 residual #1)

## The problem

`get_current_user` never rejects — it **labels**. So every route was open unless it remembered to add a guard, and the failure mode of opt-in security is the route nobody opted in.

Two were found exactly that way:

| Route | What it did, anonymously |
|---|---|
| `GET /agent/workspace/{session_id}/history` | read an agent's **full file version history** |
| `POST /agent/workspace/{session_id}/promote` | **wrote** to the workspace |

Neither took a caller identity at all — the same IDOR family as the memory API that BO‑2's first pass closed. A scan of the assembled app found them; they weren't in anyone's list.

## The fix

`require_authenticated(public=...)` is attached **once** at `FastAPI(dependencies=[...])`, so a route added tomorrow is covered without anyone remembering anything.

It asks only *"who are you"*. `require_permission` and the feature gates still answer *"may you"* — a member with an empty permission set passes authentication and then fails authorization, which is the correct sequence and is tested as such.

`gateway.main.PUBLIC_ROUTES` is the complete anonymous-reachable set: `/health`, the three provider webhook receivers, the signed agent webhook (#293), both OAuth callbacks, the Graph notification, the Meta webhook, the four WhatsApp bridge endpoints, and the two meeting-bot callbacks. Each authenticates itself by another means or is a liveness probe. Matching is on the route **template**, so a path parameter can't spell a public path.

**Two tests keep the list honest:** a `PUBLIC_ROUTES` entry matching no live route fails (a typo is dead text; a stale entry is a hole held open), and a coverage test asserts every route in the assembled app carries the guard — 447 of 447 in prod.

**One structural exception:** Swagger/ReDoc/`openapi.json` cannot carry the guard (FastAPI mounts them with no dependency chain) and publish the entire API surface, so they're now dev-only.

## The resolver now fails closed

Its legacy `executive`/`employee` fallback existed because, before authentication was enforced, refusing everyone when the tables were missing would have been an outage with no way back in. That reason is gone — quietly granting an *approximation* of access is the access model silently not being the access model. `ACCESS_LEGACY_FALLBACK=1` is the recovery hatch. Safe because `deploy.yml` runs `apply_migrations.sh` **before** restarting the gateway.

This is the fail-open flagged in #286 and promised for removal once BO‑2 landed.

# Part 2 — Handoff to multiplayer agent collaboration

Multi-tenant user management is complete as Phase 1 and is **not being extended on its own track**. The remaining scope — modules/teams, session sharing, memory and transcript exposure — is the same set of primitives the multiplayer workstream needs, seen from the other direction. Building them twice would produce two group models to reconcile later.

**§10 of `org_access_control.md` is the integration contract.** It documents:

- **What is built and can be relied on**, with the file and function for each seam, so the other session doesn't re-derive it.
- **The four collisions**, each with where it bites in code:
  1. **modules/teams is unbuilt** and both workstreams need it — build once;
  2. **`chat_session.user_id` is single-owner** with no participants table (the comment still says *"future multi-tenant"*);
  3. **whose authority runs the agent** in a shared session — Phase 1 answered this implicitly for one user, and the default ("whoever typed") leaks. `EffectiveAccess.intersect()` already exists and is tested for exactly this shape;
  4. **the transcript is a second exposure boundary** — personal memory and tool output re-exposed to everyone in the room. Every Phase 1 seam assumes one viewer per run, so this is genuinely new surface.
- **What is deliberately absent**, with reasons, so absence isn't read as an oversight — including that credential scoping is *authorization, not isolation*, until BO‑7.
- **Where the design rationale lives in code**, since the docstrings carry the "why" that a spec summary flattens.

The planning index and the parent research doc now point at the handoff, so anyone arriving from either finds it rather than starting from a document whose §4 is now implemented.
