## Summary
- The Workshop editor (`/build/apps/[slug]/edit`) had zero mobile handling — a fixed-width file tree, a fixed 400px chat pane, and a segmented Preview/Code/Tests tab control all crammed into one row, unusable below tablet width.
- Every other multi-pane app in this codebase (Email, Tasks, Chat, WhatsApp) already solves this the same way: one full-screen pane at a time on mobile, switched via `AppShell`'s bottom nav dispatching a `cc-mobile-nav` window event the page listens for. This extends that exact pattern rather than inventing a new one:
  - `AppShell.tsx`: registers 4 new bottom-nav tabs (Chat/Preview/Code/Tests) for the editor route.
  - `edit/page.tsx`: a `mobilePane` (`"chat" | "main"`) state picks which full-screen surface shows; the existing `view` state still picks preview/code/tests within `"main"`. Panes are toggled with a `hidden` class (not unmounted), so the chat session, Monaco editor, and preview iframe all stay alive underneath instead of resetting on every tab switch. The now-redundant desktop tab strip is hidden on mobile. The file tree moves into the shared mobile drawer via a new "Files" button (browsing/selection only — file creation stays a desktop affordance for now).
  - Both editor and run pages: popover widths (History, checkpoints, app info) capped with `max-w-[calc(100vw-1.5rem)]` so they can't overflow a narrow viewport.
  - Run page (`[slug]/page.tsx`): Fork/"Open in Workshop" buttons drop their text labels below `sm` (icon + title tooltip, matching the icon-only pattern already used elsewhere) — with the app name, a badge, and up to three `shrink-0` buttons in one non-wrapping row, editors on a narrow screen could overflow the header.
- The gallery page (`/build/apps`) was already fine — it uses a responsive card grid with no fixed-width columns.
