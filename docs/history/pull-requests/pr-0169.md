## Summary

Follow-up review of the Generative UI 2.0 implementation (#167) verifying it works end-to-end for **both** runtimes — native Microsoft Agent Framework agents (Tier 1) and GitHub Copilot SDK agents (Tier 1.5).

**Verified working as shipped** (reuses proven machinery):
- Emission: ContextVar queue (native MAF) / `_RUN_QUEUES` registry (Copilot's thread-hopped tools) — both reach the SSE stream.
- Blocking resume: `resolve_user_input`'s `call_soon_threadsafe` handles the Copilot cross-loop case; `wait_user_future` heartbeats the relay on both paths.
- Copilot stall detector suppression engages while a genUI form is parked (shares `_pending_user_input`).

**Three timeout surfaces didn't know about the new blocking mode — fixed:**
1. **Tier-1 idle watchdog**: a `generative_ui` event carrying a `request_id` now selects the 3600s HITL budget instead of the 600s tool-open budget (new `_is_hitl_event` helper at both `_nq` drain sites) — a native-MAF user filling a form for >10 min no longer gets the run killed.
2. **Tier-2 batch shim**: `emit_generative_ui` joins the per-tool-timeout exemption list — a blocking form on the fallback path is no longer cancelled at 300s mid-fill.
3. **Copilot no-text-end**: `emit_generative_ui` joins `HITL_BLOCKING_TOOLS`, so a turn that ends on a rendered card with no closing text is treated as a legitimate ending (the card IS the output), matching `ask_questions`.

Also: `emit_generative_ui` joins the guaranteed tool floor (`_CORE_STANDARD_TOOL_NAMES`) so no `tool_scope` can strip rich-UI capability from an agent; the scope-aware addendum follows automatically.
