## WS-28j1 — the person rows and the five pills

| Pill | Definition |
|---|---|
| **Behind** | ≥1 open task whose `due_at` is in the past |
| **At risk** | ≥1 open task due within the horizon whose *cumulative* remaining estimate exceeds the working hours before it |
| **Overloaded** | committed hours for the week > contracted hours |
| **Idle** | no open task, **or** committed below a quarter of contracted |
| **On track** | none of the above |

One pill by precedence; every applicable flag travels beside it.

**Five things the build settled:**

- **"At risk" is cumulative, and carries overdue work** (D-PC-19). Three twelve-hour tasks
  due Tuesday, with sixteen hours before Tuesday, is a week that does not fit — and
  per-task arithmetic calls all three fine, because none alone exceeds sixteen. A task that
  missed last Tuesday still has to be done, so its hours stay in the sum; dropping them
  makes every later deadline look reachable, which is how a slipping week becomes a
  surprise. Undated tasks are excluded: they carry no deadline to be late for, so counting
  them would pill somebody whose backlog is merely large.
- **"Partial" names the viewer's scope; the hidden delta is never computed** (D-PC-20).
  Reporting "12 of 20" means running the query without the scope, which is the query the
  scope exists to forbid. One integer per person is still a leak, and it is the one
  somebody would probe with.
- **One pill by precedence, every flag beside it** (D-PC-21). "Behind *and* overloaded" is
  a different conversation from "behind", and one word cannot say so.
- **Four aggregates, not four per person.** Every figure comes from one of four statements
  keyed by `lower(assignee)`, plus one absence query for the page. Built the obvious way,
  an eighty-person roster is three hundred round trips.
- **An assignee with no roster row still appears** — one mechanism covering agents
  (D-PM-4), people who left, and addresses nobody added. Work assigned to a departed
  colleague is invisible everywhere else in the product.

## WS-28j2 — the department rollup

Per department and then for the org: headcount, Σ contracted against Σ committed, people
in each pill, who is away this week, people with no open work at all, and **the spread**.

**No new query.** `rollup()` is handed `[r.model_dump() for r in rows]` — the exact payload
the client is about to receive — so §5.9's *"a projection, not a second count"* is a
property of the code path rather than a claim about it. The fence asserts **identity**
(`org["contracted_hours"] == sum(rows)`), not closeness; a second one greps the module for
`db.execute` / `SELECT` / `await`, because the cheapest way to introduce a second count is
a convenience `db` parameter on a pure module.

- **Strain is a share, not a count.** Three behind out of four is a different situation from
  three out of forty. Departments sort by it because *"a rollup nobody can act on is a
  table"* — an ordering of work, computed from pill counts, with no score on the panel.
- **The spread is stated in hours and names both people.** *"Priya has 46h due this week,
  Ravi has 6h — a 40h gap"* is arguable and actionable; a bare percentage gap is a score
  with two names attached. Computed only over rows whose hours mean something, or somebody
  holding thirty un-estimated tasks arrives at the bottom of it as though they were free.
  `None` under two usable rows: a spread over one person is not a spread, and "0h" there
  reads as a balanced team.
- **Agents are excluded and the exclusion is reported** (`org.agents`). Headcount is
  people; a silent omission is how a total quietly stops adding up.

`away_this_week` joins the person row for this — a wider window than `away` (today only),
because somebody back tomorrow and somebody leaving on Thursday are both answers to *"can I
give them a deadline this week"*.

## The tenant boundary does not rest on an owner's flip

The grant closure is applied to the `data:org:read` caller **too**, not short-circuited to
`TRUE`. `project_clause` already answers the tenant subquery for that caller (what WS-29b
changed it for), and the shortcut would make this endpoint's tenant boundary depend on
FORCE ROW LEVEL SECURITY being *enforced* — which is the owner's act.

Measured on a scratch cluster that has no FORCE RLS: with the shortcut, a second
organization's task lands on the row — **3 → 4 open tasks, 86h → 185h**. The live harness
asserts it both ways.

⚠️ `/people/{id}/work` still takes that shortcut. That is a finding for the board, not a
pattern to copy, and it is deliberately not fixed in this diff.

## Two fences were corrected, both self-inflicted

Each was a fence written over raw source, and each failed on correct code:

- The **no-ranking fence** (D-PC-14) grepped for `leaderboard`, `percentile` and their
  cousins — and fired on the docstrings that name those words in order to explain why the
  product refuses them. A fence that punishes the explanation makes deleting the reasoning
  the cheapest way to go green. It now strips comments and docstrings and matches only what
  runs, and it carries **its own fence**: four plausible guilty lines that must still trip
  it.
- The **route-order fence** read the live `router` — whose order inside pytest is the test
  session's import order, not the application's. Its first working version then compared
  bare paths, so `PATCH /people/{person_id}` in front of `GET /people/dashboard` read as a
  collision it is not. It now probes a fresh process and matches on path **and** method,
  stated as a general rule over the package so the next literal path inherits it.

Also corrected: **D-PC-17 said the avatar is WebP.** The build shipped JPEG and said so in
its commit; the decision row did not, and a decision row that disagrees with the code is
worse than none.
