## Description

Found by inspecting the **live production mailbox**, which turned out to be Microsoft/Outlook — not Gmail. Three problems, one of them a regression introduced by #78 widening the sweep from the inbox to the whole mailbox.

## 1. Domain consensus fired on the user's own company domain

The sweep falls back to a per-domain consensus for senders with no history of their own. It excluded shared free-mail hosts (`gmail.com` etc.) but **not the user's employer domain** — which is a shared domain in exactly the same way: every colleague sends from it, so "same domain" implies nothing about the sender.

Live numbers from production:

| | |
|---|---|
| `@fracktal.in` labelled Notification | 12 |
| other categories on that domain | 2 |
| dominance | **0.857** |
| `_DOMAIN_MIN_DOMINANCE` | 0.9 |
| margin | **0.043** — six more Notification-labelled internal mails |

Had it crossed, the sweep would have stamped **Notification onto 3,307 uncategorized internal colleague emails**, each also writing the label upstream to Outlook.

`_decide` now refuses a domain consensus for the account's own domain plus any configured org domains — the same set `sender_scope` treats as internal. Sender-level evidence still applies to a *specific* internal address; only the blanket is refused.

## 2. The sweep scanned Sent

Cleanup categories describe *inbound bulk mail* — a message you wrote is never a Newsletter. Widening the scope pulled 434 sent/self-addressed messages in. Now excluded by folder **and** by from-address, since self-addressed mail can sit outside Sent.

## 3. `restore-labels` lied on providers that can't read labels back

Only Gmail implements `fetch_label_assignments`; the base returns `{}`. That empty result is indistinguishable from *"your mailbox has no labels"* — so the UI told an Outlook user with **1,909 labelled messages** that they had none, the exact opposite of the truth the repair path exists to restore.

Added an explicit `SUPPORTS_LABEL_READBACK` capability flag, checked *before* authenticating, with a UI message that explains the provider limitation instead.
