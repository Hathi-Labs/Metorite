## Description

## What this is

The AI Note Taker app (`/notes`), from first principles to first working slice: record/upload a conversation → transcribe (speaker-attributed) → grounded meeting notes → act on them through the existing Tasks/Email/Chat apps.

### 1. Architecture spec + research (`ai-company-brain/specs/`)

- **`note_taker_app.md`** — full product + architecture plan: browser-native capture (mic everywhere, Chromium tab-audio dual-channel with echo-cancellation discipline), a pluggable `acb_stt` provider layer mirroring `acb_llm`'s BYOK posture (cloud tier + self-host faster-whisper/WhisperX tier with **open diarization**), notes generation on `acompletion_with_fallback` with the transcript pinned as untrusted DATA, HITL `action_item` draft→approve→task flow mirroring email capture, a 6-slice build plan, ADR-style decisions, AI-integration brainstorm (18 ideas, ranked), and the UI vision (recording dock, transcript↔notes provenance highlighting, honest pipeline progress).
- **`note_taker_research_2026-07.md`** — evidence base: source-level Meetily deep dive (verdict: inspiration, not donor — desktop-only capture, diarization paywalled in its PRO tier), an 18-project landscape survey (WhisperLiveKit / Vexa / Scriberr ranked as top donors; Screenpipe disqualified — no longer open source; Amurex dormant), mid-2026 open ASR/diarization SOTA with licenses, browser-capture constraints, and a license watch-list.

### 2. Slice 0 implementation (upload → transcript segments, end to end)

- **`infra/postgres/94_note_taker.sql`** — activates the dormant `meeting`/`action_item` tables; adds `meeting_recording`, `transcript_segment` (click-to-seek offsets, speaker labels, pgvector), `meeting_note`, `summary_run` (pipeline job state machine with `result_backup`). **Validated by a clean-room run of the full `00→94` migration chain on PG16+pgvector, plus an idempotency re-run.** ORM mirror added to `acb_graph.models`.
- **`packages/acb_stt`** — new shared package: provider interface + Groq/OpenAI (OpenAI-compatible `verbose_json`) and Deepgram (native diarization → `S1/S2` labels) providers; keys from the encrypted `provider_keys` store with env fallback; preference-ordered auto-resolution (`groq → deepgram → openai`, `NOTES_STT_PROVIDER` to pin). Unit tests cover parsing + resolution.
- **`gateway/routes/notes/`** — meeting CRUD + library search, multipart upload to `NOTES_MEDIA_DIR` with audited cascade delete, audio playback, and a background transcription pipeline with per-stage status/errors persisted in `summary_run` (no silent failures).
- **Control plane** — `/api/notes` proxy (multipart + binary passthrough), `/notes` library (search, status chips, live polling, teaching empty state) and meeting detail (speaker-labeled click-to-seek segments, audio player, honest processing/failed states), replacing the `ComingSoon` stub. Design-system compliant.
