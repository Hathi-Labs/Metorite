## Description

## What

Two Dashboard v2 items that make the dashboard actionable rather than a summary.

**1. Priority ordering of the needs-reply queue.** The live dashboard now ranks the reply queue by an urgency score — `high importance (+100) + unread (+25) + capped age (≤30)` — instead of pure oldest-first. This directly answers the "oldest-first surfaces dead loops" complaint: a high-importance unread thread from this morning sits above a two-month-old dead loop. Each row badges *why* it ranks where it does (an amber importance triangle, or an unread dot). Deterministic — no per-load LLM cost. The **emailed brief stays oldest-first**, because a brief's job is "what's going stale".

**2. Click-through analytics.** The "By category" rows and "Noisy senders" rows are now buttons: a category opens the inbox filtered to that label (same path as clicking a label chip); a sender opens the mailbox filtered to that sender, so you can triage/unsubscribe from the actual mail instead of staring at a count.

## How

- `_digest_thread_list` gains a `prioritized` flag (used only by the `full`/dashboard projection); returns `important`/`unread` per row. `_PRIORITY_SCORE` is a SQL expression, so ordering happens in the DB.
- `DigestThread` type + `DashboardView` badges; `onFilterLabel`/`onFilterSender` callbacks thread page.tsx → AutomationView → DashboardView, reusing `selectLabel` and a `from` search filter.
