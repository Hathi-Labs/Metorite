## Description

Filed straight off a real report: *"I do not have access to this in the UI."* Projects and People were absent from the sidebar, and there was no way from inside the product to tell which of **four** causes it was:

1. your roles do not grant the feature;
2. a deny override cancels a grant you appear to hold;
3. the slug is registered but no nav item points at it;
4. you are signed out, or the gateway is unreachable.

All four render as exactly the same nothing. The only way to tell them apart was for somebody with database access to go and look.

## 1. `/auth/me` resolves against the catalog, not just the code mirror

It now takes `feature_catalog` **unioned** with `acb_auth.FEATURES`, instead of iterating the code tuple alone.

Migration 130's own header calls `feature_catalog` *"the nav-pane registry the admin UI renders from, so adding a pane is a seeded row, not a code change in the gateway AND the frontend"*. `allowed_features()` iterating the code tuple makes that promise false: a slug seeded by a migration is invisible to the sidebar if the deployed `acb_auth` predates it — silently, with nothing in any log. The union covers the other direction too, so a box whose migrations haven't run yet doesn't lose every pane.

**This grants nothing.** The gate is `require_feature_router` on each router, which asks `access.has("feature:<slug>")` and consults neither list. Widening the *report* can only stop the UI hiding a pane the API would already serve — and `test_a_member_does_not_reach_a_catalog_slug_they_lack` is the fence that keeps it that way.

## 2. A new ungated `/access` page

Every pane, whether you can reach it, and one sentence saying why not — naming the permission, the roles that failed to carry it, and calling out a **deny override** separately, because that is the one case where "ask an admin to grant it" is advice that cannot work.

Ungated deliberately, and it's the only sidebar item that is: a diagnosis page you need a grant to open is useless in the one situation it exists for. It sits in Personal Center rather than Admin so a plain member can reach it without an Admin heading appearing for them.

It also lists features you hold that **no nav item points at** — the one failure the pane list cannot show, and another thing that reads as "not built".
