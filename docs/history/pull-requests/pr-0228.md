## Description

Makes a freshly-paired personal number **import its recent history** instead of starting blank — using the same `events.HistorySync` payload WhatsApp pushes to WhatsApp Desktop when you link it. No Business/Cloud API involved.

## How it works
When a number pairs, WhatsApp sends a history-sync blob to the new device. The bridge now handles that event, normalizes each conversation's messages, and streams them into the **same triage inbox** as live messages.

- **Bridge (Go):** request the larger ~1-year desktop-profile sync on link (`RequireFullSync` + `FullSyncDaysLimit`), gated by `WHATSAPP_BRIDGE_FULL_HISTORY` (default `true`) / `WHATSAPP_BRIDGE_FULL_HISTORY_DAYS` (365); `false` → default ~3-month window. `history.go` maps each `WebMessageInfo` through the existing `classifyMessage`/media/context path, names DMs + groups from the conversation header, skips status/broadcast/newsletter pseudo-chats, and posts 200-message **backfill** batches. A ~90s debounce fires one reclassify once payloads stop. Media protos are cached so recent media re-downloads (old media 404s gracefully).
- **Gateway:** `/bridge/ingest` honors a `backfill` flag — **persist but skip the post-sync hooks**, so auto-reply rules never fire on months-old messages. New `/bridge/reclassify` runs **only** the chat-status classifier once, so imported chats get their reply state without any automated replies. Re-added the `group_subject` wire field (now populated by history) so group chats are named.

Persist already dedupes on `wa_message_id`, so backfill + live messages never double up.

## Honest limits (documented in the bridge README + .env.example)
- It's **recent history, not a full archive**: ~1 year reliable, ~3 years is the server ceiling, and you only get what your phone still stores.
- **Old media often 404s** (expired from WhatsApp's CDN) — text/metadata lands, the download just fails.
- The bootstrap sync is **one-shot at link time** — can't be re-requested (only unlink + relink).
- On-demand "load older" pagination is a possible follow-up; it's best-effort (needs the phone online, WhatsApp may drop companion-device requests), so it's intentionally not wired in yet.

This is grounded in how mautrix-whatsapp (also whatsmeow-based) and Baileys implement backfill — see the design notes for the specific limits.
