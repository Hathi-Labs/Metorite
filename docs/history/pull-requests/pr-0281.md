## Description

## What & why

Addresses two issues with the AI planner: it auto-planned before you could add a prompt, and it wasn't obvious the per-run prompt actually reached (and could override) the LLM.

### 1. Plan on tap, not on open
The panel used to fire a plan the instant it opened, so a note typed afterwards was ignored. Now the panel opens on a **pre-run state** that invites an optional note + a plan-through horizon, and only plans when you press **Plan** / **Fit**. Changing the horizon **live-replans only once a proposal is already on screen** (before that it just updates the pending setting), so planning stays an explicit act.

### 2. Per-run note in **both** Plan and Fit
The note was already threaded to the LLM ranker for replan server-side, but the UI hid the box (with a stale "replan ignores free text" comment). **Fit** now accepts a per-run note too, and the "AI-ranked / fell back to priority" banner shows in both modes.

### 3. The per-run note **overrides** the standing prompt on conflict
Verified the LLM context is organized correctly and made the override explicit:
- **Standing planning philosophy** → *system* message.
- **Per-run note** → *user* message.
- Added a **PRECEDENCE** rule to the system prompt (and relabelled the note in the user message) so e.g. `"calls only, low energy"` wins over a standing `"front-load deep work"` for that run — while **never** overriding the ★ One Thing rule or the capacity limit.

End-to-end path confirmed: `note → run() → energy_note → /calendar/{plan,replan} → _replan_core → _llm_rank_day` (ordering) **and** `_horizon_from_note` (window). Both `apiPlanDay` and `apiReplan` already serialize `energy_note`, so no API change was needed.
