## Description

First real backfill (2026-08-06): 737 orgs, 1,189 contacts, 1,516 leads, 551 deals imported cleanly, zero dirty — but **all 1,909 notes skipped**.

Zoho sends `Parent_Id` as a lookup object (`{"name": …, "id": …}`; verified against the live tenant). `_text()` stringifies any non-None value, so `_text or _lookup_id` produced a truthy garbage string and the correct `_lookup_id` branch was dead code — no parent ever resolved. The sync engine's pull phase delegates Notes to this same path, so the two-way sync would have silently skipped every Zoho-side note too; the `CRM_ZOHO_SYNC` flip waits on this.

Fix is one reorder (`_lookup_id` first, `_text` fallback for bare strings). The real gap was the fixtures: they used a string `Parent_Id` the API never sends, so the dict path had zero coverage. Re-pinned all note fixtures to the live shape — **proven to fail against the old code** (2 failed / 39 passed pre-fix; 130 passed post-fix across import + sync files) — plus a test keeping the bare-string fallback contract.

After merge: rerun the (idempotent) backfill to land the 1,909 notes onto their timelines.
