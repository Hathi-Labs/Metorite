## Description

## Problem

When an email account's OAuth token expires or its stored credentials can't refresh, the email app's **live** provider calls fail — but it degraded *silently*:

- opening a message → "no preview text" (body hydration failed)
- folders → fell back to system-only (live folder list 401'd)
- importance/flags/categories → blank

Nothing told the user the account needed reconnection — only the Integrations page surfaced `sync_status`/`sync_error`.

## Fix

Bring the same surfacing into the email app:

- **`lib/types.ts` / `lib/api.ts`** — map `sync_status` / `sync_error` (already returned by `GET /email/accounts`) onto the email-app account model.
- **`page.tsx`** — show a prominent amber **reconnect banner** above the list/detail when the selected account's `syncStatus === "error"`, with the provider's error message and a one-click **Reconnect** (OAuth) CTA for Gmail/Microsoft, or a **Fix in Integrations** link for IMAP. The banner renders in both desktop and mobile layouts.

No backend changes — reuses the existing reconnect-in-place OAuth flow.
