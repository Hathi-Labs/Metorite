## Phase 3 · item 3.11

After 1.6 (digest honesty) and 2.7 (digest = projection), the digest still only tallied **volume**. A brief's job is to say what needs **doing**, so it now leads with two action sections:

- **Commitments due** — open GTD tasks captured from a sent reply on this account (linked via `gtd_items.origin.account_id/thread_id`, see `tasks/email_link.py`) due within ~3 days or overdue, soonest first. **Best-effort**: a deploy without the tasks feature never breaks the digest.
- **Awaiting your reply** — the oldest `NEEDS_REPLY` threads from the Reply-Zero status table, **aged** ("waiting 5 days"), so the backlog reads as "these are going stale", not a bare count.

Both bodies (Markdown + HTML) render the sections **action-first**, above the category/sender tallies; the in-app `DigestView` shows matching cards. A quiet inbox day with commitments due or an aging backlog is now correctly **not** suppressed — exactly the day a brief earns its place.
