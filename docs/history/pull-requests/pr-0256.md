## Description

Makes AssemblyAI the default speech-to-text, configurable in Settings → Models, with Deepgram kept as a working alternative and local sherpa diarization demoted to a true fallback.

Chosen for cost — roughly **$0.17/hr batch and $0.21/hr streaming with diarization, about half Deepgram** — and for explicit Hindi/English code-switching support, which Deepgram has [open quality issues](https://github.com/orgs/deepgram/discussions/1208) with.

## Batch — a native provider, not LiteLLM

AssemblyAI's API is **submit → poll**, which LiteLLM's one-shot `atranscription` cannot express (it only carries AssemblyAI as an opaque pass-through). So `assemblyai_provider.py` speaks v2 REST directly, behind the **existing `SttProvider` interface** — the notes pipeline is unchanged.

- Requests `speaker_labels` for diarization, and `language_detection` rather than a pinned language so mixed Hindi/English meetings aren't forced to one.
- The org glossary maps onto `word_boost`, with prose fragments filtered out (it wants vocabulary, not sentences).
- AssemblyAI's `A`/`B` speaker letters are normalised onto the shared `S1`/`S2` space, so `speaker_names`, the rename UI and live reconciliation stay provider-agnostic. Offsets convert ms → s.
- The registry resolves the tier first, then picks the provider by prefix — so AssemblyAI works set directly *or* behind `tier-stt`.

## Live — one setting, not two

`/notes/stt/live-token` now follows the configured STT tier when that provider can stream, so **choosing AssemblyAI for batch gets AssemblyAI live with no second setting**; otherwise it prefers whichever key exists. Deepgram's ephemeral-key minting is unchanged.

`LiveTranscription` (was `DeepgramLive`) speaks either the AssemblyAI v3 `Turn` protocol or Deepgram's, behind one `LiveCaption` shape.

## Fitting the rest of the app

- **Local diarization becomes a true fallback for free** — `maybe_diarize` already no-ops on an already-diarized result, so sherpa now only runs when the ASR returned no speakers.
- **Fixed a bug this would have introduced:** the "speakers aren't separated" hint hardcoded `deepgram/`, so it would have fired misleadingly on every AssemblyAI transcript. It now recognises AssemblyAI and a completed local sherpa pass.
- `ASSEMBLYAI_API_KEY` registered across settings, key store, env seeding and the Models UI (label, colour, icon, setup guide, "names speakers" badge).

## Verification

**Not yet exercised against AssemblyAI's servers** (no key available here). The batch v2 API is stable and I'm confident in it. Two things to watch on first use: the exact `speech_model` id (anything after `assemblyai/` passes through as `speech_model`, so a different id needs no code change), and **streaming diarization**, a paid add-on whose v3 query parameter I couldn't confirm from the docs. Live captions will work either way; per-speaker labels on the *live* path may need one parameter once the account docs are visible. Batch diarizes regardless, and batch is authoritative.
