## Summary

Reviews how the chat app creates inline AG-UI sections and side-panel UI, and ships the redesigned system (design spec: `ai-company-brain/specs/generative_ui_2.md`). Claude-artifacts-style architecture: **one payload, two surfaces, two interaction modes** on `emit_generative_ui`.

**New capabilities**
- `surface: "panel"` — a genUI spec opens as an immersive side-panel tab rendered natively by `GenerativeUINode` (no `.html` filesystem round-trip), auto-opened on arrival with a persisted re-open chip in the transcript.
- `hitl: true` — the tool call **blocks** on the same Future registry as `ask_questions`; the UI's submit resumes the same turn via `/agent/respond-input` and the user's values return as the tool call's result (heartbeat-protected; registry cleaned on failure).
- Panel interactions route over the `agentEvents` bus (`genui_panel_action`) into AgentChat's existing send/HITL plumbing, with fallback-to-message so answers are never lost.

**Template library: 6 → 11** (all data-only, semantic tokens + Lucide, light/dark, reduced-motion aware)
- Display: `recipeCard`, `flightStatus` (animated route progress), `trainStatus` (stops timeline)
- Input: `formCard` (schema-driven text/number/select/slider/toggle/date/textarea), `optionPicker` (rich choice cards, single/multi)

**Docs**: tool docstring + injected addendum updated with the new modes/templates; spec includes the scenario→element map (weather/flight/train/recipe/forms/decisions/…) and Phase 2/3 backlog.
