## Description

Brings the workflow editor up to `docs/workflow-editor/mockup.html`. The canvas was legible but thin: a card showed a category pill, a label and a truncated one-liner, so "what does this step actually do?" meant selecting the node.

## Node cards

Full mockup anatomy (`§.node`): category accent bar → icon plate → kind eyebrow → title → summary → capability chip → badges → status footer.

- **Summary** is derived from the node's own config — the agent's actual instruction, the tool's catalog description, the wait duration, the assignment count.
- **Detail chip** shows what the block is bound to: `zoho.create_lead`, `{{triage.intent}} equals lead`, `email-assistant`.
- **Badges** surface flags worth seeing unselected — a destructive tool reads `write`, an approval reads `pauses run`, a long wait reads `parks the run`.
- **Footer** carries live run state, the last run's duration, and the node id you write `{{refs}}` against.
- Unconfigured nodes say so ("no agent selected yet") rather than rendering blank — the same signal the validator gives at publish.

`describeNode()` replaces `summarize()`: every node type answers summary/detail/badges from its config plus the catalog.

## Edges

New custom `ccEdge`:

- A condition's branch is **labelled yes/no and coloured** (solid green / dashed muted) instead of inferred from geometry — the `sourceHandle` *is* the routing key.
- The wire a run is flowing through **lights up** during a Test run, so the path is followable without reading the console.
- **`+` on any wire** arms an inline insert: the next block picked is spliced between the two ends and rewired (RFC §5.3.1, previously unbuilt).

## Around them

- Topbar **trigger chip** now says what fires the workflow (`webhook · schedule · 0 9 * * 1-5`) instead of a bare count.
- **Palette** rows carry the same icon plates the canvas will, so a block is recognisable before and after it is dropped; group headers pick up their category hue.
- **Inspector** header mirrors the card it configures (same plate, same kind eyebrow), and the reference chips became an "Available data" section.
- A **describe-to-generate bar** sits on the canvas (RFC §5.4) and hands off to the Copilot pane, so graphs are still applied, undone and explained in one place.

The mockup's own slate/azure palette and light/dark tokens were deliberately **not** copied — the editor uses the CommandCenter design system, which was the mockup's stated goal ("reads like CommandCenter"). The category hues already matched.
