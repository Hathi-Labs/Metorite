## WS-28p — the working week

Owner-directed: *"number of days that the company works, number of hours they're
supposed to work in a day, number of shifts… so accordingly even the calendar of
the personal center can set itself up."*

**No migration.** The org policy is a row in `org_settings` (migration 151's
existing key→JSON store); the person override is the `working_hours` column
WS-28g already shipped. Three layers, one direction:

```
org policy       org_settings['work_schedule']    the company's week
person override  gtd_people.working_hours         their exceptions
effective        computed, stored nowhere
```

`gateway/work_schedule.py` is the one model — a leaf module outside both route
packages, because `routes/people/*` imports from `routes/tasks/*` and never the
reverse, and the calendar needs to read it too.

- `contracted_hours_per_week` is now **derived** (D-PC-18). The typed
  `capacity_hours_per_week` stays (R6 — the importer writes it) and is *flagged*
  when it disagrees rather than silently corrected.
- **D-PC-16** settles the seam collision with the calendar: `working_hours`
  (People) and `gtd_settings.day_start_hour` (Calendar) answer different
  questions. People **seeds** Calendar once, at first read, and never mirrors it.
- `PUT /people/schedule` is a **dry run first** — the impact panel shows how many
  people's contracted hours change before you save.

## WS-28q — the display image

Owner-directed: *"a strict policy when it comes down to the size of the image so
that random image sizes are not uploaded"*, plus a crop.

**What is stored is what the server produced, never what the browser sent**
(D-PC-17). Every upload is decoded, centre-cropped square, resized to exactly
256×256 and re-encoded; the uploaded bytes are discarded. One decision removes
four problems instead of validating for them: size drift cannot exist, weight is
bounded by the output, the crop is enforced server-side even for a direct API
caller, and EXIF/colour profiles/trailing payloads do not survive a re-encode.

Three things measured rather than assumed, each of which would otherwise have
shipped as a defect:

- **MuPDF renders SVG** — `fitz.open(filetype="image")` opens one happily, so the
  decoder is not a type check. Bytes are sniffed against magic numbers first and
  SVG is refused by name.
- **The crop must be fractional** — a 1000×400 pixel image opens as a 750×300
  *point* page; a pixel rectangle produced a 256×192 "square".
- **`Matrix(scale, scale)` is not exact** — MuPDF rounds outward and a zoomed crop
  came back 257×257. `Rect.torect` maps the clip onto the target box exactly.

JPEG rather than WebP as the spec first said: the property that matters is the
re-encode, not the container, and PyMuPDF (already a gateway dependency) cannot
write WebP. Recorded in the migration.

## WS-28k — availability & absences

`working_hours_between(schedule, from, to, absences)` is the function WS-28j will
call. Fractional, because a `partial` reduces a day rather than removing it; a
full absence beats an overlapping partial; two overlapping partials take the
smallest.

**Availability, not leave management — with a fence.** The table is facts and
nothing else: no approver, no status, no balance, no accrual, no entitlement. A
test greps the migration for each of those words, because this becomes leave
management one reasonable-looking column at a time. Absences are **self-writable**
(requiring an admin to type them is how the data ends up missing, and then every
capacity figure reading it is quietly wrong); the delete is scoped
`AND person_id = …`, and that clause is the control, not belt-and-braces.

Two read tiers on one feature: the bare "away until the 20th" is **directory**
tier and is resolved for the whole page in one query, not one per row; the spans,
notes and hours-left figure are **HR** tier.

## Two fences were refined rather than worked around

- **The tenancy ratchet caught the new table.** `gtd_person_absences` declares
  `organization_id REFERENCES organization` on day one, defaulting from the
  session GUC so no call site passes it; an unbound insert fails the NOT NULL.
  One non-obvious constraint found the hard way: `REFERENCES` must come *before*
  `DEFAULT`, because the ratchet matches the two with no comma between them and
  every form of `current_setting('app.tenant_id', true)` contains one. Written
  the other way round, a table that **is** scoped reads as unscoped.
- **D-PC-15's fence** forbade any path parameter on the ungated router — a good
  proxy until a route needed to address a child row. `/me/absences/{absence_id}`
  names a *span*, not a person, so the fence now asserts the invariant itself
  plus the stronger half it stood in for: every ungated endpoint resolves the
  person through the self predicate.
