## Description

## Problem

The email app returns a **gateway 500** on open. Root cause: the email list/detail endpoints `SELECT em.importance, em.categories` (`apps/gateway/gateway/routes/email.py:680,721`), but those columns — added by `infra/postgres/18_email_message_status.sql` — were **never applied to the live database**.

The Postgres container only mounts `00_create_databases.sql` and `01_schema.sql` into `/docker-entrypoint-initdb.d`, and those only run on **first** DB init. **Nothing in the deploy pipeline applied migrations `02`–`18`**, so the new columns never reached prod → `UndefinedColumn` → 500. (Earlier migrations like 17 had been applied by hand; 18 fell through the gap.)

## Fix

- **`scripts/apply_migrations.sh`** *(new)* — idempotent runner that applies `infra/postgres` migrations `02+` against the `acb-postgres` container via `psql -v ON_ERROR_STOP=1`. All migrations `02+` use `IF NOT EXISTS` / `ON CONFLICT DO NOTHING`, so it's safe on every deploy.
- **`17_email_accounts.sql`** — make the 3 account indexes `CREATE INDEX IF NOT EXISTS` so the full migration set is re-runnable.
- **`.github/workflows/deploy.yml`** + **`deploy/hostinger/deploy.sh`** — invoke the runner after the stack is healthy, before restarting the gateway.

Result: the next deploy applies migration 18 (fixing the 500) and all future migrations auto-apply, closing the gap permanently.
