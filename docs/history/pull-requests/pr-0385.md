## Description

Closes the regression the 2026-08-06 scope narrowing opened. Deleting the tasks app's People view took `PersonEditor` with it — and with it the only UI for creating a person, editing their skills, and uploading a résumé. The API was never touched; the product just had no way to reach it.

## What ships

- `people/components/PersonEditor.tsx` — create, edit, résumé upload; themed through `Button` / `Input` / `Icon`.
- `people/lib/form.ts` — the pure half (write-body construction, skill normalisation, résumé merge).
- `people/lib/write.ts` — the write client.
- `can_manage` on the directory and person reads.

**The GET-only `/api/people` proxy is unchanged.** The writes go to `/api/tasks/people`, where they have always lived, so no hollow second write path was minted.

**Controls are absent rather than disabled**, driven by the new `can_manage` flag. Hide-rather-than-disable is impossible unless the read tells the UI; the alternative is drawing the button and letting the click discover a 403, which is the behaviour spec §3.2 rejects.

## Restoring it turned up three ways migration 148 had already broken the write routes

Each would have surfaced as a 500 in front of an admin mid-typing rather than as a test failure, because 148 was written for the read side and nobody walked it against the routes that **write** the table.

1. **The status vocabulary moved and the editor did not.** 148 replaced 49's `inactive` / `on_leave` with a CHECK on `active | contractor | alumni | invited`. Restoring the old select verbatim would have shipped two options Postgres refuses. The vocabulary is now one tuple (`PEOPLE_STATUSES`, re-exported as `people/core.STATUSES`) read by the filter, the facets response, the editor's select and the write validation.
2. **`create_person` still refused a duplicate NAME** — preserving precisely the behaviour 148 dropped `UNIQUE(name)` to remove, on the argument that two real people share a name and one was being locked out.
3. **Nothing checked the address 148 made unique**, so a duplicate was an `IntegrityError`. Now pre-checked case-insensitively on both sides (R10), answering 409 with the name of the row already holding it; a blank address is stored as NULL, because `''` is not NULL and two blanks would collide under the same partial index.

Recorded as a pattern in `people_center_app.md` §10: a migration that changes a table's shape has to be walked against every route that writes it. The read routes were built after 148 and were correct by construction; the write routes predated it and were never revisited. #384's `name[]` cast was the same class of gap seen from the other side.
