## Description

Lands the design work for a **Visual Workflow Editor** — a no-code, node-based builder that composes automated workflows from CommandCenter's existing agents, tools and integrations, triggered on command, by schedule, by webhook, or by an inbound event.

**This PR is documentation only. There is no implementation and nothing here executes.** It is merged to capture the analysis so it stops living on an orphan branch.

### What's in it

- [`docs/workflow-editor/README.md`](docs/workflow-editor/README.md) — RFC: analysis of Copilot Studio (the UX model), [Sim](https://github.com/simstudioai/sim) and [open-agent-builder](https://github.com/firecrawl/open-agent-builder) (the implementation patterns), plus a proposed architecture and phased plan.
- [`docs/workflow-editor/mockup.html`](docs/workflow-editor/mockup.html) — a standalone interactive mockup of the three-pane editor (palette · canvas · inspector).

### The core recommendation

Build a "Workflows" surface in the control plane that **reuses the existing runtime** rather than adding a second one — `call_agent`, the integrations registry, the ingestion/webhook pipeline, AG-UI SSE streaming.

The load-bearing architectural rule, validated by both reference implementations: **separate the edit-model from the run-model.** Persist an editable graph; compile it to a flat, versioned execution DAG at run time. Never execute your database rows directly.

| Concern | Proposed |
|---|---|
| Canvas | React Flow (`@xyflow/react`) |
| Persistence | New Postgres tables + a migration (no workflow tables exist today) |
| Execution | Compile the visual graph to a MAF `WorkflowBuilder` of executors + edges |
| Triggers | Extend the existing ingestion pipeline + `webhook_routes` with a binding table |
| Streaming | Reuse AG-UI SSE + the Redis stream-relay |

### Reviewer notes

- **Version claims verified.** The RFC leans on `agent-framework-core >=1.8.0` for `WorkflowBuilder`; the repo currently resolves **1.8.1**, and `WorkflowBuilder` graphs do build on it today. So the recommended engine is available now, not blocked.
- **One caveat the RFC doesn't call out:** the separate MAF *orchestrations* package (Sequential / Concurrent / GroupChat / Magentic) requires core **≥1.9**, so those patterns are not reachable until we upgrade. `HandoffBuilder` also rejects Copilot-SDK agents, while Sequential/Concurrent/GroupChat/Magentic do not. Worth folding into the doc if we act on it.
- Scope is honest about being **mostly green-field on the graph/UI side** while heavily reusing the runtime — this is a multi-phase epic, not a next-sprint item.
