### 🔴 OWNER DECISION — §BO-20.0, and it is not the one-liner it looks like

> Answer with one line: **`BO-20 = Option A`** or **`BO-20 = Option B`**

- **Option A — in-process supervised asyncio consumer, gateway lifespan. ✅ RECOMMENDED.** Ships by ordinary merge, no VPS action. `workflows_app.md` §9 **D6** names this the house style *about this very item* (*"…no APScheduler process … **Revisit under BO-20**"*); five such loops are already wired.
- **Option B — separate `python -m ingestion.worker`.** Needs a systemd unit an agent cannot install (the four checked-in units are gateway/workbench/whatsapp-bridge/health-watchdog; `bootstrap.sh` generates a fifth for Docker infra; none is a worker). **And it leaves the dispatch step undefined:** a separate process starts with an empty module-level `event_hooks._SINKS`, so it would `XREADGROUP`, `XACK`, and dispatch to **nothing**. Ingestion doesn't depend on gateway, and importing upward is what `event_hooks.py` exists to prevent.

**Only Option A unblocks BO-20a–e as written.** Answering B buys a design round plus a rewrite of BO-20a, not a dispatch. The doc says so rather than promising a one-line answer it can't honour for both branches.

**BO-20f is dispatchable today** — no consumer, no flag, no owner decision.
