## Description

Found live during WS-26 activation, third defect of the day in the delivery chain: every apply after ~08:29Z failed with "pre-migration backup FAILED — refusing to apply migrations", yet the dumps were all succeeding.

The failure was **retention pruning**: the oldest backup dir was root-owned (a leftover from the pull unit's `User=root` era), `rm -rf` hit permission-denied, and `set -euo pipefail` took the whole script down non-zero *after* the dump and checksums had completed. The migration runner fail-closes on that exit code by design — so one stale directory silently blocked every deploy on the box, push-path and pull-path alike. It surfaced today only because today's repeated applies crossed the 14-backup retention threshold.

The dump is the product; pruning is housekeeping. Pruning failure now warns loudly (with the chown remediation in the message) and leaves the exit code alone. Box-side ownership already repaired by hand (`chown -R acb:acb /opt/acb/backups`) and the backup verified green (exit 0, 14 retained).
