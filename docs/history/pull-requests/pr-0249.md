## Summary

Fast-follow to the just-merged T2 (real React apps) work. While rebasing onto `main` I found a separate, independently-shipped system — `lib/compileArtifact.ts`, for the chat/report "artifacts" feature — that already bundles a 25-component React design kit (`@cc/ui`, `workbench/control_plane/src/lib/artifactUi.tsx`) mapped onto the same `cc-*` CSS classes T2's own `instructions.md` was telling the builder to hand-author divs for. Different lifecycle (ephemeral chat card vs. persistent shared app), so T2 wasn't redundant with it — but `@cc/ui` is exactly the reusable-block, token-efficiency win worth folding in.

- `build_t2.mjs`: alias `@cc/ui` to the shared source file. Required switching esbuild's `buildSync()` to the async `build()` API, since `buildSync()` can't run plugins — added while I was in there, an explicit import allowlist (`react`/`react-dom`/`@cc/ui` only, policed for imports made by the app's own `src/` files) mirroring `compileArtifact.ts`'s defense-in-depth, rather than relying solely on the vendor cache's contents staying clean.
- `instructions.md`: documents `@cc/ui`'s components as the preferred path over raw `className="cc-card"` markup; explicitly excludes `Submit`/`Action` (chat-artifact-only bridge globals — harmless no-ops in a Custom App, but do nothing).

`artifactUi.tsx` is pure JSX + prop types (its one `react` import is type-only, erased at compile time), so it bundles unchanged under `build_t2.mjs`'s real React despite `compileArtifact.ts` aliasing `react` → `preact` for its own, separate use case.
