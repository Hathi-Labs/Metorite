## Description

Turns the office from "characters floating in a box" into a **composed scene per agent, inside a themed room** — the system that lets us mix-and-match layers and later swap in real (Higgsfield/hand-authored) sprites.

## What's new (`src/app/observability/scene.tsx`)
- **Layered composition** — each agent is built from stacked layers: `room → rug → chair → outfit → hands → head → face → hair → accessory → desk props → desk`, all driven by an `AvatarConfig`.
- **Semantic, configurable look** — `deriveAvatar(name)` maps the agent's **role** (coder / sales / planner / triage / reconciler / orchestrator) to a **room + outfit + accessory + prop signature**, with per-agent variation (skin, hair style/colour) from a name hash. So a brand-new agent gets a fitting avatar with **zero config**, and an `override` param pins any field for when backend avatar config lands.
- **A real environment** — wall + window/board/whiteboard, floor tiles, rug, desk, monitor(s), and props. No more void.
- **Richer animation** — hands **type** on the keyboard, eyes **blink**, the screen **flickers**, the mug **steams**; sleeping dims + `Zzz`; error shakes. CSS-only, `prefers-reduced-motion` aware, descriptor-based rects with stable keys (no hydration churn).

## Asset swap seam (for Higgsfield / hand-authored art)
The **layer order + anchor grid is the contract**: to use real sprites, replace a layer's rects with ``'&lt;image href={dataUri}/&gt;'`` at the same coordinates. The full ASSET SPEC (cell size, anchors, z-order, recolor, animation strips, manifest) is in `specs/observability_e2.md`. This lands procedural **placeholders** — the art upgrades without touching the page.

## Higgsfield
`.mcp.json` now carries a `higgsfield` HTTP MCP entry, but it's **inert until you authenticate + start a fresh session** (hosted MCP tools register at client startup). Once it's live I can generate room/background scenes to spec first (where diffusion shines), then decide layers.
