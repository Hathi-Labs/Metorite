## Description

## What was wrong

Two independent bugs, both visible in one screenshot.

**1. Inline generative-UI cards vanished from earlier turns** — and the agent explained it away as *"the chat interface renders inline UI cards per turn, and they don't persist permanently when new messages arrive"*, which is false. Cards are persisted with the message and re-rendered from `message.customEvents`.

Traced on prod (session `708e7144`): `agent_run` and the Redis stream both show `emit_generative_ui` fired, and the gateway logged `chat_fold.persisted … message_id=nvyskjicv tools=2` — yet the row ended up with **0 tool events and 0 custom events**, written by a later, leaner upsert.

Three writers upsert the same `chat_message` row — the Next translator's 3s checkpoints, the run-boundary `chat_fold`, and the browser re-POSTing its whole message list on every change — under blind `= EXCLUDED.*` last-writer-wins. The leanest writer won. Two client paths fed it lean data: the poll merge spread the remote message wholesale (so a poll firing only because server *content* grew also replaced cards the client had already rendered), and the mount-time "is the DB richer?" check ignored custom events entirely.

**2. Table headers rendered as `[object Object]`** — the agent emitted `columns: [{key:"deal",label:"Deal"}, …]` and the renderer did `String(col)` on each.

## Fixes

- `routes/chat.py` — run artifacts are **monotonic**: an empty incoming `tool_events`/`progress_lines`/`custom_events` never erases a stored non-empty one; `reasoning`/`agent_state` COALESCE. `content` stays a plain overwrite (it is genuinely rewritten in place as the answer streams). One choke point for the whole damage class.
- `useAgentChat` — poll merge keeps the richer side per artifact list; custom events count toward "server is richer".
- `AgentChat` — mount-time richness check counts custom events, so a lean local cache can't win and then be saved back.
- `lib/genUiText.ts` — coercion extracted, pure and framework-free; every node type funnels through it, so *nothing* an agent puts in a tree can render as `[object Object]`. Tables accept string or object columns, object rows keyed by column, and derive headers from row keys when columns are missing.
- `write_artifact.py` — table shape spelled out with an example, plus an explicit statement that a card is part of the transcript, so the model stops offering a file as "something more durable".

## Guards

- `tests/unit/test_chat_message_upsert.py` — contract tests on the SQL (run in CI, no DB) fail if any monotonic column reverts to a blind `EXCLUDED` overwrite; a live round-trip replays the exact prod failure and skips where no Postgres is reachable.
- `src/lib/genUiText.test.ts` — 14 tests covering the shipped case and the shapes around it.
- **`pr-check` gains a frontend job** (`npm ci` + `tsc --noEmit` + `vitest`). The workbench had no CI at all — type errors only surfaced when the VPS rebuilt after merge.

## Verification

- Monotonic SQL validated against prod Postgres in a rolled-back transaction: a lean re-save no longer wipes cards, tools, reasoning, or state.
