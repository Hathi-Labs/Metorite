## Description

Adds a **work-mode axis** to the task manager, grounded in Mihaly Csikszentmihalyi's flow research: `deep_work` marks tasks that need an unbroken flow state (creative, design, writing, coding/building, architecture, strategy). It is deliberately **not** an `@context` (contexts are single-valued place/tool axes; deep-ness is orthogonal — deep work happens `@computer` or `@home`) and **not** a priority flag (a task can be shallow yet critical).

## Why flow needs first-class support
- Flow takes ~15 minutes to enter and one interruption to lose — deep tasks must get **unbroken** blocks, never be sandwiched between reactive work.
- Flow needs challenge–skill balance at high capacity — deep tasks belong in **peak-energy** windows, early, before the day fragments.
- Shallow/administrative work should be **batched around** the deep blocks, not interleaved.
