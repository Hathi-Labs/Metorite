## Description

## What & why

The first half of master-plan **3.3**. A conversation you can't deal with now can be **snoozed** — sent out of the inbox and brought back at a chosen time. One of the two most-missed daily-driver features vs any modern client (schedule-send is the other; it follows as its own PR).

## Design: a stamp, not a scheduler

Snooze sets `snoozed_until` on the message. The **wake is at query time** (`snoozed_until IS NULL OR snoozed_until <= now()`), so the conversation reappears on its own — **no background job, no scheduler**. Applied **per-conversation**: the endpoint stamps every message sharing the `thread_id`, so the whole thread leaves and returns together (a lone message is stamped on its own).

## Changes

- **Migration 90** — `email_messages.snoozed_until` + partial index on the non-NULL rows.
- **Backend** — `core.folder_scope` gains the `snoozed` view (`snoozed_until > now()`); `GET /messages` excludes sleeping mail from **every browse** except the Snoozed view and a thread load (opening a snoozed thread still shows all of it); new `POST /messages/{id}/snooze` stamps the thread, `until=null` un-snoozes. App-local — there's no provider concept of snooze, so nothing is pushed upstream.
- **Frontend** — a **Snoozed** sidebar view; right-click **Snooze until…** with presets (later today / tomorrow 8am / this weekend / next week) and **Unsnooze** in the Snoozed view; optimistic drop-from-list then reconcile; `snoozedUntil` on the `Email` type.
