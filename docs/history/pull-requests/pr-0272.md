## Description

Answers "how does the copilot know what this meeting is *for*" with three things that build on each other.

## 1. Standing instructions — a system prompt for every run

`copilot_config`, per user, prepended to the system prompt of **every** copilot run:

> *I run a 3D-printing company selling to manufacturing teams. Prefer commercial framing. Never suggest a discount — steer to value.*

The per-meeting brief changes every time; **how you want the copilot to behave doesn't**. Retyping that each meeting is how a feature stops being used. Set once from `/notes` (✨ button).

## 2. Conversational agenda building

Describe the meeting in plain language — *"30-min call with Acme to close the annual renewal"* — and the copilot drafts a structured agenda. Keep talking to refine it (*"drop the demo, add pricing"*); it returns the **full updated agenda**, never a diff.

## 3. Agenda-aware live feedback

The agenda is a structured list rather than more prose **precisely so it can be measured**. The copilot sees which items are still outstanding and nudges accordingly — *"you haven't touched pricing"* — which is impossible against a paragraph.

Coverage is a **pure token-overlap check, not a model call**, because it runs on every window and must cost nothing. A single passing mention deliberately does *not* count as covered — otherwise every item goes green the moment one common word is said and the nudging stops being useful.

## Fail-safe

A model failure, a non-JSON reply, or an empty agenda from the model all leave the user's agenda **untouched**. An empty agenda is treated as a bad response rather than a genuine "clear it", since that's far likelier.

Both cascade stages inherit the standing instructions, and the background is rebuilt per suggestion so coverage stays current — the context pack itself stays cached, only the cheap marks recompute.
