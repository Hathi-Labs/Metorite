## Summary

Fixes the HH-1 eval `test_oversized_email_thread_fits_window_and_keeps_newest`, which had gone vacuous due to tier / window-table drift.

**Root cause:** the eval builds a 200k-char (~78k-token) email and asserts it gets trimmed for `tier-fast`. `tier-fast` now resolves to `deepseek/deepseek-v4-flash` with a **1,000,000-token** window (`context_window_for` → litellm / fallback table), so the payload fits and `truncated=False`. Overflowing a 1M-token window would require a ~4.5 MB string — impractical to build and tokenize in an eval.

**Fix:** the compression invariant under test is window-agnostic — *"an over-budget single message is trimmed and its newest message survives."* The eval now **pins a small window** (`monkeypatch` on `acb_llm.context.context_window_for`) and adds a precondition asserting the payload really exceeds it. This removes the dependency on the tier's configured model, so the assertion can't drift into vacuity again.
