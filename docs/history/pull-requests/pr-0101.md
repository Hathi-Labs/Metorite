## Description

## The grouping was right; everything inside the row wasn't

Reported from the Notification tab: expanding a colleague listed their **Awaiting Reply, Done and FYI** mail alongside the notifications, so the drill-down silently contradicted the filter that produced it.

**The grouping itself is correct and unchanged.** A sender already appears under *every* cleanup category their mail carries — in the report's screenshot, Mirza Faizaan showing both `Calendar` and `Notification` is exactly that working. Ayush Sarkar shows one chip because his other labels (Awaiting Reply, FYI, Done, Follow-up) are **per-thread conversation states**, not things the Cleaner can act on, so they are deliberately not facets.

What did not follow the filter:

| | before | after |
|---|---|---|
| **Drill-down** | sender's 25 most recent, any category — 14 of Ayush's 69 aren't Notification and all were listed | scoped to the open tab, with a caption saying so |
| **Row count** | sender's whole volume — Ayush read as **69 notifications** | **55 of 69** |
| **Chips** | top 2 by volume, so filtering to a sender's 3rd-busiest category showed no chip for it | active category pulled to the front |

New `category_counts` per sender comes from the label tally that was already being computed, so this is one extra field, not an extra query.

This is the same class of defect as the Analytics range selector fixed in #99: **a number displayed under a filter it does not respect.**

## Also: the tag filter was case-sensitive

`labels=` matched with an exact `= ANY(categories)`, but the rule engine stores a rule's label **verbatim**. The Cleaner's own tally already had to fix this exact trap — an uppercase or space-padded rule name silently matched nothing. Left as-is, the drill-down would report "no Notification messages" for a sender the row says has 55.

Live data is fully canonical today, so this is **prevention, not a live fix**. Three existing tests asserted the literal SQL shape and were updated to the new contract; their behavioural intent (pills AND together, tag matches label *or* category) is unchanged and now covered explicitly.
