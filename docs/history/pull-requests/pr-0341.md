## Description

Proactive audit of the calling path. It found a race that would have broken the auto-engage flow shipped an hour ago, before anyone had a chance to hit it.

## 1. The teardown race — would have broken every call

Audio attaches the instant a call is placed. That's **before the next poll lands**, so the attached call isn't yet in the `calls` list the teardown effect reads. The effect treated "not in the list" as "ended" and closed the socket milliseconds after it opened — every time, on the exact flow meant to make calling seamless.

It now waits until the call has actually been *seen* in a poll before concluding it's gone. A call that vanishes afterwards (reaped, or hung up elsewhere) still tears down correctly.

## 2. Normal hangup reported as an error

Hanging up closes the audio socket by design; surfacing that close as a failure ended every normal call with a red banner. Now only unrequested closes are reported.

## 3. Ringback could ring forever

It only stopped on the first inbound frame, so a call that connected *without* media rang indefinitely — precisely the state we most need to be legible. It now also stops once the call is observably up.

## 4. Shared silence buffer

The uplink handed the encoder the same slice on every starved read. If the library ever mutated a frame in place, that buffer would stay corrupted for the rest of the call. Sixteen small allocations a second is a cheap price for not depending on it.

## Tests

The audio plumbing had **none**. It now has thirteen, chosen for the failure modes that actually bite:

- PCM round-trip and clamping (un-clamped `+2.0` wraps to a loud negative click)
- Starvation returns silence, **never EOF** — EOF stops the Player permanently
- Drop-oldest under pressure, without blocking
- Fan-out that a slow listener cannot stall (it's on meowcaller's media path — one wedged browser must not silence the recording)
- Idempotent detach, and detach racing a closing call
- The socket refusing unknown calls, missing secrets, and ended calls
