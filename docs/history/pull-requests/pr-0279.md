## Description

Items 02–06 of the UX plan. #278 added the missing phase (prep); this reshapes the other two so the work already running is actually visible.

## Agenda coverage escapes the copilot

`coverage()` always knew which agenda items had been discussed — but it ran inside the copilot's loop, so it fed a prompt, showed nowhere, and vanished entirely when the copilot was off. It now lives on the transcript bus (`agenda_progress.py`), so *"you're 40 minutes in and haven't reached pricing"* works either way, and it still costs nothing (token overlap, no model call).

Two properties make it trustworthy, both tested:

- **Coverage latches.** An item discussed at minute five is still covered at minute fifty. Recomputing from a rolling window alone would let items blink back to uncovered as the window moved past them — worse than not showing coverage at all.
- **Bounded text, unbounded conclusions.** The word buffer is capped; the latch is O(agenda). A four-hour meeting doesn't accumulate a four-hour transcript in RAM.

## Live console: two columns

The transcript is what your eye rests on, so it gets the width. The copilot gets a rail — its output arrives in bursts and needs somewhere to arrive *to*. Setup panels are gone; they belong in prep, and six equal-weight cards above the transcript is what made this screen unreadable.

## Library: banded by what you'd do about it

Live / Coming up / Needs you / Earlier, replacing one reverse-chronological run. Rows report outcomes (*"2 actions waiting for approval"*) rather than mechanics (*"318 segments"*) — nobody scans for segment counts.

Banding is pure (`lib/bands.ts`) so the priority rules are testable; notably **live beats needs-you**, so an in-progress call can't be filed under triage. The list SQL computes the band signals in one query rather than N+1-ing the detail endpoint per row.

## Header: one primary action

It had grown to six peers, three of them the same intent, plus a template dropdown that asked you to classify a meeting before you'd said what it was. Template moved to prep in #278; the rest are behind **New meeting**.

## Outcome strip

A finished meeting leads with its yield — actions, notes, follow-up — instead of hiding actions in tab three. The agenda recap is free (coverage was computed during the call) and turns "what did we not get to" into the start of the next meeting.

## Visual pass: one speaker, one colour

Speaker colour was defined twice with different fallbacks, and not at all in the roster, avatars or list rows. `lib/speakers.ts` is now the single source, carried through transcript edge, name, avatar and chip — so a wall of text becomes scannable. Hues come from existing semantic tokens, so there's no second colour system to keep legible in both themes.

Fixed while unifying: an unnumbered key (a *named* speaker rather than `S1`) fell through to hue 0, so every named person looked like the same person.

## Testing

- 2545 backend tests, 90 frontend tests (25 new across coverage latching, band priority, and speaker hue)
- `tsc --noEmit`, `next build`, `ruff` all clean

One test I wrote was wrong and I corrected the test, not the code: it asserted two specific names get different hues, which five buckets can't guarantee. The property worth holding is that hashing *spreads* and is stable per key.

## Not included

- **Calendar integration.** "Coming up" only holds meetings you created by hand. Worth wiring Google Calendar so it populates itself — flagged as an open question in the original mockups and still open.
- Per-suggestion copilot feedback, and series grouping.
