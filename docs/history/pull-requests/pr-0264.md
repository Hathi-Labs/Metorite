## Summary

The "cheap batch" from the gap-analysis pass: two RFC roadmap lines claimed these already shipped — neither was actually built. Both turned out to need only small additions since the underlying data/infra already existed.

- **New migration `122_app_pins.sql`** — `app_pins(app_id, user_email)`, a viewer's own bookmark, deliberately separate from `app_grants` (who *can access* an app, an owner/admin decision) since pinning needs no grant beyond already being able to see the app.
- **New `gateway/routes/apps/pins.py`** — `GET /pins` (sidebar's lightweight query), `POST`/`DELETE /{slug}/pin` (idempotent). Registered **before** `lifecycle.py` in `__init__.py`, deliberately out of alphabetical order — the literal `GET /pins` route must reach the router before `lifecycle.py`'s `GET /{slug}` or the parameterized route swallows it (verified empirically). `ruff`'s import-sorter would silently undo this, so it's disabled for the file with a comment explaining why.
- **`list_apps`** now computes pins + this-month AI usage in two *batched* aggregate queries (mirroring the existing grants-batching pattern) — 2 extra queries total for the whole gallery, not 2 per app.
- **Frontend**: gallery cards get a pin toggle (optimistic) and a usage badge (cost + call count, shown only when an app's actually been used); the sidebar fetches pins on the same polling cadence as its existing agent-updates badge and renders them under Custom Apps.
- **Docs**: fixed the two now-verified-wrong "already shipped" RFC claims, plus a separate stale claim — "Explicit non-features: a browser IDE (ADR-014 stands)" — wrong since the Advanced-view Monaco editor shipped. ADR-014's actual constraint (platform code stays VS-Code-and-Git-only) is untouched; only the RFC's own extension of that stance to Custom Apps' own code was ever walked back, at explicit user direction.
