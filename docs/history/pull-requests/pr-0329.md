## Description

Makes WhatsApp calls actually conversational. Until now the peer was recorded, heard nothing back, and none of their audio reached your speakers.

## Path

```
mic  ──► AudioWorklet ──► WS ──► gateway ──► bridge ──► Player ──► MLow/SRTP ──► peer
spkr ◄── AudioWorklet ◄── WS ◄── gateway ◄── bridge ◄── callSink ◄── decoded peer frames
```

Wire format is raw **little-endian int16 mono, 16 kHz, one 960-sample (60 ms) frame per binary message** — meowcaller's native framing, so nothing resamples or reframes in the middle. The `AudioContext` is opened at 16 kHz for the same reason: the browser resamples once in native code rather than us doing it in JS, which is where drift and crackle come from.

## Decisions that matter

- **Uplink starves to silence, never EOF.** A `Player` that hits EOF stops, and a stopped Player means permanent silence for the rest of the call — a momentary gap has to stay momentary.
- **Downlink fan-out is non-blocking.** It sits on meowcaller's media path, so a slow socket drops frames rather than stalling the call for every consumer including the recorder.
- **Playback holds a jitter buffer** (~180 ms, re-primes on underrun). Network frames don't arrive on the audio clock; playing them on arrival guarantees constant underruns.
- **Attaching is optional and per-call.** With no browser attached the call still sends silence, which is what holds the relay bridge open. Recording is unaffected either way.
- **Direct to the gateway, not through Next.** App Router can't upgrade a connection, so the browser opens the gateway origin using an absolute URL the server supplies (only it knows the public origin).
- **Short-lived HMAC token, scoped to one call.** A WebSocket can't carry the internal bearer and the workbench cookie is a different origin, so the signature *is* the authentication. Same shape as the notes app's live-STT token.

## Honest limitation

Echo cancellation is best-effort: the browser's AEC references what the browser renders, and this plays through WebAudio rather than a WebRTC peer connection. **Headphones are the reliable fix**, and the UI says so rather than pretending otherwise.
