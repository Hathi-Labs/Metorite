## Description

The four larger findings from the calendar review (the verified quick bugs shipped separately in #199).

## A — Structural confirmation gate for AI calendar writes
The agent path relied on the model choosing `apply=false` first; `apply=true` then **recomputed** a fresh plan and wrote it — not what the user reviewed. Now:
- *propose* stashes the computed plan on the day-state row (migration `97_gtd_pending_plan.sql`);
- *apply* replays that reviewed plan **verbatim** and clears it;
- an apply with nothing pending **degrades to a propose** (never a blind write), and stale proposals (>30 min) don't auto-apply.

`DayPlan` gains an `applied` flag so the chat renderer reports what actually happened. The browser "Plan my day" panel is untouched — it already proposes, then applies the reviewed blocks client-side.

## B — Fence external content in every chat-tool output
Only `gtd_list` fenced untrusted text before; `gtd_people` emitted résumé/role text **completely unfenced**. Added a `_data()` helper that wraps externally-authored strings (titles, names, résumé lines, plan rationales) in `«guillemets»` — stripping any embedded guillemets so the boundary can't be broken — applied across `_fmt_item`, `gtd_people`, `gtd_list_schedule`, `gtd_day_digest`, and the day-plan renderer. The persona and agent instructions now declare the guillemet convention so the model treats fenced spans as data, never instructions.

## C — Consolidate the calendar settings IA
The popover had grown into a flat wall with two overlapping control pairs. Grouped it into labelled sections (**When you work · Breaks & protected time · Automation · Energy & themed time · Recurring windows**) and added copy that disambiguates the overlaps: lunch is the quick preset for a recurring **Block**; energy windows are *when you're sharp* vs a **Focus** window's *kind of work*. No stored fields changed.

## D — Geometry unit tests + a frontend test runner
The correctness-critical packing/free-slot code had no tests on either end. Added **vitest** (`npm run test`) with tests for `scheduling.ts` (`blocksForDay`, `firstFreeSlot`) and `shared.ts` (`layoutBlocks` overlap lanes), plus Python tests for the planner geometry (`_free_intervals` overlap-avoidance + past-start ceil, `_place_one` earliest-fit/buffer/energy-pref/interval-mutation, `_day_window`'s 0-preserving window) — locking in the fixes from #199.
