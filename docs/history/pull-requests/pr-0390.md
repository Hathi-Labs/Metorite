## Description

The importer shipped with WS-27b and had **no control anywhere in the app**. The empty state read *"No projects yet. Create one, or import a ClickUp workspace"* — naming an action nothing performed. So a fresh install stayed empty, and the only route to real data was a curl command.

## Three steps, and only the last one writes

| Step | Call | Writes |
|---|---|---|
| **Preview** | `POST /import/clickup/plan` | nothing — reads the live tenant and lists every Space with its folders, lists, tasks and people, plus the proposed Center and the evidence for it |
| **Dry run** | `POST /import/clickup {dry_run: true}` | nothing — exercises the whole import path including the Space→Folder→List flattening, and reports what it *would* create |
| **Import** | the same call with the flag off | writes, on a button that says so |

## The mapping is still the owner's act (D-PM-10)

A wrong auto-map grants a Center sight of another department's work — the one error class this app cannot make silently. The UI is built so it stays the owner's:

- the suggestion is pre-filled and overridable per Space;
- its confidence is shown **in words** ("a guess — check it") rather than as `0.45`, because a bare number invites acceptance without looking;
- a **confirmed** mapping always beats a fresh suggestion, so re-running never silently re-maps a Space somebody already ruled on. That's the mutant most worth having red, and it is.

## Two other honesty properties

- **Unmapped Spaces are a notice, not a blocker** — matching the importer, which takes them in full. Refusing them would make the mapping a precondition of seeing the data you need in order to decide the mapping.
- **`already_present` is reported, never hidden.** The upsert is idempotent and re-running is the normal case, so "0 created" with no mention of the 400 rows it matched reads as a failure of the import rather than a success of the last one.

Also: the empty state's promise is now a button, and there's a ClickUp entry point in the header for re-running.
