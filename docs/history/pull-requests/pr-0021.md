## Description

Follow-up to #20 (already merged). Makes Rapid Inbox a thin lens over classification the system already does, and reuses the app's real draft plumbing.

## What changed

- **Categories read existing classification (no reclassify).** Content categories (Newsletter, Marketing, Calendar, Receipt, Notification, Cold Email) now come from the always-on sender categorizer (`email_senders.category` — the same source that powers the Inbox Cleaner), so they populate without any manual pass. This fixes Notification/Receipt showing empty. Conversation buckets keep reading the Reply Zero thread status; FYI reads its rule label.
- **New "Unclassified" category** — inbox mail whose sender isn't categorized yet: the home for anything the system hasn't sorted.
- **Removed the Reclassify button** — classification is ambient, nothing to rebuild here.
- **Renamed "Done" → "Actioned"** to match the rule/label name.
- **Dropped the redundant thread-status line** on each card; rows show the message snippet instead (the category already conveys status).
- **Reply composer reuses the app's existing draft flow** instead of a bespoke path: an auto-created AI draft is surfaced (green "Draft ready" pill, seeded into the editor), edited/saved in place via `saveDraft(draftId)`, improved with `composeAssist`, drafted from scratch with `draftReplySmart`, and sent via `sendDraft` — the same functions the main composer uses.
- **api:** `listEmails` gains a `senderCategory` filter (maps to the existing backend `sender_category` param).
