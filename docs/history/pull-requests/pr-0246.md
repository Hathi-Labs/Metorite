## Description

Started as a review of our artifact system against Anthropic's `web-artifacts-builder` skill, and turned into closing the two gaps that review found: no feedback loop, and no React.

## 1. Lint generated artifact HTML (`a2f2e39`)

The sandbox (`SandboxedHtml`) is strict and **silent**. A CDN `<script src>` is CSP-blocked with no error, a typo'd `cc-` class renders unstyled, a `cc-bar` missing its `--v` draws an empty track. The agent wrote the file, the tool returned success, and the user opened a broken report.

`acb_skills/artifact_lint.py` parses the markup and reports what the sandbox swallows:

- **error** — CSP-blocked remote fetches (the artifact is genuinely broken)
- **warning** — unknown `cc-` class (with a nearest-match suggestion), kit blocks missing the custom property or child that makes them draw, missing `cc-report` wrapper, hard-coded colors, and the generic-AI design tells (purple gradients, explicit Inter, over-centering) named by the Anthropic skill

`write_artifact` returns `warnings` for `.html`; `emit_generative_ui` returns them for `html` nodes. Advisory only — never blocks a write, never raises, and a parse failure degrades to no findings. Clean input produces zero findings on a realistic kit-heavy report.

`CC_CLASSES` mirrors the sandbox stylesheet and a drift test parses `SandboxedHtml.tsx` and fails in **both** directions, so a `cc-` block can't be added to the CSS without being registered (or removed while agents are still told it's valid). That test immediately found a real doc bug: the sandbox CSS comment documented `cc-cell-stat` and `cc-row`, neither of which the stylesheet defines — any agent following it emitted silently-unstyled markup.

## 2. React artifacts (`78618dd`, `e381dff`)

Agents could emit HTML but not React, so anything stateful — a filterable table, a multi-step form, a calculator, a live dashboard — had to be hand-rolled as DOM scripting. Now they write an ordinary component and default-export it, on both existing surfaces: an inline chat card (`emit_generative_ui` `react` node) and a full-page side-panel artifact (`outputs/*.jsx`).

`SandboxedReact` hands the compiled bundle to `SandboxedHtml` rather than building its own frame, so the CSP, the `cc-*` design kit, and the `ccAction`/`ccSubmit` bridge stay in one place and React artifacts can't drift from HTML ones.

### Three decisions worth reviewing

**Preact under the alias.** The frame has no network and React 19 dropped UMD, so the runtime must be bundled with the component. Agents write standard `from "react"`; esbuild aliases it to `preact/compat`. Byte-identical source compiles to **19 KB instead of 194 KB** — and every inline card inlines its whole runtime into `srcDoc`, so ten cards would otherwise be ~2 MB. Since the sandbox has no network, agents can't pull third-party packages anyway, which is where real React's advantage would show up. `RUNTIME_ALIAS` is one table — point it back at react/react-dom to ship real React.

**The import allowlist is a security boundary, not ergonomics.** This bundles untrusted model output *server-side*. Unrestricted resolution would let an artifact `import x from "/etc/passwd"` and inline the bytes into output we hand back to the client. Only the React runtime resolves, so no caller-supplied path reaches the filesystem resolver. Tested against node builtins, absolute paths, relative escapes, sibling sources, and npm packages.

**`.jsx`/`.tsx` render as React only under `outputs/`.** Elsewhere they stay source code, so an agent opening `src/components/Foo.tsx` to read it never silently turns into building and running it.

### Two non-obvious things

- `esbuild` must be in `serverExternalPackages`. Without it `next build` **fails outright**, tracing the native binary and dying on its non-UTF8 bytes.
- vitest needs `pool: "forks"` — esbuild's stdio child process deadlocks in worker threads.

## 3. A pre-existing test-suite landmine (`0bb1ec8`)

Adding a test file that sorts early and calls `write_artifact` hung the entire suite with no output. Not the new file's fault: any test that populates `_WRITE_ARTIFACT_CONTEXT` without restoring it leaks a live `session_id`, and `executor.resolve_run_queue` keys on it, so the next test down that path blocks on a gateway call that never returns.

Reproduced at `HEAD~1` with no new code:

```
pytest tests/unit/test_write_artifact.py tests/unit/test_email_tool_consolidation.py   # hangs
```

A probe that only does `_WRITE_ARTIFACT_CONTEXT.update({"session_id": ...})` hangs it identically — no file writes, no asyncio. It stayed invisible because the tests that populate the global sort near the end of the run. Fixed by snapshotting/restoring the dict in `tests/conftest.py` rather than depending on filenames.

The e2e spec is the one that matters most: it runs the real compiled bundle under the **real CSP** in an opaque-origin frame and asserts hooks re-render, `cc-*` tokens apply, and `ccSubmit` works **from first mount**. That last one is subtle — `SandboxedHtml` appends its bridge *after* the body content, so a synchronous mount would run React before the bridge exists; the mount is deferred to `load`.

## Reviewer notes

- **CI won't run the e2e spec.** `pr-check.yml` runs `pytest tests/unit/`, typecheck, and vitest. `e2e/react-artifact.spec.ts` only runs under `npm run test:e2e` (which needs a build). Worth wiring in separately if you want it enforced.
- **Bare `pytest`** (no path arg) is broken on `main` already — `apps/skills/skill-clickup-sync/tests/` collides with the root `tests` package. Untouched here; CI runs `pytest tests/unit/` so it isn't biting.
- Compilation is cached per-source in the browser; a shared server-side cache would help if the same artifact is opened across sessions.
- Multi-file React artifacts aren't supported (single component). That's App Workshop Tier 2 territory, which has its own plan in `docs/app-workshop/README.md`.
