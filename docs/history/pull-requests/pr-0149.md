## Description

## What & why

Follow-ups on the task detail view (the "next-action card").

### 1. Remove the misleading green "Done" button
The standalone Done button in the header read as "this task is complete" even when it wasn't. Removed it — status is changed through the disposition chip and the Stage card, so there's no shortcut that overstates completion.

### 2. Stage visible on local tasks + ClickUp→local stage mapping
- Local tasks now show a **Stage** in the detail (the My Next Actions workflow stage), not just synced tasks — so a local task's stage is visible and changeable here, matching the board. Synced tasks keep their raw ClickUp status picker (back-syncs on change).
- An **unmapped ClickUp status** no longer dumps every synced task into the first column. `statusColumnForItem` now also (a) matches the status directly against the axis (the per-project view, whose axis is the raw ClickUp statuses), and (b) applies the same name heuristic the gateway uses — `guessStageForStatus`, a client twin of the backend's `guess_stage_for_status` (todo/backlog→TODO, progress/review→IN PROCESS, waiting/blocked→WAITING FOR, done/closed→DONE). So a ClickUp task lands in the right Next-Actions column even before the user confirms the mapping in settings.

### 3. Whole detail-card clickable
Each meta cell (Context, Energy, Estimate, Due, Stage, Assignee) is now clickable across the entire card to open its editor — label, value, and the space around them — instead of a thin strip under the label. Opening shows an × to dismiss.

## Not in this PR
Multiple assignees (discussed) is deferred to its own PR — it's a full-stack change (DB migration + ClickUp multi-assignee sync) that needs to be tested against a live gateway.

## Testing
- `tsc --noEmit` clean; `eslint` clean on the changed files.
- The frontend `guessStageForStatus` mirrors the gateway's `guess_stage_for_status` (same heuristics, order, and first-stage fallback) so the board placement matches the mapping table shown in settings.
- Visual verification was done in a local dev build for the earlier UI work; this round's dev server was flaky in the sandbox, so the detail-view rendering is best confirmed in the production preview.
