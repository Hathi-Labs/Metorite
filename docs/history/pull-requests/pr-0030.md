## Description

## Summary

Fixes the reported reply-threading/signature bug, adds an agent-driven **categorized** email board in chat, polishes the reply UI, fixes a dropped-Cc bug in Rapid Inbox, and consolidates the email agent's tool surface from **64 → 41** while cutting the instruction prompt nearly in half.

## 1. Reply threading + signature (the reported bug)

Replies sent via the draft card landed in *Sent* as a standalone message instead of in the conversation. Root cause: when an account signature was set, the draft-send path sent a **fresh** message with no thread reference, so the provider started a new thread. Fixes:

- **Draft-send** now signs the already-threaded provider draft *in place* (`update_draft`, which preserves the thread) and sends it natively. IMAP (no native draft-send) falls back to a thread-aware fresh send.
- **Gmail** threads by the real conversation id (`thread_id`) rather than a message id; emits `Bcc` (was silently dropped); `update_draft` re-supplies `threadId` and keeps a signed HTML body as HTML.
- **`/send` reply path** resolves the reply target's `thread_id` so Gmail threads even when replying to a non-first message.
- **IMAP** sets `In-Reply-To`/`References` from the reply reference.

## 2. Reply UI

- Reply / Reply-All toggle shows Cc/Bcc for Reply-All (and Forward) and hides them for a sender-only Reply, in both the conversation draft card and the detail composer (with a manual "Cc/Bcc" reveal).
- Stopped the Reply/Reply-All toggle button text wrapping to a second line on narrow (phone) widths.

## 3. Categorized email board (AGUI)

Asking the agent for "emails to reply to, by department" produced categorized prose but a single **flat** interactive card underneath. New `present_email_groups` tool lets the agent drive the card's structure (`[{title, email_ids, note?}]`), rendering each category as its own titled, collapsible, interactive section. A side-effect-free `/email/messages/summaries` endpoint hydrates each row's label server-side. When a board is shown, the raw flat list it was built from is suppressed.

## 4. Rapid Inbox review + Cc fix

Confirmed Rapid Inbox is a read-only lens over the rule engine's per-message categories + Reply Zero buckets (no separate classifier), and drafts via the shared contextual drafter (`/email/draft-reply`) with the signature applied at send. Fixed one bug: reply-all **Cc was silently dropped** (the draft write-path carries no cc) — Cc'd replies now route through the full `/send` path (which carries Cc, threads, and signs), matching the main composer.

## 5. Tool consolidation (64 → 41) + prompt trim

Passes generalized redundant clusters into parameterized tools with **no capability lost** — e.g. `find_priority(kind)`, `read_email(full)`, `resolve_execution(decision)`, `digest(send)`, `sync_account(full/purge)`, `save_knowledge`, `list_patterns(kind)`, `send_email` (absorbs replies), `list_senders(view)`, `set_sender_status`, `run_rules(scope)`, `install_default_rules(reset)`, `manage_inbox(move/label)`. `apply_labels` folded into `manage_inbox`; `import_artifact` dropped (redundant with direct `"<agent>:<path>"` attach).

- Verified every remaining tool maps to a **live** gateway endpoint (no stale/orphaned tools) and covers the app's real actions.
- Functions the gateway `/ai/quick-action` endpoint calls by name (`search_emails`, `find_urgent`, `suggest_unsubscribes`) kept as module functions, just unregistered from the model's tool surface.
- **Instructions cut 233 → ~124 lines**: the old "Tools" section re-listed every signature, which the model already receives as tool schemas — pure context duplication. Replaced with a compact tool-family map, keeping the behavioral guidance schemas don't carry.
- Frontend AGUI card routing updated for the new tool names; legacy names kept mapped so older transcripts still render. `get_digest`'s raw-JSON card reformatted into readable bullets.

## Testing

## Notes / limitations

- Gmail and Outlook are fully handled; IMAP threading is inherently weaker (we don't yet store the RFC `Message-ID` per message).
