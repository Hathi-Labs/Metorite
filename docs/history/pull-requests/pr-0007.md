## Summary

Fixes the core **"clicking an email shows a blank reading pane"** bug and brings the email client toward Outlook/Gmail parity (folders, statuses, two-way write-back). Based on a full review of the stack against `spec_email_ai_assistant.md` (see `ai-company-brain/email_app_review.md`).

### Reading pane (the headline bug)
Root cause was twofold: Outlook sync stored only `bodyPreview` (empty `body_text`/`body_html`), and `EmailDetail` rendered plain text only and never fetched the full message.
- New **`MessageContent`** renders HTML in a **sandboxed `<iframe srcDoc>`** (no scripts, links open in new tab, auto-sized) with a plain-text fallback.
- **`EmailDetail`** lazily fetches the full message on selection with a loading state.
- Gateway **`get_message`** hydrates the body from the provider on demand when the stored body is empty, persisting body + attachment metadata.

### Two-way sync (write-back to provider)
- New `BaseEmailProvider.apply_flags()` / `move_to_folder()` (no-op defaults so IMAP degrades gracefully).
- **Gmail**: label translation (read/star/important, archive/trash/spam). **Outlook**: PATCH `isRead`/`flag` + `/move`; trash → Deleted Items.
- `update_message` / `delete_message` push changes best-effort; opening an email marks it read on the provider.

### Folders pulled from the mailbox
- Sidebar now shows canonical system folders **+ the provider's own user folders/labels**; stops clobbering the folder tree on each list fetch. Added **Junk**; wired the sidebar search box.
- Initial sync fetches all standard folders (inbox/sent/drafts/archive/junk/trash), not just inbox+sent.

### Statuses (importance / categories / flag)
- New `importance` (high/normal/low) and `categories` captured from both providers, persisted (`migration 18_email_message_status.sql`), and surfaced in the list and detail.

## Testing notes
- ✅ Python files compile (`py_compile`); lucide icons confirmed present in-repo.
- ⚠️ The Next.js build and live-provider behavior were **not** runnable in this environment (no `node_modules`, no mailbox creds) — please validate the frontend type-check and provider write-back against a real account.

## Known limitations (phase 2, documented in the review)
Incremental sync is inbox-only (other folders refresh on full sync/reconnect); Outlook `/move` returns a new message id to reconcile; Gmail user-label names aren't resolved to chips yet; Move/Label toolbar buttons still need a picker UI; no draft autosave or threaded view yet.
