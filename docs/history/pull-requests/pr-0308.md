## Description

Spends two references we had already imported but never used, and adds the test layer that keeps them honest.

## The gap

The tool registry declared `args_schema` per action. The catalog served it. The inspector rendered a raw JSON textarea and nothing validated the contents — so a ClickUp node with no `list_id` published happily and failed only when a real run reached the API.

## `args_schema` is now load-bearing

One parser (`engine/tool_args.py` — a `type[?][|description]` mini-language over a closed type set), three consumers:

- **Editor** — a typed field per argument with help text and required markers, plus a JSON escape hatch for what a form can't express. The gateway serves the **parsed** form, so the browser never re-implements the grammar and the two can't disagree about what's required.
- **Publish** — refuses a tool node with a missing, unknown, or mistyped argument (`tool_args`), reporting *every* problem at once so one attempt yields the whole fix list.
- **Runtime** — `execute_tool` re-checks before dispatch, because a draft Test run, a copilot-authored graph, and a version published before an argument existed can all reach a handler publish never saw. For a broker-gated write, that check is what stops a proposal being filed for a write that cannot succeed.

`{{refs}}` satisfy required checks and skip type checks on both sides — they resolve at run time, and demanding literals would make the state bus useless for the fields that need it most. Type checking only reports container-vs-scalar category errors: crying wolf about a number in a string field trains makers to ignore the messages that matter. An unknown type name degrades to `string` rather than raising — one typo must not take the palette down for every other tool.

## Two test layers, both mutation-verified

**Contract test (35).** Holds each declaration to its handler by AST-scanning for `args.get("x")` / `args["x"]`. The drift it hunts is specific: a handler grows an input the schema never declares, so the editor never offers the field and publish never demands it. The detector is itself tested against a known-drifting handler, and `_broker_write`'s dynamic `target_field` gets an explicit test since static scanning can't see it.

**Fixture corpus (n8n's pattern).** Whole workflows as JSON paired with an expected outcome, one generic runner — adding coverage is adding a file. Seeded with the spec's reference workflow through both condition branches, plus three gate fixtures that must *fail* to publish.

Fixtures assert **which seams were crossed**, not just the status — a workflow reporting "succeeded" while silently never calling the integration is exactly what a shallower assertion misses. Tool schemas and destructive actions come from the **real** registry, so fixtures break when the shipped catalog changes.

Proven able to fail before being trusted:

| Mutation | Result |
|---|---|
| State bus stops resolving `{{vars.list_id}}` | `lead_triage_high_priority` fails |
| Approval no longer gates the run | `lead_triage_high_priority` fails |
| Publish argument check deleted | `gate_missing_tool_argument` fails |

The pre-existing golden trajectory now compiles against the real schemas too — its ClickUp node had been missing `list_id`, which is precisely the drift this catches.
