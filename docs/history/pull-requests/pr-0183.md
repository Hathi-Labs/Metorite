## Description

## What

The last high-value Dashboard v2 item: a **✍️ action on each needs-reply row** opens the conversation and kicks off an AI reply draft in one click — so you go from "these need answering" to a drafted reply without hunting for the thread.

Drafts only. Nothing is sent — the AI draft lands in the reply composer exactly as the manual "Draft with AI" button produces it, auto-saved to Drafts like any reply, for you to edit and send.

## How

Reuses the existing viewer-command channel instead of driving the composer across component boundaries (which is why I flagged this as the risky one — this keeps it contained):

- New `"reply-ai"` viewer command. `EmailDetail` handles it by opening the reply composer (`startReply`) and bumping a nonce; a follow-up effect fires the existing `runAiDraft` (`composeAssist`) once the fresh reply state has committed. The two can't chain synchronously — `runAiDraft` reads recipients/mode that `startReply` sets on the next render — so the nonce effect sequences them. Routed through a ref because the effect sits above the component's early return.
- The page handler `await`s `openEmailById(id)` so the message is loaded and its reply handler bound before the command fires (`openEmailById` clears `viewerCommand`, so the command is set *after* the await).

Frontend-only. `tsc --noEmit` clean. `composeAssist` drafts server-side from the message id, so no client body hydration is required first.

## Try it

Dashboard → hover a "Needs your reply" row → ✍️ → the thread opens with a draft composing. (Hard-refresh for the new bundle.)
