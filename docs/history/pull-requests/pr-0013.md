## Description

Bundles three related agent-registry / picker changes.

## 1. Honor config.json `runtime` (correct MAF vs Copilot SDK labels)
Runtime was classified by a source heuristic (`repo_name && !local_path → github-copilot`), so every GitHub-sourced agent was mislabelled Copilot SDK — even `email-assistant`, which declares `"runtime": "maf"`. Now the agent's `config.json` `runtime` is authoritative (`_normalize_runtime` + `_declared_runtime`, applied in `_load_dynamic_agents` and `list_agents`). Undeclared agents keep the heuristic, so it's a no-op for anything that doesn't opt in.

**Result:** `task-manager`, `apis-config`, `email-assistant`, `reconciler` → **MAF**; the dynamic GitHub-repo agents (`agent-sales-assistant`, `agent-startup-guru`, `agent-project-manager`) → **Copilot SDK**.

## 2. Prune the registry
Remove **sales, triage, delivery, billing, strategy** completely:
- from `_AGENT_REGISTRY`, `_KNOWN_AGENTS`, and `_WEBHOOK_ROUTES` (zoho→sales, gmail→triage, etc.)
- `reconciler.agent_runtime` set to `maf`
- **Dangling references cleaned** so removal is complete: `email.py` draft-consult delegated to the removed `sales` → redirected to the real `agent-sales-assistant`; orchestrator `delegate_to_agent` prompt drops the billing/triage examples.

Remaining static agents: `task-manager`, `reconciler`, `apis-config`, `email-assistant`.

## 3. Fix chat new-session picker scroll
The agent list could overflow the viewport. The modal is now a bounded flex column (`max-h-[85vh]`) with a single scrollable body wrapping all agent sections; removed the redundant nested `max-h-72` on the MAF list.

## Notes
- `email-assistant` is a static built-in: its **label** is now MAF (from its config), but its execution path is left unchanged (no risk to the email app). Aligning static execution to the label is a separate, riskier change.
- `reconciler` has no repo/config and can't actually run; kept per the removal scope (only the 5 named agents were removed) and labelled MAF.
