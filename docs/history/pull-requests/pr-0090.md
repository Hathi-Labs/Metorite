## Description

> "in the inbox cleaner, I see a pill called 'personal'. Where is this coming from? I do not know."

Fair question — it was findable nowhere else. No message carries it, no rule produces it, it never syncs to the provider. It's a **sender-level** rollup, but the Email Cleaner rendered it identically to the rule categories, under a tooltip claiming it came *"from your rules — same categorization as the rest of the app."* Both halves of that were false for this one chip.

## Why not "Personal"

Wrong twice over:

1. **It implied private-life mail.** All 19 senders it matched on the live account are work colleagues and clients (`suresh@fracktal.in`, `geo@fracktal.in`, …).
2. **It collided with Cold Email** — which is *also* one human writing to another, one-to-one. What separates them is not that a person is involved; it's that a reply came back.

"Conversation" names the actual signal, and matches the labels it's derived from (Reply / Awaiting Reply / FYI / Done).

## The rename had a trap in it

The value is produced in `senders.py` and consumed in `messages.py`, which scores it **+15** in "important emails". Different modules, inlined string literals — a rename reaching only one side would have silently dropped the boost for those senders rather than failing.

Both sides now read `CONVERSATION_SENDER_CATEGORY` / `HUMAN_SENDER_CATEGORIES_LOWER` from `core`, and the ranking query binds the list rather than inlining `'personal'`. Pinned by a test.

## Migration 83 rewrites rows — deliberately, unlike 81/82

Those two changed only defaults, because a stored setting is a choice someone made. This value is a derived rollup the categorize job recomputes on its own schedule. Leaving the old string would strand those 19 senders under a name no code produces any more — invisible to the ranking boost, which matches on the category text.
