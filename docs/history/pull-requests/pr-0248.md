## Summary

Builds out the RFC's already-designed-but-unbuilt **T2** tier for the App Workshop: multi-file React apps, compiled by esbuild against a shared, deploy-provisioned vendor cache (never a per-app `npm install`), into the same single self-contained `dist/bundle.html` every existing publish/preview/durability path already serves via `app.json`'s `entry` field — so no new serving/publish/conformance machinery was needed, only a scaffold, a build step, one durability fix, and doc/prompt updates.

- `agent-app-builder/build/build_t2.mjs` — platform-owned esbuild step (`nodePaths` against the vendor cache, `NODE_ENV=production` define, atomic write so a failed build never clobbers the last-known-good bundle). Smoke-tested end to end against real vendored react/react-dom/esbuild, including confirming the `NODE_ENV` define strips the `process.env` reference that would otherwise throw in the sandboxed browser frame.
- `app.json` gains `tier`; the builder agent upgrades an app from T1→T2 mid-conversation when a request calls for it, not a creation-time picker — `create_app`/`_scaffold_workspace` are untouched.
- `durability.py`: mirror the manifest's resolved `entry` file into `app_files` even when it falls under a skip-dir (`dist/`), so a lost/rehydrated workspace can recover a T2 app's build output, not just its source. New unit test locks this in.
- `deploy.yml`: idempotent vendor-cache provisioning (pinned `react`/`react-dom`/`esbuild` versions).
- `instructions.md`: when to reach for T2 vs. stay T1, the build/verify discipline, JSX design-system usage.
- `testRunner.ts`: bounded retry on step/assertion dispatch instead of failing on the first DOM miss — React's effect-flush render tick made this a real race; benefits T1's async-seeded apps too.
- Status docs (`docs/app-workshop/README.md`, `ai-company-brain/AGENTS.md`) updated to reflect T2 built and T3 (backend compute) scoped-but-not-built, gated behind BO-7.
