## Description

## What

Completes the display unification: the Rules tab now shows **every mechanism that acts on the mailbox**, not just the AI rules.

New **"Also acting on your mail"** section at the bottom of the rule list:

- **Cold Email Blocker** — its mode (Off / labels / archives), with a pointer to the Settings tab that owns it. It behaves like a rule (screens mail no rule matched, inside the rule-run), so it belongs on this screen.
- **Sender dispositions** — the Cleaner's standing per-sender policy: "N auto-archived · N unsubscribed · N approved · M enforced upstream", pointing at the Email Cleaner.
- **Inbox rules at your mail provider** — read live from Outlook (`GET /me/mailFolders/inbox/messageRules`) and listed with sender + action summary. Rules the Cleaner created as block filters are badged **"Email Cleaner"** (matched by the `auto_archive_filter_id` recorded on sender rows). This confirms and surfaces what block/auto-archive has been doing upstream all along.

## How

- New provider seam `BaseEmailProvider.list_filters()` (default `[]`) + `OutlookProvider.list_filters()` with the same consumer-MSA 403/404 degrade `create_filter` documents.
- New `GET /email/rules/policies` — cold-blocker mode + disposition counts + provider rules with `managed` flag. Provider listing is best-effort (`provider_rules_supported: false` on no-auth/no-scope); a provider failure rolls the session back and the local policies still return.
- Read-only by design: dispositions and the blocker keep their own stores and management surfaces — one view, separate stores, same doctrine as #177.
