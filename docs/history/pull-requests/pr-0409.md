## Description

fix(WS-27/WS-29): tenancy alignment — regenerate the RLS set, kill the phantom table, fence it

Audit verdict: Projects is substantially aligned (19/19 pm_* tables keyed, seam
clean, R5 a-e hold, no homonym). Three gaps closed:

1. GENERATED SET STALE + PHANTOM. pm_intake/pm_task_watchers were in none of the
   four phase files — they would have promoted with a tenant column and NO
   policy. And 04_policies.sql carried "ALTER TABLE if ENABLE ROW LEVEL
   SECURITY": there is no table named `if`; the generator regexed CREATE TABLE
   out of comment prose (a backticked CREATE TABLE IF NOT EXISTS in 143). That
   statement cannot run, and phase 4 is applied BY HAND against production — it
   would have aborted the maintenance window part-way through. The generator now
   strips line comments and RAISES on a prose-shaped name rather than filtering
   it away; the set is regenerated (133 -> 135 tables); and a new fence,
   test_the_generated_set_on_disk_matches_the_tables_that_exist, compares the
   committed artifact against discover_tables() — nothing did before. Verified
   red against the stale set, green against the regenerated one.

2. run_lifecycle_sweep selects every tenant's project roots with no predicate, on
   a scheduled-workflow path H2's request-side conversion never reaches. Recorded
   as a named site on MT-1d, to be done BEFORE the phase-4 promotion.

3. resolve_organization_id resolves the tenant from inside the session and
   encodes one-person-one-org (migration 161's D-MT-1), which H6 retires.
   Recorded on H2/H6 with the measurement that 21 app_user-derived org reads span
   6 modules — a bigger surface than H6's one-line criterion suggests.

Also swept: migration 161's header now documents the generated PHASE 3 (a
duplicate _org_fk beside its inline FK, plus the 17 single-column indexes the
file itself argues against) — a maintenance-window decision, written down rather
than discovered at 2 a.m.; intake.py's recursive descent repeats the tenant
predicate like core.py's, for the reason core.py states about its own copy; and
project_management_app.md, which cited NO tenancy decision at all in 185 KB, now
cites D15, records D23's placement of Projects inside Center packages, and has a
status header matching reality (a-t merged, migrations applied on prod).

Windows papercuts fixed while here, both in the path this change tells people to
use: the generator crashed on cp1252 before writing any file, and 32 test
read_text() calls lacked an explicit encoding (3 tests failed on the owner's own
machine). Local: 1277 passed.
