## Why each fact earns its place

- **`importance`** — the true analogue of the `/tasks` priority pill. It has been in `DEFAULT_SHOWN` since WS-27x and the Table column has always drawn it; the card was the one surface ignoring a promise the view already made. Unset draws nothing, but **`0` (Low) draws** — the select's empty row PATCHes `null` precisely so "nobody said" and "Low" stay different things. Only `Urgent` escalates to the danger tone; a scale where three of four levels shout is a scale nobody reads.
- **`tags`** — named, not counted. `"🏷 3"` is the shape of a fact with the fact removed; `regression` `supplier` tells a reader what the task is *about*. Colour comes from `pm_tags.color` through the same `statusAccent` chip class the picker, the manager and the filter bar use, so one tag is one colour everywhere.
- **`estimate_mins`** — a plain omission. `TaskModel` returns it and `TableView` reads it; the card's adapter never mapped it and its comment asserted the column did not exist. Gated on `estimate`, which stays OFF by default.

**No `SHOWN_FIELDS` default changed.** `FIELD_KEYS`, `DEFAULT_SHOWN` and the gateway's mirror are byte-identical to `main` — this makes the card obey a contract that already existed rather than taking a new decision.

Deliberately left off, with reasons in the spec: `start_date` (a floating `DATE` needs a day comparison that belongs to the app adapter, not a shared module), blocking-count (`blocked_by_count` only — a gateway ticket), watchers/recurrence (not on `TaskRow`), triage (the status chip already says it), custom fields (unbounded density on a 288px card).

## Two design seams, kept as seams

A chip's `hue` is an **identity** (which tag), a chip's `tone` is a **measurement** (how late, how blocked) — which is why they draw as two shapes. Both stay *names*: `TaskMeta.tsx` remains the only file that turns either into a class, so `warning` never appears as `text-warning` at a call site.

Chip keys may now be namespaced `<kind>:<discriminator>` (`tags:ops`, `tags:more`), and everything classifying a chip reads `chipKind(key)`. This was the trap worth fencing: the visibility gate was keyed on the whole key, so a task with three tags would have fallen out of every lookup and silenced its tags on every view — silently.

## Also in this PR

- **`/tasks` list Name column** — the fix for the truncation in the same review. The column already flexed (`minmax(140px, 1fr)`), but six fixed sibling tracks took 670px of an 865px row, so `1fr` could only ever resolve to the leftovers: **147px** against content wanting 312px, 39 elements truncating. Raising the floor *alone* pushed Due date off the right edge — a browser showed that immediately — so both halves ship together: ~120px reclaimed from the fixed columns (each sized against the widest real chip it draws) and the floor raised to 240px. Measured after: **241px**, Due date back inside the row, nothing overflowing.
- **A rule-count fence.** Three files quoted three different numbers for the same gate — "five regexes", "six", seven — each true when written and each stale by the next rule. The count is now parsed from the suite's own numbered header and both docs are checked against it. Scoped so `AGENTS.md`'s "Four rules on top of the three above" (a true statement about a different list) does not trip it, with a parser guard and a floor that stops the docs passing by deleting the sentence.

## One honest finding, not papered over

Material dark's `--warning` is a pale peach (`hsl(35 90% 78%)`) and its `--destructive` a pale pink, so `High` and `Urgent` sit closer together in that theme than elsewhere. The four glyphs and the four words are what carry the level there — which is why the levels have four distinct glyphs. That is the theme's own token, so it was left alone rather than hardcoded around; recorded in spec §11.23.
