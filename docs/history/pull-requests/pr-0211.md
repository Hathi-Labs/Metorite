## Description

Adds the top-tier onboarding UX on top of the W11 guided wizard already on `main`.

## Embedded Signup (W12) — "Continue with Facebook"
Log in with Facebook → pick your number in Meta's popup → done, **zero copy-pasting IDs or tokens**. Gracefully falls back to the W11 guided manual wizard when the Meta app isn't Embedded-Signup-configured.

**Backend**
- `GET /whatsapp/connection/info` now reports `embedded_signup` + `fb_app_id` + `es_config_id` + `graph_version` (the App Secret stays server-side).
- `POST /whatsapp/connect/embedded` — exchanges the `FB.login` authorization code for a business token **server-side** (`exchange_code_for_token`), verifies the number, **subscribes the app to the WABA so webhooks flow** (`subscribe_app_to_waba`, best-effort), and stores the account via a `persist_account` helper now **shared** between the manual create route and this one.

**Frontend** (`/whatsapp/connect`)
- Fetches connection info; when Embedded Signup is available, leads with a "Continue with Facebook" card (loads the FB JS SDK, `FB.login` with the ES `config_id`, a `message`-event listener captures `phone_number_id`/`waba_id`) and offers the manual wizard as the secondary path. Otherwise it goes straight to the wizard, which hints how to unlock one-click.

**Config** — `WHATSAPP_APP_ID` + `WHATSAPP_ES_CONFIG_ID` unlock it (App Secret reused for the exchange); both documented in `.env.example`, along with the earlier connect/enrichment vars.

## Caveat
Wired exactly to Meta's documented Embedded Signup contract and unit-tested (config detection, not-configured guard, fully-mocked happy path through exchange → verify → subscribe → persist). Its **live** run needs the Meta app to have Embedded Signup access (Tech-Provider / app review), which is a Meta approval — so it's correct-by-construction and tested, not live-verified against a real app.
