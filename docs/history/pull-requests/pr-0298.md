## Description

Opening an HTML or React artifact showed its source instead of the rendered thing. Four separate causes.

## Why it was broken

**1. The modal had a stale copy of the classifier.** `ArtifactViewerModal` is the *only* artifact viewer on mobile — the side panel is gated behind `!isMobile` — and it kept its own `classify()` in which `html`/`jsx`/`tsx` fall through to `CODE_EXTS`, so it handed them to the syntax highlighter. `DocumentPane` had learned to render those kinds; the modal never did, because the logic existed twice and drifted.

**2. The card's primary action was dead on mobile.** `ArtifactCard`'s "Open" button routes to the side panel, which doesn't exist there.

**3. React artifacts got no Open button at all.** The card's `DOC_EXTS` was `md/mdx/html/htm`, so `outputs/*.jsx` didn't qualify — which is why a `workload_dashboard.jsx` card shows only an expand icon and a download icon.

**4. The card itself wasn't clickable.** Opening an artifact meant hitting one of two 14px icons in the corner. The card — the large target with the filename on it — did nothing. The rendered view was reachable but not *discoverable*, which reads as "I open it and only see the source".

## The fix

**One classifier.** `lib/artifactKind.ts` is the single source, used by `DocumentPane`, the modal, and the card. `html`/`react` are tested **before** the code-extension set — that ordering *is* the fix, and reversing it turns every artifact back into a wall of source. Removing the duplication is the point: the drift between two copies caused this.

**The card is now the primary target.** Clicking it opens the artifact **rendered**, on the right surface:

| | Surface | Default view |
|---|---|---|
| Desktop | Side panel (resizable, beside the chat) | Rendered |
| Mobile | Full-bleed sheet | Rendered |

The user never has to know which they got. Only artifacts with a rendered view become clickable — a `.py` or `.zip` keeps icon-only actions rather than gaining a click that would just show source. Keyboard reachable: `role="button"`, `tabIndex`, Enter/Space, focus ring. Buttons inside `stopPropagation`, so Download still downloads.

**Both surfaces render first and switch to editing.** The side panel has Edit ⇄ Preview; the modal opens rendered with a **Preview / Code** toggle (source is otherwise unreachable with no side panel) plus **Edit** with a live preview, returning to rendered on save.

## A deliberate non-simplification

`DocumentPane` has no PDF or DOCX renderer. Rather than have the shared classifier lie about the file type to suit one viewer, it reports `pdf`/`docx` honestly and the pane collapses those into its existing "download it" state. A viewer may decline to handle a kind; what a file *is* shouldn't depend on which viewer opened it.
