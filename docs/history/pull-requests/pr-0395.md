## Description

The owner could not see any of today's UI. `main` had it, **six deploys reported success**, and the box kept serving an old bundle.

## What happened

`deploy.yml` delivers the apply script as

```
ssh 'bash -s' < /tmp/deploy_remote.sh
```

so **`vps_apply.sh` *is* the shell's stdin.** `apply_migrations.sh` runs psql through

```sh
pgi() { ... docker exec -i "$PG_CONTAINER" "$@"; }
```

and `docker exec -i` **attaches and drains stdin**. The moment a `pgi` call didn't supply its own input, it swallowed every line of the deploy script not yet parsed. Bash reached EOF and exited **0**.

Everything after the migration step never ran: no `uv sync`, no gateway restart, and no `Rebuilding + restarting workbench (Next.js)`. The deploy job took **14 seconds** against ~2m45s for a real one — a Next build alone is ~80s.

## Why nobody noticed

- **`verify()` health-checks the public workbench**, which was still serving the *previous* deployment perfectly. A no-op deploy and a good one are indistinguishable to it. `deploy_delivery_path.md` §8.3 already flagged verify-by-health as blind to this class — this is the fourth bite, and the first where the script exited *cleanly*.
- **The trigger was new.** Every earlier psql call piped its own input or used a heredoc; the recently added ledger query is the first `-c` invocation, so stdin had never been touched before.

## Fix

`< /dev/null` on the `apply_migrations.sh` call, isolating the whole migration script from the deploy script's stdin — and the same on the ledger query, so a helper that steals stdin doesn't depend on every caller remembering.

## Tests

Three, in the file that already fences the delivery path:

1. the migration call must redirect stdin — the one line that made six deploys into no-ops;
2. the workbench rebuild must come **after** it, which is what turns this from cosmetic into "ships no UI while reporting success";
3. every `pgi psql` must pipe, heredoc, or redirect fd 0.

The third needed **two attempts to be worth anything**. Matching bare `/dev/null` passed on `2>/dev/null` (stderr); matching bare `|` passed on `|| true`. Both loose versions let the real bug straight back in under mutation. Both mutants are red now.

No migration. 112 cases green across the deploy-wiring, import and routes suites; ruff clean; `bash -n` clean on both scripts.
