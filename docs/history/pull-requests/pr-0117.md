## Phase 2 — 2.10: sync resilience (backoff, orphan cleanup, category cache, 429)

Four hardening fixes so a failing account stops being hammered and the Outlook apply stops wasting Graph calls / eating throttles (review §2.1, §3.2).

### Scheduler (`scheduler.py`)
- **Exponential backoff on sync failure** — `_next_backoff` doubles from the interval each consecutive failure, capped ~1h, resets on the first success. A revoked/disconnected account was polled every 300s **forever** (a wasted auth handshake + Graph call 12×/hour). `_sync_account` returns `{"error": ...}` rather than raising, so the loop keys backoff on that dict **and** the outer exception.
- **Startup orphan cleanup** — `_close_orphaned_syncs` closes sync-log rows stuck `running` and accounts stuck `syncing`; a crash/restart mid-sync left them in-flight forever, lying to any "sync in progress?" check.

### Outlook provider (`outlook.py`)
- **masterCategories cache** — fetched once per provider instance instead of on every `set_labels`. A warm apply where the category already exists now makes **no** masterCategories call — turning the 3-Graph-call apply into 2 across a sweep. Cache stays consistent when a category is created.
- **Graph 429 Retry-After** — `_graph_send` honours one `Retry-After` (bounded to 30s) and retries the apply once, instead of surfacing the 429 as a phantom failed apply. `set_labels`' GET + PATCH route through it.

### Verification
- `test_email_sync_backoff` (doubling + cap + reset; orphan-close UPDATEs), `test_outlook_labels_cache_and_429` (fetch-once cache; no call when warm; 429 honours + caps Retry-After; success isn't retried).
- Existing tests that mock `set_labels` wholesale are unaffected; `test_email_labels_upstream` (real `_ensure_categories`) still green. Blocking lint clean. No migration, no frontend change.
