## Description

## What

Tier-A item **2.6**, the remaining one-off. Migration 89 + the `internet_message_id`
reclaim already stopped **new** Outlook re-key ghosts from forming; this cleans the
duplicates that predate the fix.

`scripts/merge_ghost_messages.py` merges rows sharing a backfilled
`(account_id, internet_message_id)`:
- keeps the **richest** survivor — a classified row (`rules_processed_at` set) first,
  then the newest `received_at` ("prefer the newest provider id", mig 89);
- **carries** a sibling's categories / `rules_processed_at` onto the survivor where it
  lacks them, so a merge never drops a classification;
- **repoints** the FKs that `SET NULL` on delete (`email_executed_rules`,
  `email_rule_guidance`) onto the survivor, so audit/guidance history keeps its message;
- **deletes** the ghosts — their `email_attachments` / `email_embeddings` CASCADE away,
  being duplicates of the survivor's.

Rows whose `internet_message_id` is still NULL are **reported, not merged** — their
stable id can't be known until they re-sync (mig 89's note). Dry-run by default.

## How the user runs it (live)
```
# 1) sync to backfill internet_message_id on existing rows
# 2) dry run — see the groups + how many NULL rows still need a re-sync
uv run python scripts/merge_ghost_messages.py
# 3) merge
uv run python scripts/merge_ghost_messages.py --apply
```

## Risk
The **script** is inert — not imported by the app, no runtime effect until run by
hand. It mutates live data only under `--apply`; dry-run reports the exact plan
first. Follows the #112 `repair_conversation_threads.py` precedent. No migration.
CI-blocking ruff + compile clean.
