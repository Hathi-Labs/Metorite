## Description

Next Actions was showing the **union** of your 4 workflow stages + **every raw ClickUp status** — cluttered. Now it shows **only your 4 fixed stages**, and a Settings mapping translates each unique upstream status to one of them.

## Model
- **Next Actions = 4 fixed stages only.** A synced task's ClickUp `providerStatus` is translated to a stage via the new `status_stage_map` (migration 69).
- **Project view unchanged** — opening a specific project still shows that project's real ClickUp statuses (it bypasses the map).
- **Inbound:** a synced task groups into the stage its status maps to (a local stage override wins for a drag that couldn't back-sync).
- **Outbound (drag on the board):** moving a card to a stage resolves **this task's own ClickUp project** status that maps to the stage (on-demand fetch, since different projects have different status vocabularies) and writes it back. **If the project has no status mapped to that stage → the move stays local**, no upstream write.
- **Auto-guess:** statuses are pre-mapped by name heuristic (backlog/todo→TODO, in progress/review→IN PROCESS, waiting/blocked→WAITING FOR, done/complete→DONE); you confirm/adjust in Settings.

## New Settings section
"ClickUp status mapping" — `GET /tasks/status-catalog` returns the unique statuses across your connected projects, each with its mapped (or auto-guessed) stage + an "N auto-guessed" nudge. One dropdown per status.
