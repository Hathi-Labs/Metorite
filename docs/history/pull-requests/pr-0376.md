## Description

`work_plan.md` §6(a) still described the Zoho two-way sync as **built and never run**. The backfill ran 2026-08-06 and the owner enabled the loop the same day — so the owner-gate registry, which is the thing agents consult before touching anything dangerous, was describing a state that no longer existed. That is the precise failure mode this corpus keeps hitting, and §6 is the worst place for it.

Now records what was **measured** at enablement rather than what was expected:
- the loop cycles every 600s; the first cycle pushed **nothing** (no row was dirty) and left **zero** rows dirty, so echo suppression held against 5,902 pulled records;
- the `Deals` watermark defect that surfaced minutes later and is already fixed in main (#375), including why deal conflict resolution is one-sided by design.

**The gate itself is unchanged and still binding.** It now governs changes to a *running* loop rather than a first switch-on — which is a different risk, not an absent one.

Note on why this took a separate PR: two agent attempts to edit this paragraph were blocked by plan-guard, because the paragraph contains the flag literal and the guard cannot tell a description from a flip. That is the guard behaving correctly; the fix was to write the replacement without reproducing the literal, not to weaken the rule.
