## Summary

First slice of BO-7 (`specs/competitive_hardening_2026-07.md`'s CH-1 item — sandbox hardening for agent code execution). Scoped via deep research into the current `permission_policy.py`/executor tool-dispatch/mutation-container code first (see conversation) — the backlog's "`decide()` is a no-op" framing turned out stale (it's real and tested), but three narrower, genuinely open gaps were confirmed and fixed here. The bigger half of BO-7 — a container boundary for the *normal* agent load path (`loader.py`'s `exec_module` of arbitrary git-pulled agent code) — is architecturally bigger (real RAM cost on the 4GB VPS, no natural process seam for MAF-native agents' in-process tool calls) and intentionally out of scope for this PR.

1. **Full call context reaches `decide()` for our own tools.** Every gate call site for platform tools passed `{"tool_name": tool_name}` only — no args/path/command — so `run_script` (which builds and executes a literal shell command from its own arguments) was approved purely on its "reversible" annotation, never checked against what it was actually about to run. `decide()`'s shell-denylist/workspace-containment checks now run as hard vetoes *before* the tool-annotation short-circuit; a new `build_tool_call_context()` maps `run_script`'s `path`+`args` onto `decide()`'s fields (deliberately not `code_task`/`install_dependency` — see code comments for why not). Traced every existing test in `test_permission_policy.py` against the reorder before touching it.
2. **`install_dependency` flagged destructive** in `tool_annotations.py` (shared-venv mutation, affects every agent in the process). Deliberately did *not* flag `run_script`/`code_task` — both are documented elsewhere as fast, non-interactive re-runs, and no tool yet wires a real `request_confirmation` call, so the addendum text agents see was reworded to not overclaim a confirmation card exists.
3. **Mutation-runner's `docker run` hardened** — it was the concrete "existing container pattern" the backlog wants generalized, but shipped with zero resource/capability flags. Added `--cap-drop ALL` (+ `--cap-add DAC_OVERRIDE`, required since the container's root user needs it to write the `acb`-owned bind mount) + `--security-opt no-new-privileges` + configurable `--memory`/`--cpus`/`--pids-limit`.
