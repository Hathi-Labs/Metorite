## Description

Phase 1 of making the Email Cleaner work without model calls.

## 1. A fourth `_decide` step: the message's own shape

A `List-Unsubscribe` header (RFC 8058 — transactional mail doesn't carry one), or an unattended local part (`noreply@`, `alerts@`, `billing@`).

The first three steps — learned pattern, sender consensus, domain consensus — **all require the sender to have been labelled before**, so none of them can touch a sender seen for the first time. Measured live, they could reach 265 of the backlog.

Three signals of exactly this kind already existed in `engine.py`, wired only as **negative gates**: allowed to say "not a Reply", never allowed to say "this is a Notification". This promotes them.

Design points:
- **Added last**, so no verdict the user or the rules produced changes. It only reaches mail that was previously getting nothing.
- **Ambiguous role addresses are never classified** (`info@`, `support@`, `team@`). A human answers those, and the Cleaner offers archive on top of whatever gets stamped. Live: `support@fracktal.in` is the user's own helpdesk, 231 messages.
- **Long run-together locals matched by substring** (`customernotification@`, `hdfcbanksmartstatement@`) — but only tokens ≥ 8 chars. Substring matching is how a classifier starts labelling people called Newsom, so the bar is enforced by a test.

## 2. `_CLEANUP_SCOPE` — one definition, shared by the sweep and the badge

It excludes the user's own organisation, because that mail **is not miscategorized** — its correct cleanup category is *none*, and no classifier will ever make a colleague a newsletter.

Measured live: **2,799 of 3,434 "uncategorized" messages were internal human mail.** The badge could never reach zero, and the sweep re-read them every five minutes to conclude nothing.

Carve-out: internal mail carrying a `List-Unsubscribe` stays in scope (an all-staff ESP campaign is worth cleaning). An internal `noreply@` without one is given up to the rules run, which has no scope limit — that's the one thing this trades away, stated in the code.

The badge also previously ran its **own, wider** query — no Sent exclusion, no self exclusion — so it counted mail the sweep could never act on.

## A regression the existing suite caught

The shape step overrode a learned **exclude** pattern. `deals@shop.com` reads as Marketing, but the user had taught via Fix that it isn't. Step 1 honours an exclude by skipping the rule; the shape step has no rule to skip, so `_taught_otherwise` asks separately.

A guess must always yield to an instruction. Now pinned by two tests — including one that a Receipt-exclude must *not* suppress a Notification verdict, since blanket suppression would let one Fix silently mute the whole step.
