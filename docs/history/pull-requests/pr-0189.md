## Description

## What

Gives every MAF agent the GitHub Copilot SDK as a **capability, not a peer agent** (the framework review's dual-runtime verdict): agents can now write programs when their built-in tools fall short, and reuse those programs forever.

Two tiers, injected into every agent and added to the guaranteed core tool floor:

- **`code_task(task)`** — a one-shot, 600s-bounded Copilot SDK coding session running inside the calling agent's own workspace (`orchestrator/code_session.py`). Follows a manifest-first script contract: read `agent-data/SCRIPTS.md` first, keep reusable scripts under `agent-data/scripts/`, edit existing scripts in place, update the manifest before finishing. Routes BYOK through the gateway `/v1`, so model tiers, the context-window guard, and cost observability all apply.
- **`run_script(path, args?)`** — zero-LLM re-execution of a saved `.py`/`.sh` workspace script. Cheap, fast reuse of capability built in earlier sessions.

## Durability (across operations, restarts, and updates)

- Scripts live under blob-store-backed `agent-data/` (Postgres authoritative, disk is a rehydratable cache; the workspace sits outside the app dir so deploy `git reset --hard` never touches it).
- The Copilot CLI writes with its **native** file tools and scripts write their own outputs — both bypass the `write_artifact` write-through mirror. Both tools therefore finish with an explicit sweep (`_sweep_to_blob_store`) that mirrors changed files under `agent-data/` + `outputs/` into the store. `code_task` sweeps **even when the session fails**, so partial work is never lost. Sweep bounds: 2 MB/file, 200 files/run.

## Harmonisation with agent mutability

The agent's chat workspace **is** its persistent git clone, so the coding skill plugs into the existing self-mutation governance instead of forking it:

- Two script homes with different gates: **workspace scripts** (`agent-data/scripts/`, blob-durable, no approval) vs **repo-baked skills** (`skills/*/scripts/`, `agents.py` — git-tracked source). The coding-session contract teaches both: a broken built-in skill is edited **in place** and committed locally, never pushed — the executor's post-run commit scan registers every local commit as a `pending_commit` inbox row, and the loader's pre-push hook blocks direct pushes (same pipeline as failure-driven mutation and loader skill auto-sync).
- **Fail-safe** (`_commit_repo_changes`): if a session edits tracked source without committing, `code_task` commits the residue itself — the loader's next `_pull_latest` stash-drops/hard-resets uncommitted tracked changes, so an uncommitted skill fix would otherwise be silently destroyed. `git add -A` respects the loader-managed `.gitignore` (`agent-data/`, `inputs/`, `outputs/` never leak into a commit).
- Promotion path: a script proven under `agent-data/scripts/` can graduate into `skills/<skill>/scripts/`, where `loader._sync_new_skills` auto-wraps it as a first-class agent tool (also via inbox approval).

## Execution hygiene (agent-use standards)

- **Workspace jail** — script paths resolve through `resolve_in_workspace`; traversal/absolute escapes fail closed.
- **Secret-scrubbed subprocess env** — allowlist (`PATH HOME LANG LC_ALL TZ TMPDIR PYTHONPATH`) plus a `TOKEN|SECRET|KEY|PASSWORD|CREDENTIAL` deny pattern; gateway tokens, provider keys, and DB URLs never reach script code (proven by a live-subprocess test).
- **Timeouts** — `RUN_SCRIPT_TIMEOUT_SECONDS` (default 120s) per script; 600s per coding session. Output middle-truncated at 8k chars.
- Both tools registered **open-world** in `TOOL_ANNOTATIONS` and wrapped by the injected-tool permission gate (B6). Process-level hygiene; the BO-7 container sandbox remains the hardening path for untrusted code.
