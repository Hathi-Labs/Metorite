## Description

**Main is currently red on `skill-eval`.** #309 merged at `dfdebae`, one commit before this fix; the failure had already been reported on that PR's checks. One test, one file, no production code.

`evals/trajectories/test_chat_fold_trajectory.py::test_detached_run_persists_final_message`:

```
assert 0 == 1
chat_fold.persist_failed  error="…<lambda>() got an unexpected keyword argument 'actor_email'"
```

`_upsert_messages` grew `actor_email`/`agent_name`/`authority` when sessions became rooms (#309). The eval stubs it with `lambda sid, msgs`, so the call raised `TypeError` — inside `persist_final_assistant_message`'s blanket `except Exception` ("persistence must never kill the relay"). The run finished normally, the assertion saw an empty list, and the only trace was a log line.

**Production is unaffected** — the real `_upsert_messages` takes those kwargs. This is test-double drift.

The doubles now take `**kw`, with a note on why: a positional-only double of a function whose caller swallows exceptions turns a signature change into a silent no-persist rather than a loud failure, which is what made this cost a CI round instead of being obvious.

`evals/trajectories/` 133 passed locally.

Worth recording for next time: CI has three test surfaces — `tests/unit/` (pr-check, deploy), `evals/trajectories/` (skill-eval), and the frontend job. `evals/` sits outside `tests/`, so a local `pytest tests/unit` misses it entirely.
