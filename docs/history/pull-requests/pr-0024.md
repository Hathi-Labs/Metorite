## Description

Follow-up to #23 — fixes "observability doesn't seem to be working" and adds a durable history view.

## Why it looked broken
The observability page rendered blank for the operator while chat/email worked fine. Root cause: the observability (and `/debug`) routes were `require_role(EXECUTIVE, AGENT)`, but the Next SSO proxy only forwards `X-User-Role: executive` when the signed-in email is in `EXECUTIVE_EMAILS` — which ships **empty** by default (and the operator's domain isn't the `fracktal.in` default either). So every observability call **403'd**, and the proxies degrade to empty arrays → a **silent blank page**. `chat`/`memory`/`tasks` were unaffected because they aren't role-gated.

## Fix
- **Live views open to any authenticated caller.** `recent` / `stream` / `active` / `roster` / `cost` / `runs` now allow `EXECUTIVE + AGENT + EMPLOYEE` — they expose operational **metadata** (agent / model / tokens / cost / status / error message), not message content. The full message-content trace stays **EXECUTIVE-gated** at `/debug/runs/{id}`.

## History ("can I see history of activity?")
Today's live feed is the ephemeral Redis stream (~2000 events, lost on a Redis flush). Added:
- **`GET /observability/runs`** over the durable `agent_run` table (lean rows: metadata + error message, no trace blob).
- A new **History** tab (filter All / Errors) and repointed the per-agent drawer at it.

This surfaces runs going back as far as retention keeps them — **including data recorded since E2 Phase 2 (2026-07-03), before the live bus even existed** — so there's something to see immediately even if nothing has run through the new code yet.

## Testing
- +4 unit tests (employee-role → 200 on `runs`/`cost`; DB-less degrade to `[]`; bad status filter ignored). **Full unit suite: 817 passing.**
- Frontend: `next build` clean (page + 7 API routes), `tsc` 0 errors, eslint clean.

## Note on security posture
This is a deliberate choice: the operator's own live dashboard should not 403 for a logged-in non-"executive" user. If you'd rather keep it executive-only, the alternative is to set `EXECUTIVE_EMAILS` to include operator emails and revert the gate — happy to switch to that if you prefer.
