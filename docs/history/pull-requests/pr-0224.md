## Description

A full clean-up pass over the entire WhatsApp vertical (~13k lines: gateway routes, ingestion, frontend, Go bridge), driven by five parallel focused code reviews. No feature changes — dead-code removal, consolidation of duplicated logic, a few real bug fixes, and consistency/practice cleanups. Four commits, each validated independently.

## Bugs fixed
- **Expired 24h window read as open** (`rules.py`): the preview computed `expires.timestamp() > 0`, so any real timestamp — even an elapsed one — showed the window open (wrong `via_template`). Now compares against `now`.
- **Template send on a personal number 500'd** (`send.py`): `BridgeProvider.send_template` raises `NotImplementedError`; it's now caught and returned as a clean `409`.
- **Chat draft bled across chats** (`page.tsx`): `<Conversation>` had no `key`, so switching chats kept the previous composer text/panels. Added `key={chat.id}` + an out-of-order-fetch guard on `openChat`.
- **Settings pages targeted the wrong number**: insights/rules/replies/categories used a bare `accounts[0]` instead of the default account the inbox uses. Added a shared `pickDefaultAccount()`.
- **Categories edit had no rollback**: an optimistic policy change ignored the result; now rolls back and shows an error on failure.
- **Bridge media cross-account collision + session races** (Go): media cache now keyed on `(account_id, media_id)`; `StartSession` does an atomic check-and-insert with cleanup on failure (fixes a client/goroutine leak and a permanent-empty-QR zombie); graceful shutdown closes the whatsmeow container; disconnected/unknown errors return `409/404` not `502`.

## Consolidation (removed real duplication)
- **6 byte-identical ownership guards** → shared `assert_account_owned` / `assert_chat_owned` in `whatsapp/core.py`.
- **webhook.py + bridge.py duplicated the entire persist→hooks flow** → one `fire_post_sync_hooks` runner (which also gives the previously-dead `core._log` a purpose).
- `list_streams`' **5 sequential COUNT queries → 1** conditional-aggregate query; `classify_chats` no longer does a per-chat `SELECT kind` (N+1).

## Dead code removed
`chats._user_account_ids`, `outbound.WA_SEND`, an unused `UUID` import, the never-constructed `WhatsAppChat` dataclass + `MESSAGE_KINDS`/`CHAT_KINDS`, the dead `send_digest` hook field, the dead `updateSavedReply` export, an unused SELECT column, and the Go `DeleteSession`/`AccountForJID` + unpopulated wire fields.

## Practice / consistency
Stale "only cloud_api" docstrings corrected; parser `result.errors` now logged instead of swallowed; `bridge.mark_read` logs like `cloud_api`; `zip(strict=True)`; bounded `rules_preview` limit; scheduler stop() error logged; Go idiom (`strings.Contains`/`TrimPrefix`, drained response bodies, `MaxBytesReader`, LID-safe phone formatting).
