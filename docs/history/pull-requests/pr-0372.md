## The defect this chain caught

The first commit shipped a **path traversal**: `record_id` went straight into the URL, and since HTTP clients resolve `../`, `get_record("deals", "../../admin/members")` became an authenticated `GET /admin/members` — escaping a boundary that the agent's instructions, its registry description and this PR's own AGENTS.md edit all assert. All 48 tests missed it, because every fixture passed `str(uuid4())`. It matters here specifically because `record_id` is model-filled and the model's context is counterparty-authored text — lead names, note bodies, the 1,909 notes just imported from Zoho.

Fixed structurally, at the layer that already validates `entity`: `_record_uuid` **canonicalises** (so braced, `urn:uuid:` and unhyphenated spellings all normalise to 36 separator-free chars), plus an AST fence over every `/crm` path expression. Mutation-tested — removing the guard turns 32 tests red; applying it to only one of the two tools still turns 15 red. Independent re-review ran 21 adversarial spellings, captured the wire URLs, and enumerated every path expression: could not defeat it. Verb allowlist was structural; now the path is too.

Also fixed along the way: a docstring in three agents that called a real settings attribute fictional (a "cleanup" would have 403'd every call), `sharing.shareable` flipped to `false` to match siblings (run permission folds on `agents:run:*`, never `feature:*`), and a Windows-only `read_text()` encoding bug that had been leaving the identity-fence test **red on main** on this machine.
