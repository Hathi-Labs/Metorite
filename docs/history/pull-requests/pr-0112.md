## Description

Repair rides the classification path (#110), so a damaged thread heals on its **next inbound message** — and a DONE conversation may never get one. This walks the statused conversations that still show damage (**51 with stale cleanup chips, 16 rule-moved messages** at time of writing) and runs exactly the two repair steps the live runner uses, through the same functions: `_reconcile_thread_labels` + `_restore_conversation_messages`.

**Provider-aware on purpose**: the sync reads categories back from the provider, so a SQL-only fixup would be reverted on the next cycle. If the provider won't authenticate, the script refuses rather than repairing blind. Dry run by default; `--apply` to act.

Shipped through the pipeline rather than pasted over SSH so the exact code that touches the mailbox is reviewed, versioned, and re-runnable. Run plan after deploy:

```
cd /opt/acb/app
uv run python scripts/repair_conversation_threads.py          # dry run, verify count ≈ 51
uv run python scripts/repair_conversation_threads.py --apply
```
