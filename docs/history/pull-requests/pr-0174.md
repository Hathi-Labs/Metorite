## Description

## Why

Focus Mode was local state inside CalendarView — leaving the calendar (or the tasks app) unmounted the room entirely and the running timer vanished from sight. Its ✕ also "left the room with the timer silently running", which is the opposite of what a close button should do.

## What

**The session is now store-held** (`taskStore.focusSessionId` + `focusMinimized`) **and mounted once in AppShell**, so it survives navigating anywhere in the control plane. It renders in two shapes:

- **Expanded** — the full-screen room (unchanged internals).
- **Minimized** — a compact dock with the live timer, task title, state line, and pause / expand / close:
  - **Desktop:** a floating animated card bottom-right.
  - **Mobile:** a strip that extends the bottom nav bar upward — flush above Menu/Inbox/Lists/Capture/Assistant.
  - The same component instance stays mounted across the switch, so the pomodoro segment, cycle count, and pause state carry over exactly.

**Controls (both shapes):**
- **Minimize** (also `esc` in the room) keeps the timer running, visibly.
- **✕ ends the session**: stops the remote timer (stamps `actualEnd` — the durable server-side actuals signal that feeds planned-vs-actual and learned estimates) and removes the UI.
- **Restart later from the task manager:** all the calendar entry points (Start / Focus / gap-fill-into-now) set the store session, and the task-detail header gains a **"Focus"** button so a session can be started or restarted straight from any open task. Re-entering re-stamps `actualStart`.

**Fix found along the way:** entering the room from the task-detail modal left the modal (z-80) covering the room (z-70) — entering a session now closes the detail modal.
