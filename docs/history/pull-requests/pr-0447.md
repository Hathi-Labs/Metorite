## WS-28h — structured skills & credentials (migration 176)

`skills TEXT[]` answers "do they know Python" and nothing else. The questions assignment
actually asks are HOW WELL, HOW RECENTLY, and ON WHAT EVIDENCE — one row per (person,
skill) in `gtd_person_skills`, plus `gtd_person_credentials` for "is this person actually
qualified to sign this off". Both tenant-scoped on day one.

**D-PC-6 as a mechanism:** the array does not go away — four live consumers read it — it
becomes a projection. `gateway/person_skills.py` (a leaf, because People routes AND the
tasks-side résumé ingest both write it) ends every write path in one `project()` inside the
caller's transaction:

- the structured replace (new editor on My Profile and the person page);
- the flat `PATCH {skills}` — now *reconciles* the table: retained skills keep their
  level, so the older door cannot strip what the newer one set;
- the résumé merge — add-only (a CV is evidence for what it contains and silent about
  everything else), now also writing credentials, deduped so re-uploading cannot double a
  degree.

**Found & fixed:** every hand-typed skill in the product rendered as "extracted from a
résumé" — the backend writes `manual`, the UI's `skillOrigin` tested the literal `stated`
which nothing ever wrote, and its own test had pinned the wrong word.

**Measured, not assumed:** batch inserts share `now()`, so the projection orders
deterministically-alphabetically, not by insertion (the live harness corrected the first
docstring); the parser's boundary regex eats a trailing period (`solidworks.`) — the same
lookahead protecting `node.js`.

## WS-28d — capability search (`/people/search`)

Three signals, each labelled on the result with its own points: structured skills weighted
by **level × recency** · the **newest CV's matching line, quoted**
(`DISTINCT ON … ORDER BY uploaded_at DESC`, verified live) · **semantic cosine**,
best-effort with its absence *reported*, never silent.

**Outside §5.5's EVAL-LOCK by construction:** no LLM ranking prompt exists — arithmetic
over named constants, recomputable by hand from the page. Fences: the module greps clean of
model calls; no INSERT/UPDATE/DELETE (D-PC-13 — a suggester with an UPDATE has become an
assigner); the client contains no `.sort(` (the server's order IS the ranking). Gated
whole-surface on `admin:members:read` (§4.2's oracle rule). Every result carries load,
contracted hours, and availability warnings — the *reader* decides, not the ranker.
`score_skills` is exported pure for WS-28j3's suggester: one ranker, not two answers.
