## Description

The cleaner could not show its own categories and could not finish its own work. Three separate caps were involved, only one of which was defensible.

## Scope

Rename **Inbox Cleaner → Email Cleaner** and scope `/senders` to the whole mailbox (excluding trash/junk/drafts) instead of the inbox.

The inbox scope made the Marketing and Cold Email chips **structurally unfillable**: those preset rules label *and archive* on Gmail, so the mail had already left the inbox by the time the cleaner looked. Those chips were advertising categories the view was incapable of showing.

## Caps

The caps were never a database limit — one set-based `UPDATE` costs the same at 50 rows or 50,000. They existed because the **provider** was walked one HTTP call per message. The constraint was applied at the wrong layer.

- **`bulk_action`: no row cap.** The old `_BULK_MAX = 1000` silently truncated — "archive everything from this sender" stopped at 1000 and reported success. Now one set-based `UPDATE ... RETURNING`. Uncapping makes an *unfiltered* request mean "trash my entire mailbox", so that is refused explicitly — the right guard, since a cap truncates the legitimate case just as hard as the dangerous one.
- **Provider batching.** New `BaseEmailProvider.bulk_apply`, overridden by Gmail with `batchModify` (1000 ids per request). Archiving a 40k backlog is 40 calls, not 40,000. Trash stays on its own endpoint rather than assuming `batchModify` accepts the `TRASH` system label on a destructive path. Per-item failures are isolated so one 404 cannot strand the rest.
- **Outlook re-keys persisted.** `/move` returns a *new* message id; the old reconciler discarded it, leaving every bulk-archived Outlook message pointing at a dead id until a full re-sync.
- **Sweep runs to completion.** Pages until the mailbox runs dry instead of stopping at 2000, and reports `exhausted` so it never implies "done" when it means "stopped". The offset advances by exactly the rows that stayed uncategorized — categorized rows drop out of the query, no-evidence rows never do. Evidence is read **once** and held: refreshing per page would let the sweep's own projections become evidence for further projections.
- **Sender list paging.** `limit` is a payload bound, not a scope bound — `offset` paging plus "Load more" so the quiet tail is reachable, not merely counted.
- **`restore_provider_labels`:** one statement per distinct label-set instead of one per message (~20 round-trips instead of 40,000, on a synchronous route).

## Inbox filters

- **New `GET /email/messages/facets`** — per-label counts plus `unread`/`uncategorized` for a folder. The chip row now shows only filters with mail behind them: the fixed list offered "Cold Email" in Sent and "Needs reply" in Drafts, and an empty result from a chip cannot be distinguished from a broken one. An *active* chip stays visible at zero, so filtering never strands you with no way back.
- **New `uncategorized` filter** (chip, filter menu, `is:uncategorized`). The label vocabulary moves from `automation/senders.py` to `core.py` so the inbox chip and the Email Cleaner's Uncategorized tab resolve to the **same mail** — two definitions across two views of one mailbox is the drift this package keeps paying down. It means "carries none of the RULE labels", not "has no labels at all".

## Fixes

- The sender pill showed **"Blocked"** for auto-archived senders with no unsubscribe link. That discriminated on a property of the *sender*, not of how the decision was reached — so a deliberate auto-archive rendered as a status the user never picked, implying a fourth state that doesn't exist. The provider filter it meant to convey already has its own "Filtered" pill. Now always **"Auto-archive"**; "Kept" → **"Keep"**.
- Picking a **search scope** now navigates the sidebar there, so the list, the bar and the sidebar name the same place.
