## Description

Implements the top recommendations from the AI review (`calendar_ai_review.md` §4.1–4.4) so the chat assistant becomes a real day-manager — plan, reschedule, roll over, and reorganize the day by chat — instead of only moving single blocks. The server does the geometry; the agent proposes then applies on confirmation.

## Backend
- **Persisted day state** — migration `92_gtd_day_state.sql` (`user_id, day, one_thing_id, seed_ids`) + `GET`/`PUT /calendar/day-state`. The ★ One Thing and tomorrow-seeds were localStorage-only; now server-side AI (planner, chat agent, digest) can see them and they sync across devices.
- **One-Thing-aware planner** — `_compute_day_plan` orders the One Thing first, prefers a peak-energy window, and never drops it for capacity; the LLM ranking prompt gets an explicit One-Thing rule. Read from `day_state`.
- **Agent-facing endpoints** — `POST /calendar/{plan,replan,rollover}-today` build the day window from stored settings + timezone (no client geometry), reuse the exact planner cores, and **apply** on `apply=true`. Plus a cheap no-LLM `GET /calendar/day-summary` for the digest.

## Chat tools (`skill-task-gtd`, registered in `agent-task-manager`)
- `gtd_plan_day`, `gtd_replan_day`, `gtd_rollover` — propose → confirm → `apply=true`.
- `gtd_day_digest` (morning "how's my day"), `gtd_estimate_stats`, `gtd_set_one_thing`.
- `gtd_list_schedule` now marks 🔒 fixed / ✓ done blocks.
- `instructions.md` + the chat persona document the propose-before-apply workflow and the never-move-a-🔒-block rule.

## Client
- `apiGetDayState` / `apiSetDayState`; `CalendarView` syncs the One Thing (star toggle + ritual commit) and shutdown seeds to the server and hydrates on open. All best-effort, so demo mode (no gateway) is unaffected.
