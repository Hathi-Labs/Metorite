## Description

Owner-directed: *"just show up all the data that is there in the Tasks app inside the Projects app"* — one department now, real departments later.

## A second importer, not a flag on the first

`import_clickup.py` talks to the live tenant: working token, LLM budget to propose a Center per Space, and an owner-confirmed mapping **before** anything is written. Right for the migration; wrong for "show me my work today" — being made to decide who may see what before you've seen the data is backwards.

`POST /projects/import/from-tasks` reads `gtd_projects` and `gtd_items` — the ClickUp mirror already sitting on the box. No API call, no token, no rate limit, no model spend, and it still works when the connector is stale.

## One department, and the split stays cheap

Everything lands under a single root the caller names. Each child carries its ClickUp list id in `clickup_id` **and its Space id in `clickup_snapshot`**, so breaking this into real departments later is a `/move` per subtree rather than a re-import.

## The root is org-granted — narrower than it sounds

The ClickUp importer deliberately does *not* org-grant unmapped Spaces, because bulk-granting a whole tenant is a large implicit decision. Here the caller named one department and asked for their work inside it — the same act as `tree.create_node`, which org-grants for the reason a solo org must not be locked out of the thing it just made.

## Four properties the tests pin

Each is a way this could quietly do harm:

1. **Nothing outside `pm_*` is written.** The Tasks app's rows *are* the mirror and must survive untouched, or an import would damage the personal task manager it read from.
2. **Only `source <> 'LOCAL'` rows are read.** A personal capture is the member's own; publishing it to a shared board is a disclosure nobody asked for.
3. **The provider's own status names are kept**, mapped to our categories. Renaming somebody's "Backlog" to "To do" makes the board stop matching the tool it came from on day one.
4. **A task whose list didn't come across is counted, not dropped.** "412 imported" while 30 were skipped is a number that gets trusted and shouldn't be.

## A gap mutation testing found

Deleting `dry_run` from the write guards left **every test green**. On a *first* dry run `_root_department` returns `None`, so `root_id is None` blocks the write and the `dry_run` check never has to act. On a *second* dry run the department already exists and its id comes back regardless — and the projects resolve too — leaving `dry_run` as the only thing between a preview and a write. That's the realistic case (preview → import → preview again), and it now has its own test.

## Also

- The UI offers this path **first**, with the live-tenant flow folded behind a disclosure — it's what somebody with an empty board actually wants.
- The exhaustive import-route gate registry gained a third entry, deliberately. That's the point of writing it as a set: a new import route can't inherit a pass by being absent.
