## Description

A full PM + senior-engineer review of the calendar surfaced a handful of verified, low-risk defects. This fixes those; the larger follow-ups (real confirmation gate, injection fencing, settings consolidation, geometry tests) land separately.

## Fixes

- **Planner ignored a stored day-start / capacity of `0`.** `_day_window` used the `x or default` idiom, silently rewriting a midnight day-start back to 07:00 and a zero capacity to 360 on every AI-planning endpoint — which broke the "plan across all 24 hours" case. Now guards on `is not None`, matching the nightly rollover job and `settings._int_or`.
- **Capacity of `0` disabled the cap** instead of enforcing it (`if capacity_mins` treated 0 as "unlimited" and packed the whole day). `0` now means "no focus work today"; the ★ One Thing is still protected.
- **Free time could start in the past.** When `now` sat exactly on a 15-min mark but mid-minute (e.g. `10:00:30`), the next-slot rounding added 0 and booked before `now`. Now ceils to the next mark whenever `now` isn't exactly on one.
- **Chat-tool crash.** `_fmt_plan` was defined twice at module scope; the day-plan version shadowed the project-plan one, so `gtd_plan_project` called it with the wrong arity and raised `TypeError` on every run. Renamed the project renderer to `_fmt_project_plan`.
- **Stale settings label.** The working-hours control still read "Day window" after the single always-24h grid landed. Renamed to "Working hours" with a line clarifying the grid always shows 24h and these hours only shade off-time and seed the planner's default placement.

## Verification

- `python -m py_compile` clean on both Python files; module parses; `_fmt_plan` now has a single definition with all call sites matching arity.
- Dependency-free logic checks confirm the 15-min ceil never books in the past and capacity `0` schedules nothing while the One Thing stays placed.
