## Description

## Problem

Model visibility (the eye-toggle on **Settings → Models**) and **tier** assignments didn't stick — hidden models reappeared and tiers reverted, in email and chat too.

Root cause: both were saved to **git-tracked files** (`infra/enabled_models.json`, `infra/litellm/tier_overrides.yaml`). The deploy runs `git reset --hard origin/main`, so every push reverted them to the committed version. (A comment even wrongly claimed `tier_overrides.yaml` was untracked.) This is the same class of bug already fixed for the agent registry via `dynamic_agents`.

## Fix

Move both to a new `model_config` Postgres table (key/value JSONB), so config survives `git reset --hard`, restarts, and reboots.

- `infra/postgres/35_model_config.sql` — `model_config` table (idempotent; applied by `apply_migrations.sh` on deploy)
- `packages/acb_llm/acb_llm/model_config.py` — `load_blob`/`save_blob` (sync psycopg, same connection style as `key_store`)
- `apps/gateway/gateway/routes/settings.py` — `_load_catalogue`/`_save_catalogue` (key `enabled_models`) and `_load_tier_overrides`/`_save_tier_override`/`_load_config` (key `tier_overrides`) now use the DB
- `packages/acb_llm/acb_llm/client.py` — tier init reads overrides from the DB so routing survives restart

## Migration & safety

- **Seeding:** on first read, existing JSON/YAML is imported once into the DB, then the files are ignored — nothing lost.
- **Fallback:** if Postgres is unreachable, it gracefully falls back to the files.
- `config.yaml` remains the file-based tier *default*.

## Verification

- `py_compile` clean on all changed files.
- Modules import in the `uv` venv; confirmed the DB-unreachable fallback loads tiers from the legacy file.
