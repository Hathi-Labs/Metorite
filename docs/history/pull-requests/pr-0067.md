## Description

P2 from the context/output-budgeting review. Independent of #65 / #66.

> "GitHub Copilot SDK agents need to be better configured for being used in MAF because technically they are not inside VSCode anymore. Should be treated as first-class citizens."

Three things were quietly broken for **every** VS-Code-authored agent.

## 1. `tools:` was advisory only — inert

The frontmatter lists VS Code tool ids (`editFiles`, `terminal`, `codebase`, `problems`, …) that map to **nothing** here, so the model saw names in its prompt that exist in no tool schema and had to improvise onto the CLI's native `bash`/`create`/`edit`.

`derive_tool_scope()` now maps them onto the platform tools that actually do the job. On the real `technical-project-planner`:

```
config.json tool_scope : [web_search, fetch_page, write_artifact, manage_todo_list, ask_user, save_note, recall_notes]
+ derived from .agent.md: [github_search, github_repo_search, write_artifact, share_artifact, fetch_page, web_search, run_diagnostics, get_errors]
= gained               : github_search, github_repo_search, share_artifact, run_diagnostics, get_errors
```

**Widening only:** an agent with no `config.json` tool_scope stays unscoped, so adding an `.agent.md` can never silently strip tools.

## 2. `.vscode/mcp.json` / `.mcp.json` were never read

Only `config.json` + the DB table were. `technical-project-planner` declares a **draw.io MCP server in both files** while its `config.json mcp_servers` is `{}` — so it lost the server it was built to use, then failed at the diagramming it exists to do.

## 3. MCP never reached a session AT ALL (from any source)

`_inject_mcp_servers` merged into `agent._default_options["mcp_servers"]` — but the SDK consults `_default_options` for exactly **one** key (`system_message`) and resolves MCP as `runtime_options.get("mcp_servers") or self._mcp_servers` (`_resume_session` reads `self._mcp_servers` only). We pass a fresh per-run options dict, so **that write was dead**.

Now merged into `_mcp_servers` via `merge_mcp_servers()` (DB registry outranks a repo's own files). The DB path also emitted `{"transport": ...}` while the SDK's `MCPServerConfig` wants `{"type": ...}` + command/args split + `tools: ["*"]` (`[]` means "expose none"). Both fixed.

**Blast radius today: nil** — all 5 DB servers are `enabled=false`, so nothing changes until someone enables one; it will then actually work.

## Runtime note (additive)

A short note is appended to a VS-Code-authored body — the author's prose is **never** rewritten — reconciling the IDE names with the real tools and stating there is no Problems panel / `#codebase` / editor UI. It also steers file authoring to `write_artifact` rather than shell heredocs: the exact habit that truncated tool-call arguments mid-JSON.

## Deliberately not included
Mapping `.agent.md model:` (e.g. `claude-sonnet-4-5`) onto a tier. "Nearest tier" is a judgement call with cost implications; today it's coerced to `COPILOT_CHAT_MODEL`, which is predictable and works. Left for a decision.
