## Description

## Drafting is opt-in on "Process past emails"

The backfill ran **every** matched rule action, including `REPLY` / `DRAFT_EMAIL` / `FORWARD`. Each spends a call on the drafting model — on conversations that, being months old, have usually ended. Pointing the date picker at 90 days silently generated (and billed for) a pile of drafts to delete by hand.

`draft_replies` now defaults to **false**. Labels, folders, archiving and mark-read still apply: **filing** old mail is the point of a backfill; **answering** it is a separate, deliberate choice.

- Dialog gains a `Categorize only / Also draft replies` toggle, off by default, with copy that states the cost *before* it's switched on rather than after the drafts appear.
- The job reports `drafts_skipped`, so a run that suppressed drafting can't read as one where the rules ran in full.
- **Live runs are unaffected** and still draft — that's the feature working as intended on a conversation that's actually live. Pinned by a test.
- `_without_drafting` returns a **copy**: the rule dict comes from the shared rule cache, so mutating it would disable drafting for every later message in the run *and* for the live runner.

This also removes the sharpest edge of the open **H5** gap (process-past skips the thread-status re-determination that stops a resolved thread auto-drafting). H5 itself is still open — the label-stacking and missing thread status remain.

## Naming

The UI has said "AI Settings" for a while; the code still said `Assistant`. Reading the code and describing it produced a name the user couldn't find on screen — which is exactly what happened.

Renamed **the scene only**: `AssistantView` → `AISettingsView`, `components/automation/assistant/` → `ai-settings/`, feature key `"assistant"` → `"ai-settings"`.

Deliberately **not** renamed: the email assistant **agent** — the chat, `agent-email-assistant`, the message `role`, and `email_assistant_settings`. That genuinely is an assistant, and those settings genuinely configure it; renaming them would be the same confusion in reverse, plus a migration for a label change.

Also renamed internal `quickClean` → `archiveOldMail` to match the button that actually renders ("Archive old mail"). The old name existed only in source and got quoted at the user as if it were something they could look for.
