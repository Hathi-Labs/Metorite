## Description

You hit the fallback ("AI ranking was unavailable, so this used priority order…"). That means the planner's LLM call is failing in your deployment — but the message was generic and the import-failure path logged **nothing**, so the actual cause was invisible.

This makes the reason visible so we can pin it down:

- `_llm_rank_day` now returns a short **reason** on failure instead of a bare `None`:
  - import failure → *"the gateway's AI client isn't available (acb_llm import failed)"* (now also **logged**, previously silent);
  - call / parse failure → *"the AI call failed (`<ExcType>`: `<detail>`)"*.
- The reason rides through `_compute_day_plan` → `DayPlan.rank_note` (only when `ranked_by == "priority"`) → `DayPlanResult.rankNote`, and the Plan panel's amber note now appends **"Reason: …"**.

No change to a successful plan — purely diagnostics for the fallback path.

**Note:** the clarify/atomize AI features use the identical call pattern (`acompletion_with_fallback`, `tier-balanced` fallback, `json_object` mode), so if those work in your deployment but planning doesn't, the reason string will tell us exactly why (model not found, auth, response-format unsupported, connection, etc.).
