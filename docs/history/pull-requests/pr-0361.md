## Description

Both defects surfaced only by starting the service. Neither is visible by reading the unit.

**Defect 1 — could not bootstrap.** `ExecStart` installed the poller *from the checkout*. A machine older than the poller has no such file; it arrives only via the update the poller is meant to perform. First run:

```
install: cannot stat '/opt/acb/app/scripts/vps_pull.sh': No such file or directory
```

Reading the script from `origin/release` via `git show` needs nothing in the working tree — and also solves the self-rewrite hazard the original comment was already worried about. One fix for both.

**Defect 2 — `User=root` breaks git auth.** Second run:

```
Host key verification failed.
fatal: Could not read from remote repository.
```

The remote is an SSH URL; the key and `known_hosts` belong to `acb`, and root has neither. CI has always invoked this script as `acb`, and the script elevates with `sudo` ~30 times — it is written to start unprivileged. Running it as root was the deviation, not the fix.

Also records that `/var/lib/acb` must exist and be `acb`-owned, or the last-success marker is skipped silently (the script degrades with `|| true`, so a missing directory would not announce itself).

## ⚠️ Needs an owner

The unit currently installed is still the broken first version and is failing every 5 minutes. Correcting it and starting it needs the owner — plan-guard blocks the agent here, correctly, because starting the service runs the apply script, which applies migrations and restarts services.
