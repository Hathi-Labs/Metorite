## Description

Reported from production — an AI-drafted reply went out like this:

```
Hi Suresh,

Noted. Hope the appointment goes well.

On 2026-07-19T14:47:23+00:00, Fracktal Finance wrote:
> Hi,
> Please consider my half day leave by tomorrow 20th July...

Vijay          <- the signature, below the whole quoted thread
```

Two independent defects produced it.

## 1. The signature was appended below the quote — on every signed reply

`build_signed_bodies` appended the signature to the END of `body_text`. The composer sends **one** body — new text + `\n\n` + quote (`ComposePanel.combinedBody()`) — so the signature landed under the entire quoted conversation. This was never specific to AI drafting: it happened on every reply sent from Command Center with a signature configured.

It now splits at the quote boundary and inserts the signature above it, in the text part and the HTML part alike. (No composer currently sends HTML, so the HTML part was derived from the same combined text and had the identical bug.)

## 2. The reply drafter was allowed to quote the thread

`_llm_draft_reply` had rules against sign-offs, placeholders, narration and subject lines — but nothing about quoting. Its sibling `_llm_compose_assist` already said *"no quoted prior conversation"*. Because the report came from an empty-body reply, `/compose-assist` routed to the full reply drafter and inherited the gap.

The ISO-8601 timestamp in that quote header is the tell: it is our own `_fetch_thread_context` formatting (`From: {sender} · {received_at.isoformat()}`) echoed back by the model.

Fixed with the prompt rule, plus a strip in `_clean_draft_body` — a prompt is an instruction, not a guarantee, and the client reattaches the real quote itself, so a model-authored one is always a duplicate.

## Quote detection

New `gateway/routes/email/quoting.py`, the Python counterpart of the frontend's `email/lib/quoting.ts`, using the same markers so client and server agree on where a quote starts.

It diverges in one place, which a test caught: the scan starts at line 0, so a body that is **entirely** a quote (a bare forward) is returned whole rather than cut between two quoted lines. Both splitters return the input untouched whenever they cannot split confidently — a misplaced signature is a far smaller problem than a truncated message.
