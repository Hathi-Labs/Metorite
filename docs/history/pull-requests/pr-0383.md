## Description

## What the deploy log for #382's merge showed

```
==> Pre-migration backup
scripts/apply_migrations.sh: line 96: Segmentation fault (core dumped) bash "$BACKUP_SCRIPT"
ERROR: pre-migration backup FAILED — refusing to apply migrations.
  (ssh exited non-zero — verifying by health regardless)
✅ Deploy verified healthy on round 1.
```

Every deploy since #380 merged has died at the backup gate while reporting green (the verify-by-health hole, already specced as a known defect, biting again).

## Root cause

#380's `PG_MODE` seam wrote `pg() { ... else pg "$@"; fi; }` — **the docker branch calls the function itself**. Infinite recursion, bash segfault. `docker exec` existed nowhere in the rewritten script outside a comment. CI's rehearsal job only runs `PG_MODE=local`, so the broken branch never executed before it reached the box. Both `backup_db.sh` and `restore_db.sh` carried the identical defect.

Knock-on: the #382 unit-sync step never ran (the apply aborts before it), so `acb-backup.timer` is **still** unscheduled. No migrations were pending, by luck — the next PR carrying one would have stranded it silently.

## The fix

- Docker branches restored to the exact pre-#380 invocation: `docker exec "$PG_CONTAINER" "$@"` / `docker exec -i` for stdin, in both scripts.
- New guard `test_the_pg_seam_actually_reaches_docker_in_docker_mode` — it **executes** the real `pg()`/`pgi()` definitions from both scripts in docker mode against a stubbed `docker`, timeout-bound. It fails in ~1s against the recursive version. (Two Windows subtleties are documented in the test: program via stdin bytes, because argv quoting and text-mode `\r\n` each break bash differently.)
- Mutation-checked both directions: 6/6 with the fix, guard red against the broken seam.

On merge, the next deploy should finally: pass the backup gate → run the unit-sync step → schedule `acb-backup.timer`. I will verify all three in the deploy log, not by the checkmark.
