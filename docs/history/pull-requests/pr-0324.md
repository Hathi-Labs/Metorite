## Description

Fixes the "WhatsApp did not accept the call offer in time" error, and adds the debugging needed when a call still fails.

## Root cause

The dialer's own placeholder taught `+91 98765 43210` — **with spaces** — and nothing stripped them. `meowcaller` builds the call offer's JID directly from that string, and a JID containing spaces is one WhatsApp never acknowledges. The offer goes out malformed, no ack ever arrives, and it surfaces as a bare timeout with no error to explain it.

## Fixes

- **Normalise before dialling.** Targets reduce to bare digits, so `+91 98765 43210`, `+91-98765-43210` and `(+91) 98765 43210` all work. Anything already a JID or LID passes through untouched. Sub-7-digit input is rejected up front rather than becoming a silent offer timeout.
- **Call from a chat.** Every chat header now has a **Call** button that hands the dialer that contact's JID instead of a typed number — the parsing that broke this can't happen at all. Group chats dial as group calls. It prefills and does **not** auto-dial; a URL that places a call on navigation is too easy to trip.

## Debugging added

The bridge now logs what was actually dialled next to what was typed, how long the offer took to reach the wire, and every phase transition with elapsed time — where a call stalls is what says which side went quiet:

```
call: placing 1:1 from <acct> to "919876543210" (typed "+91 98765 43210") as <own-jid>
call <id>: offer on the wire in 412ms (peer ...)
call <id>: calling -> ringing (+1.2s)
call <id>: peer accepted (+6.8s)
call <id>: media active (+7.1s) — recording="/.../<id>.wav"
```

Plus `GET /calls/diagnostics` and a **Calling readiness** panel in the UI, reporting whether the session exists, is connected, is logged in, and has the calling stack attached — with a verdict naming the specific missing precondition. It appears on any call failure via a "Check what's wrong" button, so a timeout with nothing to inspect becomes a question with an answer.
