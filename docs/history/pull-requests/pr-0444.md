## The correction worth reading

**I first wrote into the board that the R1 guard could not see this. Then I tested it, and it can.** Putting the duplicate back turns `test_migration_prefixes.py` red.

The real gap is *when* it runs. `actions/checkout` resolves `refs/pull/N/merge` on a `pull_request` event; GitHub does not compute that ref for a conflicted PR; and #439 sat `dirty` reporting **`check_runs: 0`** — no jobs at all. So the guard was never handed a tree containing both files.

> **A conflicted PR runs no checks — so the window where a cross-branch collision is most likely is exactly the window where nothing is watching**, and the collision surfaces only once someone resolves the conflict, by which point they are hand-editing the very tree that hides it.

That is a sharper finding than "the guard is blind," and the opposite conclusion. It would have gone into the board as fact if the claim hadn't been checked.

## One pattern worth copying
