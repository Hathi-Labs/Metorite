## N1/N2/N3 — Notes was private to its owner in the library only

**⚠️ Stacked: #348 ← #349 ← #350 ← #351 ← this.** Retarget each child to `main` before

PR #346 owner-scoped the Notes **library** — list, get, delete, dispatch — and named six
more surfaces it did not close. This closes them. **16 routes enumerated, 15 scoped, 1
deliberately left machine-authed.**

### 🔴 First: the scope I was given was incomplete, and the gate said otherwise

N1 was specified as five files. Enumerating `routes/notes/` exhaustively found **ten more

- `GET /meetings/{id}/live` — the live caption stream of anyone's meeting

### Three judgement calls, made explicitly

**`live/wanted` stays machine-authed.** The caller is the bot worker in its own container
holding `MEETING_BOT_TOKEN` with no member identity. An owner predicate needs an owner, and
both ways to invent one — trusting a client-supplied email, or falling back to the meeting's
own `owner_email` — turn the bot token into a way to assert an identity. It discloses one
boolean and gives the same answer for a nonexistent id. Pinned by a test.

**`share.py` implements no sharing.** Read end to end: no grant, no token, no redemption
route. The draft returns to the caller's own compose window and the send is a separate
`/email/send`. So there is no redemption to leave open — the whole route is a read, and it is
scoped.

**N3's principal is the caller, not the meeting's owner.** Resolving against the row's own
`owner_email` would compare the meeting to itself and pass every time. The `requested_by`
asymmetry from #346 is preserved, and a test pins that the ingest side still reads it.

One stated departure: N3 binds the predicate **into** the `UPDATE` rather than doing a
preceding `load_owned_meeting`. Same predicate, same 404, and no TOCTOU window. Recorded in
the spec as a departure rather than smuggled.

### 🔴 A production defect found on the way, not fixed

`/notes/meetings/{meeting_id}/live/wanted` is in **neither** `main.PUBLIC_ROUTES`
(`main.py:489-490`) **nor** `core.router`'s exempt list, while both its siblings are in both.
So `require_authenticated` and then the feature gate 401 the worker before `_check_bot_auth`
runs — **the poll that decides whether to keep paying for streaming ASR is dead in
production.**

Not fixed here: the repair *opens* a route, which is the opposite of this change's direction,
and no acceptance criterion asks for it. Filed in the spec, `AGENTS.md`, and the test
docstring.

pinned by tests, both properties #346 established for good reasons.
