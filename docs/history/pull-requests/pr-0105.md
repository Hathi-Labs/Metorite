## Description

You were right, and upstream agrees with you.

## The problem

A Fix could only produce a learned **pattern** — a hard sender→rule pin that short-circuits the model. So correcting a mistake never made the assistant better at anything: it removed *one* sender from the AI's reach and left the same misunderstanding in place for every other sender.

All 21 patterns on the live account are machine-inferred. **Not one encodes something you taught.**

> "Correcting a classification should enhance future AI classifications. I am not focusing on learned patterns."

**Inbox Zero has no Fix→pattern button at all.** Corrections go through the assistant's tools — `update-rule-conditions`, `update-personal-instructions`, `add-to-knowledge-base` — all of which change what the model *reads*. Patterns are a separate, conservative background analysis. We had copied only the pattern half.

## Guidance — the missing half

Free text attached to a rule, injected into the classification prompt. One correction about "vendor product digests are Newsletter, not Cold Email" now generalises to **every vendor** instead of exempting the one that was wrong. Migration 87.

Stored as rows rather than an LLM rewrite of `email_rules.instructions`:

- **Auditable** — you see exactly what was added and from which email. A rewrite destroys the sentence you wrote with nothing to compare against.
- **Revertible** — one row, one delete. Un-editing a paragraph is not.
- **Separable** — which is what makes the two-section screen possible.

## Pattern writes are now opt-in

`_teach` is the single choke point for both include and exclude writes in the Fix flow, gated on `pin_sender`, default **off**. The dialog surfaces it as *"Always file mail from this sender here"*, stating plainly that it skips the AI and therefore suits newsletters and bulk mail rather than people.

## Two sections, as you described

| | what it does | scope | cost |
|---|---|---|---|
| **Teaching the AI** | changes how it *reasons* | every sender | a model call |
| **Skipping the AI** | *replaces* it for a sender | one sender | free |

Each carries a one-line explanation of that trade-off, so you can tell which kind an entry is before deciding whether to keep it.

The prompt labels guidance as "correction from the user" rather than merging it into the rule's description — the model should weigh something you explicitly taught differently from the preset blurb shipped with the rule. Account-wide guidance (`rule_id NULL`) gets its own block. Guidance loads *after* the pattern short-circuit, since a pinned sender never reaches the LLM.
