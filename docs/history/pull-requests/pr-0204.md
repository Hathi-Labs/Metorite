## Description

Two related note-taker UX improvements that make "who said what" and "the right kind of notes" discoverable and self-service.

## 1. Diarization hint + one-click re-transcribe

**Why** — Only **Deepgram** returns speaker labels; **Whisper** (the default STT) returns none. So a meeting transcribed on a non-Deepgram model silently shows **no speakers**, with no clue why and no way to fix it. This closes that footgun.

**What**
- Backend `POST /notes/meetings/{id}/retranscribe` (`recordings.py`): re-runs the pipeline on the meeting's **existing recording** with the **current** STT model — reusing `run_transcription` (deletes + replaces segments, updates `transcript_source`) and the same `summary_run` / `_spawn_pipeline` path as upload/complete. Picks the best channel (`mixed` > `upload` > `mic` > `system`); `404`s when there's nothing to re-transcribe.
- Frontend: the Transcript tab shows a hint when a transcript **has segments but no speaker labels** and the model isn't `deepgram/*` — pointing to **Settings → Models** plus a **Re-transcribe** button. Path to named speakers: switch the STT tier to Deepgram → Re-transcribe.

## 2. Pick the notes template at record/upload time

**Why** — Templates could only be chosen *after the fact* (re-cutting a summary). Now the meeting can be set up in the right shape from the start.

**What**
- `api.createMeeting(title, platform, templateKey)` — `POST /meetings` already accepted `template_key`; this wires it from the UI.
- The `/notes` header gets a compact template `<select>` (defaults to `standard_meeting`); **Record** and **Upload** both pass the selected key. Optional — falls back to the standard template if the list doesn't load.

## Scope / safety

No schema change (reuses `meeting_recording` / `summary_run` / existing `meeting.template_key`). Additive — already-diarized meetings and existing create flows are unchanged.
