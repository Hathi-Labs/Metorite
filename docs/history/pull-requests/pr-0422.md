## Part 1 — code

### WS-27ab · view ergonomics *(P-14/15/16)*
Panel **peek → side → full**, persisted (measured: 448 → 320 → 448 → 766). `FilterBar` says when live state has drifted from the saved view — divergence is **one exported pure function** over the `toConfig`/`fromConfig` round trip, so it compares *meaning*, not bytes. The palette's commands became a **declared registry**; `g`/`v` sequences run it and the `?` sheet is *printed from it*. Plus the `shown_fields` gap S6 found.

**The ticket's Escape wording was wrong and the browser said so** — focus after a card click sits on the card, so the panel's handler never sees the key. Built as two handlers with one rule, struck wording recorded rather than quietly reinterpreted.

### WS-27ac · calendar week layout, per-day quick-add, exact overflow *(P-19)*
The week is **the month grid's own row** — `CalendarView.tsx` contains no `new Date(`, `getDay()`, `setDate(` or `86400` at all. Mutation-measured: rewriting `weekGrid` the way nearly everyone writes it (`-anchor.getDay() + 1`, which breaks on Sundays) turns exactly two tests red.

### WS-27ae · CSV export + delta-sync *(P-26/27/28)*, migration 168
**The ticket named a pattern that does not exist** — no export-job anywhere in the tree. So: a synchronous bounded CSV, where **the cap is a refusal, not a truncation** (a short month is drawn with a banner beside it; a downloaded spreadsheet has no banner and is byte-indistinguishable from a complete one).

Delta-sync answers the deletes question rather than dodging it: `removed[]` fed by an **AFTER DELETE trigger**, because `pm_projects` cascades and an app-level write would only record deletions that went through an endpoint. Losing *visibility* stays inexpressible — documented and pinned as silence.

**Two defects the live database caught that no fake could:** the first version of migration 168 made an `organization` row **undeletable**; and a tombstone from a project cascade named a project that no longer existed, so **the deletion stranding the most rows was the one the feed could not report.**

### 🔴 Security · `views.set_positions`
Reading Plane's **GHSA-4w5x-wc9w-f47x** (a join write scoped at one end) found the same shape in ours: it validated the *view*, then wrote every caller-supplied `task_id` **unchecked**. Ours was narrower — the PK is `(view_id, task_id)` and the view *is* validated — but it still wrote rows referencing tasks the caller cannot read, while every sibling endpoint resolves visibility per task.

**The fence needed rewriting before it was worth anything.** My first version used `projects_user()`, which holds `*` including `data:org:read` — it passed whether or not the fix existed. `member_user` is the principal the fake's own docstring says every scoping test needs. Mutation-measured after the rewrite.

**This shape has now been sighted three times** — Plane's advisory, ours, and Paca's `MoveTask` (which validates neither). It is a category, not an incident; the remaining `task_ids[]` endpoints are ticketed as WS-27as.

## Part 2 — the plan

### Both references read end to end, with the licences distinguished
~3,000 TS files in Plane, ~740 in Paca. **§9.0 pins both to a commit SHA** and states the two rules, because conflating them is the real risk: **Plane is AGPL-3.0** (read and reimplement, never copy) and **Paca is Apache-2.0** (reuse legally available with attribution; we still default to reimplementing, for design-system reasons rather than legal ones).

### Our own research was wrong in ~32 places
- **Plane (4):** §5 refused rich text and the collab server as *one* thing — they are separable, verified, and only the collab refusal survives. We credited them with a per-board "kill switch" that **no code reads**. The public-roster refusal was incomplete. `apps/web` is not Next.js.
- **Paca (28):** we wrote that their migrations *"independently converged"* with our idempotency discipline — **they have no ledger at all**, and one migration drops a column in the same file that backfills it. We credited them with the presentation-vs-query-constraints split — **their saved filter config is never read by the server.** We hold that property; they do not.

### The cross-reference — the one thing neither single-repo pass could produce
1. **Both ship Base UI.** Paca for 17 of 24 primitives; Plane's `propel` likewise. Two independent products chose the same substrate for exactly the set WS-27ak enumerates — **D-PM-15 is now evidenced rather than argued.** Riders: Base UI has no Combobox, so that item is a build either way; and Paca carries a *second* primitive library that arrived via a vendored registry — the failure this decision exists to prevent, caught happening.
2. **Paca is ahead on exactly one axis, and it is ours** — its agent surface has no Plane counterpart.
3. **On everything Plane covers, Paca is the weaker reference** (no multi-select, no bulk edit, no keyboard cursor in 61k lines, native HTML5 drag only). Importing from it there would be a regression. Where they disagree, we now know which to follow.

### The most important finding is an absence
**Neither reference has any approval or human-in-the-loop primitive for agents.** Paca's autonomy is its permission set exercised unilaterally; its "you MUST invoke a skill first" rule is a paragraph in a prompt with nothing enforcing it. For an AI-driven company OS that is the biggest gap in both, so **D-PM-19** records that neither is prior art and we design it — at the tool layer. The UI contract, usefully, is an MIT library.

### 66 verified reference links
§9.6 indexes them, pinned to both SHAs. Every one mechanically checked to exist with a real line range; **two failed that check and were corrected before inclusion.** Fenced by `tests/unit/test_reference_links.py`, which **found a real defect on its first run** (§9.0's own link-prefix strings matched the pattern) and was then mutation-measured. It **skips loudly** rather than passing quietly when the clone is absent, since that is the only check proving a path is real.

Six items are **NO UPSTREAM**, which is the useful answer: the kill switch, collaboration cursors, RTL, timeline dependency arrows (so **D-PM-12 stands unchallenged**), page-batched list badges (their implementation is the anti-pattern our rule prevents), and per-tenant OAuth callback routing.

### Decisions owed — I have not made these for you
**D-PM-15** primitive substrate (now evidenced) · **D-PM-16** org-wide vocabularies — *the expensive one*: dropping `NOT NULL` later is trivial, merging twelve projects' duplicate "Bug" tags is not, so **record it even if the answer is no** · **D-PM-17** the i18n discipline · **D-PM-18** RTL as logical properties · **D-PM-19** the agent autonomy gate · **D-PM-20** optimistic concurrency, which with agents writing beside humans is a data-loss question a revert affordance makes worse.
