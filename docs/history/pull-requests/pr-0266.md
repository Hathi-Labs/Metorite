## Description

## What & why

Two fixes to how the day planner and the calendar grid handle time, from mobile feedback.

### 1. Now-line alignment (mobile + desktop)

The hour-label gutter rendered each row with a per-row negative margin (`-mt-2`) that **compounded** down the column, compressing the label stack to ~38px/hour against the day grid's 46px/hour (`HOUR_PX`). By late evening the labels had drifted ~3 hours above their hour lines, so the (correctly-positioned) current-time line looked far below its label.

Each gutter row is now exactly `HOUR_PX` tall with the label centred on the hour line at the row top — labels, hour lines, and the now-line stay in lockstep at every hour of the day. Pure CSS/geometry; the now-line math was already correct.

### 2. Plan-through horizon — schedule 24/7

You can now tell the planner **how far into the day (or night) to schedule**, so it works around the clock — e.g. waking up late and wanting to work a couple of hours.

- **"Plan through" control** on the Rebuild / Fit panel: defaults to your standing working hours, but offers *"N more hours"* from now, which crosses midnight for a late-night burst. Opening the panel *outside* working hours defaults to a few hours out so the window is never empty.
- **Free-text override in the plan note**: phrases like *"work for 2 more hours"* or *"until 2am"* set the horizon straight from the prompt (extend **or** shrink the window), taking precedence over the control.
- **Default (unspecified) stays the office working hours** from Settings — nothing changes for the normal daytime case.

Server-side, the override lives in `_replan_core` (`_horizon_from_note`), so the browser planner, the chat agent (`gtd_plan_day`), and apply all honour it consistently. The persona and tool docstrings note the new note behaviour.
