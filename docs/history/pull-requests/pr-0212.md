## Description

Two UX/management improvements so the WhatsApp vertical works like the email app.

## W13 — Multiple numbers, like email
The queue was hardwired to the first account. Now the nav footer has an **account switcher**: it lists every connected number (avatar + name + count), switches the active one, and links to "Connect another number". The active number **scopes the streams, chat list, and conversation** (`account_id` threaded through `fetchStreams`/`fetchChats`/`Conversation`); switching resets the open chat + stream and reloads. The default number is selected on load. Frontend-only.

## W14 — Manage the integration from Settings → Integrations
WhatsApp now appears as a first-class card on `/integrations`, **mirroring the ClickUp multi-account precedent** (both are per-account encrypted tokens — `wa_accounts` / `task_accounts` — not process-wide env keys).
- **Backend** (`integrations.py`): a `whatsapp` entry in `_SETUP_GUIDES` (label, docs, no env_vars) + the `communication` category + `_is_configured → False` (its connected state is the number count).
- **Frontend** (`/integrations`): overrides `configured` from the real `/api/whatsapp/accounts` count (like ClickUp), a `whatsapp → whatsapp.com` logo domain, and a dedicated `WhatsAppConnector` side panel that **lists connected numbers, disconnects** them (`DELETE /whatsapp/accounts/{id}`, already existed), and links out to the in-app connect wizard.

So the integration is managed centrally from settings, while *initiating* a connection stays in the app (as requested).
