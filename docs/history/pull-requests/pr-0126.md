## Description

## Phase 3 · item 3.12

The search backend already filtered on `received_after`/`received_before` and sender category, but the bar exposed **no controls** for them; importance wasn't a search filter at all. This surfaces all three.

### Backend
`/search` gains an `importance` param (case-insensitive match on `em.importance`), composed alongside the existing additive filters.

### Frontend
Four new pill kinds in the search model:
- **after / before** — date range (a bare `before` date runs to the END of that day, so mail that arrived on it isn't excluded)
- **sendercat** — `email_senders.category`, distinct from a `tag` pill (which matches a label on the *message*)
- **importance** — high / normal / low

The filter menu grows **Date** (native date pickers), **Sender category** (chips from `EMAIL_CATEGORIES`), and **Importance** (High/Normal/Low) sections. `after:` / `before:` / `importance:` are also typeable in the bar, consistent with the existing `from:`/`tag:` grammar.

### Tests
`tests/unit/test_email_search_scope.py` — importance predicate is case-insensitive and absent when unset (23 passed). Blocking ruff + full `tsc` clean.
