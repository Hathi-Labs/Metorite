## Description

## Inbox layout — full width, one compact header

The centered `max-w-4xl` inbox stacked a capture hero, a controls block, and a filter-pill row (~6 rows, list started ~520px down). Now full width like Next Actions, two compact rows (list starts ~150px down):

- **Row 1 (desktop):** Inbox title · capture box (flex-1: "What's on your mind? Capture now, clarify later.") · attach/link icons · Mind sweep · Shortcuts. Mobile keeps its bottom-nav capture (unchanged).
- **Row 2:** `N to process` + source/aging chips · date pills inline · search · sort · density · Tickler · **Clarify next**. On mobile the search/action cluster wraps to its own full-width line.
- **Task list spans the full width**, so long captures display whole instead of truncating in a narrow column.

## AI prompts — every decision grounded in real system state

Audited every LLM prompt in the task manager (clarify, enrich/fill-details, context backfill, title improve, atomize/dedup, parent-step match, email capture, commitment detection). Three systemic gaps fixed:

1. **Hard-coded @context vocabulary** — clarify, enrich, email capture, and commitment detection listed four of the six default contexts in their JSON schemas; a user-configured context (or even `@office`/`@home`) could **never** be suggested. All now inject the user's real `gtd_contexts`, and model output is canonicalized against that list — never invented.
2. **No current date** in clarify/enrich — "by Friday" or "next week" couldn't resolve to a real due date. Both now receive TODAY (weekday + ISO); email capture already had it.
3. **Clarify never proposed a time estimate** even though the proposal UI displays one (heuristic-only before). The clarify schema now includes `time_estimate_mins` (bounded 1–6000, shared parser with enrich), flowing through `propose_with_llm` into the card.

Prompts already well-grounded and left alone: atomize (deliberately preserves the user's wording), title improve, parent-step match (scoped semantic judgment), and the people/projects/stages/memory context in clarify.

Bonus: `ai.py` is now fully ruff-clean — extracting `_parse_minutes` + a validated optional-field update dropped `_llm_propose` below the C901 complexity limit it already exceeded on main.
