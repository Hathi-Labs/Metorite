## Description

## What this is

Follow-up to #236 (merged). Three things, in commit order:

1. Wires Custom Apps into the existing live-activity/office observability system instead of building a separate "app usage" view.
2. Fixes a real, pre-existing bug: the App Workshop frontend expected a `{app: ...}`/`{apps: [...]}` response envelope that the gateway's `/apps/*` CRUD endpoints never actually send.
3. Makes Custom Apps reuse CommandCenter's existing design system/block-kit instead of hand-duplicating it.

## 1. Live token-consumption tracking (office view)

Research before writing any code found the app-attribution signal already existed but was split across two disconnected, incomplete paths:
- `publish_app_activity` (`kind="app"`) already carried the real per-app slug identity onto the activity bus, but that `kind` was invisible to both the presence-key gate (hardcoded `kind=="agent"`) and the cost rollup (hardcoded `kind=="model"`) — so it never showed up as "working now" or in per-app cost.
- The automatic `kind="model"` event that DOES carry cost collapses every Custom App into one generic `source="apps"` bucket, because the stack-inference helper (`_infer_app_source`) can only ever resolve the calling Python module's path — every app's AI call runs through the same `gateway.routes.apps.runtime` module regardless of slug.

**Backend:** `acb_common.activity`'s presence gate widened to `kind in ("agent", "app")`; `acb_llm.context.acompletion_with_fallback` gained an optional `source` override; `ai_complete` emits a start/end presence pair around the real provider call and passes `source=f"app:{slug}"` explicitly (no double-counting — the presence event carries no cost); `/observability/roster` surfaces a live app as its own `kind="app"` entry (real name/icon from the `apps` table), visible only while actually consuming tokens.

**Frontend:** `office-topdown.tsx` gained `AppSeat` — a glowing terminal kiosk showing the app's icon, instead of falling into the character-sprite pipeline. `page.tsx`'s Feed tab no longer mislabels app events as an anonymous "Model" call.

## 2. Fix: App Workshop frontend never read the real response shape

Every `gateway/routes/apps/{lifecycle,files,publish}.py` endpoint returns a bare FastAPI `response_model` — a plain array or plain object, no envelope. The `build/apps` frontend across all three pages (gallery, run page, editor — 9 call sites) assumed a `{app: ...}`/`{apps: [...]}`/`{files: [...]}`/`{versions: [...]}` wrapper that was never actually there. Concretely: `list_apps` always rendered an empty gallery, `create_app`'s response never yielded a slug to redirect to (surfacing as "Create failed" even on a genuine 200), and every app-meta refetch (initial load, consent scope-change, rollback, `refreshAppMeta`) silently no-op'd. Fixed all 9 sites; left untouched the sites that were already correct (grants, checkpoints, publish, usage, and `ccBridge.ts`, which read the real shapes already).

## 3. Reuse the platform design system instead of rebuilding it per app

Custom Apps render through `SandboxedHtml.tsx` — the SAME component that backs every CommandCenter report and generative-UI card — so its `buildSrcDoc` already injects the identical `--cc-*` tokens and `.cc-*` block-kit classes (`cc-card`, `cc-btn`, `cc-stats`, `cc-bars`, `cc-donuts`, `cc-table`, `cc-callout`/`cc-note`, `cc-chart`, …) into every app's sandbox, unconditionally, today. Verified this actually applies through the double-nested `<html>` structure (`buildAppSrcDoc` wraps the app's own full document inside `SandboxedHtml`'s outer one) by rendering the real starter template through the real pipeline in a headless browser and reading back computed styles. Neither the starter scaffold (`starter_index_html`) nor the builder's instructions knew this existed — both hand-duplicated a separate copy of the palette from scratch, and the builder had no idea the block-kit classes existed at all (regenerating buttons/cards/stat-tiles from scratch every round). Both now point at `design.md` (via `load_design_system`, already in this agent's `tool_scope`) as the single source of truth, and the builder's instructions map the specific reusable blocks to the data shapes an internal app actually needs.
