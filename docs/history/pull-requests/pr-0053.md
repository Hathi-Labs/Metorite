## Description

> Organize the pills into columns in the list view when opening the Context — like Jira/ClickUp. On mobile keep it stacked (pills below the task). In settings, choose which columns to show/hide.

## What shipped

**Desktop columnar list.** Opening the **Context** (Next Actions) list now renders aligned columns instead of pills wrapping under each title — matching the ClickUp/Jira layout you referenced:

| Name | Priority | Context | Energy | Estimate | Due date | Assignee |
|------|----------|---------|--------|----------|----------|----------|

- Columns are the **same signals that were already card pills** — just aligned into their own tracks. A sticky header labels them; every row shares one grid template so cells line up down the page.
- **No Status column** — the list is already grouped by status (the section headers), so a Status column would just repeat the group. (Matches your note.)
- Files / Subtasks columns exist too but are **off by default** (noisier counts).
- Drag-reorder, multi-select, and subtask-expand all keep working in the columnar rows.

**Mobile unchanged.** Below the `sm:` breakpoint each task stays **stacked** (title + pills beneath) — there isn't width for columns.

**Column settings.** New **"Next Actions columns"** section in the Task settings modal — a show/hide toggle per column. Hiding one (e.g. Energy) updates the list live. It's a per-browser display preference (localStorage, same pattern as the list/board toggle) — no backend/migration, purely "hide the columns I don't want to see."

The project view (its own ClickUp statuses) keeps the stacked row.

## Files

- `lib/columns.ts` — column defs + localStorage visibility store
- `ListColumns.tsx` — per-column cell renderers (reuse the exact pill visuals) + header
- `TaskListGrouped.tsx` — desktop grid rows / mobile stacked, header row
- `TaskSettingsModal.tsx` — the toggles section
