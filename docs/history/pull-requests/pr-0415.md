## Description

feat(D30): CLAUDE.md — the always-loaded briefing, so a cloud instance never starts blind

Claude Code auto-loads CLAUDE.md into EVERY session, including cloud and headless
ones. This repo had none, and the 16 KB root AGENTS.md is not guaranteed to be in
context at session start — measured this session: it was not. So an instance that
was not this laptop began with no knowledge of the architecture, the board, the
owner gates or the method, and would discover them only by accident.

CLAUDE.md is a ROUTER plus the minimum that must be known before the first tool
call. It duplicates nothing; every claim points at its owner:

  §1 Where truth lives, in reading order — INDEX (what is ACTIVE) → work_plan §1
     (rules R1-R8) → §2 (the board, the only current-state authority) → §6 (owner
     gates to refuse by name) → §3 (decisions D1-D30) → engineering_practice
     (how we build) → the owning spec.
  §2 The architecture in one screen — Centers are projections; cross-cutting apps
     have two access paths and ONE permission model; modules are billing atoms
     while Center packages are what customers buy; tenancy is a ROW and we are
     multi-tenant from customer #1; visibility is private → Center → org.
  §3 The non-negotiables — never commit on main, refuse owner-gated work by name,
     R5 tenant-ready, R6 expand/contract, R7 name the fence, R8 real database for
     SQL, R1 migration numbers at build time, verify delivery by evidence.
  §4 How development proceeds — feature by feature, app by app, one narrowed
     slice: audit → implement → verify → review → PR → stop before merge; the
     verifier is never the implementer; the reviewer hunts for the failing case;
     re-verify anchors; EXTEND seams, never fork them; short branches.
  §5 What not to do — re-litigate decisions, refactor the tree to conform, invent
     a second way to do an existing thing, mark done from the write-up.
  §6 Environment traps that waste the most time.

One correction made while writing it, because an always-loaded file must not
carry a false claim: the board's "never run tests/unit as a directory" warnings
are narrower than they sound. Measured today, a directory run with a -k filter
that deselects the memory and calendar suites completes fine — what hangs is
running those tests, not collection. Stated that way rather than as an absolute I
had just contradicted a dozen times.

Standing rule recorded with D30: CLAUDE.md stays a router. Anything that grows
into content belongs in an owning spec with a pointer here — a briefing nobody
finishes reading is a briefing nobody follows.
