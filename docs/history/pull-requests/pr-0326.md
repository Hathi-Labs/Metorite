## Two traps worth recording

**The activation trap is inverted from what I expected.** The correction slice is **not** owner-gated: `routes/memory.py` deliberately duplicates the scope constants so authorization still works when Mem0 isn't installed (*"a router that fails open because an optional dependency is missing is not a gate"*), and the gate logic tests green against a fake — 41 passed in 0.58s. **The real hazard:** this box's `.env` already has Mem0 enabled, and **`tests/unit/test_memory_integration.py` hangs** (measured, exit 124 at 100s). Assume `test_memory_e2e.py` does too. Verification must name test files — never `tests/unit/` as a directory.

**D4 would make a correction UX lie.** `orchestrator/agents.py:520-534` builds its memory block from the user scope only — no `agent:`, no `org:global`. So a user could correct an org-scope fact, watch the inspector show it fixed, and get no behaviour change on that path. That gap is **WS-15's** (D4), but it constrains WS-9's first PR: restrict to `<email>`/`prefs:`/`agent:`, or say plainly that `org:global` isn't read everywhere yet. An implementer must not pick silently.
