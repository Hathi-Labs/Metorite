## Description

Manual drafting in the composer was slow, opaque, and one-shot. This makes it fast, legible, and iterative.

## 1 — Why it was slow

The interactive path ran on the account's `draft_model`, which is `tier-powerful` → **`deepseek/deepseek-reasoner`**: a reasoning model, called non-streaming with `max_tokens=3000`. That alone is 20–60s of blank spinner. Around it, the orchestrator stacked avoidable serial hops:

- two Mem0 `remember()` lookups, run one after the other;
- an always-on consult-plan LLM call;
- optionally a full specialist agent run (18s timeout) before drafting even started;
- **`await add_memories_background(...)`** — despite that function's own docstring saying fire-and-forget. Mem0's `add` runs an LLM extraction pass, so the user waited several extra seconds *after* the draft was already written.

**Fixes:** a new per-account **`compose_model`** (migration 113, default `tier-fast`) drives `/compose-assist` and `/draft-reply`; background rule/follow-up drafting keeps `draft_model`, where nobody is waiting. Memory recall and the qualifier now run concurrently, and the Mem0 write is properly fire-and-forget.

## 2 — Consults are necessity-gated

The planner now classifies the email (scheduling / courtesy / newsletter / sales / project / support) and calls a specialist **only when the reply must state facts the thread doesn't contain and that agent's system holds them** — with "when unsure, consult nobody" as the explicit default. Ordinary mail skips the agent hop entirely. Decisions are logged (`email.draft_consult_plan`) so gating can be audited against real traffic.

## 3 — You can see what it's doing

New `POST /email/compose-assist/stream` (SSE) — a thin event wrapper over the **same** `_compose_assist_run` pipeline as the JSON endpoint, never a second drafting path — plus a dedicated Next proxy route, since the generic `/api/email/[...path]` proxy buffers POST bodies.

The composer renders a real activity panel instead of a spinner: ordered steps with live state, the qualifier's verdict, **which specialist was asked and the exact question put to it**, its answer, and the model's reasoning in its own scroll region. It collapses to a one-line summary (`Drafted in 5.4s · asked task manager`) once settled.

## 4 — Drafting is a conversation, not a button

Previously the bar closed as soon as a draft landed, forcing one-shot prompting. Now the panel **stays open**: the next instruction refines the current draft ("shorter", "mention the deadline"), the input clears and refocuses, and the button becomes *Refine*. Every round is kept as a revision (`Yours`, `v1`, `v2`…) that can be restored non-destructively, with an undo for the previous version. A failed or declined round rolls the body back rather than leaving half-streamed tokens behind.

All three composer surfaces (compose window, inline reply, conversation draft card) share one `useDraftSession` hook, so they behave identically.

## Settings

A new **"Manual draft model"** card in email AI Settings → Advanced, described as the one you wait on (fast tier recommended). The existing "Draft writing model" is relabelled as the background one.
