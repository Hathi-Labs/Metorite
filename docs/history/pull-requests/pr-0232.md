## Description

## The gap
Unfinished tasks left on a **previous** day were stranded: they weren't in today's movable set (wrong day) and weren't in the unscheduled list (still scheduled), so **Rebuild my day silently ignored them** unless you rolled over first.

## The fix
**Rebuild my day** (`gtd_plan_day`) now also loads prior-day overdue-incomplete **flexible** tasks and treats them exactly like today's movable blocks:
- re-ranked into the time you actually have left, **or**
- if they no longer fit → **evicted back to your unscheduled list**.

So leftovers are always folded into a fresh plan, and overflow lands on your list **non-destructively** — no silent auto-unschedule of a block you deliberately placed. Fixed meetings are never swept.

**Fit what's left** stays strictly today-only, keeping the two buttons cleanly different. Auto-rollover (on by default) still covers hands-off mornings; this makes the manual path correct regardless of its state.

## Why this over "auto-move overdue → unscheduled"
Silently wiping a scheduled block's time to make it reappear in the list loses intent and fights auto-rollover. Folding leftovers into Rebuild (and only evicting genuine overflow) gives the same "they show up so I can re-plan" outcome without the data loss.

## Changes
- **Backend:** `_OVERDUE_CARRY_WHERE` + carry-forward load in `_replan_core` (Rebuild only); `PlanBlock.carried_over`; a "Carried N forward" plan note; the chat renderer tags carried blocks; `gtd_plan_day` docstring updated.
- **Frontend:** the Rebuild proposal panel shows a distinct **"Carried over from earlier"** group so you *see* leftovers fold in, with the headline counting them; `api.ts` maps `carried_over`.
