## Description

Closes the gap between the Tasks app and the task-manager agent: you can now perform essentially every app action through chat, with tool results rendered as interactive AG-UI cards — the same pattern as the email assistant's `EmailToolCards`.

## Agent tool surface (skill-task-gtd)

The agent previously covered capture/clarify/organize/planning but could NOT complete a task, change a stage, edit priority flags, delegate an existing task, or manage subtasks. Now it can:

| New tool | What it does |
|---|---|
| `gtd_complete` | Mark done / reopen (`undo=true`) — back-syncs for synced tasks |
| `gtd_move` | Bucket moves: next / someday / waiting / reference / inbox / trash |
| `gtd_set_stage` | Stage change, validated against the task's own project statuses (synced) or the local board stages — invalid names return the valid options |
| `gtd_delegate` | Reassign a synced task; promote a LOCAL task into a workspace (created upstream + tracked as waiting-for) |
| `gtd_subtasks` / `gtd_add_subtasks` | List / add checklist steps |
| `gtd_archive` | Archive / restore (mirrors upstream) |
| `gtd_detail` | Full field readout + live provider comments/attachments + its project's stages |

`gtd_update` also gained context, energy, time estimate, due date, and the `important` / `leveraged` / `deep_work` flags (tri-state, only passed fields change).

The C-04 boundary note is amended rather than dropped: managing an **already-synced** task rides the same gateway PATCH the app UI uses (server-side back-sync); there is still no bulk push-to-provider tool, and the instructions keep the confirm-before-mutate persona rule.

## AG-UI cards (frontend)

New `TaskToolCards`, mounted in `MessageBubble` beside `EmailToolCards` (inert unless the message carries `gtd_*` tool calls, so it works in the main chat app AND the Tasks Assistant rail):

- **Task list card** (`gtd_list` / `gtd_list_schedule`) — clickable rows that open the task in the Tasks app, with an inline check-off button
- **Day-plan card** (`gtd_plan_day` / `gtd_replan_day` / `gtd_rollover`) — proposals get a one-click **Apply** that commits via the agent-facing planner endpoint (new `apiAgentPlanToday`)
- **Info cards** — insights, digest, people, workspaces, projects, subtasks, task detail, clarify proposal
- **Action confirmations** — every mutating tool, context-aware labels (completed/reopened, archived/restored), with an "Open in Tasks" jump parsed from the result
