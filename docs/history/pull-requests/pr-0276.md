## Summary
- Unblocks building anything the vendored `react`/`react-dom`/`@cc/ui` set can't cover on its own — concretely, a 3D viewer needing `three.js`/`@react-three/fiber`, which previously hard-failed at the build step's import allowlist.
- New `apps/agents/agent-app-builder/build/install_t2_deps.mjs` (platform-owned, not editable by the builder agent) — the only sanctioned way a T2 app adds a package:
  - `npm install --ignore-scripts` — blocks the standard npm supply-chain RCE vector (a malicious package's postinstall script running arbitrary code before any of it ships anywhere), same rationale as `acb_skills/loader.py`'s wheel-only installs for the gateway's own Python deps.
  - Package-spec allowlist regex — plain name, optionally `@version` or `@scope/name@version`, no flags, no URLs (so a spec can't smuggle in something like `--registry=...`).
  - 300MiB `node_modules` size cap, removing `node_modules` and failing loudly if exceeded.
  - Scaffolds `package.json` if the app doesn't have one yet.
- `build_t2.mjs` now auto-detects an app-local `node_modules` and switches from the shared vendor cache + import allowlist to standard npm resolution rooted at the workspace — no allowlist in that mode, since the app can only import what it explicitly installed. Most T2 apps never opt in and keep paying zero extra build/disk cost.
- Isolation between apps stays structural: each app's `node_modules` lives inside that app's own workspace directory, already the durability/build/publish unit for exactly one app. Runtime isolation is unchanged too — installed packages only ever ship as bundled client-side JS in `dist/bundle.html`, same CSP/srcDoc containment as the vendored-only default; nothing an app installs ever runs on the gateway/orchestrator. `node_modules` was already excluded from the durability mirror and file-tree UI.
- Found and fixed a latent gap while tracing the sandboxed code path: `Dockerfile.copilot-sandbox` installs `nodejs` with `--no-install-recommends`, which on Debian drops `npm` (a Recommends, not a Depends, of `nodejs`) — so the install script would have failed inside the sandbox container whenever `app_builder` is in `copilot_sandbox_scope`. Added `npm` explicitly.
- `docs/app-workshop/README.md` updated (T2 tier row + RFC §7 point 6) to describe the opt-in per-app install path and why it doesn't change the platform's runtime-isolation properties.
