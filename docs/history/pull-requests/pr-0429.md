## 🔴 One acceptance criterion is NOT met — this is a board call

**"The background is `inert`, not merely covered."** `@base-ui/react@1.7.0` cannot deliver it. `FloatingFocusManager:339` passes `ariaHidden`; `markOthers` defaults `inert: false`; nothing in the package ever passes `inert: true`. The only real `inert` sits on the portal's own `InternalBackdrop` while **closed**. Measured in Chromium: `[inert] = 0`.

So: **screen readers cannot reach the background, Tab cannot leave the dialog — but Ctrl+F still finds the page behind the scrim.**

Closing it means an upstream change or the wrapper re-implementing `markOthers`, which is the parallel-seam move CLAUDE.md §5 forbids. The implementer stopped and wrote it down rather than reporting the criterion met.

## Two items in the dispatch brief were wrong, and only building found them

- **`outsidePressEvent="intentional"` is not a prop** in 1.7.0. It's computed, and resolves to `intentional` whenever a backdrop exists — so the fence pins the backdrop rather than a prop that doesn't exist.
- **`markOthers` does not set `inert`**, as above.

Both came from the audit; both were verified against the installed package.

## Review findings — one P1, fixed

**P1: the documented `finalFocus` fallback did not exist.** Base UI drops a disconnected opener and then focuses nothing, leaving `<body>` — the one outcome the docstring forbade. Reachable through a dialog in this very slice: **ImportClickUp's only trigger is the empty-state button**, and a successful import refetches the tree, replacing that trigger *while the dialog is still open*. Repair round 1 implements the fallback in the wrapper (explicit ref → captured opener if still connected → `<main>` landmark with a borrowed `tabIndex`) and states plainly what happens when none exists, instead of promising a guarantee.

**P2: `max-h-full` was baked into the popup's base classes**, so every call site's height was a dead knob — the importer rendered ~10% taller than designed.

## The record lied about the code in four places, including the auto-loaded contract

`Modal.tsx`'s own header and `DESIGN_SYSTEM.md` §4a both asserted the `inert` property this slice disproved. `DESIGN_SYSTEM.md` additionally named **conformance rule 8 as the fence against a hand-rolled scrim, which it does not catch** — rule 8 only forbids importing the substrate, and a `fixed inset-0` div imports nothing. That's an R7 violation: a rule naming a test that doesn't make breaking it fail. All four corrected, a real fence added, and the un-fenceable half labelled advisory.

**And one mutation record didn't reproduce.** The implementer claimed removing `Dialog.Backdrop` turned the outside-press test red; the verifier removed it, rebuilt, and got 8 passed — `DialogPortal` renders an internal backdrop whenever `modal === true`. The assertion *is* a genuine discriminator (red under backdrop-removed **plus** `modal="trap-focus"`), so it was a false ledger entry rather than a dead fence. The record now carries the reproducible measurement.
