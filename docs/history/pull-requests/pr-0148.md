## Description

## What broke

`POST /email/digest/send` returned 500 (`InFailedSQLTransactionError`) while the digest preview (GET) looked fine.

## Root cause (reproduced on prod via `PREPARE`)

`_digest_commitments` bound `:aid` twice — once against `email_accounts.id` (**uuid**) and once against `gi.origin->>''account_id''` (**text**). Postgres deduces ONE type per prepared-statement parameter, picked uuid, and every call failed with `operator does not exist: text = uuid`. The `except Exception: return []` swallowed it — but left the transaction **aborted**, so:

- **GET /digest** → 200 (commitments is the last query in the request; nothing after it to fail)
- **POST /digest/send** → 500 (the next query, `provider_session`''s account lookup, hits the poisoned transaction)

The unit test passed because the DB is mocked — asyncpg type deduction never runs.

## Fix

- json side compares to `ea.id::text`; `:aid` now binds once, in the uuid context (fixed SQL PREPARE+EXECUTEs cleanly against prod — and there''s a real commitment due that now surfaces)
- the best-effort catch now **rolls back and logs** instead of silently poisoning the rest of the request

Tests: rollback-on-failure pin + SQL-shape pin updated; 825 email unit tests green.
