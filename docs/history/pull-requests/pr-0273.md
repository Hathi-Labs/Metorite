## Description

Three things, following the shape the task manager and email apps already use.

## 1. Per-meeting-type copilot guidance

What deserves an interruption differs completely by meeting type. In a customer call a dropped objection matters; in a **1:1 an unspoken concern** does — and a sales nudge there would be *actively wrong*. All six templates now ship guidance suited to them, plus an agenda hint that seeds the drafter so "draft an agenda" produces something shaped like that meeting type.

| Type | Copilot lens |
|---|---|
| 1:1 | Trust conversation, not a status report — concerns raised obliquely, growth topics skipped again |
| Customer call | Commercial — unanswered objections, buying signals, loose commitments |
| Interview | Competencies not yet probed; never anything about a protected characteristic |
| Retro | Problems with no owner, blame aimed at people rather than systems |
| Standup | Blockers nobody offered help on; interrupt rarely |

**The layering is the interesting part.** Standing instructions ("who I am, how I work") and type guidance ("what matters in *this* kind of meeting") answer different questions, so they **compose** rather than replace. A user override displaces only the shipped default *for that one type* — every other type keeps tracking the defaults, so improving them still reaches anyone who hasn't customised.

## 2. A settings system

One row per user, one endpoint, read and written whole (`GET/PUT /notes/settings`): copilot behaviour, per-type overrides, defaults for new meetings, and the name the bot joins under (consent-relevant — people should be able to tell who is recording them).

**Sensitivity is three named levels rather than raw knobs.** The underlying controls are a minimum gap and a per-meeting cap; exposing those as numbers invites nonsense pairs. `gate()` now takes both as parameters so the levels map onto sane combinations — with a test that higher sensitivity really does mean *both* a shorter wait *and* a higher ceiling, or the label lies about what it does.

## 3. UI

`NotesSettingsModal` replaces the one-off copilot-instructions modal, showing each meeting type's shipped guidance **inline** so you can see what it *would* do before deciding to override it.
