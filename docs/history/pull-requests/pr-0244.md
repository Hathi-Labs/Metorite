## Description

Phase 1 of the meeting-bot feature (spec §3.13 / D10): paste a Meet/Teams/Zoom link and a bot joins the call, records, and feeds the **existing** pipeline (transcribe → diarize → auto-name speakers → summary → actions). Because each bot is an independent server-side job, one user can fan several notetakers out to concurrent meetings.

## Backend
- **Migration 117** — `meeting_bot` table (job state + lifecycle), auto-applied by `scripts/apply_migrations.sh` on deploy.
- **`meeting_bot.py`** — pluggable bot-provider layer with a Recall.ai client; URL→platform detection; Recall status→lifecycle mapping; a poller that runs in-process **and** poll-on-read (survives gateway restarts) and, on completion, downloads the bot's audio and ingests it as a normal `meeting_recording`.
- **Endpoints:** `POST /notes/meetings/bot-join`, `GET /notes/bots/active`, `GET /notes/meetings/{id}/bot`, `POST /notes/meetings/{id}/bot/stop`, `GET /notes/bots/status`.
- **Fully gated on config:** inert (503 with a clear message) until `RECALL_API_KEY` is set. Ingestion is claimed atomically so a bot is ingested exactly once.

## Frontend
- **"Join call"** action on `/notes` (desktop button + mobile nav tab) → paste-links modal (one URL per line to fan out), with the not-configured and consent states shown honestly.
- **"Notetakers in meetings"** surface: live per-bot status (`joining → waiting to be admitted → recording → processing`) with a stop control; polls the active list.

## Configuration (to activate — inert without it)
Set on the VPS `.env`: `RECALL_API_KEY` (required), optional `RECALL_REGION` (default `us-east-1`) and `NOTES_BOT_NAME`.
