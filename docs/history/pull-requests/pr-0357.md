## Description

## Why

App work starts next. The knowledge an app needs — how a caller becomes a principal, what an app may assume about them, what it must never do — was spread across four specs, a board row, and eight incident write-ups. **None of it was reachable from the files an agent actually reads before touching code.**

## `specs/user_management_contract.md` (new)

**It owns RULES, not FACTS.** Every fact is cited to the spec that owns it (`org_access_control.md` for the model, `colleague_onboarding.md` for the gate and matrix, `tenancy_and_visibility.md` for D11/D12), so it cannot become a fifth competing description of the access model — which is exactly what the 2026-07-31 audit found wrong with this corpus.

**Anchors are symbols, not line numbers**, deliberately. That audit found ~12 wrong migration citations and a WS-24 pass corrected six stale `rooms.py` anchors. A symbol survives an edit above it; a line number does not.

Contents: the four-hop identity chain and what each hop guarantees · the member lifecycle with every door between its states · the permission vocabulary and the one rule about extending it · **ten build rules, each learned by breaking it** · a trap list naming the incident that found each · and §6, what is *not* closed.

## Where builders will actually hit it

- **Root `AGENTS.md` constraint 10** — it said *"All gateway endpoints require auth (Bearer token + optional user identity)"*, which is no longer the whole truth: auth is default-deny **by construction**, and the interesting part is `PUBLIC_ROUTES` and where identity comes from.
- **`apps/services/gateway/AGENTS.md`** — six route-level rules: the app is default-deny so don't opt out to make something reachable; the `/admin` floor is per-route; owner-scoped reads answer 404 not 403; never take identity from a query parameter; what a destructive route owes; verify don't predict.
- **`workbench/AGENTS.md`** — the BFF is where identity comes from. Never point the browser at the gateway, and a `fetch` through the `[...path]` catch-all **cannot** replace a BFF route for a redirecting endpoint, because the catch-all follows the redirect server-side.
