## Description

## Why
Agents are imported into the gateway interpreter and run **in-process**, so every package an agent (or its skills) imports must exist in the **same venv the gateway runs from**. Nothing installed them — the loader only did `git clone`/`pull`, and `uv sync` in deploy only touches the root workspace, not `~/.acb/agents/repos/`. So cloned agents like `agent-sales-assistant` (which needs `apify_client`/`apollo`/`instantly`) silently lost tools to `ImportError` (caught by their `try/except`). This affects **both** MAF and Copilot SDK agents — for a Copilot agent, the Python tools still execute in the gateway venv.

## What
`_install_agent_deps()` runs after every clone/pull (inside `_ensure_repo`, under the per-repo lock — so it covers agent repos **and** skill repos) and after the local-path sync:
- Installs `requirements.txt` (verbatim) and `pyproject [project].dependencies`.
- Skips platform packages (`acb-*`, `agent-framework-*`, `copilot`) — already in the venv.
- Installs into `sys.executable`'s venv via `uv pip install --python <venv>` (uv resolved via PATH or `~/.local/bin`), pip fallback.
- **Best-effort + idempotent**: a SHA-256 of the dep sources is cached in `.git/acb-deps-hash`; unchanged sets are skipped; failures log a warning and never block an agent run.

## Permissions (verified on prod)
- `uv` is on the gateway's service PATH (`/home/acb/.local/bin/uv`).
- `/opt/acb/app/.venv` is owned by and writable by the gateway user (`acb`).
So installs have the permissions they need, with no infra change. The gateway-startup warm-clone reuses this path, so deps are restored after every reboot/deploy.

## Design note
This is the **shared-venv** approach (one venv, deps installed into it), which is the correct match for the current in-process execution model — a per-agent venv would require running each agent as a subprocess, a much larger re-architecture. Trade-off: all agents share one dependency resolution (incompatible version pins between agents would conflict); fine for a curated first-party fleet.
