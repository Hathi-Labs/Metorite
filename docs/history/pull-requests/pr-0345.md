## Description

Every round of debugging this feature has started from "it doesn't work" and spent a day narrowing down *where*. A failing call left almost no trace: the phase is one word, errors were gone by the time anyone looked, and the interesting part is always **where in the sequence it stopped**.

## Server timeline

The bridge now records, per call:

- dialling — **what was actually sent vs what was typed**
- every phase transition with elapsed time
- relay bound / media active
- browser audio attached and detached, with frame counts each way
- **first microphone frame up**, **first peer frame down** — the two events that separate "socket open" from "audio flowing"
- websocket close **status codes** when either leg dies

Served from `GET /calls/events`, proxied at `GET /whatsapp/calls/{id}/events`. Capped ring buffer, tail-preserving — the end of a failing call is the informative part.

## Browser timeline

Microphone acquisition (with the `DOMException` name on failure), AudioContext sample rate and state, worklet load, socket open, first frame each way, and on close: **`code`, `reason`, `wasClean`, frames sent, frames received**. Those numbers identify a WebSocket failure and were previously thrown away — `onerror` gives nothing, `onclose` gives everything.

## One button

A clipboard icon on any call assembles both timelines plus readiness into plain text, copies it, **and renders it** — the clipboard is blocked often enough that a report you can't get out of the browser is no report at all.

Deliberately excluded: peer phone numbers and the audio token. Neither helps diagnose a protocol bug; both are worth not pasting into a chat.

## Example

```
=== WhatsApp call debug report ===
call: 8F2C...  (outgoing direct)
phase: active  media_ready: true  audio: 12.4s
client audio state: live

--- server timeline ---
20:14:02.118  [signal] dialled "919876543210" (typed "+91 98765 43210"); offer on the wire in 412ms
20:14:03.402  [phase] calling → ringing (+1.28s)
20:14:09.771  [media] relay bound, media active (+7.65s)
20:14:09.902  [audio] browser attached (mic + speakers)
20:14:10.113  [audio] first microphone frame received from the browser
20:14:10.240  [audio] first peer frame sent to the browser

--- browser timeline ---
...  socket CLOSED code=1006 reason=(none) clean=false sent=214 received=0
```

That last line is the kind of thing that used to take a day.
