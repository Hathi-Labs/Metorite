## Description

## 1. Investigation: the missing "Done" stage

**Root cause.** ClickUp statuses were only ever collected from the **space workflow** (`get_schema` read `space.statuses`). But ClickUp lists routinely define their own statuses — commonly a "Done" (a `done`-type status) that's distinct from the space-level "Closed". A list-only status therefore never reached:
- the **status-mapping settings** (fed by the schema cache), nor
- a **synced task's Stage picker** (`account.statuses`, also the schema cache),

so the only closing status the user could pick was the space-level "Closed". (Completion itself already worked — `map_pulled_task` treats `status_type in ("closed","done")` as done — it was purely that the *name* "Done" was invisible.)

**Fix — three layers, no extra ClickUp API calls:**
- `get_schema` now aggregates each **list's own `statuses`** (already present on the `/space/{id}/list` and folder payloads) alongside the space workflow.
- Each sync folds the status **names actually seen on pulled tasks** into the cached schema — ground truth for whatever statuses a list really uses.
- The `/status-catalog` endpoint unions **distinct `provider_status` from mirrored tasks**, so a status is mappable immediately, before any schema refresh.

## 2. Multiple assignees

ClickUp allows several assignees but we stored only the first (`assignees[0]`). Now the full set is stored and editable:
- **Migration 91** adds `gtd_items.assignees` (JSONB), backfilled from the single `assignee`. The existing `assignee` column stays as the primary/display owner (`= assignees[0]`), so every single-owner reader (card avatar, Waiting-For "who", delegate flow) is unchanged.
- **Sync** stores every assignee; the item read (`SELECT i.*`) returns the full set.
- **PATCH** accepts `assignees` (the whole set); the ClickUp back-sync diffs new vs previous into an `{add, rem}` assignee delta.
- **UI**: the detail card's Assignee editor is a multi-select toggle list for synced tasks (local tasks keep the single-owner delegate flow, since assigning a teammate must first create the ClickUp task); cards show a "+N" on the avatar when a task is shared.
