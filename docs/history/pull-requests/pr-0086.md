## Description

Follow-up to #85. Porting `splitQuotedText` to Python surfaced a latent bug in the TypeScript original — #85 fixed it only on the Python side, so the two splitters disagreed.

## The bug

`splitQuotedText` scanned from line **1**, which skips the "is the whole body a quote?" check. A bare forward — a body that is nothing but quoted mail — was therefore cut at its **second** line, making the first quoted line look like new content:

```
> just the quote      <- became "main" (new content)
> and more            <- became "quoted"
```

Three call sites were affected:

- **ComposePanel** and **ConversationView** hand `main` to the AI drafter as the user's own text — so the model was told a stray `> …` line was the draft to improve.
- **MessageContent** leaves `main` uncollapsed in the viewer — so one orphaned quote line showed above the `•••` toggle.

The `idx < 1` guard already handles this correctly once the scan starts at 0: a boundary found at line 0 returns the body whole.

## Parity guards

`quoting.py` and `quoting.ts` must agree on where a quote starts — the client splits the compose box, the server splits at send time, and a disagreement puts the signature relative to a boundary the user never saw. This divergence is exactly that failure mode, caught only because the Python port had a test.

There is no JS test runner in CI (`pr-check.yml` is Python lint + tests only), so the two new guards read the TypeScript source directly: one asserts the scan start, one asserts both sides carry the same six boundary markers.
