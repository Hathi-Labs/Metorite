## The problem this ticket targets

`idx_pm_tasks_fts` (migration 146, `to_tsvector` GIN index) cannot be used by the existing `ILIKE '%term%'` search query — every search runs a sequential scan. Separately, `filters.py`'s list-endpoint `q` param has no minimum length, unlike `search.py`'s `MIN_QUERY=2`.

**Product decision already made and recorded** (not open for re-litigation): use `pg_trgm` + `gin_trgm_ops`, not `websearch_to_tsquery` — the latter would silently change search semantics (stemming, stop-words, no partial-match), a product change disguised as a performance fix.
