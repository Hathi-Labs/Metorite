## Description

## Problem

Observability showed **"The agent produced no text output…"** for `technical-project-planner` (a github-copilot / deepseek-v4-pro agent) during a live session.

Root-cause chain (traced from the `agent_run` trace + gateway logs):
- The agent authored markdown by shelling out (`bash` heredocs / `echo` / `base64`), fighting shell escaping.
- Its final tool call's JSON arguments were **truncated at ~13k chars** (`Unterminated string in JSON at position 12997`) — a `max_tokens` cutoff mid tool-call — so it never wrote a closing answer (`text_started == False`).
- The Copilot Tier 1.5 handler then emitted a hard `RUN_ERROR`, recorded the run as `error`, and **wiped all the folded tool work** from the UI.

Two systemic gaps behind this:
1. A per-agent `config.json: tool_scope` could **silently strip the essentials** — `email-assistant` had no `write_artifact`/`web_search`/`manage_todo_list`; `task-manager` no `write_artifact`/`web_search`. With no clean file-write tool, agents fall back to fragile shell heredocs.
2. The no-text stream end dead-ended instead of degrading gracefully.

## Changes

**`executor.py` — graceful soft-finish (`_copilot_no_text_end`)**
- Tool work happened → synthesised closing message + `RUN_FINISHED` (records `completed`, keeps the work; user says "continue" to resume the stored session).
- No tool work → genuine empty response → `RUN_ERROR` (hard stop).

**`_tool_injection.py` — guaranteed standard toolset floor**
- `_resolve_injected_scope` unions every `tool_scope` with `_CORE_STANDARD_TOOL_NAMES` (web_search, fetch_page, write_artifact, share_artifact, manage_todo_list, ask_questions, run_diagnostics, get_errors, save_note, recall_notes). A scope can ADD specialist tools but never strip the baseline.
- Steer file authoring to `write_artifact(path, content)` instead of shell heredocs.
