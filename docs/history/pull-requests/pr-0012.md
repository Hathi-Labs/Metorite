## Description

## What

Make the in-app reconnect banner trip **immediately** when a live provider call fails on auth, instead of waiting for the next background sync cycle.

Previously the banner keyed only off `sync_status === "error"`, which is set by the background sync. A freshly-expired OAuth token therefore wouldn't surface in the email app until the next sync ran.

## Changes

- **`lib/api.ts`** — `gatewayFetch` attaches the HTTP `status` to thrown errors so callers can distinguish 401/403.
- **`lib/emailStore.ts`** — new `authErrors{ accountId → message }` state; `fetchFolders` sets it on a 401/403 from the live folder fetch and clears it on a later success.
- **`page.tsx`** — the reconnect banner now shows when `syncStatus === "error"` **or** an account is flagged with an auth error.

Since `fetchFolders` runs on every account/folder selection, the banner appears the moment the inbox can't reach the provider — no sync-cycle delay. Builds on PR #11.
