## Description

Reads [`yc-software/qm`](https://github.com/yc-software/qm) (a multiplayer agent harness, released 2026-07-29, MIT) at commit `7f2c916` and lands the findings in our corpus. **Docs only — no code, no schema, no behaviour change.**

## Why it's worth a doc

qm is the closest prior art to our multiplayer work that exists, and it independently reproduced our most contested design decision. `memory-clearance.md` §3.3 says *"a run reads at the clearance of its least-cleared viewer"*; `groups_sessions_authority.md` §3 says the permissions twin. qm reached the same rule with no contact with this design and applied it to **three** resources — transcript replay, shared file handles, and **network egress** (allowed hosts = intersection across the audience, denied = union), all failing closed on an empty audience.

That is worth recording for two reasons: the rule is not an over-engineering of ours, and egress is a third enforcement point we don't use.

## The three findings that change what our docs say

| | Finding | Lands on |
|---|---|---|
| **QM-1** | **Steer before floor control.** qm ships rooms with *no baton at all* — a second person's turn folds into the live run as a mid-turn steer, the second surface stands down so the reply isn't posted twice, and steer signals are durable. This inverts README §8's Phase 2 ordering. §5.2's supersede fix survives regardless. | WS-10 |
| **QM-2** | **Skills index, bodies on demand.** One line per skill in the prompt + lazy body materialization + connector gating + index inside the cache-stable prefix. `skills_scope_out.md` §5 already named "progressive disclosure" as the core-floor diet without a reference implementation; this is one. Attacks the ≈5.4k addendum half — the ≈10.3k schema half still needs its own answer. | WS-23 |
| **QM-3** | **No ambient credentials in a shared room.** Supersedes §6.4's single `acting_identity` *in direction*: nothing ambient, every credential needs a grant bound to that room, with a consent protocol whose load-bearing rule is *"only the owner's own reply is approval — a relayed 'they said it's fine' is not."* | WS-10 Ph3, WS-2, WS-1 |

Plus QM-5 (tenure windows should narrow the **model's** replay, not only a viewer's) and QM-7 (environment attachment as a second answer to `agent-kinds.md` §9 Q1).

## Where we're ahead, recorded so we don't regress

`subject:` compartments express a case qm structurally cannot — the CEO's restricted Falcon and collaborative Acme facts share one notebook, so its only protection is to forget both in a channel. That is exactly the `context_policy='room'` failure `memory-clearance.md` §1 rejects. Also ours: semantic partition inside the query (theirs is a 300-bullet flat file injected wholesale), the per-viewer private hint, the share-mid-conversation moment, several agents per room, and clearance-tagged replay — where their own `SECURITY.md` concedes the gap on the same mechanism.

## Checked, not assumed

qm refuses to label a compacted summary that spans two personal scopes, since a summarizer is otherwise a laundering path. **We don't have that exposure**: `acb_llm/context.py::fit_messages_to_context` truncates, it never summarizes. Noted in `memory-clearance.md` §7 as a guardrail for *if* WS-9 adds summarizing compaction — not as a live gap.

## Corpus discipline

Per WS-0, the new spec is registered in the single-owner registry as **reference-only — it owns no work item and no status**, so it can't become a competing source of truth. The specs it links stay authoritative. Age caveat is stated in the doc header: qm is three days old, and its own `SECURITY.md` says it is "not a hardened public or multi-tenant service boundary" — same posture as us. Nothing here reads as "they solved it in production."

Also carries a "what not to copy" section: their skill approval flow is nominal (every call site auto-reviews under a `system:*` pseudo-reviewer; only org promotion is a real gate), `trustTier` on skill packs is stored and never read, and their security postures are mutually exclusive by construction (`strict` turns screening *off*).
