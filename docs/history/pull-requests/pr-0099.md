## Description

## The range selector was decorative

`Analytics` read **"Inbox activity for the last 30 days"** above figures with no date predicate at all. On the live account that day:

| card said | actual 30-day figure |
|---|---|
| Total **6,803** | 1,431 |
| Unread **4,517** | 739 |

6,803 reaches back to a stray 2019 message in Trash. Only the volume chart and the rule counters moved when the selector moved.

Beyond the lie, the panels were inert — read-rate, starred count and per-folder totals answer *"what is in my mailbox?"*, which the sidebar already answers, and nothing follows from the answer. Top senders ranked by raw volume, which on an internal-heavy mailbox just lists colleagues.

**The rule applied: a metric ships only if the user can act on it, and every list ends in a button.**

## What replaced it

- **Responsiveness, per thread** — median + p90 time to first reply, and what share of arriving conversations got answered. Threads enter by *arrival*, so the rate can't be gamed by a quiet week clearing old debt. The unreplied count is shown next to the median rather than folded into it.
- **Reply backlog, both directions, bucketed by age** — deliberately *not* windowed, and labelled "right now" so it never inherits the range caption. Carries **Reply Zero coverage**: "3 need a reply" means nothing if only a twelfth of threads were ever classified — a state this mailbox has genuinely been in (295 of 3,487).
- **Senders you have never once replied to** — ranked by unread, annualised (`~2,725/yr`), wired to the Email Cleaner.
- **Category mix vs the previous period** — doubles as a classifier-coverage read-out.
- **Automation *trust*, not just throughput** — how often you overruled it, how many actions failed at the provider, how many learned patterns sit unreviewed.

## What this immediately found on the live account

- **192 failed actions in 30 days.** Rows logged `APPLIED` whose Graph call returned 404 (146 `LABEL`, 137 `MOVE_FOLDER`) — the mailbox was never actually changed, and nothing surfaced it. Also 5 × `'asyncpg.pgproto.pgproto.UUID' object has no attribute 'strip'` in `DRAFT_EMAIL`, a real bug.
- **21 learned patterns unreviewed**, so the Email Cleaner is projecting none of them.
- **142 uncategorized arrivals** in 30 days vs 159 in the 30 before — classification is not keeping up.

Each is a separate follow-up, not fixed here.
