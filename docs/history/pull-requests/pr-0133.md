## Description

## Phase 3 · item 3.10

Re-scoped now that the CommandCenter calendar/timeboxing app is live (#71) — the old blocker "needs a calendar integration" is gone. When an incoming email **asks about timing**, the drafter now sees the owner's upcoming hard-date commitments so it can offer **clash-free slots and never double-book**.

- **`_asks_about_scheduling`** — a cheap keyword heuristic (meeting / available / reschedule / "when are you free" / "let's meet" / …). An LLM check per draft would cost a call for a signal this easy to spot.
- **`_fetch_calendar_context`** — the account user's `gtd_items` with `due_at + is_hard_date` in the next ~10 days (the same "shows on the Calendar" predicate the tasks app uses), open only, soonest first. **Best-effort** — a deploy without the tasks feature never breaks a draft.

Wired into the single `_build_reply_context`: the calendar is pulled **only** when the message reads as a scheduling ask (an ordinary reply never carries the owner's schedule) and injected as a prompt block telling the drafter to avoid clashes. External Google/Outlook calendar sync stays deferred — this reads the **internal** calendar.
