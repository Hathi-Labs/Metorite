## Summary
- Root-caused the reported "Create failed (HTTP 500)" on `POST /apps`: a `:name::jsonb` bind param (a colon-param immediately followed by Postgres's `::` cast, no space) is silently mis-parsed by SQLAlchemy's `text()` bind-param scanner — it drops the last character of the param name and leaves the literal cast text unbound, which asyncpg then rejects with `syntax error at or near ':'`.
- This exact pattern was present at **6 sites** in the Custom Apps write path, all broken since Phase 0 because nothing before now exercised these statements end-to-end against a real Postgres: `create_app`, `fork_app`, `publish_app`, the `app_audit` logger (`record_app_audit` — its own try/except silently swallowed every failure, so `app_audit` has never actually recorded a row, meaning **usage stats on gallery cards have always shown zero**), and both `cc.storage` write paths (`actions.py`'s action-dispatch write, `runtime.py`'s `PUT` endpoint).
- Fix: add a single space before the cast (`:name ::jsonb`) — confirmed via direct SQLAlchemy bind-param compilation and end-to-end execution against a live local Postgres (create → fork → storage write → audit log all verified to persist correctly).
- Found and fixed the identical pattern in one unrelated feature during the sweep: `tasks/settings.py`'s GTD settings `PATCH` endpoint (`workflow_stages`, `status_stage_map`, `energy_windows`, `day_templates`).
- Added `tests/unit/test_sql_bindparam_jsonb_cast.py`, a regression guard that scans the gateway source for the broken shape so it can't silently return.
