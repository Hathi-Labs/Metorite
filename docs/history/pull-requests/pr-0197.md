## Description

## Why

A comprehensive review of this session's merged work (coding skill, proactive genUI directive, on-demand design system) confirmed the core is sound but surfaced a set of real hardening gaps. This PR closes them, with regression tests for each.

## Hardening

- **Durability sweep — symlink escape (was the most serious):** `rglob` follows symlinked directories on Python < 3.13, so a `code_task` session could have dropped `agent-data/x → /` and mirrored host files (service-account keys, other agents' creds) into the agent's downloadable blob store. Each swept file's **real** path must now resolve inside the workspace. Also moved the tree walk + file reads **off the event loop** so a large sweep can't stall concurrent runs.
- **Commit safety:** `_commit_repo_changes` now explicitly unstages `agent-data/`, `inputs/`, `outputs/` after `git add -A`, so a secret a script wrote under `agent-data/` can never be committed even for an external `workspace_root` repo that lacks the loader's `.gitignore`.
- **Injection idempotency + parity:** the Copilot addendum append is now idempotency-guarded (parity with the MAF path); native MAF agents now also receive the output-discipline block (files → `outputs/`, and the `load_design_system()` pointer) they were missing.
- **Honest docstring:** corrected the `_script_env` concurrency claim to match the executor's documented Tier-0 limit (process-global env; hard multi-tenant isolation is Tier-2 / BO-7).

## Also: unblock CI — migration prefix collisions on main

Two other teams' PRs each landed migrations `93` and `94`, breaking `test_migration_numeric_prefixes_are_unique` for every PR. Renumbered the two **additive** gtd/calendar migrations out of the collisions (`93_gtd_planning_prefs → 97`, `94_gtd_day_templates → 98`) — both are additive `ALTER TABLE gtd_settings`, depend only on migrations 48/77, and no code references migration numbers, so running them later is safe. The email migrations keep their numbers.
