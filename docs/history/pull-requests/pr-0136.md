## Description

## What & why

The browse list rendered **every message as its own row** — a five-message thread was five rows each wearing a "5" badge. This collapses it: the mailbox reads at **thread level**, one row per conversation (its newest message in the current view represents the thread), and the total counts **conversations, not messages**.

This is the UI half of the one-classification-per-conversation invariant (#110/#113) — master plan **3.2**.

## Changes

- **Backend** — `GET /email/messages` gains `collapse: bool` (default **off**). When on and no `thread_id`, it `DISTINCT ON` the conversation key `COALESCE(thread_id, id::text)` (newest matching message per thread) and totals `COUNT(DISTINCT key)`. A NULL-thread message stays its own conversation. Ignored inside a thread load; default-off keeps the assistant's per-message inbox queries unchanged.
- **Frontend** — `listEmails()` defaults `collapse=true`, so every mailbox browse (folder / label / uncategorized, first page + load-more + backfill) reads at thread level. **Search stays per-message** (keeps its match highlight). The list row already renders the `threadCount` badge, so no row-render change was needed.
