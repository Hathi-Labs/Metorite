## Description

Measured against the live mailbox **first**, which reshaped the fix — my original H5 description was partly wrong.

## What was actually wrong

| symptom | reality |
|---|---|
| auto-drafting into dead threads | **already fixed** in #80 — backfills don't draft |
| label stacking | **1 message**, 68 threads. Real, but minor |
| **Reply Zero coverage** | **295 of 3,487 threads — 8.5%.** This was the real damage |

`_maybe_classify_threads` selected *"the newest 200 threads from the last 30 days"* and then skipped the already-classified ones — which, on a real mailbox, is all of them. It spun without reaching anything older, and **mail past a month could never acquire a status at all**.

It also wrote the status row but never called `_reconcile_thread_labels`, so superseded labels stayed on older messages — 68 threads carrying Reply AND Awaiting AND Done. The status row and the labels are two views of **one** decision; only the second was written. `_process_past_emails_job` did neither.

## Fixes

**Coverage.** The classifier now selects threads that *need work* in SQL (`LEFT JOIN email_thread_status`, no date window), so each cycle makes real progress. **Inbox threads ordered first** — filed threads outnumber live ones ~10:1, and ordering by date alone put 2,622 already-handled threads ahead of the 273 that might still need a reply.

**Cost.** Inbound-last threads the user already **filed** resolve to FYI deterministically — filing it *is* the answer. No model call: these are the bulk of an old mailbox, and re-litigating them would be thousands of calls on mail already put away. `preserve_done` keeps an explicit Done intact.

Net: ~273 model calls to drain the backlog instead of ~3,191.

**Parity.** Both paths now record status *and* collapse labels. The backfill does it **after** the loop, per thread, from each thread's newest in-range message — it cannot do it inline, because the live runner reads newest-first and takes the first message per thread while the backfill reads **oldest-first by design**. Inline projection would let a thread's oldest message decide its status, which is exactly what the live runner's ordering exists to prevent. Threads with newer mail outside the range are skipped rather than moved backwards.

**Tidying.** `_reconcile_thread_labels` handles `provider=None` explicitly instead of relying on `None.set_labels` raising into the best-effort handler.

## Verification

451 unit tests pass (10 new), `tsc` clean, blocking ruff gate clean.

The new parity suite asserts both paths do both writes, that the two jobs iterate in opposite directions, that projection happens after the loop, and that the backfill projection spends no model calls — the drift-guard whose absence caused this.
