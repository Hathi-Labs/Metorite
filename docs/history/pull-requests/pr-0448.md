## The constraint that shaped every other decision

`work_plan.md` §2 is **the only current-state authority**. A mutable queue that *also* described state would be the CLAUDE.md §5 defect in its purest form: two descriptions of one truth, and the **stale** one trusted precisely because it is the one loaded into every prompt.

So an entry may never restate state. It carries a **Check** — a cheap read-only command whose output says whether it is still real. That inverts the failure mode: a stale entry costs one command and gets deleted, and it can never be *quietly* believed, because believing it requires running something that would have contradicted it.

## That is not theoretical — the mechanism caught itself three times

Running the ten Checks against `main`, which the protocol demands before other work, found **three defects in the Checks themselves**:

1. **H-9 pointed at `docs/schema.generated.sql`.** The file is in `infra/postgres/`. A `docs/` check would have silently "passed" on a missing file — a green light meaning nothing.
2. **H-1 restated a migration range** ("171–175"). It was stale within the hour — 176 landed inside it. H-1 now *derives* the range and carries a note saying why it must never name one.
3. **`ls infra/postgres/*.sql | tail -1` answers `schema.generated.sql`**, which sorts alphabetically after every numbered migration and is not one. Both H-1 and H-9 used it, so both were comparing a file to itself. Now `[0-9]*.sql | sort -V`.

Three wrong Checks, three commands, three repairs. Under any scheme where the file simply *asserted* status, all three would have read as true indefinitely.

## Why a hook rather than a line in `CLAUDE.md`

`CLAUDE.md` is the router: edited when the architecture changes, which is rarely. A queue changes every session. A mutable queue inside a stable document makes the stable document stop being trusted as stable — and a stale queue entry there is **indistinguishable from doctrine**.

The hook deliberately does **not** execute the Checks. Running commands out of a markdown file at session start would be an arbitrary-execution seam pointed straight at the one file every session loads, and a hanging check would block startup. The session runs them itself, under the permission model, having read them.

## R7 — the fence covers the silent failures, not the happy path

A broken listing is obvious the first time someone opens a session. These are not:

- **no `HANDOFF.md`** → must start normally. This runs in every session of every checkout; a crash here is a repo nobody can open.
- **garbage / half-edited file** → must not throw. It is edited by hand, by agents, and by merge resolution, so it *will* be malformed sometimes.
- **content below `# DONE`** → must never resurface. If the parser read past it, deliberately closed work would come back as live work every session.
- **`[OWNER]` surviving into the injected text** → that word is the difference between reporting a gate and walking through one.
