## Description

## What this is

A new **WhatsApp Business channel vertical** (channel #2 after email) for the founder-CEO: manage WhatsApp the way the email app manages mail — an obligation queue instead of a chat list, sender categories that carry policy, drafts in the founder's voice, a digest, commitment tracking, and approval-gated automation. Built on the **official Meta WhatsApp Business Cloud API only** (coexistence), mirroring the email vertical's proven shape (provider seam → idempotent persist → post-sync hooks → Reply Zero → categories-as-policy → digest → drafting → Action Broker).

Delivered feature-by-feature with one commit per slice. Starts with the plan + mockups, then W0–W3.

## Backend (Python — gateway + a new `whatsapp_ingestion` service)
- **W0 — pipe + store:** `wa_*` schema (accounts/chats/messages/media/contacts/labels/chat-status/sync-log + FTS); the Cloud API provider + a **total** webhook parser; the single idempotent persist path (deduped on the Meta `wamid`); the post-sync hook registry; gateway routes (accounts, chats + `/streams`, messages + FTS, window-aware send, public webhook).
- **W1 — send + hand-offs:** approved-template library; message → GTD task capture (idempotent); the CRM/ERP **context** endpoint (contact + entity ref + open loops + stats).
- **W2 — triage brain:** Reply Zero chat-status classifier; a deterministic, Hinglish-aware **intent** classifier; **categories-as-policy** (notify/auto-reply/draft/escalate, Family hands-off); the digest projection; post-sync hooks wired at startup + in the webhook.
- **W3 — automation:** the auto-reply **autonomy-ladder** decision engine + dry-run preview (VIP/Family never auto-send); **commitment/waiting-on** extraction (both directions); **AI drafting** in the founder's WhatsApp voice (multilingual, sentinel-on-failure); and the **approval-gated broadcast** composer routed through the Action Broker (`SUGGEST → NEEDS_APPROVAL`, handler-only sends).
