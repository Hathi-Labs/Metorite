## Description

Live verification of the 2.6 one-off found its premise broken: `merge_ghost_messages.py` says NULL rows must "re-sync first", but no sync will ever re-touch them — the recurring poll reads only the newest ~2 pages/folder and the deep resync is floored at the initial-sync window. 4,850 of 6,889 rows on the live account are older than that window and stay NULL forever.

This adds the bounded backfill the merge script''s docstring anticipated:
- Graph `$batch` GETs of `$select=internetMessageId` only — **no mailbox writes, no message upserts**, cannot collide with the running sync loop
- `WHERE internet_message_id IS NULL` guard so a concurrent sync reclaim is never overwritten
- 404s = true re-keyed ghosts (stable id unknowable) — counted and left NULL for the merge script''s report
- Outlook-only; other providers skipped

Run order (on the VPS, app root + env):
1. `uv run python scripts/backfill_internet_message_id.py`
2. `uv run python scripts/merge_ghost_messages.py` (dry) → `--apply`
