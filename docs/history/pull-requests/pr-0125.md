## Phase 3 · item 3.8 (review §2.4)

The automation drafting paths had drifted from the interactive ones. Four fixes bring them to parity:

1. **Rule-path uses the shared context builder.** `_apply_rule_actions` hand-assembled a reply-context dict carrying neither `sender_scope` nor the To/Cc lines — so the direction note + greet-by-name were **silently no-ops on the highest-volume drafting path**. It now builds through the ONE `_build_reply_context` (same builder `/draft-reply` and "Draft with AI" use), falling back to the old dict only if the row can't be resolved.
2. **compose-assist teaches.** Its reply-from-scratch now stores the AI draft (`_store_ai_draft`) like `/draft-reply` does, so a composer edit before send teaches `_learn_from_sent`. "Draft with AI" taught nothing before.
3. **Follow-up nudge hydration.** The nudge drafter read `body_text or snippet` — a header-only Outlook row gave it a ~200-char cutoff — and now hydrates the full body first (the **last surviving snippet-bug path**).
4. **Pop-out carries `messageId`.** The popped-out composer now passes the local message id so its "Draft with AI" loads the same reply context the inline reply had (it drafted context-blind before).

### Tests
`tests/unit/test_email_rulepath_draft_parity.py` pins all three backend wirings on the source. Full draft/compose/reply/follow suite green (124 passed, 0 regressions); blocking ruff + `tsc` clean.
