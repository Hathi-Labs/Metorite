## Description

Makes on-page **live transcription** usable end to end, and lays the spine the meeting copilot will build on.

## What you can do after this deploys

Start a recording at `/notes` → live captions now also flow to the server, so a **"● Live now"** pill appears across the app and `/notes/live/<meeting-id>` shows the transcript **attributed by speaker**, with names picked up from self-introductions ("I'm Priya").

Requires `DEEPGRAM_API_KEY` (with key-management scope) — same key live captions already use. Without it, recording still works, just no live transcript.

## The design change

Live transcription used to be framed as a *disposable draft* thrown away when the batch pass ran. That traded accuracy for latency unnecessarily. Instead:

- **Chunk on pauses, not the clock.** Fixed windows cut mid-word, which is exactly where ASR loses context and diarization gets confused. VAD endpointing closes a chunk when a speaker actually pauses, so each chunk is a complete utterance.
- **A running voiceprint gallery** matches each utterance's speaker embedding against those seen so far, giving **stable speaker ids across chunks** incrementally — no end-of-file wait.
- **The batch pass becomes a refinement, not a redo.** It still owns the authoritative transcript, but now reconciles its own labels against the live ones by max time overlap (greedy one-to-one) and carries live-learned names across.

## Verification

Ran the meeting-bot worker against a real PulseAudio/Xvfb/Chromium stack rather than reasoning about it, which caught two defects:

1. **Live segments almost never carried an embedding** (1 of 15 measured). An utterance's embedding only exists once it *closes*, but the ASR streams segments *during* it — so the voiceprint was silently never attached and the gateway fell back to label passthrough, defeating the gallery. Segments are now briefly held and released once their window lands, or untagged after a bounded wait. Same audio after the fix: **42 of 46**.
2. **Chromium launch had no executable override**, so any host whose browser build wasn't installed by that exact Playwright version died outright.

Also verified on real audio: the record path recovers a 440 Hz tone through null-sink → monitor → ffmpeg → Opus; the virtual-mic speak path carries audio; the energy-VAD default cleanly separates speech (RMS ~1700) from silence (0.0).

**Still unverified:** the Google Meet *join selectors* — that needs a real meeting, and is called out in the worker README. Doesn't affect on-page live transcription.
