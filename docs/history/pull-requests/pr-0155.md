## Description

Follow-up to #153 closing the interaction gaps found in the calendar UX audit: how you *remove/modify* a scheduled block, and continuity of the experience on mobile.

## Changes

- **Block context menu** — right-click on desktop, **long-press (450 ms)** on touch, reusing the app's existing `ContextMenu` primitive: Open task · Focus on this · Mark done / not done · Make it the One Thing · Pin as fixed / Make flexible · **Reschedule…** (opens the existing `SchedulePopup`, which includes Unschedule + date/time) · **Remove from calendar** · **Delete task…** (routes through the confirm-first delete flow). A long-press swallows the follow-up click so it doesn't also open the task card.
- **Undoable scheduling** — new store action `applySchedule(label, changes)` snapshots the grid before any scheduling mutation, and `undoLastChange` now reverts `scheduled_start`/`scheduled_end`/`flexible` server-side. Timeboxing, drag-move, resize, unschedule, plan-apply, roll-over, and Focus Mode's +15 reflow each appear in the undo toast as **one** step, however many blocks moved — a mis-drag is always one tap from safe.
- **Mobile parity** — the long-press menu is the touch path to everything the hover micro-buttons do (unschedule / pin / star / focus / reschedule / delete were previously desktop-only), and week view keeps a 96 px minimum column width so phones get horizontal scroll instead of seven crushed columns.
