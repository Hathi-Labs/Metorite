## Description

A **fully-featured, AI-driven calendar + timeboxing** app built into the task manager. **Draft — for review; nothing merged.** Branch off `main`.

The calendar plans your Next Actions, timeboxes them well (energy + capacity aware), and reorganizes/replans when things change — leveraging AI throughout, with deterministic guardrails so the AI can't produce invalid schedules. Spec + full failure-mode analysis: `ai-company-brain/specs/calendar_timeboxing.md`.

## What's built (P0–P3)

**Grid & timeboxing (P0–P1)**
- Day / Week hour-grids + Month grid; tasks render as blocks; current-time line; deadline all-day markers.
- **Drag-and-drop** to schedule (rail → grid) and move (within/across days); **resize** to change duration; 15-min snap; drop-target highlight.
- New `scheduled_start/end` time-block model (mig 76) — only `due_at` deadlines existed before.

**Energy / capacity / buffers (P1)** — mig 77
- Per-user prefs the grid *and* the AI planner honor: working window, daily focus capacity (with an "Xh/Yh over capacity" meter), inter-block buffer, and **energy windows** (tinted on the grid). Gear popover to edit them.

**AI "Plan my day" (P2)** — the headline feature
- `POST /calendar/plan`: the **LLM makes the judgment** (which Next Actions today, order, energy-fit — from your energy note, the priority matrix, and deadlines) and **deterministic code does the geometry** (packs into real free slots respecting the window, existing blocks, energy windows, capacity, buffers). No overlaps/out-of-window possible; degrades to priority-ranked packing when the LLM is off.
- "Plan my day" review modal: energy-note input → re-plan, proposed blocks with rationale, unplaced list, capacity summary, Apply.

**Chat with your calendar (P2)**
- The task assistant is calendar-aware (persona gets the schedule, free time, capacity, current local time + tz) and has `gtd_schedule` / `gtd_unschedule` / `gtd_list_schedule` tools — so "reschedule my deep work to tomorrow afternoon" just works, timezone-safe, without double-booking.

**Reorganize / replan (P3)**
- **Auto-reschedule / roll-over**: `POST /calendar/rollover` packs overdue-incomplete blocks into today (deadline-aware); a banner offers one-click "Roll over to today".
- **Deadline radar**: due-soon badge + a "Due soon" rail section with one-click "Today".
- **Overlap detection**: side-by-side lanes + a red "double-booked" flag.

## Failure modes explicitly addressed
Overcommitment, no buffers, energy mismatch, falling behind, deadline slip, bad estimates, double-booking, fragmentation, tedium, rigid plans, timezone bugs — see the spec's §9b table for how each is handled with UX + AI.
