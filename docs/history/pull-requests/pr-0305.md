## Description

Streaming speech-to-text is billed per minute and ran for the whole meeting regardless of whether anything consumed it. With the copilot off, nothing did — the archival recording still goes through the batch pipeline afterwards and produces the same transcript at batch prices. So a copilot-less meeting was paying a live rate for a feature nobody was reading.

## Three modes, not a boolean

"Follow the copilot" is the right default but not the only sensible answer:

| Mode | Behaviour |
|---|---|
| `auto` *(default)* | Stream only while the copilot is on — the saving |
| `always` | Stream regardless, for live captions without an agent |
| `never` | Never stream; record and transcribe afterwards only |

## How it's enforced

The gateway owns the decision (`live_wanted`), and both producers ask it rather than each deciding for itself:

- **Browser recorder** passes its meeting to the token endpoint and gets a `409` when nothing is listening. The existing `onUnavailable` path already degrades to record-only, so this needed no new failure handling.
- **Meeting-bot worker** polls a cheap `/live/wanted`, derived from the per-meeting callback URL it already receives — so no new field in the join contract.

## Both edges, not just the start

Turning the copilot **on** mid-meeting begins streaming within the re-check interval; turning it **off** closes the socket and stops the meter. A start-only check would leave a four-hour call streaming for an agent that was switched off in minute three — which is most of the cost this is meant to avoid.

## Failure directions, chosen deliberately

- **Unreachable gateway → keep streaming.** Losing captions on a real meeting is worse than one meeting's spend, and both sides fail open consistently.
- **Unrecognised mode → fall back to `auto`, not `always`.** Of the two ways to be wrong, silently spending money is the worse one.

## The tradeoff, stated rather than buried

In `auto`, a copilot-less meeting gets no live captions **and no live agenda coverage** — both are fed by the transcript bus. That's a direct consequence and it's in the settings copy, not just the commit message. `always` buys them back.
