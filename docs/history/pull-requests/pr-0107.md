## Description

## The bug

The sidebar's **All** excluded junk and trash but never **sent** or **drafts** — so 442 + 144 of the live account's messages were the user's own mail. Every conversation appeared twice and the list read as an activity log rather than an inbox.

```python
FOLDER_ALL_EXCLUDES = ("junk", "trash")   # sent and drafts were never here
```

The principle: **All is mail that arrived, and the user's own mail never did.** Sent doubles every conversation; a draft is unfinished text with no counterparty, which belongs in a composer rather than a reading list.

Excluding them costs nothing in reach: each has its own sidebar entry, and the thread view already ignores the folder filter, so opening a conversation still shows both sides of it.

## Search deliberately does not follow

That constant was shared with the search bar's "All folders" scope, under a comment saying `all` must never mean two things. I split it anyway:

| | answers | the user's own mail |
|---|---|---|
| Browsing All | "what came in?" | hidden |
| Searching All folders | "where is that message?" | **included** |

"What did I tell them?" is one of the commonest reasons to search. A scope labelled *All folders* that silently skipped your own replies would be a worse defect than the one this fixes — and half-written text is a poor thing to browse but a fine thing to go looking for. `folder_scope` grows an `include_sent` flag that only search passes.

## Two things that would have been easy to miss

**The frontend keeps its own copy of the set**, and it both filters the list *and* derives the sidebar's All count. Fixing only the server would have left the badge claiming mail the list beneath it could not account for. Both updated; the existing parity test guards them.

**No `"spam"` or `"draft"` entries**, though `"spam"` was in my first draft as "defensive for Gmail". `providers/base.py` canonicalises spam → junk and draft → drafts on ingestion for *every* provider, so both would have been dead weight that reads as coverage.
