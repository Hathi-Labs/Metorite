## Summary
Reported with screenshots from a real device: tapping "Restore" then "Confirm" on a checkpoint on mobile showed a garbled, barely-visible UI. Root-caused and fixed:

- **Root cause**: the checkpoints popover is `absolute right-0` anchored to the History button, which on mobile sits well short of the header's right edge, not pinned to it. A 320px-wide popover anchored `right-0` to a button at, say, x=150px renders from x=-170 to x=150 — the large majority of it off-screen to the left, exactly matching the screenshot (only a few characters of each checkpoint's message visible at the left edge).
- **Fix**: extracted the popover's inner content into a shared `CheckpointsPanel` component. Desktop keeps the anchored popover (unaffected). Mobile gets a proper bottom sheet (`fixed inset-x-0 bottom-0`, no anchor-point math to get wrong), matching the same pattern already used for the Files browser on this page. The existing outside-click-to-close handler is now scoped to desktop only — the mobile sheet isn't nested under the button's ref anymore, so that handler would otherwise treat every tap inside the sheet as "outside" and close it before the tap's own handler ran.
- **Also decluttered the mobile header**, addressing the crowded/overlapping toolbar visible in the first screenshot: hid the Advanced toggle and the aggregate test-pass badge on mobile — both are redundant there since the bottom nav's Code/Tests tabs already cover the same ground (tapping either already auto-enables Advanced), and a phone-width header has no room to spare for controls with a working equivalent one tap away.
