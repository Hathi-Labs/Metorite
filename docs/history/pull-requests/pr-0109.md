## Description

## The symptom

An agent that ended its turn by **asking the user a question** was reported as a broken run:

> "I finished the steps above, but my final summary was cut off before it could be written — **the response hit its output length limit**. … Say "continue" and I'll pick up where I left off."

Nothing was cut off. The agent had called `ask_user` and was waiting for an answer. The advice was wrong too: the correct move was to **answer the question**, not say "continue".

## Why it happened

`_copilot_no_text_end` had exactly two branches — *tools ran* (assume truncation) or *no tools* (error) — and no notion of a turn **parked on a human**. But `ask_questions` / `ask_user` / `request_confirmation` all stop the agent by design: the card they render **is** the output, so no closing text is due. `ask_tools`' own module docstring says it outright: *"The agent MUST stop after calling this tool."*

The message also asserted a cause the code cannot observe. All it actually knows is *no text arrived*. It named one specific reason — and the first time it fired in production, that reason was wrong.

## The evidence

Production run `252c24dc` (`technical-project-planner`, deepseek-v4-pro):

- last tool = **`ask_user`**
- the gateway's usage log for that run shows a **4,473-token** completion — *above* the old 4096 ceiling and nowhere near the 32000 cap, so **nothing was truncated**
- largest prompt in the window: 73,592 tokens, well inside a 1M model's context

It fired **once in 7 days** — rare, but actively misleading when it does, and it undermines trust in every other message the agent sends.

## The fix

All at the **one site** that produces this message, so every Copilot-SDK agent is covered — not just the one that hit it.

- **Track the last tool started**, read off the **emitted events** rather than any single translator branch. A native SDK tool (`ask_user`) and a platform tool reach the stream through different branches; only the emitted event is common to both. It resets on the stale-session retry, so a name from a discarded attempt can't decide how the real attempt ends.
- **Ending on a blocking HITL tool finishes silently** — no message talking over the question card. It also logs at `info` with `awaiting_user=True` instead of `warning`: a normal wait shouldn't look like an incident, and shouldn't bury real ones.
- **The message no longer asserts a cause.** It now describes only what's known: the summary is missing, the work survived, say "continue".
- **`HITL_BLOCKING_TOOLS` + `is_hitl_blocking_tool`** live in `acb_skills.ask_tools`, beside the tools themselves, so the set can't drift from what it describes.

## Scope: all agents

**Native-MAF agents were never affected** — that path emits `RUN_FINISHED` and no such message. Verified by checking every `text_started` reference: this handler is the only site that makes the decision, and it is shared by all Copilot-SDK agents.
