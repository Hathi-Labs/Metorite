## Description

Fixes the three UI/UX gaps reported in the WhatsApp app.

## 1. Opening a sub-app dropped the navigation
Pulse / Categories / Replies / Rules were separate **dead-end routes** with only a "← Queue" link, so entering one lost the WhatsApp app's own nav (the global app-switcher sidebar was always there — it's the *WhatsApp* nav that vanished). The email app — the template — avoids this by keeping everything under one shell.

→ Added **`whatsapp/layout.tsx`** with a persistent top sub-nav — **Inbox · Pulse · Categories · Replies · Rules · Numbers** — shown on *every* WhatsApp route. Removed the redundant per-page back-link headers and made each sub-page scroll within the shell.

## 2. No way to delete/disconnect a number from the app
Disconnect was only on the Integrations page.

→ Added a **Numbers** page (new nav tab) listing connected numbers with per-number **Disconnect** (confirm → `DELETE /api/whatsapp/accounts/{id}`) and a Connect action. Added `disconnectAccount()` to the app API.

## 3. Non-native icons
The triage streams used emoji (`✦ ⏳ 👥 💬 💤`) and Rules used a raw `⚖`.

→ Replaced with **lucide** icons — the native set the rest of CommandCenter uses (the app is registered as `MessageSquare` in the nav). `STREAMS` now carry lucide components; each sub-app header shows its lucide icon.

The inbox keeps its triage-stream spine + account switcher; the automation links moved up into the shared nav (de-duplicated).

## Notes
- "Delete my account" is interpreted as **disconnect a connected WhatsApp number** (the WhatsApp app's notion of an account). If you meant deleting the whole workspace user, that's a platform-level setting — say so and I'll wire that separately.
- Multi-number scoping for the sub-apps still uses the default account (per the current "one number for now" scope); the shared nav is ready for a per-account scope later.
