## WS-26h — stage entry requirements + rot badges (`9102819`)

Generalizes the lost-reason gate into per-stage entry requirements, and adds the rot half of `crm_app.md` §5.1 system 3. **Migration 169** — number taken from the directory at build time (R1); every test finds the file by content, so a renumber at merge is free.

**Schema.** `crm_deal_statuses` gains `required_fields TEXT[] NOT NULL DEFAULT '{}'` and a nullable `max_dwell_days SMALLINT`. Deal-only, the same asymmetry `probability` already has: the allowlist is deal columns, and rot is measured off `status_changed_at`, which migration 144 gave deals and withheld from leads.

**Gate.** `pipeline.py::_require_entry_fields`, called from `apply_status_transition` immediately after the lost-reason refusal, so it inherits all three of that rule's properties — entry-only (the transition is entered only when `status_id` actually moves), refused before any of the three effects, and satisfiable by the *same* PATCH. That last one is what lets `MoveModal` send fields + status in one request; two requests can half-apply, and the half that lands is the one that moved the deal.

**UI.** Rot is presentation only — amber past the threshold, destructive past 2×, strictly-past so a card is fine *on* the allowance day. Nothing moves, closes or hides. `LostReasonModal` was absorbed into `MoveModal` rather than left beside it: a lost stage can also be a gated one, and two dialogs each raised by its own 422 is the shape where a user answers a question and is refused again.

### Deploys inert

Every existing stage lands with `required_fields = '{}'` and `max_dwell_days = NULL`, so no move is gated and no card rots until someone ticks a box in Pipeline settings. Dark by data rather than by flag. The only visible change on deploy is that the lost-reason dialog now renders through the shared `Button` components.
