## Description

## What & why

Builds out the observability layer into a live, operator-facing view of **every agent and model across the whole platform** — chat AND every app (email, tasks, …) — with cost, live status, and per-agent error drill-down. Complements the existing post-hoc E2 debug layer (`agent_run` + `/debug`) with the *live* signal.

## Highlights

- **Live activity bus** (`acb_common.activity`): a global `cc:activity` Redis stream. `publish_activity()` is best-effort, non-blocking, never raises; presence keys track in-flight runs and self-heal via TTL.
- **Universal, zero-touch app coverage:** activations are published at the shared choke points, so coverage is automatic:
  - Agent lifecycle — the executor run boundary + `copilot_chat` (the default orchestrator bypasses `run_agent_stream`, so it's instrumented explicitly).
  - Model calls — `acb_llm._emit_usage`, `acompletion_with_fallback` (email/tasks, attributed by module via `_infer_app_source`), and **`v1_compat`** — the OpenAI-compatible endpoint every MAF/Copilot agent POSTs through, which previously emitted nothing.
- **Live LLM cost:** every call is priced via litellm (`completion_cost` → `cost_per_token`; unknown model → “—”). Folded into a per-day Redis rollup → `GET /observability/cost` (per-day, by-model, by-app).
- **Per-agent correlation:** agent runtimes stamp `X-CC-Agent`/`X-CC-Source` via `default_headers`; `v1_compat` reads them so model calls + cost attribute to the specific agent (orchestrator + email-assistant). Fail-soft — absent header falls back to `source="chat"`, so it cannot regress.
- **New `/observability` UI:** 3 views — **Office** (8-bit room: agents work at desks / sleep / error live; server rack lights up per active model; today's $ ticker), **Live feed** (stream + per-call cost), **Cost** (daily bars, by-model, by-app). Click any agent → drawer with recent runs + errors. Dependency-free (CSS keyframes, no chart lib), theme-aware.
- **Gateway API** (EXECUTIVE/AGENT-gated, like `/debug`): `/observability/activity/{recent,stream}`, `/active`, `/roster`, `/cost`.
- **Cleanup:** removed the permanently-shadowed duplicate `/v1/chat/completions` in `main.py` (v1_compat is the real implementation).

## Review findings fixed along the way

A full trace of how activations connect to the chat agents surfaced three real gaps, all fixed: (1) chat-agent model calls + cost were bypassing instrumentation via `v1_compat`; (2) the default orchestrator never showed as working (it doesn't go through `run_agent_stream`); (3) the orchestrator wasn't in the roster (not a registered specialist). See `ai-company-brain/specs/observability_e2.md` (Phases 5, 6, 6.1, 6.2).

## Notes / follow-ups

- Model calls via `v1_compat` for `GitHubCopilotAgent`-based agents (task-manager, apis-config) and Copilot-SDK mutation traffic stay app-level (their SDK client has no header hook here) — their start/end lifecycle events still carry the agent. Per-agent model correlation there needs an SDK-level header pass-through.
- Daily cost rollup is Redis-backed (~45-day TTL) — durable if Redis persists; a Postgres cost table is the durability follow-up.
