## Description

## Phase 3 · item 3.4 (review H6)

`rule_feedback` taught patterns + guidance so **future** mail classified right, but the message the user corrected **kept its wrong category chip** — the fix looked ignored until the next matching email arrived.

### What changed
- **`remove_label`** — the mirror of `apply_label`: provider-FIRST (so an authoritative round-trip provider like Outlook doesn't re-add it next sync), then a race-free `array_remove` on the local `categories` mirror.
- **`correct_applied_labels`** — after teaching, strips the label(s) the wrongly-matched cleanup rules applied and, when the correction names a cleanup rule, applies that rule's label. It reads the exact `email_actions` LABEL values the **undo path** already uses, so it strips precisely what the rule put on, and never removes a label it's about to re-apply.
- Conversation-status corrections set thread state (not a category), so they're excluded here.
- The Fix toast now says which label it removed (`Removed "Newsletter" from this email.`).

### Safety
Best-effort and self-contained: a provider hiccup updates the local mirror and returns what it managed, **never unwinding what `rule_feedback` already taught**.

### Tests
`tests/unit/test_email_fix_strips_label.py` — strips wrong + applies correct (provider-first); "none" only removes; never strips a label being re-applied; provider-auth failure still corrects the local mirror. Existing fix/pattern suites still green (16 passed); blocking ruff + full `tsc` clean.
