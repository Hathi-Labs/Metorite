## Summary

Four batches of email-app improvements from mobile/desktop testing:

### 1. Dashboard triage actions + data correctness (`28f51ad`)
- **Waiting-on-them rows gain Mark done / Dismiss** (files as FYI) — stale loops could never be closed and sat in the list (and the 104 count) forever. Row actions are now always visible on touch screens (they were hover-revealed, i.e. invisible on phones).
- **Commitments are clickable** and open the email they came from (`message_id` via LATERAL join on the linked thread).
- **Stat tiles say which clock they're on** ("last day/week" vs "all open"); list caps raised 50 → 500 with a "showing N of M" note.
- **Correctness fix:** snoozed conversations are excluded from open-loop lists and counts — the dashboard's own Snooze action used to drop a row only for the re-sync to bring it straight back.
- **Inbox quick filters:** FYI + Done chips added, and facets now tally EVERY label the rules write (custom labels included, busiest-first, capped at 40) so each gets a pill.

### 2. Structured chat cards + RulesTab header (`81e62e3`)
- The assistant chat rendered `get_rules_and_settings` as a raw `id=… | …` dump. New **RulesOverviewCard**: structured rows with name, Approval badge, a working On/Off toggle, per-rule delete, "If" condition and "Then" action chips. `list_labels` renders as coloured label chips.
- RulesTab header: "Past emails" / "Add rule" buttons no longer wrap to two lines.

### 3. Signature lives IN the draft body (`7a04b8e`)
Upstream (Gmail/Outlook) drafts looked unsigned because the signature was appended only at send time.
- Every draft-write path signs the body (idempotent, quote-aware): /draft-reply, compose-assist, /drafts/save, PUT /drafts, rule REPLY/DRAFT_EMAIL + FORWARD drafts, follow-up nudges.
- Composers seed the signature into the editable body (Gmail-style, caret at top); the separate SIGNATURE preview card is removed.
- compose-assist strips the in-body signature before routing/improving (a signature-only body routes to the full reply drafter); edit-learning diffs ignore the signature block.
- Send stays the idempotent safety net and now swaps an in-body plain signature for the rendered HTML block, so signed drafts still send multipart with the rich signature.
- `/assistant/settings` returns `signature_text` (server's plain-text rendering) so client seeding matches the backend byte-for-byte.

### 4. Rich signature editor — Tiptap v3, MIT (`a79e5f6`)
Replaces the minimal execCommand editor:
- **Tables**: insert with header row, drag-resize columns, context bar (add/remove row/col, header toggle, merge/split, delete).
- **Images**: insert by URL or upload, drag to reposition, corner-handle resize (stored as `<img width>` — honoured by mail clients).
- Font size, colour picker, alignment, lists, links w/ autolink, HR, clear formatting, undo/redo; collapsible raw-HTML source view (lossless round-trip).
- Output stays DOMPurify-sanitised; allowlist extended for resizable-table markup.
