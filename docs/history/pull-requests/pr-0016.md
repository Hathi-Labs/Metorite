## Summary

Seven feature commits that take the GTD task manager's **capture → inbox → clarify → organize** loop to feature-complete, wire in the `task-manager` MAF agent, and give the app its own settings — every slice browser-E2E-verified against a real Postgres + gateway stack.

### 1. Provider sync pull (`f4d4fe2`)
`POST /tasks/sync` pulls existing ClickUp tasks into the GTD mirror via a new `BaseTaskProvider.list_tasks` (paginated, incremental cursor). GTD lens on pulled rows: closed→DONE, backlog→SOMEDAY, mine→NEXT, others'→WAITING (+`gtd_waiting`), unassigned→team-pool NEXT. Overlay-preserving upsert — re-syncs never clobber user decisions; provider owns completion. Background pull on app open + per-workspace Sync button + `gtd_sync` agent tool.

### 2. Inbox/capture feature-complete + agent rail (`9cb2a7b`)
The server AI clarify proposal (org-knowledge capability matching, project auto-match, stage defaults) now upgrades the Clarify panel in place — human edits always win. The AssistantRail placeholder became a live chat pinned to the `task-manager` agent (email-app pattern: shared AgentChat, sessions, Mem0, live GTD persona, quick actions).

### 3. Harness Tier 1 (`3417476`)
App-level pass against awesome-harness-engineering: risk annotations on all 13 GTD tools (machine-checked invariant: **no destructive tool** — C-04), lethal-trifecta guards (SYNCED text delimited as data), the first agent-quality eval suite (which immediately caught + fixed two real heuristic bugs: substring hint matching misfiling "profile…" as REFERENCE, and duplicate-project proposals), and `tool_scope` adoption. Spec: `ai-company-brain/specs/task_manager_harness_2026-07.md`.

### 4. Mind-dump atomizer + capture dedup (`4311f41`)
`POST /tasks/ai/atomize`: a pasted paragraph becomes individual atomic captures, each judged against open items — `new` / `similar` ("same or different?" — the human decides) / `duplicate` (auto-skipped, undoable). LLM does the split + judgment; a deterministic splitter + token similarity is both the fallback and the guardrail (an unsupported LLM "duplicate" claim degrades to "similar" — a poisoned title can never silently discard a capture). Wired into sweep review, single capture (background check + resolution banner), and the agent's capture tools.

### 5. Email → task capture (`28a1037`)
The email inbox becomes a GTD capture channel: "Add to Tasks" in the email right-click context menu (single + bulk), desktop toolbar, and mobile toolbar. The LLM drafts a capture naming the ask (deterministic fallback); items land in the inbox with an `origin` link (migration 50), idempotent per email. Also fixes the GTD-audit calendar gap: a calendar decision now requires a date.

### 6. Origin through the lifecycle (`2c160a9`)
The email reference follows the task everywhere: chips on every list row, inbox-card line, clarify header, item detail — all with deep links (`/email?account=…&email=…`, consumed via `openEmailById`). Pushing an email-origin item to ClickUp appends the source reference to the description; the agent's `gtd_list` shows it too.

### 7. Per-user settings (`f0aaa5f`)
`gtd_settings` (migration 51) + `GET/PUT /tasks/settings` + a Settings dialog (email-app model-roles parity, per user): AI tier per function — assistant chat / atomizer / email drafting / clarify — with tiers + enabled-models pickers, plus capture-dedup and auto-sync toggles that actually gate behavior. Includes a proxy fix: `/api/tasks` never forwarded PUT.
