## Summary
Grounded in research (Apple's Human Interface Guidelines design principles, and Anthropic's own published research on agent harnesses for app-building), plus a real, concrete bug found while investigating.

**The bug**: `ccIcon()`/`data-cc-icon` — the icon bridge injected into every app's sandboxed frame, already documented in `design.md` (shared with the chat-artifacts system) — was never actually wired up for Custom Apps. `SandboxedHtml`'s `icons` prop needs to be pre-resolved and passed in; the Workshop preview and the published run page never did that, so every Custom App calling `ccIcon('Name')` silently got nothing back.

**Fixed and extended**:
- New `extractCcIconNames(html)` in `ccBridge.ts` (regex, pure function, unit tested) — scans an app's HTML for `ccIcon('Name')` calls and `data-cc-icon="Name"` attributes. Wired into both the Workshop's preview (`edit/page.tsx`, both desktop and the phone-frame view) and the published run page (`[slug]/page.tsx`) via `buildIconMap` — the same resolver the chat-artifacts renderer already uses.
- `lucide-react` joins the T2 default vendor cache (pinned to the exact version `workbench/control_plane` itself uses — zero runtime deps of its own) and `build_t2.mjs`'s default-mode import allowlist, so T2 apps get real icon components for free, no install step. Verified end-to-end against a live build.
- `instructions.md`: a new "Icons" bullet (T1 → `ccIcon`/`data-cc-icon`, T2 → `lucide-react` directly, never emoji as UI iconography) and a new "Quality bar" section:
  - Anthropic's harness-design research found a generator asked to grade its own UI "confidently praises the work — even when... obviously mediocre." The actionable takeaway: actually look at the rendered preview before calling a round done, not just read back the code — ties directly to the desktop/phone preview toggle shipped earlier. Four judging criteria from that research: coherent, original (avoid "purple gradients over white cards" — the canonical AI-output cliché named in that research), craft, functional.
  - Apple's HIG principles (clarity, deference, hierarchy, consistency) translated into concrete rules already load-bearing elsewhere in the file: one primary action per view, hierarchy from size/weight/contrast not color alone, chrome defers to content, generous spacing, motion only with purpose.
