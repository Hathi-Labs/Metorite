## 1. Keep mobile recordings alive — screen wake lock + backgrounding safeguard
Best-effort resilience for long recordings on phones, within what the web platform allows.

**Screen Wake Lock:** request `navigator.wakeLock('screen')` while recording so the phone doesn't auto-lock mid-meeting (browsers suspend mic capture when the screen sleeps). Released on pause/stop; re-acquired on resume and whenever the page returns to the foreground (the OS drops the sentinel when hidden). Fully best-effort — silently no-ops where unsupported (older iOS, Firefox) or denied.

**Backgrounding safeguard:** watch `document` visibility. When the app is hidden (screen off / switched away) we force `MediaRecorder.requestData()` and flush the upload queue, so whatever was captured is uploaded *before* the OS freezes the tab — a truncated recording instead of a lost tail. Surfaced honestly in the UI: a standing "keep this app open" reminder during recording, and, if the app was ever backgrounded mid-recording, a warning that capture may have paused and the transcript could have a gap.

This does **not** make iOS record in the background (the platform forbids web mic capture when backgrounded) — it maximises reliability while the app stays open and is honest about the limits.

Files: `recorder.ts` (wake lock + visibility), `recordingStore.ts` (`hidden` / `wasBackgrounded` state), `session/[id]/page.tsx` (reminder + warning banners).

## 2. Docs: meeting-bot capture (§3.13 + decision D10)
Records the design for remote-call capture (join a Meet/Teams/Zoom call as a bot):
- **Phase 1 — on-demand "join by link"** (near-term): paste a meeting URL, a bot joins and feeds the existing transcription/diarization/summary pipeline.
- **Phase 2 — calendar auto-join** (deferred): per-meeting opt-in toggle + rules; documented for later, explicitly out of scope for now.

Captures the hard dependency (the gateway can't join a call itself — needs a pluggable `bot_provider` backend), provider trade-offs (Recall.ai managed vs self-hosted Vexa/Attendee) and why a managed API is the only fit for the single 4 GB VPS, the dock-based UX, and the consent posture.
