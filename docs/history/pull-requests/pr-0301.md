## Description

Logos and icons silently vanished from full-page artifacts. Four separate causes, all fixed here.

### 1. Full-page frames received no icon map at all

Inline generative-UI cards declare their icons via `props.icons`, but a full-page artifact is just a file with nowhere to declare anything — so `DocumentPane` and `ArtifactViewerModal` passed no `icons` prop. `ccIcon()` returned an empty string and every `[data-cc-icon]` placeholder stayed empty.

Both viewers now derive the map from the source itself via `iconsUsedIn()`, which recognises all three spellings — the `Icon` component's `name` prop, a raw `data-cc-icon` attribute, and a `ccIcon()` call in script. Only referenced icons are injected, so the `srcDoc` stays small.

### 2. The kit had no `Icon` component

A React artifact had no supported way to ask for an icon. Added an `Icon` component (`name`, `size`) to `@cc/ui`.

### 3. Remote image URLs fail silently and nothing said so

The sandbox CSP is `img-src data:`, so every CDN logo, favicon service and remote image tag is blocked with no visible error. The linter only ran on `.html`, so a React artifact with a remote logo got no warning whatsoever.

Added `lint_artifact_source()` for `.jsx`/`.tsx`, plus a `design.md` section spelling out what actually works: the `Icon` component, `data:` URIs, and the kit's own blocks.

### 4. Two render defects from the same reports

- `cc-badge` was scoped to `.cc-phase`. Used anywhere else it either came out unstyled or, as a bare grid child, stretched to full row height — a solid block of primary colour instead of a chip. It is now a standalone chip that holds its size in any grid or flex parent.
- A callout's `cc-tag` stretched the same way.
- A stat's unit jammed against the number with no gap, and inherited `line-height: 1` so a wordy unit ("risk-adjusted", "near-close") collided with the digits above.

### Note on module layout

`iconsUsedIn` lives in its own `iconRefs` module: it is pure string scanning, and keeping it free of the `react-dom/server` import lets it be tested under the node-environment vitest config.

### Known limitation

`iconsUsedIn` only matches literal names — resolution happens on the parent before the frame runs, so an icon name computed at runtime still renders empty. Documented in the module and covered by a test.
