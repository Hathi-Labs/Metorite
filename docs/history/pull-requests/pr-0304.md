## Description

Adds **Workflows** — a visual builder that runs deterministic automations over the existing agent fleet, integrations, and code modules. Spec: `ai-company-brain/specs/workflows_app.md` · RFC: `docs/workflow-editor/README.md`.

Ten commits of Workflows work (82 files) on top of earlier already-reviewed branch history; `main` is an ancestor, so this fast-forwards cleanly.

## What it is

A workflow is **data, not code** — a React-Flow graph persisted verbatim, compiled at publish time into an immutable version that runs on **MAF `WorkflowBuilder`**. There is no second runtime: constraint #6 is strengthened, not weakened. Editing never breaks a live automation, because runs execute versions, never the draft.

Every node type resolves through the platform's own registries at run time, so the builder can never offer a capability the platform doesn't actually have, and node config never holds a secret:

| Need | The node | Resolved by |
|---|---|---|
| Call an LLM | agent | live agent registry → `orchestrator.executor.run_agent` (MAF batch path) |
| Touch an external system | tool | `acb_skills` integration registry; write-class dispatches through the Action Broker |
| Custom logic | module | Module Studio — AST-validated, import-free pure transforms |
| Branch / gate / delay | condition, set, approval, wait | engine |

## Shipped features

- **F1/F2** gallery + three-pane editor (palette · canvas · inspector) with run console; duplicate, search, delete
- **F3/F4** served node catalog (never hard-coded) and `{{…}}` references with design-time validation
- **F5/F9** Test runs with live per-node status over SSE; run history, and clicking a past run replays its recorded results onto the canvas
- **F6** publish → immutable versions; rollback republishes an old version as a new one, never mutating history
- **F7 Module Studio** — describe a transform in plain English, get a validated typed Python module, test it against sample data, save it to the org library
- **F8/F10** all five trigger kinds: manual, api, webhook (per-workflow tokened URL + optional HMAC), schedule (cron scanner with CAS claims), event (platform event bindings)
- **F11** approval node — pauses the run into the **existing** `/approvals` inbox via the Action Broker; resume replays completed nodes from stored outputs, so no side effect fires twice
- **F13** workflows callable by any agent as tools
- **F14 Workflow Copilot** — describe a change in the editor, get the updated graph; modules it needs that don't exist are generated, validated, and saved automatically
- **F15** keyword capability search powering both the palette and the copilot (semantic ranking is deliberately deferred to BO‑22, platform-wide)
- **wait node** — ≤60s sleeps inline; longer pauses durably with a deadline and the scheduler resumes it, so "wait 2 days, then follow up" survives a restart

## Safety

- **Publish authority** (`workflows:publish`, migration 133) on publish/rollback/disable/enable — the acts that arm triggers to run unattended. Drafting and Test runs stay open to any member with the feature.
- **Publish gate** blocks unresolved `{{refs}}`, secret-shaped strings, and write-class nodes with no approval ancestor.
- **Auto-disable** after 5 consecutive failed runs from unattended triggers, with the reason recorded and a one-click re-enable (spec R2).
- Startup sweep marks runs orphaned by a restart as failed rather than leaving them "running" forever.
