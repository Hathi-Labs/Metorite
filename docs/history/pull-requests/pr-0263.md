## Description

The STT tier rendered **"? unknown"** and **"No key"** with a perfectly valid AssemblyAI key configured.

## One missing line caused both

`_provider_from_model()` had no `assemblyai/` branch, so it returned `"unknown"`. That cascaded:

- the provider badge showed `"unknown"` verbatim, with `?` as the fallback icon;
- `_is_provider_configured("unknown")` then looked up an env var that doesn't exist and reported the key as **absent** — so a working key looked missing.

## Why it got through

Registering a provider means touching **four** separate maps — env var, display label, model catalogue, and model→provider inference. I updated three and missed the fourth, and the miss fails **silently in the UI** rather than raising anywhere.

So the fix comes with a test that checks all four together for every catalogued STT provider (`assemblyai` and `deepgram`), including that each catalogued model id round-trips back to its own provider. The next provider can't half-register.

Also refreshed the panel copy, which still credited only Deepgram with naming speakers — AssemblyAI does it on live captions too.
