## Description

Two related asks: columns on every grouping, and a smart way to combine context/priority/energy filters without cognitive overload.

## 1. Columns on every grouping
There were **two** grouped-list components — one for Status (with columns) and one for the other lenses (plain rows). I **unified them**: `TaskListGrouped` now renders *any* grouping axis — **Status / Priority / Suggestion / Energy / Context** — with the same aligned desktop columns and multi-select. Drag-reorder stays on the **Status** axis only (you can't drag a card to change its computed priority). `LensGroupedList` is retired.

So: group by Priority (or Energy, or Suggestion) and you keep the columns. Mobile still stacks.

## 2. The filter design — how I avoided overload

Stacking three pill rows (context, priority, energy) is exactly the noise you wanted to avoid. Instead I used a **facet bar** (Linear/Notion pattern):

```
[Search…]  [Filter ▾ (2)]  [@computer ×] [🔥 Critical ×]      Group: Status ▾   Sort: Priority ▾ ⇅
```

- **One `Filter ▾` button** opens a popover with **Context / Priority / Energy** sections — each a **multi-select** checklist with live counts.
- Active values surface as **removable chips** right in the bar, so the current filter state is always visible without opening anything.
- Each facet is **OR-within** (Energy = Low OR Medium), facets **AND-across**.
- **Grouping** (how it's sliced into swimlanes) and **filtering** (what's shown) are cleanly separated — you can group by Status *and* filter to @computer + Critical.

This scales to any number of facets with no extra rows, and replaces the old context/assignee dropdowns *and* the @context pill row (one control instead of three). Assignee stays single-select and only on non-Next-Actions views.

## Under the hood
`TaskFilters` gains `contexts[] / priorities[] / energies[]` (multi-select) + `applyFilters` (OR/AND) + `activeFilterCount`.
