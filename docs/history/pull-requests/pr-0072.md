## Description

Task-manager card UX batch — the Next-Action / Inbox cards get real actions (schedule, stage, eliminate) plus right-click menus.

## What's in it

1. **Schedule on calendar button** on the Next-Action card → opens a smart Schedule popup.
2. **Right-click context menu** on Next-Action cards: Schedule on calendar · Change stage · Mark as Done · Eliminate.
3. **Right-click context menu** on Inbox cards: Clarify · Schedule · Someday/Maybe · Reference · Delete.
4. **Removed the one-click Done button**; replaced with a **stage selector** on the card — local tasks had none, now they do, and picking the *Done* stage completes the task (synced tasks show their mapped stage).
5. **Priority sub-card**: the suggestion pill now sits at the **top-right next to the priority cell badge** (was stacked below).
6. **The "Schedule" pill anywhere** now opens a popup that picks an appropriate time (today's next free slot / tomorrow / exact-time), instead of just opening the task.
7. **"Eliminate"** now opens a popup: **Delete** (with the existing confirm) or **move to Someday / Maybe**.

## How it's built

- **`lib/scheduling.ts`** — extracted the pure slot geometry (`firstFreeSlot`/`blocksForDay`/…) out of `CalendarView` so the Schedule popup reuses the *exact* calendar logic (one source of truth).
- **`SchedulePopup` / `EliminatePopup`** — global, store-driven (`openSchedule`/`openEliminate`), mounted once like `DeleteConfirmModal`.
- **`ContextMenu`** — a reusable right-click menu (the tasks app had none) following the established click-away popover pattern, with viewport-flip + Esc.
- **`useCardActions`** — one hook that turns a card's affordances into store writes, shared by the inline controls and the context menu so they never drift.
