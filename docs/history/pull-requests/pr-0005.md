## Description

## Why
Follow-up to PR #4. Two prod issues surfaced while verifying email sync:

1. **Outlook account stuck on "Provider authentication failed"** with no way to fix it. The OAuth callback rejected re-auth of an existing account (`error=duplicate`), so a stale refresh token could never be repaired from the UI ("it says it's already connected").
2. **mem0 memory extraction failing with OpenRouter `402`** ("LLM extraction failed") — it hardcoded `deepseek/deepseek-chat`, which the gateway `/v1` doesn't recognize as a tier and routed to OpenRouter (out of credits).

## What
**Email reconnect**
- OAuth callback now **updates** an existing account's credentials in place instead of rejecting as duplicate — clears the error state and resets `last_history_id` to force a full re-sync (also re-normalizes mail stored under raw provider folder IDs).
- `/email/accounts` now returns `sync_status`/`sync_error`.
- Integrations → Email: **Reconnect** button per OAuth account + inline error banner with a reconnect CTA, and the status dot turns red with "Auth error" instead of a misleading green "Active".

**mem0 tiering**
- mem0 now sends the `tier-fast` alias so it routes through the configured DeepSeek tier (matching `graphiti_client`).
