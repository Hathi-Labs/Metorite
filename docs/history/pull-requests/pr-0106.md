## Description

## What & why

Drafting a reply with the AI bar left blank ("What should this email say?" empty) returned a **502 gateway error** and produced no draft.

**Root cause:** the Next.js email proxy (`workbench/control_plane/src/app/api/email/[...path]/route.ts`) aborts every POST to the gateway after **30 seconds**, and on abort its `catch` returns `{ status: 502 }`. An empty reply body routes server-side to the heavy orchestrating drafter — memory retrieval + a routing LLM call + a specialist agent (capped at ~18s) + a `tier-powerful` generation of up to 3000 tokens — which routinely runs past 30s. (The lighter "improve existing text" path usually finishes in time, which is why only the blank case failed.) The GET handler in the same file already grants 120s for the same reason.

## Change

- Give the known LLM/agent-backed POST endpoints (`compose-assist`, `draft-reply`, `ai/chat`, `rules/generate`, `rules/run-message`, `messages/summaries`, …) the same 120s budget the GET handler uses for large downloads.
- Every other POST keeps the tight 30s abort so a genuinely hung upstream still fails fast.

One file, +33/−1. No infra change needed — the gateway is co-located at `127.0.0.1:8000`, so this proxy timeout was the sole source of the 502.

## Email-chain threading (reviewed, no change)

Also reviewed whether replies thread correctly instead of starting a new chain. They do, across all three providers: **Gmail** threads via `threadId` + matching `Re:` subject, **Outlook** uses Graph's native `/reply` + `/createReply`, and **IMAP** sets `In-Reply-To`/`References`. The send choke point resolves the thread id from the replied-to message and hands it to the provider. No fix required.
