## 🔐 The finding worth reading

**WS-6b as originally scoped would have built a forgeable budget record.** The proposed `X-CC-User` header lands on `/v1/chat/completions`, which is guarded by `require_llm_api_auth` — a **shared** token that every agent's BYOK client holds (`sk-local-dev-change-me` by default), establishing **no per-user identity**. The codebase has already been burned here: `deps.py` records that trusting a bare `X-User-Email` was "a full cross-account auth bypass".

Since WS-16's per-member budget caps are gated on exactly this record, a caller-asserted `member_email` is a budget-evasion vector baked into the schema WS-16 inherits. WS-6b is amended: `member_email` must be established **server-side** (run context, or joined via `run_id` — `agent_run` already carries `user_id`), or persisted flagged self-asserted and excluded from enforcement. Widening the guard to fix it is OWNER-GATE, since that changes auth behaviour.
