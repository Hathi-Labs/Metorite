## Summary

Three email-app improvements, batched onto one branch:

- **Full-HTML email signature** (Outlook/Gmail style): a hybrid rich-text / raw-HTML editor, the signature rendered visibly in the draft, and sent as real HTML (`multipart/alternative`) with a plain-text fallback — appended once at send time across both send paths.
- **Reply / Reply All toggle + Cc/Bcc** in the AI-draft reply card — the one reply surface that lacked them (the manual composer and Rapid Inbox already had them).
- **Fix-button honesty**: no more false "Learned…" toast when a conversation-rule fix can't resolve a thread.

## How it works

- Signature stored as HTML in `email_assistant_settings.signature` (**no migration** — column already exists).
- `build_signed_bodies()` appends the signature at send time (HTML block + stripped plain-text fallback), wired into `/send` and the native draft-send. The native draft-send routes through the signed full-send when a signature is set (it otherwise ships the stored, signature-free draft as-is).
- The AI drafter no longer bakes the signature into the body → no raw tags in the compose box, no doubling.
- Editor + preview sanitise with the DOMPurify the app already ships; **no new dependencies**.
