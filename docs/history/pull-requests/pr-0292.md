## Description

Pre-test review of the paths that actually get exercised. Both of these are in code I shipped this session, and both would have shown up on the first real meeting.

## 1. The agenda recap reported every meeting as a failure

Live coverage is held in memory and deliberately dropped when a meeting ends (`pipeline` calls `agenda_progress.reset`). The post-meeting recap then read that empty state back and rendered **every agenda item as "never reached"** — on every completed meeting, including ones where everything was covered.

Exactly inverted, on the feature I'd described as *"free, because coverage was computed during the call"*.

Fixed by reading the right source for the phase: the live buffer while the meeting runs, the stored transcript once it's over. The stored path needs no latch — a finished transcript already contains the whole conversation, so there's nothing to remember across calls.

## 2. The prep screen showed the wrong time outside UTC

It fed a `datetime-local` input a sliced ISO string, which is a UTC wall clock. A meeting set for **10:00 IST reopened showing 04:30** — and blurring the field then saved that wrong time back.

Now converted to the viewer's timezone properly. Worth noting this class of bug is invisible in a UTC-based test run, which is how it survived to here.

## Checked and found sound

- `attendees` / `agenda` JSONB columns both default to arrays, so `jsonb_array_length` in the new list query can't error on a NULL or an object
- Copilot auto-start is idempotent across reconnects (`copilot.start` guards on `is_running`)
- Band assignment puts a live meeting above "needs you", so an in-progress call can't be filed under triage

## Noted, not changed

`/notes` endpoints don't filter by `owner_email` — `_load_meeting` selects on id alone. This is a pre-existing pattern across the whole notes app, not something these changes introduced, and not a one-line fix to make safely in a pre-test pass. Flagging it rather than half-doing it.
