## Description

## Caught in post-deploy verification of #110, before it acted

The gate accepted **any** `email_thread_status` row as proof of conversation. But FYI is also the default stamp for "nothing matched" — **3,226 of the live account's 3,535 threads carry one**, newsletters included. Left alone, the deployed gate would have classified virtually the whole mailbox as conversations: an LLM determination per repeat newsletter, and every Newsletter/Receipt label suppressed in favour of FYI.

**Damage check at detection: 0 suppressed rows, 1 rule run since deploy — nothing misfiled.**

## The fix

The status-row signal now requires `NEEDS_REPLY / AWAITING / DONE` — statuses only ever written from a genuine two-way judgement. FYI rows fall through to the participation test, where a blast (external-only) stays bulk and a genuine FYI conversation (a colleague thread) still qualifies via back-and-forth.

Under the corrected definition, the real repair backlog: **309 conversation threads, 51 wearing stale cleanup chips, 16 rule-moved messages awaiting restore.**

The new test pins the FYI exclusion explicitly — including that the SQL filters it — so a future "simplification" back to `EXISTS` fails a test that explains why. 689 email tests pass.
