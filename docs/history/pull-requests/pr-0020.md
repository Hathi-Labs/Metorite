## Description

## Summary

Rebuilds the email **Reply Zero** automation view into **Rapid Inbox** — a category-based triage surface where you browse every rule category, open each email in an expandable card, draft/send a reply inline, and archive/delete without leaving the view. A second pass adds keyboard-first triage and other interaction polish drawn from inbox-zero upstream.

The internal feature key and API path stay `reply-zero` (only the UI is renamed) to avoid a cross-cutting rename through the store, mobile nav, and gateway routes.

## What changed

**Category browser**
- Category chips across the top, grouped **"Needs you"** (To Reply / Awaiting / Done) vs **"Sorted"** labels (FYI, Newsletter, Marketing, Calendar, Receipt, Notification, Cold Email), each with a live count. Conversation buckets read from the Reply Zero thread-status projection; label categories read from the message list by label (`listEmails({ label })`). Both collapse to one card type.
- Newest / Oldest / Unread sort + a per-category filter.

**Card + inline reply**
- Each email opens inline as an expandable card (like the AI Settings History/Test previews), rendering the full body via `MessageContent`.
- An inline reply composer under the card mirrors the main inbox composer: AI draft (memory + specialist agents), editable body, Save to Drafts, Send. Seeds from an existing thread draft.

**Cleanup actions**
- Per-card Archive / Delete plus multi-select bulk Archive / Delete (Inbox Cleaner parity). Conversation buckets keep Mark Done / Reopen.
- Instant, reversible archive/delete with an **Undo** toast instead of confirmation dialogs.

**Interaction polish (inbox-zero-inspired)**
- Keyboard-first triage with auto-advance: `j/k` move, `Enter` open, `r` reply, `e` archive, `#` delete, `d` done, `x` select, `[`/`]` switch category, `?` shows the shortcut legend. Acting on the focused card advances the cursor so the list empties without the mouse.
- Deterministic colored sender avatars (reusing the label palette), unread bold + dot, one-line snippet/reason preview.
- Awaiting is a follow-up lane: a "Find follow-ups" scan and nudge drafting (`draftReplySmart` follow-up).
- Loading skeletons replace the bare spinner.
