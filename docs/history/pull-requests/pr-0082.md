## Description

Follow-up to #81, found by **watching the deploy on the live account**: thread-status coverage climbed 303 → 321 and then stopped dead.

`_maybe_classify_threads` is reached through the `on_new_mail` hook, which the scheduler fires only `if new_mail`. So the classifier — whose entire job is working through a **backlog** — could only run when fresh mail happened to arrive.

On a mailbox with 3,167 unclassified threads, processing 25 per cycle, gated on inbound deliveries, it would never catch up. #81 made the backlog *reachable*; this makes it actually get *reached*.

Registered as its own `classify_threads` post-sync hook, called unconditionally alongside the digest and follow-up hooks. Cheap when idle — the selection query is indexed, returns no rows, and the hook does nothing.

Kept inside the `post_sync` registry rather than importing the gateway from the scheduler, so the C2 layering inversion stays fixed. `test_email_layering` asserts the new hook is registered.
