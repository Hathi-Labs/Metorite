## Description

feat(D29): track the agent harness — a cloud instance now inherits plan-guard and the review loop

`.claude/` was a blanket gitignore. Every checkout that was not the owner's
laptop — a cloud Claude instance, a fresh clone, a headless run, an agent's own
worktree — therefore ran with NO plan-guard, i.e. no enforcement of work_plan.md
§6's owner gates at all, plus none of the supervisor-worker agent definitions and
no /next-ticket. The control that refuses VPS reach, deploys, commits on main and
.env edits was travelling by accident, and only to one machine.

Tracked (doctrine in executable form, scanned — no secrets):
  .claude/AGENTS.md
  .claude/agents/{spec-auditor,ws-implementer,ws-verifier,diff-reviewer}.md
  .claude/commands/next-ticket.md
  .claude/hooks/{plan-guard.mjs,plan-guard.test.mjs,rtk-bash.sh}
  .claude/settings.json

Still ignored (local or derived), each with its reason written into .gitignore:
  settings.local.json   per-machine permissions, may name local paths
  worktrees/            ephemeral full checkouts made by parallel agents
  scheduled_tasks.lock  runtime state
  skill-observations/   local observation logs
  skills/               third-party skill bundles (impeccable v3.9.1) — tooling a
                        developer installs, not project doctrine

Derived indexes stay ignored and get REBUILT: the CodeGraph symbol index would be
large, churn on every commit and conflict on every merge. Its config (.mcp.json,
codegraph.json) was already tracked, so a fresh environment installs the tool and
builds its own index. The general rule, now written down: anything derivable from
source is rebuilt on the new machine; only sources of truth are tracked.

The fence (R7 — a rule names its enforcing test): `node
.claude/hooks/plan-guard.test.mjs` runs BLOCKING in pr-check's lint job, 21 cases.
Break the guard and CI goes red, instead of the guard silently permitting
everything on a machine nobody is watching.

Recorded as D29 in work_plan.md §3 and engineering_practice.md §5.1.
