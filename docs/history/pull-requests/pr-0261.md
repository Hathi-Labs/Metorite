## Summary

Follow-up to the earlier "chat-in, read-only-code-out" design discussion: Advanced now gets real hand-editable code instead of a read-only `<pre>`, plus a Simple/Advanced toggle so casual users keep the original chat+preview-only experience by default.

**Backend** (`gateway/routes/apps/files.py`) — a `PUT` write endpoint already existed (scaffolded, never wired to the frontend); this adds what was missing:
- `DELETE /{slug}/files/content` — same edit-gating + containment guard as the existing endpoints. Disk-only; the `app_files` store's reconciliation rides the caller's follow-up `POST /sync`, matching `write_app_file`'s own stance.
- `POST /{slug}/build` — reruns `build_t2.mjs` for T2 apps (resolved from `entry.startswith("dist/")` — the same signal every other backend path already uses, never the `tier` display field), so a manual `src/` edit's `dist/bundle.html` actually reflects it. Clean no-op for T1 apps. Resolves the build script via the same agent clone-cache lookup the loader itself uses.

**Frontend** (`edit/page.tsx`) — replaces the flat read-only file list with a real hierarchical file tree, Monaco editor (save button + Cmd/Ctrl+S), new-file/delete-file actions, and a localStorage-persisted Simple/Advanced toggle. Saving a T2 app's `src/` file triggers a rebuild + preview refresh; build failures surface inline instead of silently leaving a stale bundle.

**`instructions.md`** — the app-builder was telling itself to ignore `inputs/` as a generic "leave platform folders alone" carve-out, never updated for the fact that it's also where a user's chat upload lands. Fixed to say uploads should actually be used (base64 data URI — the sandboxed `srcDoc` runtime has no file-serving path for a relative path to resolve against).
