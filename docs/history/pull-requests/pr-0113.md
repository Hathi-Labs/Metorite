## Description

## Found while verifying the repair the user asked for

The repair sweep and the Email Cleaner **fought each other, live**:

```
07:24:26  repair strips stale Receipt/Marketing chips (12 threads)
07:25:41  email.cleanup_sweep  scanned: 566, applied: 36   ← re-labels them
07:31:12  email.cleanup_sweep  applied: 0                  ← steady state restored
```

Root cause: most messages of a statused thread legitimately carry **no chip** — the status label sits on the latest inbound message only. The sweep read those bare messages as "uncategorized" and projected the sender's category straight back on. Each system was correct by its own definition; the definitions disagreed about who owns a conversation's messages.

## The fix

The armistice line goes where every other scope decision already lives — `_CLEANUP_SCOPE`: messages of `NEEDS_REPLY / AWAITING / DONE` threads are not the cleaner's to label; the thread's status **is** their classification (#110).

**FYI is deliberately absent from the exclusion**: it's also the default stamp for "nothing matched" (#111), so excluding FYI threads would put 3,226 of the live account's 3,535 threads — newsletters included — beyond the cleaner's reach. The test pins both directions.

690 email tests pass. After deploy: re-run `scripts/repair_conversation_threads.py --apply` (third pass) and verify the chips survive a sweep cycle.
