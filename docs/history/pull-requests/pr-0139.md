## What this is

The first slice of the Phase 2 "converge the seams" work — plus an important
correction: **re-auditing Phase 2 against the code showed the plan was badly
stale.** Several items were quietly completed alongside Phase 1 / migrations
88–90 and never struck. This PR ships the one clean safe-dedup that genuinely
remained, and records the true state.

### 1. `provider_session()` — 2.11 (partial: helper + request paths)

The instantiate → `authenticate()` → `_persist_rotated_creds` dance was
hand-copied at every provider call site, each a chance to forget the persist
and drop a refreshed OAuth token (next request then re-auths from a stale
refresh token and eventually fails). Now in ONE place — an async context
manager that:

- loads the provider (user-scoped, 404 on miss), authenticates, and persists
  rotated creds in a `finally` **only on a clean exit** — never after the body
  raised (a half-failed request must not commit a token write onto a
  rolling-back session). Preserves the pre-refactor "persist after the work
  succeeds" ordering exactly; the caller still owns `db.commit()`.
- `require_auth=True` → HTTP 401 on auth failure (send/draft write paths);
  `require_auth=False` → yields `authed=False` so best-effort readers branch.

**Converted (clean user-scoped request paths):** `hydrate_message_body`, the two
draft-create handlers, the digest test-send, mailto-unsubscribe. **+6 unit tests**
covering persist-on-clean-exit, no-persist-on-raise, auth gating, and scope.

**Deliberately deferred to Tier A** (documented in the plan): the large `/send`
handler (persist sits mid-body among post-send learning) and the
background/scheduler jobs (digest scheduled-send, cleaner sweep, senders
categorize) — those query by `account_id` with no user, so they need an
unscoped loader variant + a live sync-cycle to validate.
