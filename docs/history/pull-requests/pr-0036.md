## Description

## Problem

`github-copilot`-runtime BYOK agents (e.g. project-manager) failed in chat with a misleading *"GitHub Copilot session error: Authorization error, you may need to run /login"*. The GitHub token is not the cause — BYOK model calls route to the gateway `/v1`, and the orchestrator's BYOK provider builders presented the wrong internal credential, so the gateway rejected them and the Copilot session surfaced the generic auth error.

## Root cause

The gateway's `/v1` guard (`acb_auth.require_internal_auth`) resolves its expected token as `gateway_internal_token` → `litellm_master_key`. The BYOK builders presented `litellm_master_key` only. When a deployment sets those to different values, the call is rejected.

## Changes

**BYOK internal-token precedence (the fix)**
- New `Settings.gateway_internal_token` (reads `GATEWAY_INTERNAL_TOKEN`).
- Every BYOK/internal `/v1` caller now presents `gateway_internal_token or litellm_master_key or "sk-local"`, mirroring `require_internal_auth`, so BYOK always sends the credential the gateway expects. Sites: `executor.py` (sub-agent, early BYOK, both write_artifact tokens), `_model_resolution.py`, `agents.py`, `mutation.py`.

**ClickUp "not connected / not fully configured" (Agents view)**
- `_is_configured("clickup")` is intentionally `False` (ClickUp is multi-account via `task_accounts`). The APIs tab overrode this client-side; the Agents view didn't. Now resolved from the real `task_accounts` count server-side so both surfaces agree.

**De-hardcode tier/model references**
- Consolidate the tier-alias vocabulary to the single canonical `acb_llm.client._TIER_ALIAS_MAP` (was re-listed as literals in `_model_resolution.py` and `settings.py` ×2).
- Fix malformed model defaults that no tier resolves to: `mutation_model` `openai/tier-powerful` → `tier-powerful`; `.env.example` `COPILOT_MODEL` `tier2-gemini` → `tier-balanced`.

## Not changed (deliberately)
- Tier→model routing is already dynamic (`infra/litellm/config.yaml` + DB `tier_overrides` + `set_tier_model`).
- Settings model-picker catalogs are already live-fetch/cache-backed with the static lists as never-empty fallbacks; a fully-dynamic-only rewrite would risk empty pickers on provider outages.
