## Description

Recreated from #48 after its stack (#46, #49) merged; rebased onto `main` so the diff is only this feature.

## 1. Priority & Engage show only tasks assigned to me on ClickUp

- **Engage** was already `NEXT & isMine`.
- **Priority** also showed `WAITING` tasks delegated to **others** (`is_mine=false`) — not assigned to me, so they now drop out. Priority = `isMine & (NEXT | WAITING)`. `viewCounts` mirrors the filter.

### The "assigned to me" mechanism is sound (and now locked)

`isMine` = my ClickUp user id (from `verify()` → `GET /user`) ∈ the task's assignee ids, computed in `sync.map_pulled_task`. New tests lock the parts that could silently break it:
- **Type-robust match** — numeric assignee id `42` matches string `"42"` (both stringified). ClickUp returns numeric ids, so a strict `==` would silently drop every one of my tasks out of Priority/Engage.
- **No false positives** — a blank/missing id never matches.
- **Authoritative source** — the "me" id is ClickUp's own user id.

## 2. @context pills on Next Actions (Engage-style)

New `ContextPills` row in the Next Actions header — **All** + one pill per @context with tasks (+ the **@no context** bucket), counts included. Selecting a pill sets `selectedContext` — the same signal the left-sidebar drill-down uses — so pills and sidebar stay in lock-step. Replaces reaching for a dropdown; the sidebar drill-down stays as-is.
