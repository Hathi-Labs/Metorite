## Description

Reported: no way to stop a notetaker mid-meeting from the app. Confirmed, and it's specific.

## The gap

The only stop control for a bot was a small square icon inside the "notetakers in meetings" strip on the library page — not somewhere anyone looks mid-call. The **live console**, which is where you actually are while a meeting runs, had none at all.

In-app recording was already fine: `RecordingDock` is mounted globally in `AppShell` and carries stop/pause everywhere. This gap was specific to bot sessions.

## The fix

The console header now ends the session, branching on source because the two stop differently:

- **Bot** → `stopBot()`, which has the provider leave the call
- **Browser** → the recording is owned by the tab that started it. Same tab: stop it directly. A different tab or device: say so plainly rather than pretending the button worked

Confirmed before acting, because it isn't undoable — the bot leaves the call and can't be sent back into the same session. The confirm also states that audio captured so far still gets transcribed, so "stop" doesn't read as "throw away".
