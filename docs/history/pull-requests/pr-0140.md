## Description

## What

Tier-A structural convergence, item **2.2**. The match→resolve half of the
classification pipeline was already one place (`classify_matches`); this collapses
the **apply+watermark** half, which was hand-rolled at **four** sites — the
single-message re-run, process-past, the live runner (`_run_rules_job`), and the
PENDING-execution retry. Each re-implemented the apply loop, the "no rule matched"
SKIPPED row, and the permanent `rules_processed_at` stamp with its "only when the
run could act" guard — four chances for one copy to drift and burn mail the run
never touched (the expired-refresh-token bug class).

### Two shared helpers now own it
- **`_apply_matches`** — the apply loop (with the `sole_match` learning guard),
  the no-match SKIPPED row, and the cold-email blocker.
- **`_stamp_processed_watermark`** — the guarded stamp (`dry_run or provider is
  None → skip`).

After this there is **exactly one** `rules_processed_at = now()` write and
**exactly one** `_apply_and_log_match` call in `runner.py`.

### Deliberate carve-out preserved
`_process_past_emails_job` still classifies **oldest-first with the raw match
helpers** (inline resolve would let a thread's oldest message decide its status —
the exact thing the live runner's newest-first ordering prevents), but now routes
its apply+watermark through the shared helpers. The runner keeps Reply Zero
projection **between** apply and stamp, so the watermark stays last.

## Behaviour
Preserved exactly — guards, ordering, dry-run / no-provider semantics, the
cold-blocker `!= "OFF"` condition. No functional change; pure convergence.
