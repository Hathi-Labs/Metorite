## Description

## Why
The AI planner **already** respects protected time — lunch and recurring "Block" windows are added to the busy set before packing, so no task ever lands on them (regardless of whether the LLM ran). But none of that was **visible** on the calendar, so it looked like the day was being filled wall-to-wall no matter what you'd set. This surfaces the reserved time and locks the behaviour in with tests.

## What
Reserved windows now render as labeled bands on the day/week grid:
- **Protected lunch** and recurring **Block** windows (gym, family, hobbies) → a hatched **🔒** band, the time the planner keeps free of tasks;
- recurring **Focus** windows → a subtle themed band, reserved *for a kind of work* (biased-into, not blocked).

Bands are **day-of-week aware** (empty days = every day) and mirror the gateway's `_expand_templates` / `_lunch_interval` exactly. Non-blocking, so you can still tap to manually schedule over them. Set up under **Settings → Protect a lunch break** and **Settings → Recurring windows**.

## Tests
- **Frontend** (`reservedWindowsForDay`): lunch on/off, day-of-week filter, focus-vs-block kind.
- **Backend**: lunch + a recurring block carved out of `_free_intervals`; a focus window stays a bias not a block; weekday filter skips non-matching days.
