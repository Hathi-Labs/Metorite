## Phase 3 · item 3.5

Two knowledge-base problems, both fixed **always-on** (no embedding dependency, no dormancy):

### 1. Relevance ranking (was recency first-fit)
The KB filled the 4k drafting budget by **recency**, so the newest entries won even when an older one actually answered the email. `_load_assistant_about` now takes a `query` (the message being replied to / composed) and ranks the KB by lexical term-overlap before the budget fill — pulling a wider recency window (40) so there's something to reorder. No query → recency (unchanged). Wired into `/draft-reply` and `/compose-assist`.

### 2. KB out of the thread-status classifier
The same enriched `about` (KB included) fed the thread-status classifier, where drafting facts are **pure noise + token cost** — that prompt only decides whether a thread needs a reply. `include_kb=False` now drops the block **and skips the `email_knowledge` query entirely** on the three thread-status determination paths in `replyzero`.

The embedding-based cosine variant can layer on later once semantic search is enabled; lexical relevance already replaces recency-first-fit today.

### Tests
`tests/unit/test_email_kb_relevance.py` — ranking surfaces the relevant entry; no-query keeps recency; ties stable; `include_kb=False` drops the block without querying the table; default ranks by query. 5 passed; classifier + draft suites green (76); blocking ruff clean.
