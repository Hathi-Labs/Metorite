## Description

## What

Completes **2.3** — the mechanical, import-only split of the two monolith modules,
in two commits:

### Commit 1 — `runner.py` → `actions.py` + `learning.py` (2,344 → 1,735)
- **`actions.py`** — the single label writer (`apply_label`/`remove_label`,
  provider-first), `correct_applied_labels` (the Fix), and the `_apply_rule_actions`
  dispatcher + helpers (sensitive-content guard, action attachments, template fill).
- **`learning.py`** — the auto-learn gate (`_is_auto_learnable_rule`,
  `_ai_confirms_sender_pattern`, `_sender_is_a_correspondent`,
  `_sender_consistent_for_rule`).
- `runner.py` keeps routes + jobs + the shared apply/watermark loop, and
  **re-exports** the moved names — lazy importers (cleaner sweep, senders, rules)
  and tests keep addressing the runner seam, and a patch on `runner.apply_label`
  still intercepts every caller.

### The one behavioural fix (planned with the split)
`_sender_consistent_for_rule` matched the sender by **substring**
(`LIKE '%sender%'`): `a@b.com` collided with `aa@b.com` / `a@b.com.mx`, so one
sender's history corroborated (or vetoed) another's — corrupting both the
consistency count and the "no other rule ever matched this sender" invariant.
Now **exact case-folded equality** on the bare address the apply loop writes.

### Commit 2 — `replyzero.py` → `chat.py` + `followups.py` (2,167 → 1,565)
- **`chat.py`** — `/ai/chat` SSE + `/ai/quick-action` + shared context builder
  (~390 lines of chat plumbing finally leave Reply Zero).
- **`followups.py`** — follow-up scan endpoint + the scheduler reminder job.
- `replyzero.py` keeps the **thread-status authority + views**. *Deliberate
  deviation:* no separate `thread_status.py` — every consumer imports the authority
  from `replyzero`, so a rename is pure churn with no concern-separation gain.

Both new route modules are wired through `automation/__init__` (94 routes verified
registering); `scheduler_hooks` imports the reminder job from its new home.
