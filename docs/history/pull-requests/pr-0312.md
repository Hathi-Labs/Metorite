## Summary

Reported: archiving a set of senders in the Email Cleaner left the rows sitting there, so the action looked like it had done nothing. Investigating turned up two genuine defects plus the scope question.

### 1. Archive was un-deleting trashed mail (bug)
A sender-wide "Archive all" carries no folder filter, so the set-based UPDATE swept that sender's **trashed and junked** mail back out into the archive — silently un-deleting mail the user had already thrown away. Archiving is now scoped to non-disposed mail; trashing keeps its full reach (archived mail is still live mail you may want to bin).

### 2. `affected` over-reported (bug)
Rows already in the target state were matched and returned, so "Archive all" on an already-archived sender claimed *"Archived 320 emails"* having moved none — and re-pushed 320 no-op calls at the provider. Every action now excludes rows it would not change; a 0 result says so plainly instead of reading as a broken button.

### 3. Archived mail now leaves the cleaner (scope change)
`/email/senders` excludes archived mail by default, alongside the trash/junk/drafts it already excluded — so archiving a sender clears its row off the list.

- `include_archived=true` restores the whole-mailbox view, surfaced as an **"Include archived"** toggle. It exists for the one case that needs it: the preset Marketing / Cold Email rules label AND archive in the same pass, so those chips only fill in with archived mail counted.
- Senders carrying a saved disposition (unsubscribed / auto-archived / approved) stay listed in either mode — their mail is archived by definition, and hiding them would empty the Unsubscribed and Auto-archive tabs, leaving the user unable to review or undo their own decisions.
- The optimistic update drops archived rows to match, and the notice reports what actually changed (including per-sender failures, which the bulk path used to swallow silently).

### 4. Provider-side archive verified and made reliable
Read both providers: **Gmail** archives by removing the `INBOX` label via `batchModify` (with a per-message fallback), **Outlook** moves to the well-known archive folder and re-keys the message id. Both are correct — the gap was purely in failure handling:

- `bulk_apply` (base + Gmail) takes an optional `failed_out` list. Failures were logged per message and otherwise discarded, so a run where every call 429'd looked identical to a clean one.
- The reconciler retries what failed (3 attempts, 2s/8s backoff) — this covers the dominant real cause, Gmail 429 / Graph 503 under a large sweep.
- What still will not apply has its **local folder reverted**. The mirror said `archive` while the provider had the mail in the inbox, and the next sync (provider is authoritative for `folder`) pulled it back minutes later — the "I archived it and it came back" symptom. The mirror now matches the mailbox.
- Outcomes are logged: `email.bulk_reconcile_ok` / `_incomplete` (with failed/total) / `_unauthed`, so a live failure is diagnosable.
