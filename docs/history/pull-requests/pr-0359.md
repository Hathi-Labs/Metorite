## Description

## What broke

The BO-23 timer was installed on the box today and **failed on its first real run**:

```
/opt/acb/app/scripts/backup_db.sh: line 142: /tmp/verify_restore.log: Permission denied
!! pg_restore FAILED — see /tmp/verify_restore.log
acb-backup.service: Failed with result 'exit-code'.
```

## Why

`--verify-restore` wrote pg_restore output to `/tmp/verify_restore.log`. Ubuntu sets
`fs.protected_regular=2`, which forbids opening an existing file in a sticky
world-writable directory owned by a different user — and **root is not exempt**, unlike
ordinary DAC permissions.

So the first manual run as `acb` created the file, and every subsequent root-run systemd
invocation hit EACCES. The dump itself was always fine; the unit reported FAILURE, which
is the worst shape for this bug — a backup that looks broken while the data is actually
there, discovered during an incident.

## Fix

The log now goes to `$DEST/verify_restore.log`, beside the dump it describes. Immune to
the ownership problem, and the evidence for a backup now travels with that backup instead
of being clobbered by the next run.

## Verification (on the box, after clearing the stale `/tmp` file)

```
Result=success
ExecMainStatus=0
public tables: live=228 restored=228
restore verified
4 backup(s) retained, 90M total
```

## How it was found

By running `systemctl start acb-backup.service` instead of trusting the timer. The unit
would otherwise have failed silently at 02:30 every night.
