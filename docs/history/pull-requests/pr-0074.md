## 1. Security (authorized fixes)

| Issue | Fix |
|---|---|
| **Cross-account mailbox takeover.** `X-User-Email` was trusted *without* the internal Bearer token. The gateway is reachable directly through Caddy, so anyone could set that header and read/send as any user. | [`deps.py`](packages/acb_auth/acb_auth/deps.py) now refuses a bare `X-User-Email` whenever an internal token is configured — the header is only trustworthy when it arrives *with* the token proving it came from the authenticated Next.js proxy. |
| **Postgres + Redis on the public internet.** Docker's `-p` publishing writes iptables `DOCKER` rules that bypass UFW, so `5432:5432` / `6379:6379` exposed both stores despite the firewall. Redis has no auth at all. | [`infra/docker-compose.yml`](infra/docker-compose.yml) binds both to loopback via `${POSTGRES_BIND:-127.0.0.1}` / `${REDIS_BIND:-127.0.0.1}`. |
| **SSRF** via unsubscribe + image proxy. | Unsubscribe uses `follow_redirects=False`; the image proxy revalidates *every* hop and now requires an authenticated caller. |
| **IDOR** on attachments. | Ownership check moved *ahead* of the Redis cache read; filename sanitised. |

### ⚠️ Deploy prerequisite — read before merging

The auth fix **fails open when no internal token is configured** (mirroring `require_internal_auth`'s existing contract) so an unprovisioned/dev gateway isn't bricked. Two consequences:

1. **Prod must actually have `GATEWAY_INTERNAL_TOKEN` set**, or the hole stays open.
2. **The Next.js proxy's token and the gateway's must match.** If they drift, legitimate proxied traffic silently becomes *anonymous* rather than erroring — the same class of mismatch that caused the earlier BYOK/Copilot `run /login` incident.

`GATEWAY_TRUST_UNVERIFIED_SSO_HEADERS=1` is a deliberate temporary rollback hatch for exactly that mismatch. It restores the vulnerable behaviour — align the tokens instead.

## 2. Refactor (behaviour-preserving)

- **C3 — one provider factory.** `email_ingestion.providers.factory.build_provider` replaces **8** inline copies; `core._instantiate_provider` adapts `ValueError` → HTTP 400.
- **H4 — `core._llm_json()` seam** de-duplicates **8** JSON-mode LLM call sites. (Guards the known DeepSeek failure mode where a missing `response_format=json_object` returns empty content.)
- **H3 — `AssistantView.tsx` split: 4833 → 234 LOC**, into `automation/assistant/{actionFormat, common, fixDialog, TestTab, HistoryTab, SettingsTab, RulesTab}`.
- Deduped `engine._fmt_recipients` → `core._fmt_addr_list`.
- Fixed a **scheduler engine leak** (`NullPool`), a manual-sync **body clobber** (`COALESCE`), and removed a dead `body_truncated` computation.

## 3. Correctness

**C1 —** the scheduler and inbound webhook paths now persist `unsubscribe_link` off the same provider message (COALESCE on update), matching manual sync. Previously a background- or webhook-synced email was silently **not** unsubscribe-eligible and **not** Reply-Zero classified — only manually synced mail was.

## 4. UX

- **Rapid Inbox removed.** Its job moves to **QuickFilters chips** layered over the normal search/filter pipeline, so it's one code path instead of a parallel one (coloured tag pills; Follow-up mirrored locally).
- **Inbox Cleaner** (`BulkUnsubscribeView`) reworked: category tabs driven by real message labels, provisional guesses dropped, Blocked / Unsubscribed / Auto-archive states shown, per-sender drill-down, optimistic row removal on trash & archive.
- **SearchBar**: coloured tag pills + From/To people search.
- Path-traversal guard on the Next proxy's email upstream URL builder.

## 5. Tests

- `test_rbac` — new secure `X-User-Email` contract, plus escape-hatch and fail-open coverage.
- `test_email_categorization` — rule-projection categorization; inferred rows reconciled.
- `test_email_search_scope` — `FOLDER_ALL_EXCLUDES` frontend↔backend parity guard.
- **`test_email_upsert_unsubscribe_parity` (new)** — asserts all three received-message ingest paths bind `unsubscribe_link`, so the C1 drift can't come back.
