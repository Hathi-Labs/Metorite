## Description

A measurement pass over the whole artifact path, looking for tokens spent without buying anything. Two real problems, both fixed; the rest measured and left alone.

## 1. `design.md` was all-or-nothing — 5,413 tokens per call

`load_artifact_kit` was built with tiered loading. `load_design_system` never was, so every caller got the entire document. ~60% of it is three reference blocks — the report kit, the data-viz blocks, the React section — and an artifact needs **at most one**. An agent that wanted the colour palette also paid for the timeline-chart markup.

This compounds: the surface-routing rule merged in #271 deliberately makes agents render more often, so the load happens more.

| Call | Tokens | |
|---|---|---|
| `load_design_system()` | **3,345** | core — was 5,413 → **−39%** |
| `load_design_system("blocks")` | 350 | `cc-report` document kit |
| `load_design_system("charts")` | 1,176 | KPI/chart/table/timeline blocks |
| `load_design_system("react")` | 670 | React artifacts |
| `load_design_system("all")` | 5,413 | unchanged escape hatch |

The core keeps what's needed on *every* artifact — palette, typography, spacing, motion, do's/don'ts + anti-slop, the lint contract, and the surface-routing rule — and names what else is available.

Chunks are cut out of the real file at load time, so there's no second copy to drift. If someone renames a heading, the markers stop matching and it **falls back to the full document** — serving too much beats silently serving an empty reference. There's a test for that.

## 2. Compile diagnostics were unbounded — up to ~3,385 tokens

`artifact_lint` caps findings at 14. `formatErrors` joined *every* esbuild error. A file with 60 bad imports returned 60 copies of the same sentence — and error text is paid for twice, once when the agent reads it and again when it re-emits the whole artifact to fix it.

| | Before | After |
|---|---|---|
| 60 bad imports | 13,540 chars / **~3,385 tok** | 1,061 chars / **~265 tok** (−92%) |
| Lines | 60 | 9 |

Three changes: de-duplicate identical messages with a `×N` count, cap at 8 distinct errors plus a remainder line, and shorten the per-occurrence allowlist message from four lines to one (the long "why" belongs in the docs, not stapled to every diagnostic). Still names the first offender, so it stays actionable.

## What I measured and deliberately left alone

- **Always-injected addendum: 5,642 tokens**, 43% artifact-related. Already scope-gated and working — a sub-agent gets **1,571**, and a scope without `emit_generative_ui` drops the UI guidance entirely. It's stable per scope, so prompt caching covers the per-turn cost.
- **No duplication** between the short per-scope blurb and the long-form guidance — they're mutually exclusive (verified, not assumed).
- **`load_artifact_kit` is already right**: 507-token index, ~60 tokens per component. It's the model the design-system tool now follows.
- **`@cc/ui` bundle cost** is unchanged and already small: an 8-component artifact is 21 KB vs 19.6 KB for bare React, i.e. the kit is ~1.5 KB after tree-shaking.

The addendum grew **+5 tokens** for the pointer that makes the cheap path discoverable — it buys back 2,068 tokens on every `design.md` load.

## Net effect

A typical artifact turn that loads guidance drops from ~11,055 tokens of input (addendum + full design.md) to ~8,992, and a turn that hits a broken compile saves a further ~3,100.
