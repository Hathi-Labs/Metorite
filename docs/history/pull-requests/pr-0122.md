## Description

## Phase 2 — 2.1 (core): manual sync stops losing refresh tokens and wiping the cursor

`trigger_sync` (manual) and `_sync_account` (scheduler) are two sync cores that had drifted. Two concrete defects on the manual path (review §3.2):

- **Refresh-token loss** — `trigger_sync` persisted a rotated OAuth token only at the *end* of the sync. Microsoft rotates the refresh token on every refresh, so any failure between auth and the end lost the new token → the account needed a manual reconnect. Now it persists **immediately after auth** (before the sync body), exactly as the scheduler does.
- **Cursor drift** — it wrote `last_history_id = :history_id` unconditionally, but Outlook runs full-snapshot with `new_history_id = None`, so a manual sync **wiped the cursor to NULL**. `COALESCE` keeps the existing one, matching the scheduler.

### Deferred (the risky remainder of 2.1)
Fully collapsing `trigger_sync` into a thin wrapper over `_sync_account`, and **reviving label-change learning on the scheduler path** (dead in production — only the manual path runs it). That needs a shared sync body / per-message hook so the pre-upsert category diff survives the email_ingestion↔gateway layer boundary — its own change, warranting live-account verification rather than a blind smoke-test-only pass.
