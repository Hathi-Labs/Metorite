# The brief contract

A brief is the input of a task. A stranger should be able to do the task from the brief alone.

## The six parts

| Part | What it holds |
|---|---|
| Objective | What the work achieves, in one or two sentences. |
| Deliverable | What exists when the work is done. Name the files, the change or the answer. |
| Done when | The test or the check that proves the work is done. A person can run it. |
| Boundaries | What the agent must not touch or decide. |
| Tools | The tools and the data the agent may use. |
| Context | Links to the records the agent needs: the spec, the related tasks, the earlier decisions. |

## Rules

- Keep each part short. Five hundred characters is a good limit.
- Write the done-when as something a person can check, not as a feeling.
- If the brief has no boundaries, the agent will invent some.
- A brief that needs a long conversation to understand is not ready.

## Check yourself

Give the brief to a new colleague. Can they start without asking a question?
