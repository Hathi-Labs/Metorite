## What

🔨 **BUILT, dark (2026-11-14, task 3160).** SKL-1, part 1: **the offer, with no model call.** After a finished turn, one card asks "Save this as a skill?". A pure rule in `lib/studio/skillOffer.ts` decides. It offers only when all of these are true. (1) The turn is finished. (2) The chat is solo, and the viewer typed the prompt. (3) The turn has three or more finished calls, and none is an error or a refusal. (4) Each call maps to a catalog row through a new `tool` field, which `actions.py` takes from `skill_packs.action_tool` (the one map). A `run_workflow` call maps through its workflow id. (5) The viewer has not answered an offer on this message. `SkillOfferCard` shows the name, the description, the instructions and each action with its class. `skillStarter.starterFor` makes the text from the viewer's typed message. The actions are the catalog ids, in call order. **No tool argument and no tool result goes into the draft.** Save sends one `POST /api/studio/skills`. That makes a private draft (D127.2), and the card then links to `/studio/skills/<id>`. Save never publishes. Dismiss sends nothing. A catalog 404 draws nothing. The slice adds no model call, no migration, no route and no chat tool. It ships dark behind `NEXT_PUBLIC_SKILL_OFFER`, default off. A turn that calls a mail or CRM tool gets no offer, because those tools have no catalog action. **Built:** each row of `GET /studio/actions` carries `tool`, which `actions.py` takes from `action_tool`. `MessageBubble` mounts the card once, under the action bar, so its late arrival moves no part of the turn. `ShowMore` cuts a long body. `AgentChat` gives each assistant turn its prompt (`promptBefore`) and the solo state on proof only (`provenSolo`): the room read answered with one member. The dock form reads no room (`compact`), so it gets no offer. Each other form reads the room. With the flag off, the solo state stays false (`offerSolo`), so no bubble draws again when the room answers. The chat keeps the typed mark on the live message only (`ChatMessage.typed`), so a reloaded turn gets no offer. Rule 3 needs positive evidence. Each result must hold the success mark of its tool at its fixed place (`SUCCESS_MARKS`, the constants of `knowledge_tools.py` and `workflow_tools.py`): the whole line at its line, or the exact start. A mark that a failed call echoes elsewhere does not count. A waited workflow run counts only when its answer holds "'): " once, holds no error, and its status part ends with `succeeded`. So a refusal in plain text, such as "The member declined. Nothing was filed.", gives no offer. A tool that two rows name maps no call. A `run_workflow` call maps only through a workflow UUID, never through a name. A call of any tool outside the catalog stops the offer, such as `ask_user`, `load_skill_tools` or a sub-agent. The member can change the name before Save. A name with no ASCII letter or digit sends a slug of its own (`fallbackSlug`). A refused Save shows member words through `skillErrors.placeOfFailure`: a taken name shows under the name box, and a stale catalog offers a reload of the actions. A refusal that the card cannot repair closes the offer, with the one next step "Make this skill in Studio". **Known limits:** a new mapped tool gives no offer until its success mark joins `SUCCESS_MARKS`. `NEXT_PUBLIC_SKILL_OFFER` is inlined at build time. So the flip is an edit of `workbench/control_plane/.env.local` on the box and a rebuild at a release slot. It turns on for every org of `STUDIO_ORGS` at once, and it has no fast kill switch: a second rebuild turns it off. **Not built:** an offer after a reload, because the history read does not carry `member_typed`, and an offer in the dock form. On the dev stack, the demo ran to the Save and the Publish. Its last step needs a model turn, and the dev stack has no model
