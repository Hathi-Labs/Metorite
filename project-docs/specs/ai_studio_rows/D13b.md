## What

🔨 **BUILT, dark (2026-11-14, task 1421).** **The file store of a rendered record, and its serve route** (migration 442, booked). Studio does NOT use `attachments`: it has no `organization_id` and no RLS (`52_gtd_attachments.sql`, BASELINE_UNSCOPED), and its route serves by `user_id`. The table `studio_record_files` holds the bytes itself: `organization_id, id, package_id, object_id, record_id, field_key, name, mime, size_bytes, content BYTEA, created_by, created_at`. It has FORCE RLS in the house idiom of `441_studio_saved_views.sql`, a composite foreign key to `studio_records` with ON DELETE CASCADE, a cap of `MAX_DOCUMENT_PDF_BYTES` (10 MB), and an index on `(organization_id, record_id)`. Expand only. `files_store.py` is the one SQL module, with `put_file` (for D13c) and `read_file`. The serve route is `GET /studio/packages/{pid}/objects/{name}/records/{rid}/files/{fid}`. It follows the door order of `invoke._check`: the owned package first (a paused one gives 423), then the install behind `PACKAGE_HOST_ORGS`, then the object (a viewer needs a declared `object:<name>.get`), then `get_record` with the viewer (C8 row rules), then `project_record` for a viewer, and last the visible field value must hold `{"id": <file id>}`. Each other failure gives 404: another org, no row access, an uninstalled or paused install, a deleted record, a hidden key, a field of a newer version, an id of another record and a bad UUID. A viewer takes the reader slot. The I1a connection gate (`STUDIO_CONNECTION_GATE_ORGS`) binds the route as it binds the door: the route calls `invoke._needs_connection` with the declared get action, and an unmet connection gives 404. The route takes the field type of a viewer from the installed version, not the draft. The route sends `inline` only for `application/pdf`, with `nosniff` and `Cache-Control: private, no-store`. One shared owner-or-viewer resolver replaces the copy in `views._reach` and keeps the paused check. No new flag: `STUDIO_ORGS` and `PACKAGE_HOST_ORGS` apply. No upload route and no action (D13c). Book check: `~/lanes/reserve_migration.sh stu-box-r1 1421` gave 442. **Built:** `infra/postgres/442_studio_record_files.sql`, `gateway/studio/files_store.py`, `gateway/studio/reach.py` (the one owner-or-viewer resolver, which `views._reach` now uses), and `gateway/routes/studio/files.py`. The route sends the 423 of a paused package to the owner only. A viewer past the reader cap gets 503 `store_busy`, the one answer that is not 404. Until C8b gives a viewer its roles, a viewer with no role reads no record of an object with `access`. Fences: `test_studio_record_files.py` and `test_studio_record_files_r8.py` (in `tests/fences.json`, key `r8`)
