# D13b

Tier: HIGH

Gate: **OPEN.** AGENT-SAFE. After D13a. The `file` field check against this table is **D13b-2** (below)

## What

**The file store of a rendered record, and its serve route** (migration 442, booked). Studio does NOT use `attachments`: it has no `organization_id` and no RLS (`52_gtd_attachments.sql`, BASELINE_UNSCOPED), and its route serves by `user_id`. The table `studio_record_files` holds the bytes itself: `organization_id, id, package_id, object_id, record_id, field_key, name, mime, size_bytes, content BYTEA, created_by, created_at`. It has FORCE RLS in the house idiom of `441_studio_saved_views.sql`, a composite foreign key to `studio_records` with ON DELETE CASCADE, a cap of `MAX_DOCUMENT_PDF_BYTES` (10 MB), and an index on `(organization_id, record_id)`. Expand only. `files_store.py` is the one SQL module, with `put_file` (for D13c) and `read_file`. The serve route is `GET /studio/packages/{pid}/objects/{name}/records/{rid}/files/{fid}`. It follows the door order of `invoke._check`: the owned package first (a paused one gives 423), then the install behind `PACKAGE_HOST_ORGS`, then the object (a viewer needs a declared `object:<name>.get`), then `get_record` with the viewer (C8 row rules), then `project_record` for a viewer, and last the visible field value must hold `{"id": <file id>}`. Each other failure gives 404: another org, no row access, an uninstalled or paused install, a deleted record, a hidden key, a field of a newer version, an id of another record and a bad UUID. A viewer takes the reader slot. The route sends `inline` only for `application/pdf`, with `nosniff` and `Cache-Control: private, no-store`. One shared owner-or-viewer resolver replaces the copy in `views._reach` and keeps the paused check. No new flag: `STUDIO_ORGS` and `PACKAGE_HOST_ORGS` apply. No upload route and no action (D13c). Book check: `~/lanes/reserve_migration.sh stu-box-r1 1421` gave 442

## Done when

A viewer with access opens the file and the bytes match. A viewer of another org, without the row or outside the install gets 404. A record delete removes the file. R8 in a private database, with `tests/unit/test_tenancy_boundary.py` updated
