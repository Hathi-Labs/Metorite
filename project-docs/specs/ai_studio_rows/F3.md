## What

🔨 **BUILT, dark (2026-11-11, Metorite task 1181).** The read runs only inside `_tool_injection._apply_tool_packs`, so only for an org in `TOOL_PACKS_ORGS` with a non-empty `TOOL_PACKS`. It also needs the org in `STUDIO_ORGS` and a member with `feature:studio`. **Built:** `skills_store.list_loadable` and `loadable_versions` read the skills that the member may load: published, with a version, and owned by the member or of visibility `org`. A `group` skill loads for its owner only, until J2 adds the group. `acb_skills/skill_packs.py` turns one version into a `SkillPack`. `action_tool` is the one map from an action to a chat tool: a door op gives the tool of its row, and `workflow:<id>` gives `run_workflow`. Each other action has no chat tool before F10, so its skill fails to load. A skill also fails to load with no instructions, a `{{` or `}}` in a text, more than 35 tools, or rules over 4,000 tokens. The match is layer (a): the name or the slug of the skill as a whole phrase in the words of the turn. `tool_packs.choose` puts the matched skills after the code packs, in the order of the skill id, in the places that the cap of 3 packs leaves. A skill pack adds no tool of its own, so a skill whose tool the run does not hold fails to load. TOF-1b changes this for a `tool:` action: the skill brings the pack of that tool (`ai_studio_rows/TOF-1b.md`). Its rules follow the rules of the code packs in the persona, so `changes_prefix` is True. `token_cost` is the length of the rules over 4. Each loaded skill writes one `executor.skill_loaded` log line with its id, version, hash, tools, cost and prefix effect, and never its text. **Not built:** a skill pack is never sticky, and `load_skill_tools` (layer (b)) never offers one. The match reads no description, because layer (a) makes no model call. No event store of the session exists yet, so the log line is the record. Published skills load as org tool packs in `tool_packs.choose`. Each skill pack states its token cost and whether it changes the prompt prefix, and packs load in a fixed order (§11.1). Each loaded skill is a session event

## Done when

A turn that matches a skill loads its actions and its rules. A skill of another member that is not shared never loads. A skill whose instructions hold an unresolved variable fails to load. The loader calls `hidden_text.strip_hidden` on each text of a skill (F1b), because a store before F1b could keep a hidden character
