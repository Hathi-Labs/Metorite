## What

**Place blocks on a page by drag** (task 3159). Rung 8. Split in two slices. **AF-11b-1 (task 3326, built dark 2026-11-14):** the pure `lib/studio/dropModel.ts`: `dropIndex` (the `to.index` that `moveCell` reads after the removal), `positionOf`, `dropVerdict`, `canDrop` and `applyDrop` (they call `moveCell` and `addCell` through `layoutAct`). A full list refuses a drop with the sentence of the button. A no-op drop changes nothing. A cross move needs two tabs of one page. **AF-11b-2 (task 3327, built dark 2026-11-15; as built below):** a drag layer ON the rows of `CellsEditor.tsx` in the Pages tab, with no second component for the same cells. A member drags a cell row to reorder it inside a list, drops it on another tab block, or drags a view chip from a strip of the draft views into a list. The drag is native HTML5, as `FieldStudio.tsx` and `KanbanBoard.tsx` do. The keyboard and phone path is the buttons of AF-8b-3b (Move up, Move down, Move to tab, Add cell, the span select), because HTML5 drag does not fire on touch. A drop is one `act((m) => ...)` that runs `drop` of the new `lib/studio/cellDrag.ts`, which asks `dropVerdict`. So it is one `editor.edit`, one Save sends one `PUT`, Revert drops it, and G5 Undo reverts the saved change. A refusal shows the sentence of the model as a `role="alert"` line (a full list says "A list holds at most 12 cells."). A `role="status"` line says each move. The drop highlight is `ring-2 ring-primary/40`, with a top or bottom border for before or after. **As built (AF-11b-2):** `cellDrag.ts` is pure (`begin`, `hover`, `leave`, `drop`, `end`, `listEnd`, `isOver`) and holds the state of a drag: what is held, the row under the pointer, and the one line. `CellsEditor.tsx` holds one `DragState` for each page card, so a drag cannot cross to another page. Each cell row has a grip handle (a `GripVertical` button, `draggable`, named "Drag cell N in <list>"). The open Layout section has a strip of one draggable chip for each view of the draft. A row, and the empty part of a list, take a drop. An empty list shows a dashed "Drop here to start this list." zone while something is held. A place that the model refuses has no ring and still takes the drop, so the member reads why. A click in the section ends the last sentence, so it never describes an old draft. `PagesTab.tsx` passes `manifest` so a hover can ask `canDrop`; the editor still sends only through `act`. On a touch screen (the `pointer-coarse` variant) the handles, the strip and the line slot are not drawn, and the buttons are the path. Fences: `cellDrag.test.ts` (the pure steps), the markup tests in `CellsEditor.test.tsx`, and the drag pins at the end of `pagesTab.test.ts` (one `act` in the drop, every drag source locked, one `moveCell(`, no touch handler, the highlight). G6 holds through the `Move to tab` menu. **Non-goals:** a new view, page or tab (AF-8), `cols` or `side`, a row-and-column grid, a tile preview (a later AF-11c, read-only), a drag between pages, touch drag, a palette outside the Pages tab, a new flag.
