## What

🔨 **BUILT, dark (2026-11-14, task 3296).** Server only. No UI, no flag, no route and no migration. **The door op `object:<name>.tree`.** With one call, the door gives one tree or the whole forest. `OBJECT_OPS` and `OBJECT_OP_CLASSES` hold `tree` as class A. `OPEN_EXECUTORS` and `_READS` in `routes/studio/invoke.py` serve it. The catalog gives one `tree` row for each object. **The input.** The body is `{root_id?, depth?, limit?}`. `root_id` is a UUID. `depth` is an `int` from 1 to 20. `limit` is an `int` from 1 to 2,000. The door refuses each other value with 422 `query_value_invalid`, before any read. It never clamps a value. So the door refuses a bool, a float, a text, a negative and a huge number. **The rights of the viewer.** `objects_store.read_tree` takes a REQUIRED `viewer`, as `query_records` does. The door passes the viewer of the session, never a value of the body. The row rule of the viewer binds each root and each step down, in the one statement. A hidden key leaves each node. A parent field that a grant can hide refuses the read with 422 `query_op_not_allowed`. **The cut subtree.** A node that the viewer cannot read is not in the answer. Its subtree is cut too, also the nodes below it that the viewer can read. A child under a hidden parent would show the id of that parent, so the walk stops there. The levels, the parent ids and `truncated` count only the nodes that the viewer reads. A `root_id` of a record that the viewer reads starts a read at that record. That root shows no parent, and its data holds the parent id, as a get does. **The answer.** It is `{nodes, truncated}`. Each node is `{record, level, parent_id}`. It holds no count of children and no path. A tree of 2,000 nodes gives `truncated` false, and 2,001 nodes give true. **Not found.** A `root_id` that names no record that the viewer reads is 404 `Not found`. This is the one answer for a record of org B, of another package, of rows that the viewer cannot read, and for no record. An object with no hierarchy is 422 `query_op_not_allowed`. **The modes.** A preview reads, as a list does. A viewer of an install (J2a) reads the tree, as it reads the aggregate (C2d-a). That viewer reads only the installed fields, and only when the installed version declares the hierarchy. A read of a viewer takes a reader slot. With `STUDIO_ORGS` off, the door is 404. **Fences:** `tests/unit/test_studio_tree_door.py` and `tests/unit/test_studio_tree_door_r8.py` (R8). `test_studio_row_rules.py` lists `read_tree` with the six. **Open:** the tree block itself (D18), a lazy load of one level, a tree read for a run with no viewer (B6a), and the `READ_SOURCE` of `realDoor.ts`. **A finding for the board.** With the planner stats of an empty table, the walk scans the hot rows once for each node. Then a read of 2,000 nodes and the write check of C18 can pass the 5 s deadline, until autovacuum analyzes the tables. The R8 suite runs `ANALYZE` first.
