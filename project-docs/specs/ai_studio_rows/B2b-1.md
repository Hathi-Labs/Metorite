## What

🔨 **BUILT, dark (2026-11-02).** The list executor of the door: `object:<name>.list`, in `gateway/routes/studio/invoke.py`, beside `object:<name>.get`. B2b elsewhere in this spec means the three rows B2b-1, B2b-2 and B2b-3. **The flow:** `objects_store.get_object_by_name`, then `objects_store.query_records` (C2a), each with the package id of the path. The org is the bound session and the member is `user.email`, never request input. Only the owner of the package reaches it, as in B2a. **The class** comes from `OBJECT_OP_CLASSES` and the declaration from the manifest, so this slice does not need B1c. **The final order of the checks:** the switch, the shape of the action, the app id, the package, the declaration, the class and the approval, as in B2a. Each one runs before the door reads a byte of the body, so a non-owner and a refused action read nothing. Then the body: the door reads `request.stream()` with no session open, because a wait on a slow client must not hold a pool connection. The read stops past `MAX_BODY_BYTES` (1 MiB), and the answer is 413 `body_too_large`. B2c may raise the cap for writes. Then the second check, in a new session: `_check` runs again, so the door reads the package as this member, then checks the declaration and the class on that fresh manifest. **The reason:** a slow client can pass the first check and hold the read open. Without the second check, it reads after it lost access or after the package changed. The owner-only rule hides this today, but J2 (sharing) and C8 (row rules) build on this door. A miss gets the same 404, and a declaration that is gone gets the same 403. An action that now names another source gets 403 `source_not_open`. Then the executor, in that session. **The input:** an empty body means `{}`. The door accepts only the keys of `studio_query.list_input_schema()`: filter, sort, limit and offset. Any other key gets 422. `limit` and `offset` must be an `int` and not a `bool`. The door checks this before the store, because `json.loads` takes `Infinity` and `paging.bounds` raises `OverflowError` on it. An `int` out of range takes the rule of `paging.bounds`, and the answer holds the values that it used. **The answer** has the shape of `RecordPage`: `records`, `total`, `total_at_least`, `offset`, `limit` and `line`. Each record has the shape of the `object:*.get` answer. An object that the package lacks, and None from the store, get 404 `object_missing`. An `ObjectStoreError` gets the same 404, because the body names no id, so a stored value caused it. **The errors:** the door catches `QueryError` before `ObjectStoreError`. Five codes get 422 `{code, message, field}`. A refused body gets the same shape with `query_value_invalid` and no field, and the door reads nothing for it. `query_timeout` gets 503 `{code, message}` with `Retry-After: 2`. The session stays usable after a refusal, and the audit row is still written. The row holds the code and no record data. **The audit:** each served or refused call writes one row. A raw fault writes none, because the session is not safe to write on. ⚠️ **The known limit:** a read holds a pool connection for up to 5 seconds. This is advisory while the surface is owner only and dark. A wider surface needs a cap of reads before it opens. **Not built:** the door op (B2b-2), an integration (B2b-3) and each write (B2c)
