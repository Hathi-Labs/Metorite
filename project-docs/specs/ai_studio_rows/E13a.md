Tier: HIGH (reads member text and webhook secrets)

Gate: AGENT-SAFE. **BUILT (2026-11-13, PR 2227).** NO flag gates the tool. It is live for members with `feature:studio` at the next release slot. Production has `STUDIO_ORGS=*` and `studio` in `TOOL_PACKS`, so it ships at the next release slot

## What

**STB-6a: read a workflow from chat** (task 3117, parent 2134, Rung 3, demo 2894). ONE read tool in the STUDIO pack: `studio_workflow_read(workflow_id="", offset=0, limit=30)`. A blank id returns a paged list from `GET /workflows`. A UUID returns one workflow from `GET /workflows/{id}`. Any other id is refused with no call. **Why one tool:** the studio pack is at its room limit of 23 tools. A Studio turn that also loads the email pack totals exactly 110 (56 base, 1 loader, 31 email, 23 studio, minus 1 specialist) against `MAX_REQUEST_TOOLS` 110. The tool is an HTTP tool, so the route gates bind and the parity fence sees it. **Non-goals:** no write tool, and never a write in the `workflows` family. The F13 in-process tools (`list_workflows`, `run_workflow`, `get_workflow_run`) stay as they are. J3c "the stop of a workflow" stays out of scope. **Files:** the studio pack tools, `packages/acb_skills/acb_skills/chat_parity.py`, `tests/unit/test_studio_workflow_tools.py`. **Design:** member text (name, description) goes into an `UntrustedFrame`. `hook_token`, `hook_url` and `hook_path` are dropped, and the output says "webhook: on". Triggers show as kind, enabled and summary. The graph shows as node counts by type only. A result carries `trigger_count`, `triggers_shown`, `versions_read`, `versions_read_cap` (20, the `LIMIT 20` of the route), `versions_shown` and a `not_shown` sentence. **Since the build (checked 2026-11-26):** the TS-1b split (task 3207) moved `studio_workflow_read` to the pack `studio-more`, so the counts of 23 and 110 above are history. PAR-8a (`chat_parity.md` §6.4) later took the `workflows` ceiling to 0.
