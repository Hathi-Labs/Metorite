# C6

Tier: STD

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-02).** No route, no flag and no UI reach it, and it needs no migration. **State machines** (§3.7 layer 2): a select field names its allowed moves, and each move may have a guard on the record. **Scope (narrowed, 2026-11-02).** Store level only: no route, no flag and no UI. No migration. **Not in C6:** a role guard waits for C8 (a declaration with a role is refused, and the message says so). A history row waits for C4. An expression, a money guard and a read of another record wait for C7. **Where it is declared.** The manifest is the one source. An object gets a `rules` list beside `fields`, and C6 lifts `rules` from `RESERVED_KEYS`. `state_machine` and `states` stay refused. The store keeps the list in `studio_objects.constraints` as a fourth kind, `state_machine`, so A5 can pass the manifest list unchanged to `set_constraints`. The manifest check calls `parse_rules` and `check_rules_fit` of `studio_rules.py`, the one parser. **The grammar.** `{name, kind: "state_machine", field, initial, moves: [{from, to, guard?}]}`. `field` is one select, not `many`, and it may be cold. `initial`, each `from` and each `to` are options of the select. A machine has 1 to 64 moves and no move twice. An object holds one machine for each field, and at most 16 rules (the C1b cap). A guard is a list of 1 to 4 atoms, and all must hold. An atom is `{field, op, value?}` with the ops eq, ne, lt, lte, gt, gte, in, is_empty and not_empty. A guard reads the merged record only. It never reads another record, another object or the clock. The ops of a type are a subset of the C2a table (`OPS_BY_TYPE`), plus not_empty. A money field takes no guard yet, and a datetime field takes no order op. **Enforcement.** `_check_records` of `objects_store.py` judges each written record from `mark.before` and `mark.after`, under the same org lock and SAVEPOINT, with no new SQL. A create takes `initial` when the field is absent, and another value is refused. An update that changes the value needs a matching move and a guard that holds. An unchanged value passes. A cleared field is refused. A stored state that is not an option is refused as the start of a move. An unchanged one passes, so an edit of another field can still save a record after an option goes. A guard value must equal the stored form of its field. A batch judges the net move of each record, so draft, then approved, then sent counts as draft to sent. A delete is not a move and has no check. A stored machine that the parser cannot read fails closed, as a stored rule of an unknown kind does. `touched_keys` answers no key and `hot_keys` answers none for a state machine, so the batch queues no SQL key check for it. **The error.** `MoveViolation(RuleViolation)` holds `rule`, `object`, `from_state` and `to_state`. It never echoes a guard value.

## Done when

A refused batch writes nothing. At least 30 new pure cases in `test_studio_rules.py`.
