## What

🔨 **BUILT (2026-11-15, task 3310), owner preview pending.** **The editor changes a record.** Rung 3. The Opus audit of 2026-11-15 split WFC-4a-2b into two rows. This row is front end only. It changes no route, no gateway, park or engine code, no flag and no migration, and `studio_write` stays in `catalog.UNOFFERED_NODE_TYPES`. **The offer:** for a package that the owner owns, the editor offers each plain `object:<name>.update` action (`verbMap` skips an action with a `set`) of an object that also declares a plain `object:<name>.list`. An update with no list shows a plain line, and the editor does not offer it. The editor never offers a delete, a read or a `set` action. **The picker, with no free text:** the owner picks the record in a `SelectButton`. It reads `object:<name>.list` through a door that `readActions(detail.actions)` builds, so the door holds reads only. The form never calls `.run(`. It reads 100 records at a time, and "Show 100 more records" reads the next page, up to offset 10,000. Each option shows `recordTitle`. A failed read shows a plain sentence and Try again. A member who is not the owner starts no read and sees the record id only. **The keys:** an update step holds exactly `package_id`, `action`, `record_id` and `data`. A create step holds no `record_id` (`CREATE_KEYS`), because publish ties no rule to the verb. A new package or a new action sets `record_id` to `undefined`, so the save drops the key. The form never writes null or an empty id. **The data:** `data` starts empty. The owner adds each field to change, from the fields that no rule fills and that are not lines. Only the added keys go into `data`, so an untouched checkbox writes nothing. An added field cannot be blank, and a step cannot clear a field. An update with no added field writes nothing, and the form says so. A value with `{{` writes nothing. **No leak:** the graph stores the record id only. No title and no value of the record goes into the config, the node label, the node summary or the approval message, and no value of the record fills `data`. The owner sees the title of a saved step from one `get` read, when the package declares `get` and the loaded page does not hold the record. A 404 says "The record of this step is gone. Pick another record." **The palette:** a second item, "Change a record", drops the same pair with no action, for the owner only. The node summary of a step with a record id reads "Changes a record after the owner approves it." `FormView` takes an optional `fieldAction`, which draws the remove control beside each added field. **Known limit:** the editor has no phone layout (row E7). **Non-goals:** no delete, no clear with null, no lines, no record id from a trigger, no server search, no route, no gateway, park or engine change, no flag and no migration. **Demo (R10):** the owner drops "Change a record", picks a package, the change action and a record by its title, adds a field with its new value, and saves the workflow
