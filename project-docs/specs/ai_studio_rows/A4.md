# A4

Tier: STD

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-01).** No route, no flag and no UI reach it, as with A3 and C1. No migration: every column exists. **Publish, version and roll back**, over `app_versions`. **The install (its scope, its end date and its removal) is WS-PKG** (`package_host.md`, D147). The organization share is J2. The review step is J2 too. **Built** in `gateway/studio/packages_store.py`, the one writer: `publish_version(db, member, package_id, notes, *, catalog)`, `rollback(db, member, package_id, version, *, catalog)`, `list_versions` and `get_version`. Each locks the package row first (`FOR UPDATE`), so two writers get N and N+1, and `UNIQUE (app_id, version)` is the backstop. **Publish** re-reads the stored draft and runs `check_manifest`. Then it runs `validate_manifest` WITH the catalog, so a colour, a px size, an unknown block, an action that the catalog does not serve or a class X action fails to publish (D12). The caller passes `catalog` as `{id: class}` from `routes/studio/actions.catalog_rows`, because a store must not import a route. The version row holds `bundle_html = ''`, `bundle_sha256` (the SHA-256 of the manifest JSON text), `scope_set_hash = ''`, `review_status = 'auto'` and `published_by`. Then `apps.status = 'live'` and `apps.live_version = N+1`. `apps.manifest` stays as it is. `live_version` is the pointer of the author only. `package_install.version` is WS-PKG. **Rollback** makes a NEW version N+1 that copies the older manifest. In the same transaction it sets `apps.manifest` to that copy (the name and the description follow) and `live_version` to N+1. ⚠️ It overwrites the draft, and the audit detail says so. A missing package or version answers None. A rollback to the live version raises. Rollback runs the same catalog checks on the copied manifest, and a refused rollback writes nothing. A `catalog` of None is refused. **Audit:** an `INSERT INTO app_audit` (kind `publish` or `rollback`) in the same transaction. The store never calls `record_app_audit`, which opens its own session. **No review:** the store never proposes `app.publish_review`, and it never updates a version row. The run-keeps-version test belongs to the first slice that runs a package workflow.

## Done when

R8: a publish makes version N+1 and `live_version = N+1`, and leaves the draft. A rollback to v1 after v2 makes v3 with the manifest of v1, and the draft equals it. A publish or a rollback never edits an old row. Org B and another member see no versions, and cannot publish or roll back. An invalid draft publishes nothing. Two writers on two connections get N and N+1. The audit rolls back with the write.
