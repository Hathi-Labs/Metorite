## What

🔨 **BUILT, dark (2026-11-14, task 3324).** **The cells of a matrix.** No migration and no flag. `group_by` is one group, or a list of 1 or 2 groups. One group and a list of 1 behave as before, byte for byte. With 2, the first is the row axis and the second is the column axis. The same field twice is refused (`query_value_invalid`). Each key follows the rules of one group: a hot field, a type of `GROUP_TYPES`, a bucket for a date, no person and no money. Each axis takes at most `MAX_AXIS_VALUES` = 20 values, and a missing value counts as one. Past it, the read is refused with `query_too_big` and a sentence that says to filter first or to bucket the date. Nothing folds, so no cell is wrong, and a matrix has 400 cells at most. The answer keeps `groups` (by the first key, with the fold of `MAX_GROUPS`) and `total` as before. It adds `cells`, a list of `{key, key2, count, values}` for each non-empty cell, in the order of the first key and then the second. A select is in the order of its options, and a missing value is last. A one-key answer has no `cells`. A second statement (`build_aggregate_cells`) reads the cells and the count of the values of each axis. It holds the row rule of the viewer in every part. So the cap counts only the rows that the viewer reads. It never shows how many values hidden rows hold. **Two checks guard the second statement.** The cells come from a second statement under READ COMMITTED, so a write can land between the two. Each cell reads the lowest and the highest currency of each money measure, and a mixed cell gives the refusal of a mixed total. A cell currency that differs from the one of the first statement is `query_timeout`. A sum of cell counts that differs from `total.count` is `query_timeout` too. A two-key answer with no cells, for example for a viewer with no read, has no `cells` key. `parseAggregate` reads that as an empty list. The cells statement also runs the `hot_or_small` guard, so a cold guard that flips between the statements refuses and never gives empty cells. **Known gap.** The matrix is a display read. The checks catch a count change and a second currency. A write of a value between the two statements can show cell sums that differ from the totals. A move of a record between cells, or a delete and an insert that net to zero, can show cells that differ from `groups`. The next read is right. The store does not use REPEATABLE READ. `_read_aggregate` does not retry the `query_timeout` raise of these checks. **Preview twin, not built here.** `sampleDoor.ts` `sampleAggregate` casts `group_by` to one object. The D20 block slice must update that twin. `_refuse_hidden_aggregate` checks both axes. A viewer with no read gets a total of 0 and no cells. The TypeScript twin `parseAggregate` reads `cells`. **Known gap:** the J2a formula gap (the values of the newest version) applies to a cell too. **Non-goals:** the matrix block UI (D20, task 2364, lane-ui), a fold of cells, a third axis, and a person or a money key
