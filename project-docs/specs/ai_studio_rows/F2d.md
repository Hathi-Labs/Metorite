## What

🔨 **BUILT, dark (2026-11-03).** **Chat tools for a skill** (Metorite task 1498). Scope (narrowed, 2026-11-03): each act of the F2b skill creator also works from chat. **Files:** in `packages/acb_skills/acb_skills/studio_tools.py`, a second tuple `STUDIO_SKILL_TOOLS` holds the three tools, and `STUDIO_TOOLS` keeps its eight read-only tools. The module adds `_get`, `_post` and `_patch` on the idiom of `_read_catalog`. `agents.py` of `agent-studio-builder` returns both tuples. `config.json`, `skill_families.py` (family `studio`, its `summary` and `description`), `tool_packs.py` (`_STUDIO_RULES`, `when`, `words`) and `chat_parity.py` follow. **Tools:** `studio_skill_list(skill_id="", offset=0, limit=0)` is read-only. It lists with `paged` (30 rows: id, name inside guillemets, state, version) or, with an id, reads one skill with its newest version. The description and the instructions sit in one `UntrustedFrame` block each. A text over 12,000 characters comes back with `truncated: true` and no text past the cut. Escapes can move that cut lower. Each read of a version gives `based_on`, the content hash of the stored body. A read measures its cut with the widest row and version, so the cut hangs on the body alone, as the hash does. `studio_skill_save(name, description, instructions, actions, skill_id="", based_on="")` creates (`POST /studio/skills`) or, with an id, adds a version (`POST /studio/skills/{id}/versions`). A version reads the newest body, copies it whole, and overwrites only the keys that were sent. The tool refuses a name with an id. A version that sends a `description` or `instructions` must send `based_on`, equal to the hash of the stored body at the save, because the sent text replaces all of it. A sent text that the read shows in part (cut, or changed by the frame) refuses first, also when the hash matches, and the refusal says to change that text in Studio. A save of the other text still works. A sent text that looks like the one-line view of a card refuses too. A missing, old or wrong value refuses and writes nothing. A create and a save of only the actions need none. In a clear chat it asks on no card. `studio_skill_state(skill_id, state)` takes `published` or `paused` and nothing else. It sends `PATCH /studio/skills/{id}/state`. **A move to published (a publish or a resume) asks on ONE card** with `request_confirmation` inside the tool, `fenced=True`, bound to the member of the run. In the UI the member clicks Publish. In chat the model calls the tool, so the card puts the click back. **Each card comes from `acb_common.card_body`** (D169 item 9). The name, the version and each action with its class are short rows, and nothing cuts them. The description and the instructions take the room that is left, and a cut card ends with `CUT_MARK`. Short rows that do not fit refuse in each chat. In a chat that `egress.chat_is_held` reads as held, a cut card refuses with `cut_refusal` and shows no card. Before a card, the tool runs the checks of the route that need no call: the moves of `TRANSITIONS`, the fields that a body must hold, the slug of a new name, the count, the repeats and the catalog of the actions, and the name and description limits of the store for a create. That catalog drops each package row of `GET /studio/actions`, because the skill route serves none. A refusal there gives the status and the text of the route, with no card. After `revised` or `stopped`, `context` holds the short rows and the line "Read the skill before you change it." After `no_card`, `context` is the card, with `truncated: true` when it is cut, and the `note` says that it is a one-line view that a save never sends back. A held refusal names, for each cut text, a size that fits. A card drops each character that shows nothing (`untrusted.is_invisible`, the variation selectors, the C1 controls and the Hangul fillers). The store keeps them, so one short row of the card counts them. In a held chat, a save or a publish of a text with a TAG character or a variation selector of the supplement refuses with no card. Since F1b (task 1555), the store refuses such a text. The tool reads the skill before the card and again after `approved`. It sends the PATCH only if the state, the version and the `content_hash` are equal. A decision of `revised`, `stopped` or `no_card` sends nothing and returns `ok: false` with the `decision`. In a clear chat a pause asks on no card. In a chat that read outside mail, save and pause ask on a card too (`write_must_show_card`, D169). They read the skill again after `approved`, and send nothing for `revised`, `stopped` or `no_card`. In a clear chat they act at once. **No tool takes an org, a member, a visibility or a confirm argument** (R5). Each tool uses the internal bearer and the `X-User-Email` of the run. **Errors:** the result is the one `_result` shape. The message of each error is the server `detail`, unchanged, with `status` 404, 409 or 422. A network miss on a write says that the write may have worked, and it names the act: save, publish, resume or pause. **Chat parity:** the six DEBT rows of P-9 leave `chat_parity.py`. `COVERED` takes `GET /api/studio/actions` (`studio_list_actions`), the two skill reads (`studio_skill_list`), the create and the version (`studio_skill_save`) and the state move (`studio_skill_state`). `TOOL_SOURCES` gains `studio_tools.py`, and `DEBT_CEILING["studio"]` becomes 0. **Residual:** `PATCH /state` and `POST /versions` take no expected version, so a small window stays between the last read and the write. Only the same member can use it. **Non-goals:** a rename, an archive, a delete, a share (J2 must then call `_close_profile_writes()` on a read of a shared skill), a version list or diff (F7), "Mira drafts" (F2c builds on the save tool of F2d), an `expected_version` on the route, an edit of `egress.py` or `HELD_WRITE_OWNERS`, any UI change, any `TOOL_PACKS` line, and any `STUDIO_ORGS` change. **Ships dark:** the pack is empty for an org outside `STUDIO_ORGS`, which is empty on every box. No switch flipped.
