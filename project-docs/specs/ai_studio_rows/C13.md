## What

It adds no route and no migration. Each batch of the store runs one more statement, to read the lines relations of its package. This is safe today, because no stored manifest held `lines` before this slice. **Line items** (task 2343). Wave 1 (D202). Child rows inside a parent, edited and saved as one: BOM lines, ingredients, order lines, a BOQ. A `lines` relation names the child object. The door saves the parent and its lines in one `apply_writes` batch (C1b), so a save holds at most 49 lines. **The field.** A lines relation is a `relation` field of the parent with `lines`, as `{"key": "lines", "type": "relation", "to": "order_line", "lines": "order"}`. `to` names a line object of the same package by its name. `lines` names the relation field of that object that points back. The field takes no `many`, `hot` or `required`, and it holds no value. `studio_fields.lines_problem` is the one fit rule, and A2 and the store each call it. An object is the lines of one parent at most. A published `lines` cannot change. **The door.** The data of a create or an update holds the lines under the key of the field: `{data}` for a new line and `{id, data}` for a changed line. A new record takes new lines only. `invoke._split_lines` refuses more than 49 lines (`too_many_lines`) and another shape (`bad_lines`), each with 422, also at the ask of a delegated write. The record is write 0, and each line is a write with `parent=0`. A refusal of a line names its place, as "Line 17 of `lines`". The answer holds the record after its roll-up, and `lines`: for each lines field, its new and changed ids in the order of the body. The audit row holds their count only. **The store.** `Write.parent` links a line to the create or the update of its parent earlier in the batch. A linked create gets the parent field from that record. A linked update must be a line of that record. Neither names the parent field. A line that names a parent by itself, on a create or a move, must name a record of the parent object of this package. One statement after the writes reads them, under the deadline of the batch. A parent of another package or another org is not found, so the store refuses the line with `field_invalid`. A parent id takes one form only: 36 lower-case characters with 4 dashes. The store refuses each other form with `field_invalid` before the statement of the write. A linked create needs no read, but its parent must still be there at the end of the batch. A refusal of a move names the write that moved the line. A stored relation that no longer fits refuses each write of its line object. **Not shipped.** A delete of a line through its parent, because a delete is class C and a save is class B, so a line goes through its own delete action.
