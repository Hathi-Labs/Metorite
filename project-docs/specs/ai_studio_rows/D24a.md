# D24a

Tier: STD

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-15, task 3343).** **The photo re-encode.** An audit of task 2368 split D24 in four rows (D24a to D24d). It found one part with no table and one with no door check. D24a is the pure part. It adds no route, no table, no migration and no flag. **Built.** `gateway/signature_image.py` gains a third kind, `capture`, and the public `encode_capture(data)`. `signature_image_worker.py` runs it in the same confined child (Landlock, seccomp, no fork). `KINDS` stays `("logo", "photo")`, so `encode(data, "capture")` gives 422 and the signature route cannot store a capture. **The rules.** The image keeps its aspect ratio, with no square crop. The EXIF orientation applies BEFORE the re-encode (MuPDF turns the page, and the child swaps the stored width and height for a quarter turn). The long side is at most `MAX_CAPTURE_SIDE`, which is 2048 px, and the scale never goes up. The child re-encodes from pixels and copies no metadata, so no EXIF, GPS or maker tag survives. The output is a JPEG when no pixel is clear, else a PNG. **The caps.** The upload cap is `MAX_CAPTURE_UPLOAD_BYTES`, which is 15 MiB. It matches the shared per-file cap, and it is not the 2 MiB of the avatar. The output cap is `MAX_CAPTURE_OUTPUT_BYTES`, which is 3 MiB. The child steps the long side down (2048, 1536, 1024), then refuses with `too_big`. The sniff accepts JPEG and PNG only. It refuses SVG, WebP and GIF before any decoder. **Verify:** `uv run pytest tests/unit/test_email_signature_images.py tests/unit/test_studio_capture_image.py -q -rs`. **Non-goals:** HEIC: MuPDF 1.28.2 does not decode it and the sniff does not know it, so the client converts first. Also out: the capture UI (lane-ui), offline capture (D26), the gallery (D19), a table, a route, a video, and a signature. `gateway/avatar.py` is not used
