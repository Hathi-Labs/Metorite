# B4a

Tier: HIGH

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-13, task 1216).** **A first-party logic module, in process.** The module is a typed function in the repository. It reads through a reader and returns PROPOSED writes. The platform applies them. **Built.** `gateway/studio/logic/__init__.py` holds the contract. `LogicModule` is frozen: a name, a pydantic input model, the `reads` (object names) and the `writes` (`(object, op)` pairs), and `run(input, reader)`. `ProposedWrite` is frozen too: `object`, `op`, `id` and `data`. `MODULES` is the registry, and **it ships EMPTY**. A test adds its own module (`test_echo`) with `monkeypatch.setitem`. The reader is a closure over `objects_store.query_records` in the same session, with the viewer of the CALLER (C8a). So a row that the caller cannot read never reaches the module. The module gets no `db`, no engine and no HTTP client. `gateway/studio/logic/apply.py` holds `run_module` and `apply_proposed_writes`. The apply is ONE `objects_store.apply_writes` call, all or none, with one `app_audit` row for each write in the same transaction (outcome `ran`, no value in the row). **Refused before a write:** a proposal that is not a list or has a bad item (`logic_bad_output`), more than the cap (`too_many_writes`), a pair outside `writes` (`logic_undeclared_write`), a read outside `reads` (`logic_undeclared_read`), and an object that THIS package lacks (404 `object_missing`, so an object of another package or org is never found). A module that raises applies nothing, and the answer is 422 `logic_failed` with no text of the error. **The door.** `logic:<name>` is a `uses` form (`parse_uses`, source `logic`, the new field `logic`). The class is B (`LOGIC_CLASS`). The catalog serves a row for each registered module, only for an org on `STUDIO_LOGIC_ORGS`. A dark org gets 403 `source_not_open`. A viewer gets 403 `read_only`, a preview too. A call that is not DIRECT gets 403 `approval_required`, and **the door builds NO card** (B4b). A preview (`preview=1`) runs the module, rolls the whole batch back, fires no record event and answers `{preview, simulated, writes}` with ids and names only. A real batch fires the C3 record event of each applied write once, after the commit, through `emit_record_event`. **Decisions.** (1) `via` is None, because the change history has no `logic` kind and a migration is not in this slice. (2) The store caps a batch at `MAX_WRITES_PER_BATCH = 50`, so a module may propose 50 writes. **Known limit: §3.7 and §19.3 (the limits table) say 5,000 proposed writes, and the store does not hold that.** A larger run waits for a decision on a bigger batch. (3) A call that is not direct gets `approval_required` and not a card. (4) The manifest has no `logic[]` key yet. The `runtime` key stays on the root (B7). The contract version stays 1, because `uses` is a plain string and the change is additive. Flag: `STUDIO_LOGIC_ORGS` (`flags.logic_allowed`, reload in `docs/flag_reload.md`). **Not built (non-goals).** No card for a batch (B4b). No MRP module (B4c). No lines (`parent`) in a proposal. No time limit and no sandbox: a module is trusted code of the repository, and `reader.__closure__` holds the live session, so B5 must not reuse that closure as its boundary and needs a process or RPC boundary. No `limits` of L6a. Fences: `tests/unit/test_studio_logic.py`, `tests/unit/test_studio_logic_r8.py`.

## Done when

A module that returns writes to two objects applies both or neither. A bad second write leaves no row. An object that the package does not hold is refused, also when another package of the org or of another org holds it. A viewer, a dark org and a call that is not direct are refused before the module runs. A preview leaves no row and no event
