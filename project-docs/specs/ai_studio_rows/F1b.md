## What

🔨 **BUILT, dark (2026-11-05): F1b-1.** F1b-2 and F1b-3 are open. **Hidden characters in a skill** (Metorite task 1555). A model reads a skill as instructions. So a character that no person sees can carry a second text into the prompt. **F1b-1** (this slice): the store refuses such a text, and the chat tools defang the read of an old row. The store does not strip in silence, because a strip changes what the owner saved and breaks the trust of `content_hash` and `based_on`. **One rule:** `packages/acb_skills/acb_skills/hidden_text.py`, with `find_hidden`, `strip_hidden`, `hidden_problem` and `body_hidden_problem`. It builds on `reply_card.is_invisible_char`: the Unicode table `Default_Ignorable_Code_Point`, U+2800, U+1D159 and category C (each control, format, surrogate, private use and unassigned code point). A new line, a tab and a carriage return are legal. U+200C and U+200D are legal between two visible characters, and a legal U+FE0E or U+FE0F counts as visible on the left. At a word end (the end of the text, or white space that a person sees), ONE joiner is legal directly after a virama (canonical combining class 9). A legacy input writes a Malayalam chillu and a Bengali khanda ta as a virama and a ZWJ, and an explicit halant as a virama and a ZWNJ. The rule refuses each other joiner: at the start, next to white space, next to a second joiner, or at a word end after any character but a virama. It refuses a Persian ZWNJ before a space, because the space already breaks the join, so that ZWNJ changes no shape. U+FE0E and U+FE0F are legal only directly after one visible symbol of category S, after one of the five emoji bases outside category S (U+203C, U+2049, U+2139, U+3030, U+303D), or after a keycap base with U+20E3 next. The rule refuses two in a row, and a selector after other punctuation, such as a period. **The store** (`skills_store._text` and `check_body`) refuses the name, the description and each string and each key of the body. **The 422 text** is one sentence: "PATH: This text holds a hidden character at position N (U+CODE). Remove it." It never echoes the text. **The route** answers 422 to a publish or a resume of a stored body, name or description with a hidden character. A pause stays open. No route renames a skill, so a skill with a hidden name cannot go live again, and the member makes a new skill. **The chat tools:** a read with an id leaves each hidden character out of the description, the instructions and the actions. It does this before the frame, the cut and the counts. The read gives a `hidden` count for each field and one note, and the tool refuses a save of such a field. A list leaves them out of the name. A save sends the stored body as it is, so the store names an old field in its 422. The checks of a held save and of a publish call the same functions, so no card shows for a text that the store or the route refuses. The notes of a read and of a refused save say that each save from chat sends the stored text back, so the member replaces the whole text in Studio first. The gateway reads stay raw, because the F2b editor must show the mark. **Cost, accepted:** the LRM and RLM marks, the Arabic marks U+0600 to U+0605 and U+06DD, the Japanese ideographic variation sequences and the tag flags (England, Scotland, Wales) fail the rule. So does a character newer than the Unicode of the runtime (Python 3.12 has Unicode 15.0), such as the emoji U+1FAE9, because the runtime reads it as unassigned. Plain Arabic, Hebrew and Japanese text works. **The rule takes, by choice:** NBSP and the other Zs spaces, U+2028 and U+2029, long runs of marks, and look-alike words of mixed scripts. **Residual risk:** each gap between two visible characters can hold nothing, a ZWJ or a ZWNJ, which is about 1.6 bits. A visible symbol adds about 1.6 bits (nothing, U+FE0E or U+FE0F), and so does a virama at a word end. So 1,000 characters of plain text can carry about 200 bytes. The rule bounds the channel to these places but cannot close it. **No migration:** the trigger `studio_skill_versions_immutable` refuses each UPDATE of a version, and the pack is dark. **Follow-ups:** F1b-2 (task 1681) adds the mark in the editor and the `skillErrors.ts` rule, with an owner preview. F1b-3 (task 1682) runs after G1c and MCP-P1b-1 merge: the card helpers of `studio_tools.py` and `gateway/app_requests.py` call `hidden_text`, and the dead smuggle code goes.
