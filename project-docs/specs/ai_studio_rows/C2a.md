# C2a

Tier: HIGH

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-01).** No route, no flag, no UI and no migration. **The object query:** filter, sort, paging, the cost guard and its errors. **Built:** `acb_common/studio_query.py` holds the grammar: the shape, the op table of each type and the caps. It holds no SQL and no gateway import. The list of B2b-1 and the chat tool pass their input through it, and `list_input_schema()` is the JSON Schema of that input. `objects_store.query_records(db, *, package_id, object_id, filter, sort, limit, offset)` is the one reader, beside the reads of C1. It answers None for an object of another package or org. `build_query` and `build_count` are pure. **The filter** is a list of at most 8 conditions `{field, op, value}`, and a record must meet each one. **The ops of each type:** text and email take `eq`, `ne`, `in`, `contains` and `is_empty`. Select takes `eq`, `ne`, `in` and `is_empty`. Number and money take `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in` and `is_empty`. Date and datetime take `eq`, `lt`, `lte`, `gt`, `gte` and `is_empty`. Checkbox takes `eq`, `ne` and `is_empty`. Another type and a field with `many` take no filter. The grammar refuses a range op on text. **The values** go through `studio_fields.check_value`, so an email compares in lower case and a select value must be an option. `in` takes at most 100 values. A money filter compares the minor amount, and it does not check the currency. A date value means the whole day in UTC. So `lte` a day is up to the end of the day, and `gt` a day is after its end. Apart from the checkbox rule, `ne` matches only a record that holds a value, and only `is_empty` (true or false) matches a record with no value. An empty text is a value. **The checkbox rule (the one exception).** The build loop decided this rule on 2026-11-02, and the owner can change it. A checkbox has two states for a member. `eq true` and `ne false` match a ticked record. `eq false` and `ne true` match an unticked record and a record with no value, because a form that does not send an unticked box writes no value. `is_empty` matches only a record with no value. **The 256-character rule:** `v_text` holds the first 256 characters. So `eq`, `ne` and `in` with a value of 256 characters or more check `data` too. `contains` checks `data` when `v_text` holds 256 characters. **The sort:** one hot field, then the record id. A text sorts by its first 256 characters. A record with no value of the sort field comes after the others, in the ascending order of its id. A checkbox field takes no sort, because `v_bool` has no index. With no sort, the order is the record id. **Paging:** `paging.bounds` gives a page of 25 records by default and 100 at most. The offset is at most 10,000. The total is exact below 10,001. At 10,001 the page gives `total_at_least` in its place. `page_line` gives the line, and it names no offset past 10,000. **One statement for a page (fix round 1).** One statement reads the page and its total, so one snapshot serves both. A write between two reads cannot put a record on a page twice. For a sort, the head reads the hot index of the sort field in order. The CTE `hc` counts the head up to the end of the page. So the tail reads only the rows that the page needs, and no rows when the head fills the page. A Sort node takes at most the rows of one page. **The candidates.** Each part of the statement reads its candidates from the hot rows of one hot condition (a time or a text match first). With no such condition, it reads the records of the object by the records index, in the order of the id. Each other condition tests the candidate id. A condition that reads `data` runs after a lookup of the record by its primary key. **The cost guard**, in three layers. (a) The caps of the shape. (b) `hot_or_small`: the grammar refuses a sort on a field that is not hot. A filter on a field that is not hot reads `data`, so it runs only when the hot filters leave at most 5,000 records. The page statement holds this count as the CTE `g`, so a write between two statements cannot pass the guard. Then the MATERIALIZED CTE `m` holds those candidates once, and `data` is read only for them. The count and the page read `m`. (c) One call has one deadline of 5 seconds. Each statement of the call, from the read of the object on, runs in a SAVEPOINT. Before each statement, the store sets the LOCAL `statement_timeout` to the time that is left. With no time left, it refuses with `query_timeout` and runs no more statements. **A field that turns cold.** The page statement counts the fields that it reads as hot and that are still hot (the CTE `v`). A field that turned cold after the store read the fields has lost its hot rows. So the store reads the fields again and runs the query once more. A second change gives `query_timeout` with the sentence "The fields of this object changed during the query. Try again." A timeout rolls back the SAVEPOINT only. The caller's transaction stays usable, and the old timeout comes back. **The six errors:** `QueryError` holds `query_field_unknown`, `query_op_not_allowed`, `query_value_invalid`, `query_not_indexed`, `query_too_big` or `query_timeout`, and one sentence. The sentence never echoes a value. A route answers 503 for `query_timeout` and 422 for each other code. **Injection:** a field key and a value are always binds. The SQL text takes a column name and an operator from a constant map only. ⚠️ **The known gap:** no `numeric` comparison is LEAKPROOF in Postgres 16. So the app role gets no index condition on `v_num`, and a number or money filter reads the hot rows of its one field (`docs/rls_and_indexes.md`). A sort on a number still reads the index in order. A checkbox filter reads the hot rows of its field too. The verifier measured a number range filter at 2.3 seconds on 600,000 records. No cap limits the records of an object after a field turns hot. A later slice fixes the gap with a migration. C2b built the group, the count, the sum and the average. B2b-1 gives the query its route

A long text matches against `data`. A sort pages each record once, with the ties in id order and the empty records last. A query of another package, object or org reads nothing.
