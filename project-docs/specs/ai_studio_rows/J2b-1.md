## What

🔨 **BUILT, dark (2026-11-13, task 3088).** **The approval for the org, path A.** Four routes in `routes/studio/packages.py` ship behind `STUDIO_ORGS` and `PACKAGE_HOST_ORGS`. Either switch off gives 404 with no session. (1) `POST /studio/packages/{id}/versions/{n}/approval`: the owner asks. The answer is 202 `{review_status: pending}`, and a second ask writes nothing. An approved or a rejected version is 409 `review_conflict`. Another member, another org and no such version get 404. The ask reads no right. (2) `GET /studio/approvals?state=pending`: a holder of `studio:publish` reads each pending version of the bound org. Each row holds the package id, the name, the version, `owner_email`, `requested_by`, `requested_at` and the full manifest with its hash. Each other caller gets 403. `pending` is the one state, and another value is 422. The one new store read is `packages_store.list_pending_versions`, at most 20 rows with `truncated`. (3) `POST .../approval/approve` and `.../approval/reject`: the route passes `user.has_permission("studio:publish")` to the store as `can_publish`. `ApprovalRefused` is 403, so a member without the right, the publisher and the owner get 403 on an approve. A version that nobody asked for (`auto`), another org and no such version get 404. A 409 there would tell a holder that a private package exists (review P3). Another state is 409 `review_conflict`. (4) The org branch of `POST /studio/packages/{id}/install`: a paused package is 423 `package_paused`, the code of the door of J3a. A live version that is not approved makes the route ask, and the answer is 202 `{install: null, review_status: pending}` with no install. A rejected live version is 409 `review_conflict`. An approved live version installs as before (201 or 200). The group and the private branches do not change. The store writes each audit row (op `package.review`) in the same transaction. No migration and no new flag. **Known limit:** the install route is the owner's. So a member without `studio:publish` can ask, but only an owner who holds the right installs for the org

## Done when

Owner A asks (202). Admin B, a holder, approves exactly one version, and a second version stays pending. Owner A approving their own version gets 403. A member without the right gets 403. A version that nobody asked for gives 404. Org B cannot see the pending list of org A. The org install answers 202 and writes no `package_install` row without an approval, and installs after it.
