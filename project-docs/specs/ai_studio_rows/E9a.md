## What

🔨 **BUILT, dark (2026-11-13, task 2376).** **The record timer and the breach run, backend only.** Parent: E9, wave 1 (D202). "Due in 4 h" on a record, and a breach starts a workflow. **Audit (Opus, 2026-11-13, on `559acf2ca`).** No migration, no flag, no tool pack, no chat tool and no UI. **The rule.** A new rule kind `timer` sits in the `rules` of an object: `{name, kind: "timer", field, pause?: {field, in: [values]}}`. `field` is a hot `datetime` field. `pause.field` is a hot `select` or `text` field. `pause.in` holds 1 to 20 values, and a select value must be an option. A timer refuses no write, and the store writes nothing for it. `objects_store._check_records` skips it. `rule_reads` and `touched_keys` give nothing for it, so it never taints a write of a viewer (C8a). Its two fields stay hot (`Rule.hot_keys`). A2 checks it through the one parser. **The trigger.** An `event` trigger with source `studio` and the filter `{package_id, object, op: "breach", timer: "<rule>"}`. Its event type is empty or `studio.record.breached`. `crud._validate_event_filter` checks the shape. The save path refuses a `timer` key outside the filter. `triggers.event_trigger_matches` never matches a breach trigger, so a record write never starts one. A save that keeps the package, the object and the rule keeps the arm time (`crud._trigger_identity`). A save that changes one of them re-arms the trigger. **The scan.** `scheduler.scan_due_timers(org)`. Only the org loop of `scan_due_waits` calls it, after `unattended.org_allowed` and `routes/studio/flags.studio_allowed`. It adds no loop. The scan arms a trigger only when it is live: enabled, published, its author owns the package, no task node, and its timer is there and fits. The arm time is the DB clock (`workflow_triggers.last_fired_at`), and `config.timer_arm` keeps the print of the timer: its due field only (`objects_store.timer_print`). A new print arms the trigger again. A new pause value does not, because it can only stop a breach. So a late rule, a late grant, a removed task node and a changed field start no catch-up storm. A read that proves a trigger not live disarms it: a disabled trigger, a workflow that is not published, a timer that is gone and a task node. A true no of the owner check disarms the trigger, and its return arms it fresh, with no catch-up. A fault keeps the arm, so it drops no breach. The resolver runs in strict mode for this (`resolve_access_in_org(strict=True)`), so a read error is a fault and never a no. Each refusal logs at most once in 10 minutes for each trigger. `crud.update_workflow` carries `timer_arm` across a save, and drops a value that the body sends. A record breaches when its hot due value is after the arm time and at or before the DB clock. Its pause field must hold no pause value. A record that leaves a pause breaches at the first scan after. One pass reads at most 50 triggers of an org and 20 breaches of each trigger, oldest due first. A breach whose due time is more than 7 days old starts no run (`TIMER_LOOKBACK_DAYS`). That bounds the walk over the fired and the paused records. The read runs under a LOCAL `statement_timeout` of 2 s (`TIMER_READ_TIMEOUT_MS`, `_time_limit` of C2). A timeout logs one line, and the scan goes on to the next trigger. A cursor moves the next pass to the next page of triggers. The read leaves out a breach whose run exists, so a fired record never holds the head of the list. Each step holds one session, and no session is open at a start. **The start.** The scan calls `service.start_run` itself, with the org of the workflow row. The delivery key is `timer:<rule>:<record id>:<due ISO>`. Migration 420 holds one run for each workflow and key, so a second scan gets `DuplicateDelivery`. A new due value starts one new run. The scan binds no tenant and never calls `dispatch_event` (H-328 part (c)). The payload holds `source`, `event_type`, `package_id`, `object`, `record_id` and `rule`, and no field value. Each member who reads the runs of the workflow reads the payload, past the row rules and `hide`. So the due time is only in the delivery key, and no route answers with a delivery key. The author of the workflow must OWN the package (`studio.access.member_owns_package`). A viewer through an install reads the package and still starts no breach run. The scan asks `members_studio_state` first, outside any session. A workflow with a task node (`_member_blind_write_nodes`) starts no run. A run cap leaves the breach due for a later pass. **Not in this slice:** the clock that stops during a pause (E9b), the bell (E9c), working hours (E9d), a breach step that writes (it needs B6, PR 2203), a UI, a chat tool, a migration and a flag. ⚠️ **For C8b.** The scan reads the record ids and the due values of each record of the object, past the row rules. So only the owner of the package hears a breach, and the owner passes each rule. A due field that a grant hides from a viewer reaches no viewer through a run. C8b must keep this rule, or add a row-rule and hide check for each record before a viewer may hear a breach. ⚠️ **The delivery keys share one space.** A hook of the same workflow takes any `Idempotency-Key`, so a caller that holds the hook token can send `timer:<rule>:<record>:<due>` first. That run then takes the key, and the breach starts no run. A later slice can give each door its own prefix. Known limits of E9a (review 2026-11-14). A member who reads runs sees `record_id` and `started_at` of a breach run. So a viewer who cannot read the due field learns the due time to within one 30-second scan. C8b gates the read of a breach run to the workflow owner, or accepts this limit. When `STUDIO_ORGS` or `WORKFLOW_UNATTENDED_ORGS` goes off and on again, the arm stays, and the breaches of the gap start runs, up to 7 days back.

## Done when

A record past its due starts exactly one run for each listening workflow, also after two scans at once and three passes. A late rule, a late grant, a changed field and a trigger that comes back start no run for a record that was overdue at the arm. A timer with no pause breaches in any state. The stored payload holds no due value and no other field value. A new pause value keeps the breach of a record that leaves the pause. A true no of the owner disarms, and a fault keeps the arm. ⚠️ Known limit: a record that stays in a pause more than 7 days past its due time never breaches when it leaves the pause. E9b moves the due time, and so it closes this. A read past its deadline starts nothing, and the scan goes on. A viewer through an install starts no breach run. A record whose pause field holds a pause value starts no run. It starts one at the first scan after it leaves the pause. A new due value starts one new run. A record due before the arm time starts no run. A record of org B never starts a workflow of org A. An org that is not on both `STUDIO_ORGS` and `WORKFLOW_UNATTENDED_ORGS` reads no trigger and starts nothing. An author who does not own the package starts no run. Demo path: the run reaches a `human_step`, and the manager gets one task
