## What

🔨 **BUILT, dark (2026-11-14, task 2354).** It is the type half of C23, with no list. **The type.** `coded` is the 24th type of `FIELD_TYPES`. The stored value is `{"system": "<spec.system>", "code": "<text>"}`. The spec key `system` is REQUIRED for this type and no other type takes it. It is 1 to 32 characters from `A-Z a-z 0-9 . _ -`. **The value check is pure.** It takes a map with exactly the keys `system` and `code`. `system` must equal the one of the field. `code` is text of 1 to 64 characters, with no control character and no space at either end. It reads no list and no database. **The flags.** `required` and `many` are allowed, as for `quantity` and `barcode`. A `many` list has no editor in the Form yet (`manyUnsupported`). `coded` cannot be hot, because it is not in `HOT_TYPES`. **A sync.** `system` is one of the parts that a manifest sync cannot change (`_FIELD_ATTRS`), because a stored value repeats the system, and a change would make each older value stale. **PKG-13.** A packaged app MAY declare a `coded` field. `REFUSED_TYPES` stays `relation`, `file` and `autonumber`. The type has no host side effect, as `quantity`, `rating` and `barcode` have none, and the declaration holds its own `system`. A value that no longer fits a changed declaration is left out on read, as for those types. **Migration 445** (booked for this slice, so check it again at merge, R1) widens the two type CHECKs, `studio_object_fields_type` and `package_field_value_field_type`, to the 24 types in the order of `FIELD_TYPES`. It adds no table. **Stack.** C23a is stacked on C15a (PR 2376), which added `autonumber` and migration 444. It widens the same two CHECKs. **C15a merges first.** **The TypeScript twin.** `fieldCheck.ts` (`coded`, the two limits), `manifest.ts`, `blocks.ts` (`FIELD_TYPE_LIST`, `extrasOf`, the one text of a value is the `code`), `draftEdit.ts` (label "Coded value"), `StudioForm.tsx` (a plain input for the code, with a hint that names the system, and the Form builds `{system, code}` from the draft), `StudioDetail.tsx` (the code in the mono face), `sampleDoor.ts`, and the golden cases of `studio_field_cases.json`. No cell edits it: `coded` is not in `INLINE_TYPES`. **NON-GOALS.** No list table, no search, no favourites, no maps, no combobox, no suggestion (C21), and no search of a company (a coded list does not join `retrieval/sources.py`). **No data of a code system ships:** no ICD-10, LOINC, SNOMED or CPT row, not even in a fixture. The tests use made-up codes such as `X-0001`. **Not built:** the package read of `studio_describe` (`_package_objects`) does not show `system`, a gap that C23b can close
