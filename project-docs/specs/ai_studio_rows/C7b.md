# C7b

Tier: HIGH

Gate: AGENT-SAFE. After C7a. The deploy applies the migration, not the builder

## What

🔨 **BUILT, dark (2026-11-03).** No route, no flag and no UI reach it. **Migration:** `338_studio_hot_relation.sql` widens the CHECK `studio_object_fields_hot_type` (expand only, R6). The number is taken at build time and must be checked again at merge (R1). **Roll-up fields.** The rule kind `rollup`, `{name, kind, target, source, via, agg, field?, where?, currency?}`: sum, count, min or max of a hot field of the child records of the same package that point to the parent through a hot relation field. **Exact and synchronous:** the store recomputes each touched parent after the writes of the batch, in the same SAVEPOINT under the org lock, then runs the formulas and the rules of the parent. The rules are `range`, a guard, and each `unique` and `group_sum_min` that reads a field which the derived write changed. A formula can read a roll-up target and fill a key. So the store refuses a child write that breaks a key of its parent, and the batch writes nothing. A move recomputes the old and the new parent, and a delete recomputes after the delete. A child write recomputes a parent only when the relation field, the read field or a `where` field changed, or on a create or a delete. At most 100 parents and 100 aggregate statements for each batch (`BudgetExceeded` past that). The aggregates, the derived writes and the key checks share the one 5 s deadline of C1b. One aggregate runs for each parent and each roll-up. The derived write of a parent is a store write: it runs the formulas again, validates, rebuilds the hot rows, sets `updated_at` and `updated_by`, and writes no history row. `updated_by` names the member of the batch. `delete_record(db, actor, object_id, record_id, *, package_id)` takes the member too, so a single delete names it on the parent. **Lock order:** the org lock, the object rows in ascending id (the parent objects join them, found from the package rules), the child records, then the parent records in ascending id. **Prerequisite, built:** `relation` is a hot type (`HOT_TYPES`, `hot_value`, the C2a ops `eq`, `ne`, `in`, `is_empty`, no sort). A UUID id has one lower-case form in the hot row. **Refused at declaration:** two hops, another package, a `many` relation, a roll-up of a roll-up (also through a formula), a target that is a `unique` key, a `group_sum_min` field or key, or a state-machine field, and a declaration on an object that holds records. A field that a roll-up reads in its source cannot turn cold (`Rule.source_keys`). **Not shipped:** an average (C2b), a backfill (C7c), a UI, a route. A money roll-up needs `currency`. A child that the roll-up counts must hold that currency, or the store refuses the write with `currency_mismatch`. The aggregate decides which children count: a child that names a parent record and meets the `where`. So a child that the roll-up leaves out passes in any currency. The store checks an update that makes a child count at that write. The store refuses a number sum that a stored number cannot hold exactly with `rollup_precision`, and not with `result_too_large`. That is a sum whose JSON number does not read back as the same value, or that needs an exponent. The message asks for fewer decimal places in the child values. No rule declares a scale for a roll-up target, so the store does not round.

## Done when

Sum, count, min and max are exact after each write, with `where`. A move, a delete and a create each leave both parents exact. Two real connections that each take 7 from 10 give exactly one success and a sum of 3. 50 child writes to one parent run one aggregate statement. A parent `range` that breaks rolls back the child write. The plan of a sum over 50,000 children shows no Seq Scan. A source in another package is refused. The store refuses a child write that breaks a `unique` or `group_sum_min` key of its parent through a formula. A child that the roll-up does not count passes in another currency. A single delete names its member on the parent. Fence: `tests/unit/test_studio_rollup_r8.py` (R8) and `tests/unit/test_studio_rules.py`
