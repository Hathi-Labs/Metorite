# F4

Tier: STD

Gate: AGENT-SAFE

## What

Skill tests on a dry-run door

**Status: F4a built 2026-11-18 (no model, no credit, no migration, no flag). F4b open.**

### The shape

A saved skill holds tests in the version body, as `body.tests`, at most 20:

```json
{"id": "t1", "input": "Add Ravi from Acme as a lead",
 "expect": [{"action": "tool:create_lead", "fields": {"company": "Acme"}}]}
```

- `id` is a unique non-empty string of at most 64 characters. `input` is a non-empty string.
- Each `expect` entry has `action` of the form `tool:<name>` and `fields`, an object of text, number, true, false or null. Nested values are refused. `fields` may be absent.
- `expect: []` means that the turn writes nothing.
- `fields` is a subset match. Each named key must equal the argument after a trim of a string. The match has no case folding, and a type that differs is no match. A key that `fields` leaves out is ignored.
- A test list of the wrong shape is reason `bad_test`. `skills_store.check_body` refuses it, in the store's own error style, after the hidden-character walk. The message names a path and never a value.

### The pass rule

The end state decides, never the words. `skill_tests.evaluate(test, calls, *, skill_tools)` reads only the calls that the dry-run door recorded. It has no text parameter. A test passes only when both hold:

1. Each call is a tool of the skill's actions. A display tool (`DISPLAY_TOOLS`) is the one exception. A call to `load_skill_tools` is an `other_action`, because the harness loads the forced skill. A read outside the skill's actions fails (owner decision). The reason is `other_action`.
2. The held writes match `expect` one to one. The reasons are `missing_write`, `extra_write` and `field_mismatch`. A detail names the key or the tool, and never a value.

F4b adds two more terms: the forced skill loaded, and the run ended before any cap.

### Reason codes

`passed`, `other_action`, `missing_write`, `extra_write`, `field_mismatch`, `cap_reached`, `call_cap`, `cost_read_failed`, `hold_unarmed`, `skill_unloaded`, `run_failed`, `bad_test`, `not_run`. `skill_tests.REASONS` holds the set, and TOF-3a uses the same one. F4a can give the first five and `bad_test`.

### Owner decisions

- A read outside the skill's actions fails the test. A display tool is excepted.
- Equality is exact after a trim. No case folding.
- The server carries `tests` forward. The route of a new version calls `skills_store.carry_tests`. A body with no `tests` key gets the `tests` of the newest version. The undo copies exactly and carries nothing. The read takes no lock. A save at the same moment may carry the older list. `"tests": []` clears them. A list replaces them. The editor form sends no `tests`, and the chat save and the undo copy the body whole.
- A change of `tests` alone returns a published skill to `draft`, as any new version does.

### F4a built

- `gateway/studio/skill_tests.py`: `parse_tests`, `evaluate`, and the dataclasses `SkillTest`, `ExpectedWrite`, `TestResult`, `SuiteResult`.
- `acb_skills/skill_dry_run.py`: `dry_run_scope` (the one setter of the mark), `DryRun`, `RecordedCall`, `HoldAndRecord` and `DryRunProvider`.
- The door runs a tool for real. The tool must be `read_only=True` and `open_world=False` in the registry. It must be no member tool, no extra-call tool, no delegation tool and no loader. Each other call is recorded with its arguments and answered with one fixed text. A tool with no registry entry is held. An unarmed door holds every call.
- The carry-forward of `tests`: `skills_store.carry_tests`, called by the route of a new version. A stored list that fails `parse_tests` is dropped, never copied.
- Fences: `tests/unit/test_skill_tests.py`, `tests/unit/test_skill_dry_run.py`.

### F4b builds

- `run_suite`, the run of each test on a real turn with the forced skill pack, in a dry-run scope.
- The attach points in `_tool_injection.py`, and the one run boundary that calls `dry_run_scope`.
- The credit cap and the call cap, with `cap_reached`, `call_cap` and `cost_read_failed`.
- The flag `STUDIO_SKILL_TESTS_ORGS`, the routes and the UI.
- The hold trusts the registry by tool name. An MCP tool that shares a registered read-only name would run for real. F4b must close this. It keys on tool identity or source, or it holds every tool that is not an action of the skill.
- A read-only tool can cost credits. `analyze_image` is `read_only=True` and `open_world=False`, and it calls a vision model. F4b must run no such tool for real, or it must count the cost against the cap.
- **F4b replaces `runs_for_real` with a frozen allowlist** (Opus review of 2026-11-18). A tool runs for real only when it is an action of the skill under test. Its identity must be on the allowlist: the `FunctionTool` of the forced pack, never the bare name. A fence tests the list. Only a GET read of a first-party store may join it. It makes no model call, no embedding call, no member ask, no card, no page move and no network write.
- **The hold must leave out `DISPLAY_TOOLS`.** `runs_for_real` does not. So `studio_plan` would write a plan record, and `render_board`, `render_tasks`, `render_timeline`, `open_in_app` and `show_view` would draw cards or move the page. These tools have `read_only=True` and `open_world=False`, and they must never run for real: `analyze_image`, `studio_plan`, the render and show tools, `search_company`, `crm_search_notes`, `get_errors` and `run_diagnostics`. Hold `remember`, `recall_*` and `query_history` until someone confirms that they make no embedding call.
- **A held call is checked against the tool schema.** The hold records the raw arguments. So a call that the real tool refuses, such as one with a missing required field, can pass a test. F4b records `valid=False` when the schema check fails. `evaluate` never matches an invalid write.
- **`expect` names the catalog action with its pinned arguments.** Generic tools such as `studio_record_create` and `run_workflow` carry the object or the workflow id in their arguments. `fields` refuses nested values. So `evaluate` today passes a record write with a wrong `data.company`, and a write of another object. F4b matches the action, its pinned arguments and its nested fields.
- **`HoldAndRecord` is the outermost function middleware.** `TestResult` carries member values in `writes` and `calls`, so the F4b store keeps codes and key names only. `carry_tests` takes the same locked read as the undo route. `parse_tests` gets a cap on `expect` entries, `input` length and `fields` count.

### The interface of TOF-3a

```
run_suite(*, org, member, skill_id, version=None, body=None, tests=None,
          inputs=(), cap=None, runner, meter) -> SuiteResult
```

`SuiteResult` holds `skill_id, version, content_hash, results, passed, credits, cap, stopped`. Each `TestResult` holds `test_id, passed, reason, detail, writes, calls, credits, model_calls, run_id`.

## Done when

A test fails when the turn calls another action. No write leaves the dry-run door. A test run stops at its credit cap
