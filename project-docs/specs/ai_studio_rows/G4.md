# G4

Tier: HIGH

Gate: AGENT-SAFE

## What

🔨 **BUILT, dark (2026-11-11, task 1189), the server half.** Preview on sample data, with a preview store and simulated sends. **Built narrowed: the door only.** A call to the one action door with `preview=1` commits no write and runs no send (`routes/studio/invoke.py`, `PREVIEW_MARKER`). Any other value of `preview` is 422 `bad_preview`, so a typo never falls through to a live write. **A write.** A create, an update or a delete runs the one write path (`_do_object_write`, with each field, rule and line check) in a SAVEPOINT that ALWAYS rolls back (`_run_preview_write`). The answer shows what the write would give, with `preview: true`, and no row of `studio_records` or `studio_record_hot` changes. The call needs no proof, opens no card and spends no request. The "preview store" is the client: it keeps the rows that the answers give, and the server keeps none. **A send.** A class B or C action of another source (a workflow, a door op such as a send, an integration) runs no executor. It answers `{preview, simulated: {action, uses, class}}`. Class X, an id outside the catalog and a class A source with no executor stay refused. **A read** in a preview is a real read with its audit row. **The audit row** of a preview write or send says `simulated` and holds `preview`, so no row says `ran`. A preview create names no record. **The event (C3 is built, and a preview emits nothing).** `gateway/studio/preview.py` holds the mark (`preview_scope`, `in_preview`) and `emit_record_event`, the one emit of a record event. The door emits through it, and it checks the preview mark. A preview emits nothing, so a preview cannot start a workflow. **No migration, no new route, no new flag:** the door is dark behind `STUDIO_ORGS`, and a call with no `preview` key runs as before. **Not in this slice:** the client half (G4b), a preview of a draft object that is not published yet (404 `object_missing`), and the dry-run door of F4, which can reuse this mark.
