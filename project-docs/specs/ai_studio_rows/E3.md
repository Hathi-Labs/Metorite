## What

Studio triggers: record, form submit, button, skill. Each trigger registers as a contribution of its install (§11.1). 🔨 **E3-1 BUILT, dark (2026-11-13): the record trigger.** An event trigger with source `studio` takes an optional `filter` on `package_id`, `object` and `op`. It fails closed, and one event starts one run of a workflow even when two triggers match. **Access fix (task 3076, 2026-11-13):** a record event starts a workflow only when its author (`workflows.owner_email`) can read the package that the payload names. The check is `studio/access.py::member_reads_package`, the read rule of the action door. The owner reads, and a viewer reads through an install when the org is on `PACKAGE_HOST_ORGS`. It runs in the org-bound session of `dispatch_event`, for each workflow, before the version loads. A missing package id, an unknown package or a read error starts no run, and the log line holds no payload. The author must also be an active member of the org with `feature:studio`, by the same resolver as the run door (`resolve_access_in_org`). A suspended author, or one with no `feature:studio`, starts no run. The log line shows once for each workflow. **Pool fix (task 3087):** `dispatch_event` never holds two pool connections. A short session reads the candidate rows and closes. Then `studio/access.py::members_holding_studio` resolves each distinct author once, outside any session, so many workflows of one author cost one resolve. Last, a second session runs the package read (`member_reads_package`, with the answer passed in) inside a savepoint, and loads each version. Before the fix, a burst of record writes made each dispatch hold one connection and wait for a second, until the pool timed out and every check answered False. Fence: `test_workflows_triggers_r8.py` (the real resolver, and a spy on the open sessions). **Trigger write rule:** a save of a workflow (`PUT /workflows/{id}`) by a member who is not `workflows.owner_email` answers 403 when it ADDS or CHANGES an enabled Studio record trigger. The compare is by the whole config. A removal, an unchanged trigger and each other trigger kind stay open to every author. Without this rule, a member could point the workflow of another member at a package that they cannot read, and then read the run payload. The rule does not change other event sources. Fence: `tests/unit/test_studio_record_trigger_filter.py`, `test_workflows_triggers_r8.py`. **Open:** form, button, skill, and the stop on install removal
