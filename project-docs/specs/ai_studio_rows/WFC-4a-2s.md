# WFC-4a-2s

Tier: HIGH

Gate: AGENT-SAFE. Before any org turns on the four flags **Known edge (Opus review, accepted):** a copy of a workflow gives the copier a write that another member wrote, and the card of the copy asks the copier. The copier chose to copy it, can read every value in the graph, and must publish and approve it. A follow-up may blank the write config of a copy (task to file).

## What

🔨 **BUILT (2026-11-15, task 3309).** **A server rule: only the owner may add or change a `studio_write` config.** The gateway answers 403 when a member other than the owner of the workflow saves a graph that adds a `studio_write` node or changes its config. This rule must ship before any org turns on the four flags of the unattended path. The owner approval card hides a key that looks secret, and it clips a long value (`park.py`). So the owner may approve a write that holds more than the card shows. The editor is not a security boundary, and WFC-4a-2a only hides its form. **As built:** `crud.update_workflow` calls `_refuse_foreign_studio_write` on each Save. It checks a Save that holds a graph from a caller who is not the owner. `_is_author` compares the two addresses trimmed and in lower case. `engine/graph.studio_write_prints` is the one read. It takes each node of `nodes` whose type is `studio_write` in any case or with outer spaces. Its print is the id, the exact type and the config as JSON with sorted keys. A print of the Save that is not in the stored draft gets 403. So a new id, a changed config, a type that changes to a write and a new spelling of the type each get 403. A second node with the id of a kept write and a write with no id get 403 too. A missing config and `{}` give one print, because the run reads both as `{}`. The check reads the stored draft `FOR UPDATE` in the tenant session, after the trigger lock of the Save. The answer is `Only the owner of this workflow may add or change a step that writes a record. Ask {owner}.` No route, flag or migration changes. **The writers of the draft:** the PUT is the one writer that a member can reach. A create starts empty and belongs to its maker. A copy belongs to the member who copies it, so its write runs as that member. The Copilot and the Studio chat tools never save a graph. **Known edges:** a rollback republishes a stored version and never writes the draft. So a version published before this rule can still hold the write of another member. A write that another member added to a draft before this rule stays, and that member may keep it. The browser cannot hold an integer past 2^53 exactly, so a write with such a value can make the Save of another member get 403

## Done when

A save by a member who is not the owner gets 403 when it adds or changes a `studio_write` config. A save that leaves each `studio_write` config as it was stays open. Fences: `tests/unit/test_workflows_studio_write_owner_rule.py`, and case g of `test_workflows_author_gate_r8.py` (R8, two orgs)
