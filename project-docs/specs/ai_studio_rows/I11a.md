## The connections rule after I9a (2026-11-15)

**The rule.** `invoke._live_unmet` calls `resolve.first_unmet_connection(manifest, met, False)`. That is the call `_needs_connection` makes for a preview of each other source. A draft is no install, so `org_approved` is False.

**What it means.** `mcp:<server>` is an `org` need, because an MCP server is an org row and I9 opens no `as: member` for it. I9a meets an `org` need only with an org row AND an approved org install. So a live preview of a draft never meets the need. It answers 409 `needs_connection` with `provider` and `as`, and it calls no server. This holds when the org holds a connected row and the member holds the grant. A viewer of an approved org install gets `source_not_open` (I11a reads for the owner only). So the live read never calls a server today. It fails closed.

**Owner question (open).** Choose one:

1. The owner's preview of the owner's own draft counts a connected org row as met. That applies only with the grant `integrations:use:mcp-<server>`, and only in a preview. It needs a change to the I9a rule for previews.
2. The live read waits for an install. A viewer of an approved org install reads live through the I9a rule, and the owner previews the installed version.
3. I11a stays closed until I9b.

Do not open the rule without this decision.

**Tests.** `TestTheRealRule` in `tests/unit/test_studio_live_preview.py` proves the refusal: 409, no `tools/list`, no `tools/call` and no read of the registry. It covers a plain name, `{name}`, `as: org` and `as: member`. `test_with_the_real_rule_a_draft_sends_nothing` (I11-0) and `test_r8_a_draft_never_meets_the_mcp_need_on_real_rows` (R8) cover the same refusal. The other tests of the live path use a marked STAND-IN for option 1. It counts an org row as met, so they fence each step after the rule.
