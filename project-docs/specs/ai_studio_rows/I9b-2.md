## What

(Task 3357.) **OPEN.** The approval of the org ACCOUNT, and the pin of that approval (task 3169, the audit of 2026-11-15). I9b-1 checks the scopes. It does not record which account an admin approved. So a second org account, or a reconnect to another account, still meets an approved need. I9b-2 closes this. 

**The design:** (1) A new table `studio_org_account_approvals (organization_id, app_id, version, provider, connection_id, consent_id, approved_scopes TEXT[], approved_by, approved_at, PRIMARY KEY (organization_id, app_id, version, provider))`. It has FORCE ROW LEVEL SECURITY and passes the source gate of `test_tenant_coverage.py`. (2) Composite foreign keys: `(organization_id, app_id, version)` to `app_versions` (this needs a new unique index there), and `(organization_id, connection_id)` to `integration_connections` with `ON DELETE CASCADE`. (3) An expand-only column `integration_connections.consent_id UUID DEFAULT gen_random_uuid()`, regenerated in the `DO UPDATE` of each upsert. A token refresh does not regenerate it. A reconnect to the SAME account asks again too. This fails closed, and it is recorded as a known limit. (4) A new route `POST /studio/packages/{id}/versions/{n}/approval/account`. It needs `studio:publish`, and it refuses the publisher and the owner. It writes with the `review_status` move, under the version row lock, and it writes one `app_audit` row. (5) The pin in the rule: the `connection_id` and the `consent_id` of the approval must equal those of the connected org row now. (6) The migration number: 446, booked. Re-check it at build time (R1). 

**R8 tests to name:** `test_org_b_never_meets_org_a_approval`, `test_account_b_after_approval_of_a_unmet`, `test_same_account_reconnect_asks_again`, `test_fewer_scopes_unmet_reconnect`, `test_more_scopes_met`, `test_widened_version_asks_again`, `test_publisher_and_owner_cannot_approve_account`, `test_non_holder_403`, `test_draft_private_group_org_need_text`, `test_deleted_connection_cascades_unmet`, `test_rls_forced_on_new_table`. **Mutations to run, each turns a named test red:** drop the `organization_id` of the pin, drop the `consent_id` test, drop the publisher refusal, drop the version lock, let a widened version keep the old approval, and drop the cascade. 

**Decisions (owner, 2026-11-14, task 3169):** an admin is a holder of `studio:publish`. A private install, a group install and a draft keep failing closed. The scopes are the strings of the provider, compared literally.
