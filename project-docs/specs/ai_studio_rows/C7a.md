# C7a

Tier: HIGH

Gate: AGENT-SAFE. After C6

## What

🔨 **BUILT, dark (2026-11-02).** No route, no flag and no UI reach it, and it needs no migration. **Formula fields** (§3.7 layer 2), stored and computed on write. **Ships:** `acb_common/studio_expr.py` (a pure closed JSON tree, no SQL) and the rule kind `formula`, `{name, kind, target, expr, scale?, rounding?, currency?}`, in the `rules` list of C6. `rounding` is required for a number target, and `scale` defaults to 0. The store computes each formula inside `_apply_write`: it validates the record without its targets, then runs each formula in dependency order, then builds the hot rows from the result. A read never computes. **Grammar:** literals (`num` as decimal text, `money`, `text`, `bool`, `date`), `ref` to a field of the same record, and the functions by type. Null propagates, and `coalesce` and `is_empty` take it. `if` is lazy. Caps: depth 8, 64 nodes, 4 args, 256 steps, 8 formula rules for each object. **Money:** whole minor units, no float, a named `rounding` (`half_up`, `half_even`, `down`, `up`) on each `div` and on each `mul` with money. Division by zero is `division_by_zero`. **Number precision:** a number target has a `scale` (0 to 4) and a `rounding`. The stored result holds at most 15 significant digits at its scale: `abs(result) < 10 ** (15 - scale)`, or the write is refused with `result_too_large`. So a JSON float holds it exactly. Money stays a whole number of minor units below 10^15. **Targets:** number, money, text, checkbox, date. A target is not `required`, and a caller cannot write it. **The description.** `StudioObject.computed` and the `computed` part of `studio_describe("fields")` name each formula target as computed, so a Form shows it read-only and sends no key for it. A write that holds a key for a target is refused with `computed_field`, also with the same value. **Declare first.** A new formula, or a formula with a changed `target`, `expr`, `scale`, `rounding` or `currency`, on an object that holds records is refused (`ConstraintError`, "declare before the first record"), because there is no backfill. A change of only `name` or `message` passes. ⚠️ A stored formula that is malformed counts as a new one. The author removes it first, and can add it again only with C7c. A removed formula is allowed, and its stored values stay as plain values. **The other rules.** `range`, `unique`, `group_sum_min` and a state-machine guard that name a formula target read the stored result, because the checks run on the record after the formulas. `rule_reads(rule)` answers every field key that a rule reads, and C9 uses it. **Errors:** `FormulaError(RuleViolation)` holds the rule, the object and a code (`division_by_zero`, `currency_mismatch`, `result_too_large`, `step_cap`, `type_error`, `bad_argument`, `bad_result`, `computed_field`, `declaration`). It never echoes a value. A tree over a cap is refused at declaration with the JSON path and one sentence, and a forged stored tree refuses each write. A forged stored list of more than 8 formulas refuses each create and update with `declaration`, and a delete computes nothing, so it passes. A `lower` or `upper` of a `longText` ref into a `text` target gives `result_too_large` when the value passes the text limit, and that blocks the writes of the record. **Not shipped:** roll-ups (C7b), a clock, a backfill, a restricted field (C9 adds the refusal, using `rule_reads`, and it is advisory in C7a), a text syntax, a UI, a route. The manifest key `formula` is no longer reserved (a rule uses `expr`), and the field type `formula` stays refused with a message that names the `rules` list.
