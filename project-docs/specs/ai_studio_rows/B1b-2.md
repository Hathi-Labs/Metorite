One deadline of 20 s covers the connect and all pages, and the read follows 5 pages at most. An `outbound_guard.AnswerBudget` counts the bytes while they are read. One answer may hold 1 MiB, and the whole read 4 MiB. A cap that fires stops the read at once, with the code `mcp_too_large`. The cap counts wire bytes, and httpx inflates a coded answer after the count. So a budgeted session sends `Accept-Encoding: identity`, and a stored header cannot change it. The cache is `tenant_redis`, namespace `studio-mcp`: one key for each server and one `index` hash of the cached servers. Each key holds the last good list with `fetched_at`, and it lives 7 days. The GET carries `stale`. The org is the session org. A bad key is 404. A server of another org is 403 `mcp_not_allowed` since the I11a review. A second refresh of one server within 30 s is 429 with `Retry-After`. A failed or slow server is 502 with a code: `mcp_timeout`, `mcp_refused`, `mcp_too_large` or `mcp_unreachable`. The code reads each exception of a group and each cause, so a wrapped refusal is `mcp_refused`. A failure drops the list of that server only. A refresh notes its start time when it takes its slot. A failure drops the stored list unless that list is newer than the start. So a late failure keeps the list of a newer refresh. It drops an older list also when the slot has expired. The server key must match in full, so a key with a new line at the end is 404.
