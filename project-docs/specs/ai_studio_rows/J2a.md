# J2a

Tier: HIGH

Gate: AGENT-SAFE. Dark behind `PACKAGE_HOST_ORGS`

## What

🔨 **BUILT, dark (2026-11-11, task 1200).** **The read of a viewer.** A viewer is a member who does not own an app and sees an install of it. `GET /studio/packages/{id}` reads the owner first, and that answer does not change. When the owner read misses and `PACKAGE_HOST_ORGS` holds the org, `package_host/viewer.py` reads the app. It calls `resolve.visible_installs`, the one read of the sidebar (`read_installs` and `widest_per_app`), so no second install query exists. The answer holds `access: viewer`, the installed `version`, its manifest and its hash, and never the draft. The objects are the rows that the installed version names, with only its fields and its rules (`InstalledApp.project`). A later publish adds fields to the rows. The door reads the declarations of the installed version in `invoke._check`, at both runs of the one check. A viewer's get and list run. A record that a viewer reads holds only the values of the installed fields, and names no writer (`project_record`). A filter or a sort on another field is 422 `query_field_unknown` before any read. A viewer's create, update and delete get 403 `read_only` before the body, also with a proof or `ask=1`. A read of a viewer takes a slot before its session (`_reader_slot`, in the shape of `_IN_FLIGHT`): 3 for each org and 6 in all. Past the cap the answer is 503 `store_busy` with `Retry-After`. A read of the owner takes no slot. The audit row of a viewer holds `viewer: true` and the version. No migration and no new flag. **The page (fix round 1):** `/studio/package-preview` reads `access`. For a viewer the door holds the reads only, and the Table and the Board do not edit. The page draws no Form, no Edit, no record delete, no IDE link and no app delete. One line says that the owner changes the app, and a 403 `read_only` says the same. The chat read `studio_package_get` gives a viewer `access` and the installed version, and a note. The note names the owner. ⚠️ **A viewer sees every record of the app until C8** (row rules, §19.7). ⚠️ **Known gap (fix round 2, not fixed in code):** a stored value of a formula or a roll-up follows the rule of the NEWEST version. The trigger is narrow: the owner publishes a changed formula or roll-up while the object holds no records, and records come later. A viewer of the older version then reads values of the newer rule beside the older rule. J2b or C8 closes it, with the R8 case `test_r8_a_pinned_viewer_reads_the_values_of_the_installed_formula`. **The aggregate (C2b):** when the door gets an aggregate executor, it runs `studio_query.parse_aggregate` on the `project()` fields of a viewer first, as the list runs `parse_query`. **The IDE (fix round 2):** `getPackageDraft` refuses a viewer with the "not on" state, so `/studio/build` shows "This app is not available to you", as before J2a. **Defaults, owner to confirm at the preview:** (1) the switch is `PACKAGE_HOST_ORGS`, and J2a adds no flag. (2) The widest install wins when a member sees an app at two scopes, as in the sidebar. (3) The cap is 3 reads for each org and 6 in all. (4) A write of a viewer is 403 `read_only`, and it asks for no card. (5) The answer to a viewer names no owner and no slug, and shows only the objects, the fields and the rules of the installed version. A record names no writer. (6) Each other package route stays the owner's

## Done when

A group member reads an app installed for that group: `GET /studio/packages/{id}` gives 200 with the INSTALLED version, never the draft. A member outside the group, a member of org B, and any caller while `PACKAGE_HOST_ORGS` is off get 404. A viewer's object get and list give 200 on the declarations of the installed version. A viewer's create, update and delete give 403, and the page offers no write. A field that a newer version adds never reaches a viewer of the older version. A draft-only install never reaches a non-owner. A paused, archived or expired install gives 404 at both door checks. Past the cap of reads the answer is 503 `store_busy` with `Retry-After`, and the answers to the owner do not change.
