## What

🔨 **BUILT, dark (2026-11-11).** No flag and no migration. **D4b (2026-11-11, task 2954):** the action door serves it as `object:<name>.aggregate`, and the D4 Chart and Stat read it through `realDoor.ts`. See the D4 row. **The aggregate:** a group, a count, a sum and an average, on hot fields only. **Built:** `acb_common/studio_query.py` holds the grammar: `parse_aggregate`, `check_aggregate_shape` and `aggregate_input_schema()`. The door of D4b reads the keys of the schema, and the list input of B2b-1 does not change. `objects_store.aggregate_records(db, *, package_id, object_id, filter, group_by, measures)` is the one reader. It answers None for an object of another package or org. `build_aggregate` is pure. **The input.** `filter` has the grammar of C2a. `group_by` is None or `{field, bucket?}`. `measures` is a list of 1 to 4: `{op: count}`, or `{op: sum or average, field}`. No measures means one count. **The rules.** A group and each measure read a hot field. Another field gives `query_not_indexed`. A group takes each type of the op table except money, because a money value has a currency. A sum takes a number or a money field, and an average takes a number field. The grammar refuses an average of money, because no rule rounds it. A date or a datetime groups by day or by month in UTC, and a group that names no bucket takes `day`. A text groups by its whole text, as `eq` reads it, so a value of 256 characters reads `data`. A checkbox has two states, so a record with no value joins `false`. For each other type, the records with no value form the group None, and it comes last. **The groups.** The 50 groups with the most records stay, with the ties in the order of the key. The rest fold into one group, `other`, and `folded` counts them. The answer lists the kept groups in the order of the key, and a select in the order of its options. `total` holds each measure over every record that the filter keeps. A sum with no value is 0, and an average with no value is None. **Money (HANDOFF H-333).** The statement reads the currency of each amount of a money sum from `data`. Two currencies, or an amount with no currency, refuse the whole sum with `query_op_not_allowed`, also when each group holds one currency. The sentence names no currency. One currency comes back in `currencies`, for a sum and for an average of money (D4b). A money filter does not check the currency (C2a), so a filter cannot pick one currency yet. **One statement.** It reads the groups, the total and the currencies in one snapshot, so a write between two reads cannot add a second currency to a checked sum. It reuses `_q_filtered`, the guard `g` and `m` (`hot_or_small`), the check `v` of the fields that are still hot, and `_time_limit`: one deadline of 5 s, a SAVEPOINT and a LOCAL `statement_timeout`. It uses the six errors of C2a and adds none. **The candidates** come in no order (`_q_source(ordered=False)`), because the order of the id with no LIMIT made the planner read a table of 50,000 records by a Seq Scan and sort it. Each candidate reads the hot row of the group field and of each measure field by the key of the hot table. ⚠️ **The known limit.** An aggregate with no hot filter reads each record of the object. On a table that holds the object and little else, the planner may read it by a Seq Scan, which its estimate makes cheaper. Measured on one PC, a month group with a sum over 50,000 records took 0.8 s under EXPLAIN ANALYZE. No cap limits the records of an object, so a big object can reach `query_timeout`. **Not built:** a chat tool (B2b), two group fields, an average of money, a group by a currency, and a restricted field (C9). C9 must refuse a group and a measure on a restricted field.
