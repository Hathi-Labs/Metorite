## Done when

Each of the 13 kinds renders from a C2b result. **Build note:** `lib/studio/aggregateModel.ts` reads the C2b result and builds the short spec of `kinds.mjs`. `LiveChart` stays the one renderer, and no chart library is new. The Chart is the `chart` template and the Stat is the `sparkTrend` template. Both bind through `bindsSource`, and `BoundSource` in `GenerativeUINode.tsx` draws them with `StudioChart` and `StudioStat`. The door answers an aggregate as one row, the C2b result. The manifest has no change: kind, group and measures go in `source.args`. A chart draws at most 30 groups. It keeps the largest and the server `other`, and a line says what is left out. An empty result says "No data". A kind that the result cannot draw says why. A failed read shows the door error. The Stat shows the count, the sum or the average of the total. Its trend is the last day or month against the one before, and it needs a date group. **D4b build note (task 2954).** The action door serves `object:<name>.aggregate` as a third class A read, beside get and list, and no route is new. `OBJECT_OP_CLASSES` gives it class A. `RECORD_OPS` holds the five record verbs, and `complete_record_actions` adds only those, so a package declares its aggregate action itself. The catalog lists one more row for each object. The body takes only `filter`, `group_by` and `measures` (`AGGREGATE_INPUT_KEYS`, from `aggregate_input_schema()`). The door runs `check_aggregate_shape` before it reads the object, so a bad key, a bad op and five measures get 422 and read nothing. Then the list path runs: `get_object_by_name` in the package of the path, then `aggregate_records`. The errors, the 404 `object_missing`, the 413 and the audit row are those of the list. The answer is the one row of `parseAggregate`. A measure names its field by the key, a `Decimal` is exact text, and a money sum is an `int` of minor units with its currency. **Money (finding F1).** The C2b grammar refuses an average of money with 422 `query_op_not_allowed`. An R8 test holds the refusal with one currency, so the refusal of a mixed sum cannot hide it. As a second guard, `aggregate_records` now sends the currency of a money average too. An R8 test opens the average in the grammar and gets the currency, and `aggregateModel.test.ts` holds that a currency scales an average. `realDoor.ts` accepts the verb, sends only the three keys of `source.args`, and answers one row. So `kind` in `source.args` never reaches the door, and an aggregate body cannot match the keys of a write. **D4c build note (task 2955).** The mapper is built, and the manifest has no change. `chartViewBlock` and `statViewBlock` in `aggregateModel.ts` turn a `chart` or `stat` view into the nodes `chartBlock` and `statBlock`. The view names an action id of `actions`, and that action uses `object:<name>.aggregate`. A view with only `source.object` reads the aggregate of that object. `source.args` holds `kind` (one of the 13), `group_by`, `measures` and `filter`. A stat also reads `measure` (an index) and `good` (`up` or `down`). The A2 validator already passes an aggregate source, because the class of `aggregate` is A. A bad kind, a missing or unknown action and a non-aggregate action each give one plain sentence. The page preview shows the sentence in a panel. The sample page has a Visits stat and a Visits by status donut on the Plan tab. The sample door answers `object:visit.aggregate` from its own rows, so no live door runs. **Not built:** the mapper in the installed app (no installed-app page maps views yet, and H1 owns it), and a chat tool for the aggregate.
