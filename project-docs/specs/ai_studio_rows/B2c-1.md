# B2c-1

Tier: HIGH

Gate: AGENT-SAFE for code. The key on a box is env-write

## What

🔨 **BUILT, dark (2026-11-03).** **Direct writes** (§20.4). A member's own act in the app's screen is the approval: a form Save, an inline edit, a board move. The door opens the create, the update and the delete of an object for a DIRECT call, with no card. **Not in this slice:** delegated writes (B2c-2), the door op, integrations, workflows, a batch route (E8), the UI calls (D2b) and the page confirm of a delete (D2b). **The proof.** The orchestrator runs inside the gateway process, so two tokens cannot tell the callers apart. The proof is a signed header, `X-Studio-Direct`, that only the workbench BFF signs. The key is `STUDIO_DIRECT_KEY`, in the gateway `.env` and in the workbench `.env.local`, with the settings field `studio_direct_key`. A key under 32 bytes, or equal to `GATEWAY_INTERNAL_TOKEN` or `LITELLM_MASTER_KEY`, counts as unset. Then no call is direct. The header is `v1.UNIX_SECONDS.HEX_HMAC_SHA256` over the time, the lowercase member email, POST and the gateway path. The window is 60 s, with 5 s of skew. `packages/acb_auth/acb_auth/direct_proof.py` verifies it with `compare_digest`. The door checks it once, before the body read (`invoke._is_direct`). A call is direct only if the proof holds AND `user.agent` is None AND the user is a member whose email has an `@` and does not start with `system:`. A missing or bad proof gives the same 403 `approval_required` as before, so the door gives no oracle. **The door.** `DIRECT_EXECUTORS` holds object create, update and delete. `OPEN_EXECUTORS` stays get and list, and B2b-2b adds the door op. The bodies are `{data}` for a create, `{id, data}` for an update and `{id}` for a delete, and no other key (422). One `apply_writes` call with one `Write` runs the change. The store refuses a computed key. **One transaction.** `record_app_audit_in(db, ...)` in `routes/apps/_common.py` writes the `app_audit` row in the session of the write and raises on failure. A failed audit therefore fails the write. The row names its record in `record_id`. A create gives its new id, and an update or a delete gives the UUID of its body. A refusal writes its audit row, leaves the session, and only then answers, because an `HTTPException` inside the session would roll the row back. **Writers.** The door admits at most 3 writes in flight for each org, before it takes a session. The first writer of an org always gets a slot. A second or later writer also needs fewer than 6 in all, so two busy orgs cannot shut out a third. A call past the cap gets 503 `store_busy` with `Retry-After: 1` and holds no connection. The count lives in the process. The gateway runs one uvicorn worker, so it holds for the box. The door catches `StoreBusy` before `ObjectStoreError` and answers 503 with `Retry-After: 1`. A rule-check timeout is 503 with `Retry-After: 2`. **Refusals.** HTTP 422 with `{code, message, rule, fieldErrors}`. `FieldError` gives `field_invalid` and a `fieldErrors` entry for the key. Each `RuleViolation` (`ConstraintViolation`, `MoveViolation`, `FormulaError`) gives `rule_refused`, the `rule` and the message. A write to a formula target gives `computed_field`. `FormulaError` gained an optional `field`, so `fieldErrors` names the target. `RecordError` and any other store refusal give `record_invalid`. A body of the wrong shape gives `bad_input`. A missing record is 404. **BFF.** `/api/studio` signs the proof from `lib/gateway.ts` (`studioDirectHeaders`) for a POST to `apps/ID/actions/ACTION` only. It signs only a request from a page of its own origin (`sameOrigin`), because the session cookie is `SameSite=Lax`. A POST from another origin goes on unsigned and gets 403. It forwards `Retry-After`. It adds no other header and no identity. **Delete confirm:** the server cannot see it and does not need it. D2b holds the test that the Delete button asks first. D2b also maps the HTTP detail of a refusal into its `ok`, `message` and `data` (`readRefusal` in `lib/studio/formModel.ts`). **Deploy.** The code ships dark. With the key unset, no write is direct. `scripts/vps_apply.sh` copies `STUDIO_DIRECT_KEY` from `.env` to `.env.local` and never makes one. It reads the last line of the key, as systemd and dotenv do. `.env.example` documents it. Setting the key on a box is gate `env-write`. Generate it on the box with `openssl rand -hex 32`, then restart `acb-gateway` and `acb-workbench`. **Known limit.** Skills run in the gateway process, so in-process code could read the key. The fence `test_only_the_proof_module_and_settings_read_the_direct_key` and review stop that.
