## What

🔨 **BUILT, dark, preview only (2026-11-14, task 2363).** **The gallery block on sample data.** Rung 6. Wave 1 (D202). Cards with a cover image, for a set of photos or a list of products. **The model** is `lib/studio/galleryModel.ts`. It reads `{name: "gallery", source, data: {fields, titleField, coverField, cardFields, openBase}}`. `coverFile` is the one pick of a cover from the `file` fields. `coverSrc` gives an image address only to a card that the observer reported as seen. It takes only a path of this site or the data of a raster image. **The view** is `components/studio/StudioGallery.tsx`. It draws a grid of `TaskCardShell` cards. A card has a cover box with a placeholder, the title, and at most 3 card fields. A field draws through the Board's `CardValue` (`ValueElement`). A single select named status, stage or state draws as its chip, with the `statusAccent` hue of its Board lane. A card with an id links `openBase + id`, as a Board card does, and the link covers the card. One IntersectionObserver and `loading="lazy"` hold the load, so the first markup holds no image address. **The door.** `fileAddress` is an optional member of `StudioDataDoor`. Only `sampleDoor.ts` has one, and it gives pictures that ship in `public/office-objects`. The real door has none, so a live card draws the placeholder. `bindsSource` takes `gallery`, and `BoundSource` has one branch for it. **Preview:** a Gallery section on `/studio/blocks-preview`, with 200 sample assets. One asset in 9 has no photo. **Not in D19a:** a `BLOCKS` token, a `ViewDef` key, the schema JSON, `manifest.ts`, `draftProblems.ts` and `studio_describe`. D19a adds no `mapView` kind, no AF-4 layout, no route and no migration. It takes no cover from a `url` field, adds no chat catalog entry and pages no further than 100
