## What

🔨 **BUILT, dark (2026-11-11).** Store level only: no route, no flag, no UI and no migration. The rule kind binds only an object whose rules declare it, and only the door of an org in `STUDIO_ORGS` reaches the store. **Hierarchy** (task 2349). Wave 2 (D202). Parent and child records inside one object: BOM levels, a site with its buildings and floors, lots. A new rule kind refuses a cycle, and a depth cap of 20 holds. **Built:** `studio_rules.py` gains the kind `hierarchy`, `{name, kind, field, message?}`. `field` is one hot relation field of the object, and its `to` is the bare name of the same object. An object holds one hierarchy. A record with no value is a root, and a root is level 1. The field cannot turn cold while the rule stands. `tree_moves` names the new parent of one written record, and `check_tree` judges the walk. `objects_store.py` gains `_check_trees`, a step after the writes of a batch, under the org lock and the one deadline of the batch. One recursive statement for each object walks up from each record that got a new parent, and down to its children. It refuses a cycle (`tree_cycle`), a parent that is no record of this object, package and org (`field_invalid`), and more than 20 levels on a path through the record (`tree_too_deep`). A write that keeps the parent runs no walk, so an old tree never blocks an edit of another field. `read_tree(db, *, package_id, object_id, viewer, root_id?, depth?, limit?)` reads one tree, or the whole forest, in ONE recursive statement: at most 20 levels and 2,000 nodes, level by level, with `truncated`. A record whose parent is gone reads as a root. The door op `object:<name>.tree` serves it with the rights of the viewer (D18-2a, built). Each walk carries its path, so an old cycle cannot make it run forever. **Not built:** a refusal of a delete that leaves children, and a check of old data at declaration (as C1b)
