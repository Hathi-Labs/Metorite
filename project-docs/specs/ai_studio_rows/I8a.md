## What

🔨 **BUILT, dark (2026-11-14), task 3168.** The Connect step of a build in the IDE. No migration, no new flag and no tool pack change. It rides `STUDIO_ORGS` and `STUDIO_CONNECTION_GATE_ORGS` (I1a). **The read:** `GET /studio/packages/{id}/connections` (`routes/studio/connections.py`) answers one row for each name of the draft's `connections`, in order: `name`, `label`, `met`, `checkable`, `setup_href` and `can_connect`. Only the owner of the package reads it, and each other member gets 404. With the gate off, it answers 404 and reads no registry. `met` comes from `resolve.met_connections`, the one read of I1a, so an org row of org A never meets a need of org B, and the member row of X never meets a need of Y. `label` comes from the connector list (IN-11) for a provider id, and it is the server name for `mcp:<server>`. **The provider-level map:** a missing connection has no registry row, so its link cannot come from a row. `routes/integrations_connections.setup_href_for(provider)` reads the owning app of the provider in the connector list, then `_SETUP_HREF`. The IN-11 name `console` is the registry's `integrations`. An id off the list, and the bare id `mcp`, are blocked with no button: no registry writer writes them, so the read never meets them (`routes/studio/connections.checkable`). The line for the bare id `mcp` ends "Name the server, as mcp:<server>." `mcp:<server>` gives `/integrations?add=mcp&name=<server>`. The map now holds Calendar (`/calendar?settings=1`) and Knowledge (`/knowledge/sources`), so the console row of a calendar or a Drive connection links to its own app too. ⚠️ This console change is live with no flag: a Calendar or a Drive row of `/integrations` now reads Calendar or Knowledge, with an Open in link (`_app_of` and the two new keys). A provider that signs in with a key links to `/integrations`, the Connections view, and not to the API keys view, because the key flow is I8e. **Outside the registry:** a mailbox lives in `email_accounts`, a WhatsApp number in `wa_accounts`, and each key of the console (the 8 rows of the connector list with `signin: key` and owning app `console`) in `provider_keys`. So the read cannot meet them until I9 and I8e. `connections/store.OUTSIDE_REGISTRY` is the one set of such providers, and the store computes it from the connector list. Their row has `checkable: false` and `can_connect: false`. While the gate lists the org, the action door refuses each action of an app whose draft names one (I1a). So the IDE line says what is true and the next step: "<Provider> cannot be connected from Studio yet. This app will not run while the draft names it. Remove the name until Metorite can check it." It has no button, and the header counts it. A test fails when a listed provider has neither a registry writer nor an entry of the set, and when a `_MET*` statement reads a table of the set. `may_connect(user, provider)` is true for a holder of `integrations:manage`, and for a member connection of the list (`integrations_console.md` §3.5). **Its step:** the IDE of the app, `/studio/build?pkg=<id>`. **The return:** Connect adds `return=/studio/build?pkg=<id>` to the server's `setup_href`. `safeStudioReturn` (`src/lib/studio/returnPath.ts`) is the one guard. It passes a path of this site under `/studio/`, read as the browser reads it, and it drops each other value. In I8a only the console reads `return`. `/integrations?add=mcp&name=<server>&return=<path>` opens the Add form with the name, for a holder of `integrations:manage`, and a successful add goes back through the guard. Each other owning app ignores `return`, so the member comes back by hand. **The UI:** the Problems panel of the IDE shows one line for each name. A met name reads "<provider> is connected." An unmet name has Connect, which opens a sheet over Studio (`components/studio/ConnectSheet.tsx`, the AF-6 pattern). Its one action is a link to the connect page, so the leave guard of the IDE asks before an unsaved draft goes. A member who may not connect reads "An admin must connect <provider>. Ask one, then come back." and gets no button. The page reads the lines again after each save and on focus. The header counts each name that is not met, blocked names too: "1 connection needs attention". A read that fails (a 5xx, the network) shows one line, "Metorite could not check the connections of this app. Try again in a moment.", with Retry. Retry shows its busy state while the next read runs. The rows of the last answer stay, with their count in the header. With no rows, the header reads "connections not checked", never nothing. On a phone, the Problems tab counts each problem and each name that is not met. **Tests:** `test_studio_connect_in_place.py`, `test_studio_connect_in_place_r8.py` (R8, in both `--must-run` lists), `test_studio_route_gate.py`, `src/lib/studio/connect.test.ts`, `src/components/studio/ConnectSheet.test.ts`, `src/app/integrations/components/mcpConnect.test.ts` and `src/lib/studio/viewerSurfaces.test.ts`
