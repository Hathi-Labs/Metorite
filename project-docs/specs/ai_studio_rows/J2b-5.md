## What

🔨 **BUILT, dark (2026-11-13, task 3103).** **The per-person unshare.** `DELETE /studio/packages/{id}/share/{email}` (`routes/studio/packages.py::unshare_package`) takes the share of the private install back from one person. It ships behind `STUDIO_ORGS` and `PACKAGE_HOST_ORGS`. Either switch off gives 404 with no session. A bad id is 404. The right is `studio:publish` (D180.3), as for the share. A member without it gets 403 `forbidden` before any session. Then the store checks the address before any session: 422 `bad_people`, `not_a_person` or `own_address`. The address is folded as the share folds it. Then one session. `_owned_private_install` holds the `apps` row `FOR KEY SHARE` first. A package of another member, of org B or an archived package is 404. An owner with no private install is 409 `private_only`. Then the writer `promotion.unshare_person` takes the org lock and the row lock, in the order of the share. It refuses a member who is not the owner (403 `not_owner`) and an install that is not private (409 `not_private`). It deletes only the row of `app_grants` that `sharing.SHARE_ROW` counts for that install and that person, with `granted_by` the session member. A consent row and the share row of another member stay. **Decision: a pause never blocks an unshare.** The writer does not call `refuse_unless_kept_private`. A paused, archived, draft or not kept private install still unshares, because the owner must always be able to take access back. **Decision: the unshare is idempotent.** A person with no share row of this owner gets 200 `{removed: false}`, and no error. A removed row gives 200 `{removed: true}`. One `app_audit` row (kind `action`, op `package.unshare`) commits with each 200. It holds the install, the person and `removed`, and no value of the app. The sharer comes from the session, never from the path or a query (R5). No migration and no new flag. Until C8b maps the roles of an install, a grantee holds no role. So a grantee reads each record of an object that has no `access`, and no record of an object that names `access`. A grantee never writes (403 `read_only`). J2b-3b carries that warning in the chat twin, and the screen slice carries it on the screen. No chat twin and no screen call the route yet
