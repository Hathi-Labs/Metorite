## What

🔨 **BUILT, dark (2026-11-04).** **Live door and writes for the three blocks, on a preview route** (task 1397). After B2b-1 and B2c-1, both merged. **Built:** (1) `lib/studio/realDoor.ts`, the first real `StudioDataDoor`. Its scope is the package id plus `:live`. `read` accepts ONLY `object:<name>.list` and `object:<name>.get`, and refuses every other source with no network call. The BFF signs the direct proof for EVERY same-origin POST to the action route, so it cannot tell a read from a write: this client guard is the only line. The door maps the verb to the action id that the manifest declares (`{id, uses}`), because the route takes the id. It flattens each record of the list answer to a row of `id` plus `data`. `run` maps a 422 (`code`, `message`, `rule`, `fieldErrors` as a list) to `data` with `fieldErrors` as a map, `rule` and `message` (`readRefusal` in `formModel.ts`), a 503 to a retry sentence with the `Retry-After` wait, and a 403 `approval_required` to a plain sentence. It never shows the raw error text. (2) Inline edit in the Table for the scalar types (text, number, select, checkbox, date, url, email, phone), in the store `lib/studio/inlineEdit.ts` on the pattern of `boardMove.ts`, drawn by `components/studio/StudioTable.tsx` through an optional `edit` prop of `DataGrid`. The cell shows the new value at once, one update follows with the id and one key, and a refusal restores the old value and shows the rule or field sentence. A field that a `formula` or `rollup` rule fills never edits. Other types edit in the Form. (3) The Form creates and updates through the real door, with no change to `StudioForm`. (4) `components/studio/DeleteRecordButton.tsx` on `ui/ConfirmDialog`, in the Detail sheet, with the store `lib/studio/deleteRecord.ts`. (5) The preview route `/studio/package-preview?pkg=<id>&object=<name>`, in no nav pane: a package picker, an object picker, then the Table, the New-record Form and the Detail sheet. A package with no object shows "Publish the package first". An org outside `STUDIO_ORGS` gets an empty state and no error. (6) Chat READ tools `studio_package_get` and `studio_record_list` in the studio pack, with their `chat_parity.py` rows (the studio ceiling stays 0). (7) `scripts/dev_seed_studio.py` makes and publishes a sample package with three records on the local stack. `dev_up.sh` passes `STUDIO_DIRECT_KEY` to the gateway and the web app only when the operator sets `DEV_UP_STUDIO_DIRECT_KEY` in the shell. **Fix round 1 (2026-11-04):** Two guards keep a read from writing. The client guard holds for the manifest that the page read at open. A later draft can point an action id at a write. So each `.get` body is `{id, read: true}`, and every write refuses a body with that key (`_write_input` takes exactly the keys of the write). Both Forms leave out a field that a `formula` or `rollup` rule fills, because the store refuses it with 422 `computed_field`. The page keeps one door while the package and its actions stay the same, so a focus read does not reset the edit store or the delete flow. A failed read shows one alert with the sentence of the door, and Retry shows only for a 503 or a network fault. A rule refusal shows only the own message of the rule after its name. An editable cell wears a small pencil mark that needs no hover. The seed holds a `line` object with a formula, `total = qty * price`, and no record, because a formula must exist before the first record. **Not in this slice:** a chat write tool and any agent write (B2c-2), a view-to-node mapper and a sidebar entry (PKG-8, H1), a nav entry, a Board change, a batch route, a delete in the Table row, a gateway route, a change to `route.ts` or `lib/gateway.ts`, and setting `STUDIO_DIRECT_KEY` on a box (gate `env-write`).
