# WhatsApp bots for multi-tenant SaaS: official facts (researched 2026-11-10)

Legend: [V] = verified in Meta docs fetched 2026-11-10 (docs pages carry no "last updated" date unless noted). [3P] = third-party claim. [GAP] = could not verify.
Base docs path: https://developers.facebook.com/documentation/business-messaging/whatsapp/ (add `.md` for raw text; index at .../whatsapp/llms.txt)

## BLUF
- Official Groups API EXISTS, but it is a business-OWNED-group model: the business creates the group, humans join by invite link. **Max 8 participants. Cannot add the bot to an existing human-created office group. Cannot add participants directly.** So "bot joins our office group and answers @mentions" is NOT possible officially.
- Groups API needs an Official Business Account (OBA), Cloud API number only (not WhatsApp Business app, not coexistence numbers).
- AI policy: Business Solution Terms s4.7 (eff. 2026-01-15) bar AI Providers whose AI is the *primary* functionality. A company's own support/scheduling bot is not that. A Metorite "AI assistant for all" product on one number could be.

NOT possible officially (summary): join an existing human group; add members directly; groups >8; read history; interactive/poll messages in groups (documented as unsupported); use on coexistence or Business-app numbers; edit/delete group messages. Mentions/reactions unconfirmed.

Design consequence: the official path for "bot in a group" is a small (<=8) Metorite-created group per team/project, with the company number as 1 of 8 members, and only for OBA-verified tenants. For a whole office group, the official alternative is a 1:1 bot chat plus the company's humans forwarding. Slack-style @mention bots in existing groups need an unofficial client (section 4).

If offered, make it opt-in per tenant, on a dedicated secondary number, reply-only, with an explicit risk acknowledgement.

## 5. Webhook/API design details

| # | Fact | Source | Status |
|---|---|---|---|
| 5.1 | Signature: HMAC-SHA256 of raw request body with the **app secret**; compare to hex after `sha256=` in `X-Hub-Signature-256`. (Overview page itself does not describe it; create-webhook-endpoint page does.) mTLS optional (enable per app). IP allowlisting discouraged (IPs change). Self-signed TLS not supported. | webhooks/create-webhook-endpoint.md; webhooks/overview.md | [V] |
| 5.2 | GET verify: echo `hub.challenge` when `hub.verify_token` matches. POST: return 200. | create-webhook-endpoint.md | [V] |

| 5.4 | Webhook server sizing from Meta: handle 3x outgoing status traffic and 1x incoming; median latency <250 ms, <1% above 1 s. | throughput.md | [V] |
